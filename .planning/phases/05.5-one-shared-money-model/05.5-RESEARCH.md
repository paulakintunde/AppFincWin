## Summary

05.5 is a consolidation phase. Most of what it must "build" already half-exists: 06.1 shipped a Decide-side `monthPicture()` "to the 05.5 contract shape" (`src/engine/decide/v3/month/picture.ts`, new on the 06.1 branch), Grow shipped three of the seven connection points as `src/features/grow/connect/*` with parity tests on main, `afterBuy.ts` already exposes `homeFigure`/`monthAfterPlans`, and the shadow/golden/reviewed-diff pipeline from 05.4 is the right tool for the D-07 changed-answers page. What is genuinely new: the shared `src/engine/month/` owner including `leftSoFar` and `countsForMe`, Home reading it, the cap merge into `categories.monthly_cap`, the builder rebuild that reads rows directly, the deletion of 34 old-engine files and ~100 old test files, two expand/contract migrations, a per-sentence copy guard that also runs in ESLint, and a nightly Maestro-on-emulator workflow.

Two facts shape the wave plan. First, 06.1 (PR #102, state OPEN, "CONFLICTING" with main today) rewrites or deletes most of the files the builder swap touches (`buildSnapshot.ts`, `buildV3Inputs.ts`, `computeV3.ts`, `settingsSource.ts`, `data/queries/decide.ts`, `decideV3.ts`, `db/decideSettings.ts`, `exportManifest.ts`, `decideSetup.ts`, `en.ts`, `jest.config.js`, `eslint.config.js`), so everything except new-file work must wait for it (D-02). Second, Phase 8 plans hard-code three things from 05.5: an exported name `countsForMe` found by `git grep -E "export (function|const) countsForMe" origin/main -- src`, a BO-07 contract-test file whose path matches `bo-?07|contract` and `test`, and the unchanged path `src/engine/decide/share.ts` (08-03 greps `from '../decide/share'`). Wave 1 must satisfy those exactly, and old-engine deletion must keep `share.ts` where it is (or leave a re-export).

The largest semantic risk is Home's lead figure. Home's "left after everything" (`paidIn + paidOut - unpaid outflows`) and Decide's `monthLeft` (money in including expected pay still due, minus bills paid and due, everyday logged, everyday still to come, set-asides, minus carried overdraft) are different quantities built from different pipelines (stamped home amounts vs cautious conversion; Activity rows vs `V3Line` roles). Making Home lead with Decide's figure changes every user's Home number, so it belongs on the D-07 changed-answers page, and Home needs the Decide `Prepared` (17-read snapshot) which conflicts with `useHomeViewModel`'s "no extra server call" design.

**Primary recommendation:** Wave 1 (new files only, safe beside 06.1): `src/engine/month/` types plus `countsForMe`, the BO-07 contract suite (`test.todo` for household scope, settlements, income profile, visibility; live for the Grow-owned points that Grow already tests), the accounts depcruise contract, the copy-guard module in report mode, the ENG-16 lint rule and the nightly Maestro workflow. Everything that edits 06.1-touched files starts only after 06.1 is merged: new builder beside the old with a parity harness, then month picture re-homed and Home switched, then caps/forms/detectors/calendar, then expand migration, then old-engine deletion and column drop last.

## Common Pitfalls

### Pitfall 1: Editing files 06.1 is rewriting
**What goes wrong:** merge conflict storms (1,118-file diff; PR #102 already CONFLICTING with main). **How to avoid:** the gate table above; wave 1 = new files; no rebase of 06.1 into the 05.5 branch; start wave 2 from merged main. **Warning signs:** a plan's `files_modified` appears in the overlap table.

### Pitfall 2: Home reads the whole Decide scope
**What goes wrong:** `useHomeViewModel` deliberately "mounts no extra server call" (header comment) and uses only Activity's `useMonthView`. `leftAfterPlans` needs `Prepared` from `useDecideV3` (17 reads: snapshot, settings, answers, dismissals, checks, links, accounts, goals, debts...), so Home gets slower and Home's query keys change (APP-08 is exactly "fewer, smaller reads"). **How to avoid:** use the current month's picture only for the current month; past months use `leftSoFar` from rows already loaded (UI-SPEC says past months show only the lead "left at month end"); share the same query keys so no second fetch happens; measure first (APP-08 step 1) and gate Home's lead on that measurement; keep Home's loading/error/offline states from UI-SPEC (error shows no figures). Put `DecideV3Scope` high enough that Home and Decide share one `Prepared`.

### Pitfall 3: "left so far" and "left after the plans" are different pipelines
Home's `paidIn/paidOut` come from `monthTotals` over Activity rows at stamped home amounts; Decide's `thisMonth` uses `V3Line` roles (income/refund/other_in/envelope_withdrawal in; spending/debt_payment/saved_invested/other_out/envelope_deposit out; own_transfer neither) at cautious conversion, and `monthLeft` also subtracts a carried overdraft (D-86). ARC-05 says currency conversion is a deliberate difference. Defining `leftSoFar` once in `engine/month` from the same `V3Line` set as `openingBalance` (`afterBuy.ts` `MONEY_IN`) makes the identity hold, but Home's number moves. Put Home's lead and small line on the D-07 changed-answers page, with the unconverted-rows note ("rows with no rate", `unconverted` in `MonthPosition`) carried through, and keep Activity's header consistent per OFO-8.

### Pitfall 4: `test.todo` hiding a switched-on rule
A todo can be silently deleted. A manifest test (list of todo titles with owner phase) fails when titles change without the manifest.

### Pitfall 5: Dropping columns while older builds still select them
`DECIDE_SETTINGS_COLUMNS` is a literal select list; an older install selecting a dropped column fails its Decide settings read. Preview APKs on test phones (Pixel 9 `6823b228`, Pixel 6 `dd80bb8d` per memory) run old JS until an OTA arrives (OTA reaches JS only). Push Band B after the D-03 OTA and a tester check; the squawk gate requires `contract-ok` and `docs/ops/migration-compatibility.md` says app versions cannot be forced to update.

### Pitfall 6: Tier-word guard blocks the new builder
Renaming the old `'rough'` snapshot kind is required (see anti-patterns). Also `Confidence`+`Level` type name anywhere.

### Pitfall 7: Moving `share.ts`
Phase 8's wave 1 (08-03) imports it by path. Keep it or leave a re-export until Phase 8's revision round updates the plan text.

### Pitfall 8: Coverage list is by folder name
Forgetting to add `month` to the FULL list means 95%, not 100%, and Stryker not covering the new folder. Add all four places (jest, Stryker `mutate`, `check-stryker-disables.mjs`, `check-coverage-ignores.mjs`).

### Pitfall 9: Cap currency and ownership
`categories.monthly_cap` is home-currency minor units on a user-owned category (system categories refuse a cap, `categories_cap_not_system`). The rules-document cap carries a `categoryId` and a value in the settings currency (`moneyUsable` check in the builder). The Band A copy must skip rules whose category is gone or whose currency differs from home, and report counts.

### Pitfall 10: Maestro nightly writes to production
Only the demo account; flows undo their writes; never log credentials; failed runs must not leave partial rows (add a cleanup step using History > Undo or a read-only guard).

### Pitfall 11: Local jest cannot run in this worktree
`C:\dev\fincwin-55` has no `node_modules` (no junction, per the EAS/junction memory). Plans should run quick checks from a checkout with real `node_modules` or run `npm ci` in the worktree first; CI is authoritative.
