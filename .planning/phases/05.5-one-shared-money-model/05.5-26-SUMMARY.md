# Phase 05.5 Plan 26: second half of the old-engine importer move

Gate: the 06.1 gate was met (PR #102 merged, `06.1_SHIPPED` recorded, BASE contains main); `gates/05.5-26.gate` written.

## What changed

**Task 2, Grow lines on the v3 Prepared.** New `monthRows(prepared)` and `standingPlans(prepared)` in `src/engine/month/rows.ts` (pure, integer minor units, 100% covered). `monthBreakdown(prepared)` is now a thin adapter over `monthRows`; `GrowLinesScreen` and `useDebtMonth` read `useDecideV3().prepared`. The rows add up exactly: income - spending - debts - saving - setAside = result. The `'rough'` source is now `'typed'` (so `monthBreakdown.ts` and `snapshot/types.ts` leave the tier-word allowlist).

**Task 3, snapshot helpers off the old engine.**
- `checkInputs.ts`: dead engine mapping deleted (toEngineCheck, engineCtxOf, EngineCtx, EngineCheckResult, effectiveMethod, cheaperFinalPrice, uniqueReplaces, repriceInputs, withItemType; no non-test caller, proven by grep). `finalPriceOf` now uses the new engine `priceAfterLines` plus `salesTaxOf`; `ITEM_TYPES` and `suggestItemType` come from the v3 barrel; `ZERO_PERCENT`, `percent` come from the payoff barrel; DEFAULT_SETBACKS and MAX_PROJECTION_RATE are cited local constants. `MAX_INPUT_MINOR` comes from `features/record/forms/limits` (05.5-17) and is re-exported so the 9 screens that import it from here need no edit (they belong to other plans in this wave).
- `types.ts`: old-engine import gone. SetbackCode, InstalmentFreq, RunningCostCategory are now local JSON unions. The dead Assessment-path types are deleted (QuickComputation, BasisOutcome(s), CheckComputation, StackSelection, EMPTY_STACK, ChipComputation, CREDIT_TERMS, CreditTerm). `SnapshotResult`, `CardChoice` and the base shape moved into `buildSnapshot.ts` (the one file that keeps the old engine until 05.5-19); 9 files re-pointed their type import there.
- `stacking.ts` and `useOtherChecks` deleted (no caller outside its own test), with their tests.
- `decideGoAhead.ts`: it is live (ActionRoutes uses `useGoAheadV3`); its only old-engine import was an unused type line, removed. It writes no accounts (depcruise `decide-never-writes-accounts` clean).

## Grow figures for D-07

Compared old (`prepareContext`) against new (v3 month model) on the builder-parity fixtures. Money in minor units.

| Fixture | Figure | Old | New | Reason |
|---|---|---|---|---|
| demo account | usual money left each month (Debts screen "left", Lines breakdown result) | 20,000 | 110,000 | The v3 usual month does not subtract saving that was only logged as lines (old subtracted 90,000 of logged saving and investing). Saving counts only when it is a standing plan (a series). |
| demo account | saving row / floors default | 90,000 | 0 | Same cause. |
| demo account | "Met" badges and default floors for investing and saving | investing 40,000, saving 50,000 (logged averages) | 0 and 0 | The badge and an unset floor now read standing plans only (`standingPlans`). A rule with a figure of its own and logged-only saving can flip from "Met" to "Not yet". |
| household, no debts, no saving | income, spending, left | 300,000 / 140,000 / 160,000 | same | No change. |
| goal plus a 20,000 saving series | saving, set-aside, left | 20,000 / 23,000 / 117,000 | same | No change. |
| typed estimates only (income 400,000, spending 300,000, saving 20,000) | left; saving row | 100,000; 0 | 80,000; 20,000 | Typed saving, debt and investing figures now count (old rough path ignored them). |
| any logged month | usual pay (income) | average of logged months | median of the usual-month window | v3 uses typicalIncome; equal on the fixtures above, can differ on a variable earner. |

The `DEBTS`-case fixture (income 0) was a fixture artefact and is not listed. The key owner point: the v3 usual month ignores logged-only saving. If the owner wants the old behaviour on the Debts and Lines screens, the month model would need a logged-saving average (it cannot split saving from investing today).
