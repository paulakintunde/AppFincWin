# Phase 05.5 Plan 13: costs that stop end the Activity bill (ARC-23) and the record-as-bought contract (ARC-24) Summary

Partial. The gate is recorded, and the client builds `endSeries` from stopping bills. The server does not yet write `end_reason`, and the ARC-24 contract cannot be written because three of its five behaviours have no writer to test.

## Done

- Task 1: `gates/05.5-13.gate` says `met` (PR #102 merged, `06.1_SHIPPED` present, origin/main is an ancestor).
- Task 2, client half: new `endSeriesOf(stops, recorded)` in `boughtWrite.ts`, used by `buildBoughtWrite` (new optional `stops` and `recorded` args, also on `record` and `canRecord`).
  - A bill stop gives `{ id, expected_version, end_date: stopDate - 1 day, end_reason: 'stopped' }`, the same end date the Activity Stopped action writes (`seriesStatusPatch`).
  - An everyday stop writes nothing. An unrecorded bill is skipped. A bill already ended on or before that day is not written again. The same bill twice ends once. An end before the anchor is clamped to the anchor.
  - `DecideGoEndSeries` got an optional `end_reason`.
  - Tests added to `boughtWrite.test.ts` (5 cases).

## Not done, and why (owner decisions)

1. Server does not set end_reason. `record_decide_go` ends each series by calling `end_recurring_series(id, version, end_date, null)` (migration 20261016000300), which sets `end_date` only. `end_reason` is written only by `edit_recurring_series_from` (20261028001200), or by Grow's `grow_end_series` (20261106000300), which sets both in one statement and is undo-safe. So today the payload's `end_reason` is ignored and the bill ends without the "Stopped" label. Fix needs a new migration (record_decide_go calls `grow_end_series`, clamped to the anchor) and so a band and push-order decision (production is the only database). The plan did not list a migration. Undo of the end should also be checked against that helper.
2. Task 3 (ARC-24 contract) is blocked. Today `buildBoughtWrite` writes a day-one row, payment rows or series, one debt for a new loan, and ONE monthly running-cost series from `purchase.runningMonthly`. It has no:
   - fixed-versus-varying flag on running costs (`RunningCostLine` has none), and no "expected spending" record type to write the varying ones to;
   - sale write or loan payoff write (`record_decide_go`'s `p_debt` only creates a debt; a payoff needs a new server path);
   - Save-for-it goal close in the same save (`decideOutcome.ts` has no goal link in the bought path).
   Writing the contract with those cases would mean inventing a table, an RPC and a model. The two todos in `bo07.recordAsBought.contract.test.ts` are left as todos; the first one is now only half true until item 1 is fixed. `recordAsBought.contract.test.ts` was not created.
3. Callers: nothing passes `stops` and `recorded` to `record` yet. The screen is 08.1; `BoughtWriteHarness.tsx` and the v3 screens still send none, so no bill ends in the app until they pass `check.replaces.stops` and the recurring-series read.
