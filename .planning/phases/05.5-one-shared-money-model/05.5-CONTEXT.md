## Implementation Decisions

### Order and split
- **D-01:** Phase 8's plugs come first. The first wave builds: the one `countsForMe` engine rule (personal unless shared; fix plan §5 rule 5), the contract tests for every connection point (D-08), and the month picture's agreed shape (types and contract, D-05). Each contract test is marked "to do" until its owning phase switches it on. Phase 8 plan 08-25 depends on this wave, not on the whole phase.
- **D-02:** Timing against 06.1. The plugs wave can build now, beside 06.1, because it is mostly new files. The rest waits until 06.1 (PR #102) is merged and shipped to testers: the input-builder swap, old-engine deletion, one bill detector, one date calendar, removing columns, and the cap merge. This keeps testers' Decide answers stable during the 06.1 sign-offs.
- **D-03:** One release at the end. 05.5 reaches testers in one preview/OTA after the old-vs-new comparison shows only owner-approved differences (D-07), with a short note to testers. No per-wave tester releases.

### Money left this month
- **D-04:** One owner works out "money left this month". Today there are two: Home uses `src/engine/activity/monthFigures.ts` (`monthPosition`, "left after everything"), and Decide uses `src/engine/decide/v3/afterBuy.ts` `homeFigure` with `v3/month/thisMonth.ts` and `picture.ts` ("left in {month}"). One month-picture module replaces both. The other screens become thin readers.
- **D-05:** Same lead figure on both screens. Home and Decide both lead with **"left after the month's plans"** (bills and plans still to come taken out). Home also shows **"left so far"** as a smaller second line. The month picture also returns 05.4 D-57's three account figures: "balance on {date}", "After bills due before payday", "expected at month end". New Home words are new copy keys and go through the signed-wording mechanism (`decideWordingSigned.json` / the 05.4-41 review page) before release. **Owner, 2026-11-12:** Decide's label is renamed inside 06.1 before its wording sign-off (plan 33; PR #102 comment), so 05.5 only swaps the calculation behind it and changes Home's words.
- **D-15:** [informational — done: UI-SPEC approved 2026-11-12] 05.5's screen changes get a UI spec from `/gsd-ui-phase 05.5`, run by the owner before planning. The spec covers: the Home card's lead line plus the "left so far" line; how a category money rule and the Activity cap show as the same value (`AddRuleSheet`, `RuleEditSheet`, `CategorySheet`); and how Decide's setup items open Activity's own forms (D-12), given that 06.1 built `PaySheets` and `BillSheets` inside its setup step frame.
- **D-06:** The settlement rule survives (Phase 8 plan 08-30, ARC-18). Settlement records count as neither spending nor income in the month picture. Whichever of 05.5 and 08-30 lands second keeps this, and a test pins it.
- **D-07:** Review every changed answer. The builder swap and old-engine deletion will change some saved test answers and Grow's money-rules figures (`src/features/grow/lines/GrowLinesScreen.tsx` and `monthBreakdown.ts` still use old-engine `prepareContext`). This works the same way as 05.4 D-14: a changed-answers page shows each moved answer old vs new, with its reason. The owner approves or sends back each one. Nothing ships with an unapproved change. Rounding changes are not waved through automatically.

### Who owns what
- **D-08:** Seven connection points, each with one owner and a contract test: month picture, goal, safety net, debt, Activity bills, household scope (BO-07's six), plus **accounts**. D-10 adds accounts as the seventh, settling the item 05.4 deferred.
- **D-09:** 05.5 removes all four old `decide_settings` columns: `share_pct` and the three interim safety-net columns (`safety_net_protect`, `safety_net_size`, `safety_net_locked`; migrations `20261103000300` and `20261103000800`, marked "removed in 05.5"). It does this in safe steps: stop writing, stop reading and exporting (`src/db/decideSettings.ts`, `src/data/mutations/decideSetup.ts` RESET_COLUMNS, `src/data/exportManifest.ts`), then drop the columns. Household's share rules (08.1) start clean. `08.1-CARRY-OVER-08-29.md` shrinks accordingly (on the Phase 8 branch / PR #103).
- **D-10:** Accounts owns overdraft limits and account purpose. The account sheet in Activity is the only place to set them. Decide only reads them, and a contract test proves it.
- **D-11:** One cap. A money rule that is a monthly limit on a category **is** the Activity category cap (`categories.monthly_cap`): one store, and setting it from Decide or from Activity changes the same value. Rules that are not category limits (for example "never below $500") stay Decide's own (v3 `Limits` / `LimitLine`). Fix plan ARC-09.
- **D-12:** Decide uses each question's home form. The setup-question ownership table (fix plan §5 "Setup questions that move") is recorded as a decision file. Where Decide asks a question owned by Activity (how you're paid, regular pay, confirming found bills, account purpose, expected income), it opens Activity's own form, so the question is asked and stored one way only (fix plan §5 rule 4).

### Proof and robot tests
- **D-13:** The Maestro core flows run nightly in CI on a GitHub Android emulator, beside the existing nightly checks. They don't run on every PR. Today `.maestro/` has 3 flows and nothing runs them. 05.5 adds the core flows (APP-13 core) and the nightly job, and this success criterion is met when they run green.
- **D-14:** The wording guard checks each sentence and also runs in lint (CMP-F09). Today it is a jest test over whole strings (`src/i18n/__tests__/decideCopy.test.ts`, grow `copyLint.test.ts`). Any new failing sentence fails the build. Existing hits go on a dated allowlist that must be empty before any public release, and each rewrite goes through the owner's wording sign-off.

### Screens (owner, 2026-11-12, before /gsd-ui-phase)
- **D-16:** [informational — superseded for Home by D-19] Home "This month" card. The big figure is "left after the month's plans". Under it, small and muted and always visible: "{amount} left so far". Nothing to tap. The bar rows stay as today.
- **D-17:** One cap, edited at its home. A money rule that is a fixed monthly amount for a category (`category_cap`) shows in Decide's "Your money rules". Its "Change" opens Activity's category sheet (`CategorySheet`) over the screen, the same way saving and investing rules open Grow today. The category sheet notes "Also a money rule in Decide". Percentage rules (`category_share`) stay Decide's own and are edited in Decide.
- **D-18:** One shared form, same look. Activity and Decide use one shared pay form and one shared bill form (one code path, one store). Decide shows it inside its 06.1 setup step frame, exactly as testers see now. Activity's income and regular-payments screens use the same form. Testers see no visible change to Decide setup.

### Owner answers after research (2026-11-13, before planning)
- **D-19 (amends D-05 and D-16 for Home only):** Home keeps its own sum. Home's big figure stays exactly as today: `monthPosition` "left after everything" (paid in and out so far, Activity rows at stamped rates), same caption `home.month.caption`. No Home number moves. The small line under it shows the shared month picture's **"{amount} left after the month's plans"** (the same `leftAfterPlans` value and words Decide leads with). Decide still leads with "left after the month's plans" (D-05 unchanged for Decide). D-04 still applies to "left after the month's plans": one owner, read by both screens. Home's own sum is not moved into the month picture in 05.5 and is not on the D-07 changed-answers page. The "left so far" wording is dropped from Home. The UI-SPEC Home section is amended to match.
- **D-20 (cap clash, A5):** When a category limit in Decide's rules differs from that category's `categories.monthly_cap`, Activity's value wins. The migration fills only empty caps, counts the clashes per user class for the log, and shows users nothing.
- **D-21 (column drop timing, amends D-09 order):** The four columns may be dropped right after the app update that stops reading and writing them ships (the D-03 OTA). No wait for a tester check. The drop migration still pushes only after that OTA is sent.
- **D-22 (Maestro, amends D-13):** Write the nightly Maestro workflow and the new core flows, but keep the nightly job switched off (`workflow_dispatch` only, no schedule) until the owner picks a sign-in account. Flows are run locally on the emulator to pass. Success criterion 6 is met by green local runs plus the job file ready; the owner turns on the schedule later.
