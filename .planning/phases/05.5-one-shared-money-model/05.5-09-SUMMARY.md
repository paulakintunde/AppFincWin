## Deviations

1. **[Plan assumption] No staleTime patch was needed.** Phase 06.1 (plans 46, 72, 78) had already put the 5-minute stale window on every Decide-scope read. The harness confirmed 0 refetches on remount, so no query code or key changed (`keys.ts` untouched). The "before" figure is a measured proxy (window removed), not a pre-06.1 build.
2. **[Rule 3] No `addBreadcrumb` existed in errorReporter.ts**, and it is not in this plan's files. `decideBreadcrumbs.ts` calls `Sentry.addBreadcrumb({ category: 'decide', message })` from the SDK directly; the existing `beforeBreadcrumb` scrub still applies.
3. **Property test reshaped.** `scrubMessage` only redacts 4+ digit runs, so "no 2+ digit run for any input" cannot be shown through the scrub path. The property is instead over the four fixed events (message equals the event, only category and message sent, no 2+ digits, no currency symbol); free text is stopped by the type.
4. useCheckEngine has no try/catch, so `engine_error` fires from a try/catch (rethrown) around the judge and when the read status becomes `error`; `check_started` fires once per check id, `answer_shown` once when the first evaluation lands (4 `decideBreadcrumb(` calls).
