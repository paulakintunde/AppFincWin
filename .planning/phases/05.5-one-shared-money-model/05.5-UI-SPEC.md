# Phase 05.5 (One shared money model) - UI Design Contract

> Small contract. 05.5 is engine and plumbing. This file covers the four screen changes in CONTEXT D-15 (D-05, D-16, D-17, D-18) and the new copy. It adds nothing to the palette, type scale, spacing or icon set. The design system is the one in `06.1-UI-SPEC.md` (approved 2026-11-06, on PR #102 until merged) plus Home's existing `ThisMonthCard` styles.
>
> Precedence: CONTEXT decisions D-01..D-18 are locked. Tokens come from `src/theme/*`. Words are drafts until the owner signs them through `decideWordingSigned.json` (05.4-41 review page).

Sources: 05.5-CONTEXT D-04, D-05, D-11, D-12, D-15..D-18; 06.1-UI-SPEC; CLAUDE.md (design fidelity, compliance voice); read in code: `src/features/home/ThisMonthCard.tsx`, `src/i18n/locales/en.ts` (`home.month.*`, `categories.cap.*`), `src/features/record/categories/CategorySheet.tsx`, `src/features/record/accounts/AccountSheet.tsx`, and on the 06.1 branch `YourMonthCard`, `MoneyRulesCard`, `RuleEditSheet`, `AddRuleSheet`, `SetupItemFrame`, `PaySheets`, `BillSheets`.

## Typography

No new sizes or weights. Roles from `textRole` as already used by `ThisMonthCard`.

| Role | Size | Weight | Line height | 05.5 use |
|------|------|--------|-------------|----------|
| `heading` | 26 | 700 | 1.16 | Home lead figure (unchanged) |

The "left so far" line uses `label` (13), not `meta`. Reason: it is a real figure a person reads, and `label` is the smallest role the Home card already uses for the caption. It is "small and muted" (D-16) through colour, not through a new size.

## Screen Contracts

### 1. Home "This month" card (D-05, D-16)

> **Amended 2026-11-13 by owner decision D-19 (CONTEXT). This box overrides the rest of section 1 and the Home copy rows below.**
> - Big figure: unchanged. Home's own `monthPosition` sum, caption `home.month.caption` "left after everything", same sign and colour rules as today. No Home number moves.
> - New small line under the headline block (`label`, `inkMuted`, `marginTop: space.gapSm`, always visible, not tappable): `home.month.afterPlans` "{amount} left after the month's plans", value = month picture `leftAfterPlans`, the same number Decide leads with. When `leftAfterPlans < 0`: `home.month.afterPlansShort` "{amount} short after the month's plans" (the word "short" carries the meaning; still `inkMuted`).
> - Past months: hide the small line (nothing still to come). Empty month: hide it. Loading/error/offline: hide it; the big figure behaves as today.
> - Accessibility: `home.month.headlineA11y` becomes "{figure} left after everything. {afterPlans} left after the month's plans." (short variant uses "short after the month's plans").
> - Not used on Home: `home.month.leftSoFar`, `home.month.captionPast`, the changed `home.month.caption`. OFO-2 and OFO-3 no longer apply to Home.
> - Link with Decide: a render test pins Home's small line and Decide's "Your month" lead to the same month-picture fixture and compares the formatted figure and caption key.
> - New copy keys need owner wording sign-off.

File: `src/features/home/ThisMonthCard.tsx`. Figures come from the one month-picture module (D-04), through `useHomeViewModel`. The component only formats.

Layout, top to bottom (only the headline block changes):

1. Header row: "This month" / month name, `MonthChips` (unchanged).
2. Headline block: lead figure in `heading`, then the caption `home.month.caption` in `label` / `inkMuted` on the same baseline row (unchanged structure; it wraps under the figure at large text, as today).
3. New line directly under the headline block: `home.month.leftSoFar`, "{amount} left so far", `label`, `inkMuted`, `marginTop: space.gapSm` (8). Always visible. Not tappable. No chevron. No accessibilityRole button.
4. Empty-month text (unchanged) sits under this line.
5. Bar, three figure columns (In, Out, Unpaid), unconverted note: unchanged.

Rules:

- The lead figure is "left after the month's plans" and uses the month picture's `leftAfterPlans`. The small line uses `leftSoFar`. Both come from the same module and the same call, so they cannot disagree about the month.
- Sign: unchanged. Lead is `+$X` when `>= 0` (accent) and `-$X` when below zero (danger). The "left so far" amount follows the same rule for its sign (`+` prefix when `>= 0`) but stays `inkMuted`. Money is formatted with the existing `fmt`.
- Negative case. The caption changes with the sign so the sentence stays true: `left >= 0` reads "left after the month's plans"; `left < 0` reads "short after the month's plans" and the figure shows the amount without the sign confusion (still `-$X`, still `danger`). Colour is never the only signal: the word "short" carries it. Flagged for owner wording sign-off (OFO-1).
- The "left so far" line has no short variant. A negative so-far amount reads "-$40 left so far". It is a running balance, not a verdict, and this keeps the line one fixed sentence. Flagged (OFO-2).
- Past months (`month < currentMonth`): nothing is still to come, so the lead and the small line would be equal. Show only the lead figure with caption `home.month.captionPast` "left at month end" and hide the "left so far" line. Future months are not shown today (unchanged). Flagged (OFO-3).
- Empty month (`isMonthEmpty`): figure shows `fmt(0)` in `inkMuted` as today; the "left so far" line is hidden (nothing to say). The existing empty text stays.
- Loading: the existing placeholders stay. Add one more placeholder block under the headline placeholder: height 16, width 120, `colors.line4`, radius 8, `marginTop: space.gapSm`. The loading card keeps `accessibilityLabel={t('home.loading')}` and `busy`.
- Error / offline: unchanged (header plus the state sentence). No figures.
- Text scale: the lead keeps `scale="capped"`, `maxFontSizeMultiplier` 1.3 and `adjustsFontSizeToFit`. The small line is not capped: it wraps to two lines before it truncates, and the amount never breaks across lines (`"{amount} left so far"` uses a non-breaking space between amount and "left"). At scale above 1.3 the three bottom columns stack as today.
- Motion: none new. The bar segment animation is unchanged. No count-up on the figures.
- Accessibility: the headline block stays one accessible element. `home.month.headlineA11y` becomes "{figure} left after the month's plans. {soFar} left so far." (one sentence, both figures, read in that order). Short case: "{figure} short after the month's plans. {soFar} left so far." Bars keep `barA11y`. The `home.month.heading` header role is unchanged.
- Link with Decide: the Home lead figure and Decide's "Your month" lead figure must be the same number with the same name (D-05, 05.4 D-24). A render test pins both screens to the same month-picture fixture and compares the formatted figure and the caption key.

### 3. One cap (D-11, D-17)

A `category_cap` rule IS `categories.monthly_cap`. One value, edited at its home (Activity's `CategorySheet`). `category_share` stays in Decide.

#### 3a. "Your money rules" row (Decide, `MoneyRulesCard`)

- A `category_cap` rule keeps its present row: 52 px (64 when it wraps), `Row`, category name, amount, chevron. Same look as today. The row now reads its amount from `categories.monthly_cap`, not from the rules document.
- A category with no cap shows no row. Removing the cap in Activity removes the row. Both are the same change.
- A `category_share` row is unchanged and still opens `RuleEditSheet`.
- Cap rules have no "Answers check this rule" switch (owner, OFO-4). If a category has a cap, Decide always checks it. To stop checking, remove the cap. Nothing about caps is stored in the rules document.

#### 3b. "Change" on a cap rule

- Tapping a cap row opens Activity's `CategorySheet` (mode `edit`, the category) over the Decide screen, as a sheet, using the same `Sheet` stack. It mirrors saving and investing rules, which open Grow through `onOpenGrow` in `RuleEditSheet`. Difference: Grow is a navigation; the category sheet is a sheet, so no screen change and focus returns to the cap row on close.
- `RuleEditSheet` is not shown for `category_cap`. `RuleEditSheet` keeps `debt`, `keep`, `largest` and `category_share` (its amount-field branch for `category_cap` is removed).
- Save, Undo toast and the "over cap" toast follow `CategorySheet`'s existing behaviour (`categories.cap.overToast`, REC-11 undo). A cap change that makes an open check cross the rule still gets the `hapticWarning` and the "This changes 1 open check" sentence from `commitRule`. Planner wires the crossing check to the cap write.
- The sheet title, field labels and the primary button are `CategorySheet`'s own (`categories.sheet.titleEdit`, `categories.cap.label`). Nothing is renamed.

#### 3c. `CategorySheet` note (new)

- Where: directly under the "Monthly cap" field helper line (`categories.cap.helper`), inside the same column, `marginTop: space.gapSm`.
- Look: `label`, `inkMuted`, one line of text, no icon, no link, no tap action.
- When: shown only if this category's cap is used as a Decide money rule. In 05.5 that is every capped category once Decide reads caps as rules (the rule exists as soon as `monthly_cap` is set). Concretely: show the note when `monthly_cap` is set (draft or stored) and the Decide rules are available to this user. Hidden when the field is empty. Hidden for system categories (they have no cap field).
- Words: `categories.cap.alsoRule` "Also a money rule in Decide" (owner wording in D-17).
- Accessibility: the note is read after the helper text. It is a plain `Text`, so no extra label. `accessibilityLiveRegion` not used.

#### 3d. Add-rule path for a new category cap (`AddRuleSheet`)

- The radio list is unchanged: "Category" (`category_cap`), "Category share", "Largest purchase", "Keep at least". Category cap still asks for a category and an amount.
- Difference is behind the button: "Add rule" for a cap writes `categories.monthly_cap` for the chosen category (same write as Activity), not a rules-document entry. Result: the cap shows in Activity at once and the row shows in "Your money rules".
- If the chosen category already has a cap, the radio row for it is marked taken in the category picker and the sheet shows the sentence `decide.screens.sheetsHome.addRule.capExists` "{category} already has a monthly cap. Change it to set a new amount." with a text link "Change {category} cap" that opens `CategorySheet`. The primary stays disabled until another category is picked. Flagged (OFO-5).
- The 5 own rules limit (`canAddRule`) counts non-cap own rules only; caps are limited only by the number of categories. Planner confirms against `homeCardsModel`. See OFO-6.
- Toast after add: existing `decide.screens.sheetsHome.addRule.toast` with Undo. Undo clears the cap.

### 4. Shared pay and bill forms (D-12, D-18)

Contract: testers see no visible change to Decide setup. One shared pay form and one shared bill form; Decide and Activity differ only in the frame around them.

| Concern | Shared form owns | Host owns |
|---|---|---|
| Fields | All fields and their order: pay (amount, day, account); other income (name, amount, how often, counts as available or kept); bill (name, amount, how often, due day, account/category as built in 06.1 `BillSheets`). Field labels, helper lines, keyboard types, `MoneyInput` use | Nothing |
| Validation | Rules and inline messages (`role="alert"`, `warn1` text with a shape, never `danger`): required amount, amount range, day 1..31, name length (`BILL_NAME_MAX` 40, `OTHER_INCOME_NAME_MAX` 40) | Nothing |
| Store | One mutation per kind (series write). Both hosts call it | Whether to also close, navigate or toast |
| Save button | Renders the primary `Pill` slot only; it takes `primaryLabel` from the host | Supplies the label: Decide "Save pay details" / "Save bills" (06.1 names, unchanged); Activity keeps its own present labels (`Save` family already in `src/i18n/locales/en.ts` for income and regular payments) |
| Presentation | A plain content component (no frame, no sheet chrome) plus its own `Sheet` variant for the edit-one-item case (`PayEditSheet`, `BillSheet` stay sheets) | Decide: inside `SetupItemFrame` (back, "Save and close", "Why we ask:", footer). Activity: inside its screen or sheet as today |
| Dirty state and discard | Reports `dirty` up | Host decides the discard prompt (`Sheet dirty`) |
| Pre-fill | Takes initial values as props | Host supplies them (Decide from candidates; Activity from the saved series) |
| Test IDs | Stable ids on the fields | Host keeps its own frame ids (`setup-item-frame`, `item-back`) |

Visual contract: the form content in Decide is pixel-identical to 06.1 (same spacing, `label` field labels, `body` values, 52 px rows, same order). Where Activity's form differed from Decide's (field order, helper words), Decide's 06.1 form wins and Activity changes to match, because Decide is what testers have signed off. Any Activity-visible change from this is listed for the owner in the changed-screens note (OFO-7).

Edge states stay as 06.1: no pay found shows the fields directly; brand-new records show the 06.1 D37 empty state. Errors from a failed save use the app's write queue copy (offline queue, `FailedWritesSheet`).

Questions Decide asks that Activity owns (D-12): pay and payday, regular bills, confirming found bills, account purpose, expected income. The setup item opens the shared form (its home form), never a second copy. Account purpose and overdraft are asked in `AccountSheet` (see "No UI change"). The ownership table lives in a decision file; it is not a screen.
