```ts
export interface ExpectedMonthFigures {
  readonly month: string;                 // 'YYYY-MM' of snapshot.asOf
  readonly income: MinorUnits;            // logged + pending + still due, mine
  readonly spending: MinorUnits;          // same, my share
  readonly debtPayments: MinorUnits;      // = context.debtPayments
  readonly saving: MinorUnits;            // saving + investing = context.pausable
  readonly setAside: MinorUnits;          // = context.setAside (pots)
  readonly result: MinorUnits;            // signed: income - spending - debtPayments - saving - setAside
  readonly stillDue: { readonly income: MinorUnits; readonly spending: MinorUnits }; // the schedule's share of income / spending
}
export function expectedMonth(context: AssessContext): ExpectedMonthFigures;

/** D-107: the month's money alone, from a snapshot and its resolved existing-spending share (no context needed). */
export interface ExpectedMonthMoney { readonly month: string; readonly income: MinorUnits; readonly spending: MinorUnits; readonly stillDue: { readonly income: MinorUnits; readonly spending: MinorUnits } }
export function expectedMonthMoney(snapshot: DecideSnapshot, spendingShare: SpendingShare): ExpectedMonthMoney;
```
`expectedMonth(context)` = `expectedMonthMoney(context.snapshot, context.spendingShare)` plus `debtPayments`, `pausable`, `setAside` and the `result`. All the algorithm below lives in `expectedMonthMoney`.

Algorithm (all arithmetic in bigint, one `minorFromBigInt` at each output):
1. `month = monthOf(snapshot.asOf)`; `record = snapshot.months.find(m => m.month === month)`; if absent use `{ month, full: false, lines: [] }`.
2. Logged part: take the record's lines, drop `status === 'skipped'`, relabel `pending` as `paid`, and call `summariseMonth({ ...record, lines }, { currency, smoothedSeriesIds: new Set(), spendingShare, smoothedBillsMonthly: 0, smoothedPay: new Map() })`. One call, so the refund netting and the floor at 0 happen once. Logged income = `income + oneOffs.income`; logged spending = `spending + oneOffs.spending` (one-offs count this month, D-106; the averages still leave them out).
3. Still-due part: `from = month + '-01'`, `to = month + '-' + daysInMonth(...)`. For each confirmed series (bills and income series; assertValidBill first) take `occurrencesBetween({anchorDate, freq, endDate, occurrenceCount}, from, to)`, then drop an occurrence when it is already settled (`lastPaidDate !== null && date <= lastPaidDate`) or when it is taken by a line. A line takes at most one occurrence. The series' non-skipped lines in this month (any status, any date, seriesId equal) are matched to its occurrences in date order, each line to the nearest unmatched occurrence within the occurrence's own period: for monthly, quarterly and yearly series the period is the calendar month (any line of the series this month takes the month's occurrence, however its date was edited); for weekly and fortnightly series the period is the occurrence date plus or minus 3 days (weekly) or 6 days (fortnightly). A taken occurrence is not added from the schedule; the line is already in the logged part. This covers a pending row moved off its schedule date and a paid line while lastPaidDate is null. Then, for the occurrences that remain, amount = `latestAmount * count`, my part = `myPart(amount, shareForCategory(spendingShare, categoryId))` (`spendingShare` is the function's parameter; `expectedMonth(context)` passes `context.spendingShare`) (the same total-then-share order as `billsDueWithin`). For each `snapshot.incomeSeries` entry do the same with no share. An occurrence earlier in the month that was never paid is still owed (the `billsDueWithin` rule), so it counts.
4. income = logged income + income still due; spending = logged spending + spending still due; `result = income - spending - debtPayments - pausable - setAside`.
5. Export from `src/engine/decide/index.ts`: `export * from './expectedMonth';`.

Do NOT change `prepareContext`, `deriveMoney` or `summariseMonth` (checks keep their basis, D-106 "card only"). Do not read `futureChanges` (the dated changes feed the cash path, not the Net Free Cash Flow hero).

Write the tests first with the exact names above. Build fixtures with the existing helpers in `src/engine/decide/__tests__/helpers`; do not duplicate builders. The fast-check property uses `fast-check` (already a dev dependency).
