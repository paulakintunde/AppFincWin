  <action>
RED (commit `test(01-03): ...`) then GREEN (commit `feat(01-03): ...`).
- `localeSeparators(locale)`: `new Intl.NumberFormat(locale).formatToParts(1234567.5)`; decimal = part type 'decimal' value (fallback '.'), group = part type 'group' value (fallback ',').
- `parseDecimalString`: trim; empty → 'empty'. Normalise digits: map U+0660-U+0669 and U+06F0-U+06F9 to '0'-'9'. Build a set of group characters: the locale group char, and when that char is any whitespace (U+0020, U+00A0, U+202F) accept all three. Scan characters left to right: digits append to the current part; the locale decimal char switches to the fraction part (a second one → 'invalid'); a group char is skipped only while in the whole part (in the fraction part → 'invalid'); anything else (letters, '+', '-', U+2212, a decimal mark from another locale that is not this locale's group char) → 'invalid'. If both parts are empty → 'invalid' (covers '.'). Fraction longer than maxFractionDigits → 'too-many-decimals'. Return `whole || '0'` plus `'.' + fraction` when fraction is non-empty. Never call parseFloat, Number() or parseInt on anything but a pure-digit string.
- `parseAmount(raw, { locale, exponent })`: validate exponent is an integer 0..4 (throw RangeError: a programming error, not user input). Call parseDecimalString with maxFractionDigits = exponent. On error return `{ ok: false, error, maxDecimals: exponent }`. Otherwise digits = whole + fraction.padEnd(exponent, '0'); strip leading zeros; if digits.length > 16 or `BigInt(digits) > BigInt(MAX_ABS_AMOUNT_MINOR)` → 'too-large'; else `{ ok: true, value: minorUnits(Number(digits)) }` (safe because bounded by 1e13).
- Docstrings explain D-24: the region's decimal mark is authoritative, so '12.5' in de-DE is 125, not 12.50; the UI (Record) shows the parsed value back to the user before saving.

RED then GREEN, as in Task 1.
- `toDecimalString`: pure string maths on `Math.abs(amount).toString()` padded to exponent+1 digits; insert '.' exponent places from the right when exponent > 0; prefix '-' for negatives. No division.
- `formatAmount(money, opts)`: exponent = opts.exponent ?? currencyExponent(money.currency). `const whole = money.amount % 10 ** exponent === 0` (integer modulo, safe). `fractionDigits = exponent > 0 && (opts.showCents || !whole) ? exponent : 0` (D-23: whole amounts drop decimals unless Show cents is on; JPY has exponent 0 so never shows decimals). Decimal string = toDecimalString(abs amount, exponent). If opts.customSymbol is set: `Intl.NumberFormat(locale, { minimumFractionDigits: fd, maximumFractionDigits: fd })` then prefix the symbol. Pass the decimal STRING to `format()` (Intl.NumberFormat v3 treats strings as exact decimals; engines without v3 coerce to Number, which is display-only and never stored — say so in the docstring). For negatives format the absolute value, then prepend U+2212 placed where the locale puts the sign: simplest correct approach is to format the negative decimal string and replace every U+002D with U+2212. Hide-balances masking is not implemented here, and the function returns a plain string so masking can wrap it later.
