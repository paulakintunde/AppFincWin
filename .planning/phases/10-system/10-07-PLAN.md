New API (exact):
```ts
export type DataTable = 'accounts' | 'savings_goals' | 'debts' | 'holdings';
export interface DataCsvSchema { table: DataTable; required: readonly string[]; allowed: readonly string[]; money: readonly string[]; enums: Readonly<Record<string, readonly string[]>>; dates: readonly string[]; currencyColumn: 'currency' }
export const DATA_CSV_SCHEMAS: Readonly<Record<DataTable, DataCsvSchema>>;
export type DataRowIssue = 'name-missing' | 'currency-missing' | 'bad-amount' | 'too-many-decimals' | 'bad-date' | 'bad-choice' | 'bad-id';
export interface DataCsvRow { index: number; values: Record<string, string | null>; money: Record<string, number | null>; issues: DataRowIssue[] }
export type DataCsvResult = { ok: true; table: DataTable; columns: string[]; rows: DataCsvRow[] } | { ok: false; error: 'empty' | 'unreadable' | 'too-many-rows' | 'header-mismatch'; missing?: string[]; unknown?: string[] };
export function unescapeCell(cell: string): string;
export function parseDataCsv(table: DataTable, text: string, exponentOf: (currency: string) => number): DataCsvResult;
export type RowMatch = 'new' | 'same-id' | 'same-name';
export function classifyRows(rows: readonly DataCsvRow[], existing: readonly { id: string; name: string }[]): RowMatch[];
```
Required columns: accounts [name, kind, currency]; savings_goals [name, currency, target]; debts [name, kind, currency, balance]; holdings [name, type, currency, value]. `allowed` = the export columns for the table minus server bookkeeping (household_id, created_by, deleted_at, created_at, updated_at, check_id, series_id, extra_series_id, tombstone_of) — those columns are accepted in the header (so an export imports) but ignored.
Money cells: a plain integer string = minor units (as exported); a value with a decimal mark = major units parsed with the currency exponent; more decimals than the exponent -> 'too-many-decimals'; anything else -> 'bad-amount'. Never parseFloat.
**Superseded 2026-11-27 (code review D-1, PR #201, owner choice):** money cells are whole numbers in minor units only, as Export writes them. A cell with a decimal mark is flagged `decimal-amount` and never re-scaled (a spreadsheet that re-saves 150000 as 150000.00 must not import 100x). The decimal rule on this line, the `too-many-decimals` issue (replaced by `decimal-amount`) and the `'2500.00' -> 250000` behaviour below no longer apply; see `src/engine/dataCsv/parse.ts`.
