# Phase 05.1 Plan 38: One settling module Summary

One order-free, nearest-first matcher (month/settle.ts) now settles bills, debts and pay for thisMonth, unspent, evaluate and incomeProfile; the cash path no longer lands a pay that is already logged.

## What changed
- settle(): symmetric window (matchWindowDays), nearest first, ties by due date, line date, line id. Linked lines or unlinked typed/statement lines within the amount band settle; the date passing settles nothing.
- thisMonth: bill dues now run from the first of the month, so an unsettled bill dated before asOf stays due (D-51). A typed/statement line that settles a bill counts as billsPaid, not everyday.
- unspent: anchor bill list uses `liveSeriesOf(..., anchor.at, 'bill', asOf)` and `seriesOccurrences(..., asOf)` (05.1-34 carry-over, D-41); matched typed/statement lines do not move unspent.
- evaluate/path: paidOccurrences covers bill, debt_payment and pay (pay with W4 month boundary); path.ts skips paid pay keys (H-01).
- incomeProfile: settle() with PAY_MATCH_DAYS; neighbouring months' occurrences are in the due set so a line is claimed by its nearest date; localeCompare and TWO_DATE_TOLERANCE_DAYS removed.
- No file declares its own MATCH_DAYS.
