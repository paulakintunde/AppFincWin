## Code review findings folded into gap closure (orchestrator, 2026-10-26)

05.1-REVIEW.md (status: issues_found; 0 critical, 3 high, 9 medium, 9 low) is closed in the same gap-closure plans as the gaps above, so that the shadow re-review covers one final engine.

**High.** Each can produce a wrong "fits". Each fix needs a regression test.

- **H-01.** `cash/path.ts` ~424: a pay due on asOf that has already been logged is added again. Fix: add `pay` to `paidOccurrences` in `evaluate.ts`, and skip those keys in the cash path.
- **H-02.** `month/incomeProfile.ts` ~213: pay matching checks a lower bound only. Early pay is counted twice, and a late line can cover a missed occurrence. Fix: use a symmetric window and match to the nearest unused line.
- **H-03.** `instead/futures.ts` ~503:
  - `emergencyUntouched` contradicts an `emergency_used` fact on `monthly_short`.
  - `buyNow.unspentAfter` disagrees with the judge's `unspent_before_after`.

**Medium.**

- **M-01.** The ended-series rule is implemented differently in `needsInput` and in `isCounting` (see gap 2).
- **M-02.** The "paid line settles a due date" matcher is copied in four places, `MATCH_DAYS` is declared three times, and the match depends on line order. Consolidate it into one module.
- **M-03.** Fact and notice value keys don't match the `en.ts` placeholders: `envelope_used`, `quoted_differs`, `implied_rate`, `line_crossed`, `at_todays_rate`, `deferred_interest_term`, `typical_short`, `month_heading_short`. Add a test that every emitted key is used by its copy string.
- **M-04.** `judge.ts` ~433: `readyMonth` has no upper bound. Cap it like `SIMULATION_MONTH_CAP`.
- **M-05.** `lines.ts` ~149: `BigInt(spec.times)` throws on a fractional value. Validate it, or catch it as a line problem.
- **M-06.** Savings accounts are in `balance`, but spending covers cash and checking only, so a transfer to savings gives a false drift notice and rough confidence.
- **M-07.** `buildV3Inputs` `moneyOf` rejects a negative unspent anchor, which leaves the answer stuck at `needs_input`.
- **M-08.** The preset questions `trade_in`, `sales_tax` and `deposit` are added to day one as costs. `trade_in` should be a credit; the other two duplicate `taxPercent` and `pay.deposit`.
- **M-09.** `customOf` drops every custom option when any one is invalid.

**Low (L-01 to L-09).** Recorded in 05.1-REVIEW.md. Fix where cheap; any left over go to 05.3.
