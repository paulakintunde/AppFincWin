# Phase 05.1 Plan 45: Held-back bridges and unexplained money Summary

Funds now expose `unspent.available` (confirmed figure less held-back bridges, plus any spare-covered amount), a `breakdown.heldBack` line, and `Funds.unexplained` with the stored answer applied.

## What was built

- Task 1 (D-38, commit 7960dc68): `unspentState` takes `heldBridges`, sums valid ones in bigint (first of each id, safe integer >= 0), and returns `available = value - heldBack` and `breakdown.heldBack`. Drift and staleness still read the confirmed value. `build.ts` passes `inputs.heldBridges ?? []`.
- Task 2 (D-50, commit 9fb186c2): when unspent is confirmed, `raw = max(0, suggested - unspent.value)`; a valid `unexplainedAnswer` covers `min(amount, raw)`. `spare` adds the covered amount to `available`; any other use adds it to `Funds.ringFenced`. `Funds.unexplained = raw - covered`, undefined when unspent is not confirmed. Invalid answers are ignored.
