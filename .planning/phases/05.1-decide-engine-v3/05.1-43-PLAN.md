Rules fixed by this plan (cite each in code comments):
- Swing (D-34): over the newest up-to-12 full history months' recorded income x1..xn with n >= INCOME_SWING_MIN_MONTHS and S = Σx > 0: swings when `(n·Σx² − S²) · 100² >= INCOME_SWING_CV_PERCENT² · S²` (CV >= 22%, exact bigint, no square root).
- Pattern (D-34): stated = profile?.pattern ?? null. stated 'variable' or 'seasonal' → treated = stated, confirmNeeded false. Otherwise, swings and not (stated === 'steady' && profile.patternConfirmed === true) → treated 'variable', confirmNeeded true. Otherwise treated 'steady'.
- Window (D-33): steady → V3_HISTORY_MONTHS; variable/seasonal → V3_VARIABLE_HISTORY_MONTHS (newest kept months, same exclusions as today).
- Lean (D-36): a window month is lean when `income · n < Σ income` (below the window average). leanLeft = the lowest `left` among lean months (the payment must be covered in every lean month); null when none is lean.
- Expected (D-35): confirmed entry for the month → as given ('confirmed'); else treated steady → null; else fullMonths < RECONFIRM_MIN_MONTHS → null; else seasonal → income of the most recent window month with the same calendar month, null if none; variable → the LOW_MONTH_RANK-th lowest window income (lowest when fewer than 3).
- Same season (D-39): treated variable/seasonal and fullMonths >= RECONFIRM_MIN_MONTHS → the everyday of the most recent window month with the same calendar month; else null.
- dependsOnMonths (D-35, D-37): the current month; plus the months of schedule payments in [asOf, addMonthsClamped(asOf, SEASON_CYCLE_MONTHS)); plus, when runningMonthly > 0, the next SEASON_CYCLE_MONTHS − 1 months; unique, sorted.
- leanRun (D-37, seasonal): over the dependsOn months in order, skip leading months that are not lean (by isLeanMonth), then count consecutive lean months, stop at the first non-lean month after the run.
