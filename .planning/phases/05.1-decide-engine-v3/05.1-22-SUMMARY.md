# Phase 5.1 Plan 22: Lines as facts and needs-input rules Summary

Lines evaluate to a `line_crossed` fact only (bigint cross-multiplication, never a gate), and `needsInput` applies the fixed UP §5.4 rules plus the purchase's own missing facts.

## Commits
- 4c0cb3dd: lines.ts and tests
- needsInput commit: needsInput.ts and tests

## Decisions
- Fact shape: `line_crossed { lineId, kind, value, line }`. Percent kinds: `value` integer percent (number), `line` integer-percent string ("36"). unsecured_multiple: value is the multiple to one decimal, line is `times`. Money kinds: both minor units.
- A share line only fires when the purchase itself adds to the numerator (housing: purchase is housing; debt: financed; unsecured: financed and unsecured; category share: category matches). Category kinds only fire when `purchase.categoryId` matches the line's category. Zero income gives no fact.
- Built-in line ids: `builtin_housing`, `builtin_debt`, `builtin_unsecured`. `validateLimits` counts only `builtin` and `own` sources (legacy uncounted).
- needsInput output is unique and sorted alphabetically (the plan's "in order" and "sorted" conflict; sorted wins). Added `everyday_unknown` (e null and no rough). 5.4.3 is skipped when `month.e` is null (everyday_unknown covers it); no spending entries counts as "old". A series with status ended counts as confirmed income only if endDate >= asOf.
