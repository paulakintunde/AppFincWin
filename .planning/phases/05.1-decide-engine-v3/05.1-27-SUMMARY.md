## Findings (engine behaviour left unchanged, per orchestrator notes)

1. **I1 holds only for full thinning, not partial thinning.** With every history month thin the code is never better, and thinning any months never raises confidence. Thinning only some months changes which months feed the median E and the leftovers, so the figures move either way and the code can improve. Counterexample: Sam, price $1.06 (106), months 2026-04/05/06/09 and the current month thin, 2026-07 and 2026-08 kept (E falls), extra spend 49,534 on Oct 1: treated-full gives fits_unspent, thin gives fits_month. Recorded as `it.failing` replaying fast-check seed 88886437 (path in the test), so it turns red when the engine closes the gap. Needs an owner decision: either I1 means "all thin", or the judge should be stricter on partially thin history.
2. **I31 is not literally "every figure identical".** The suggested unspent sum subtracts the emergency fund (I17 partition), so a fund of $0 vs $1M changes the `unspent_drifted` notice value, and can switch drift on/off, which caps confidence. The check answer (code, variant, split, readyBy, facts, month figures, band, layers) is identical and is asserted; notices other than drift and confidence are asserted equal. If the intent is that drift must not depend on the fund, the suggested figure used for drift needs to add the fund back. Counterexample: Sam with unspent 240,000, balance 653,750, fund 1,000,000 gives suggested -99,445,000 vs 555,000 with fund 0.
