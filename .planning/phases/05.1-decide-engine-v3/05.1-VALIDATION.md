# Phase 05.1 — Validation Strategy

> This is the validation contract for each phase. It says how test feedback is sampled during execution. The source is the Validation Architecture section of `05.1-RESEARCH.md`, together with CONTEXT D-01..D-29.

---

## Test Infrastructure

| Property | Value |
|----------|-------|
| **Framework** | Jest 29.7.0 (jest-expo preset) + fast-check 4.10.2 |
| **Config file** | `jest.config.js`. The 100% branch thresholds already cover `./src/engine/decide/` (including `v3/`) and `./src/features/decide/snapshot/` (including `snapshot/v3/`) |
| **Quick run command** | `npx jest src/engine/decide/v3 --maxWorkers=4` |
| **Full suite command** | `npm run test:coverage -- --maxWorkers=4` |
| **Wave gate** | `npm run typecheck && npm run lint && npm run depcruise && npm run check:ignores && npm run verify:gates && npm run test:coverage -- --maxWorkers=4`, then `npm run check:recurring-mirror && npm run check:money-mirror && npm run check:decide-demo-mirror` |
| **Estimated runtime** | quick about 60 s; full suite about 15 min on Windows |

---

## Sampling Rate

- **After every task commit:** run `npx jest src/engine/decide/v3/<area> --maxWorkers=4`, then `npm run typecheck`.
- **After every plan wave:** run the full wave gate above (upgrade plan §7.4), and CI must be green.
- **Before `/gsd-verify-work`:**
  - the full suite is green;
  - the shadow report has been generated;
  - the owner's D-14 approvals are committed in `approved-changes.json`.
- **Max feedback latency:** 120 s for the quick run.
