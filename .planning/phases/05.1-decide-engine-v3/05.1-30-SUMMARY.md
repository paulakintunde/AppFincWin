Roles come from the transfer pair's account kinds: out of cash/checking to savings/investment is saved_invested; to a card/loan is debt_payment; between spending accounts own_transfer; a leg tagged to a live pot/goal is envelope_deposit (out of spending) or envelope_withdrawal (back into spending); the receiving leg is own_transfer so nothing counts twice. Live pots/Wait goals become Envelopes; Savings-category series are re-read from the source as saving/investing series; occurrence counts become an end date; legacy line settings carry over via legacyLimits; own lines, custom options, profile, anchor, marks and rough fields parse totally (invalid becomes null/default, never throws, T-05.1-62). USD rate for missing-currency band edges comes from stored rates (convertFloored probe).
- **computeV3 / reanswerSaved**: v2 stored checks read as stored; a v1 typed in another currency is converted with the existing `inHomeCurrency` and marked `foreign {atTodaysRate: true}` (D-09); with no stored rate the price is null so it reads needs_input. reanswerSaved never receives the recorded decision, so verdict_at_decision cannot be touched (D-20, I42).

## Things 05.3 / the owner should know
1. **'ended' with no end date**: the snapshot source CAN produce this. `series_extra[id].status = 'ended'` with the stored `end_date` null passes through as `status: 'ended', endDate: null`, which v3 keeps counting (owner decision pending). Nothing here sets an end date for it.
2. **D-16 coupling (recorded)**: buildV3Inputs reuses buildDecideSnapshot (old-engine types). It MUST be decoupled before the D-16 cleanup deletes the old engine (05.3 close-out task); a TODO is in the file header.
3. **Lines the shared parse path drops**: Savings-category outflows and lines of debt-covered or Savings series never reach a month (the old builder folds them into monthlySaving/minimums), so they are absent from v3 lines. A 'rough' or 'none' snapshot carries no bills, series or debts, so those are empty for such users.
4. **Pot saved quirk (pre-existing)**: the old builder adds the absolute value of every goal-tagged paid leg to the pot's saved, so a tagged withdrawal leg would raise Envelope.saved instead of lowering it. Unspent money is unaffected (it uses the signed envelope lines). Fix with the D-16 decoupling.
5. `reserve_account_id` and `V3Line.expected` / `incomeKind` have no source column yet and are not mapped.
