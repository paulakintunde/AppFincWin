Rules (implement exactly; cite D-36/D-37 in comments):
- Let `pic = month.incomePicture`. If `pic` is absent, `pic.treated === 'steady'`, or M === 0: today's rule, unchanged.
- planMonths = dependsOnMonths(asOf, purchase.schedule, purchase.runningMonthly), dropping months before the first payment's month when there is a schedule.
- leftOf(ym) = expectedFor(pic, expected, ym).amount − recurringBills − (seasonEveryday(pic, ym) ?? e) − setAside. (needsInput guarantees expectedFor is non-null here; if it is null, return code 'needs_input'.)
- Seasonal: lean = planMonths with isLeanMonth (records path, fullMonths >= 12) or with leftOf < M (confirmed path, fullMonths < 12); if lean is empty use planMonths. leanLeft = min leftOf over lean. toCarry = records path: leanRun(pic, planMonths) (if 0, the count of planMonths with leftOf < M); confirmed path: count of lean.
- Variable: leanLeft = month.low.left (if month.low is null, today's rule); toCarry = min(planMonths.length, count of pic.months with left < M).
- Step 1: leanLeft − M >= 0 → 'fits_month', reason 'lean_months_used' (seasonal) .
- Step 2: shortfall = M − leanLeft; bridge = shortfall × toCarry; available = funds.unspent === null ? null : (available ?? value); null → 'needs_input' (missing unspent_not_confirmed); afterOneOff = available − (fromMonth + fromEarlier of the one-off split); afterOneOff >= bridge → 'fits_unspent' with fact lean_bridge { monthly: M, leanLeft, shortfall, months: toCarry, bridge, after: afterOneOff − bridge }.
- Step 3: 'not_yet', variant 'not_covered', readyBy = readyMonth(month, fromMonth + fromEarlier + bridge, available).
- Combine: code = stricter(one.code, mon.code). If code is 'not_yet', take the variant and readyBy of whichever not_yet part has the later readyBy key (date; month-01; null last); ties → the one-off part. A 'needs_input' monthly part makes the whole result needs_input with missing ['unspent_not_confirmed']. The low_month variant stays a steady-path clause only.
