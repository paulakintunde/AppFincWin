# Phase 02.1 Plan 10: PDF branch of the import hook Summary

A picked PDF now runs through the same `useStatementImport` machine as CSV and OFX, gaining the upload notice, server read, password retry, account-section choice, year question, closing-balance prompt and the "I've checked these N rows" gate, with the bytes dropped the moment they are read.

## What was built

- Stages `pdf-consent`, `pdf-password`, `pdf-balance`; abandon stages `consent`, `password`, `balance`; rejection reasons `pdf_offline | pdf_too_large | pdf_scanned | pdf_unreadable`.
- Offline PDF stops before the notice (D-06). Bytes live only in a ref (`pdfBytesHeld` mirrors it), cleared on read, any rejection, cancel, commit and unmount (D-10, D-16). The password is a parameter of one call, never state, ref, event or error (D-21).
- `applyPdfDrafts` runs `preparePdfDrafts` for the account (re-run on account change and on `chooseYear` with a `yearOverride`); `import_pdf_unread` is built from fingerprint fields only (D-14).
- `derive()` no longer skips a remembered PDF reading while a year question is open; `confirmFormat` is a no-op until the year is chosen (D-27, D-23).
- `submitClosingBalance` strips a leading minus, parses strictly through `useAmountParser`, stores `statedClosing` on the section's draft (D-24); skip leaves rows unverified.
- `reviewGate` / `rowsChecked` guard both `continue()` (review to matches) and `commit()`.
- 02.2 behaviour (refunds, pay-match pre-ticks, suggestion cap, sample-clear prompt, `suggestionToSeries`) untouched; no tier check.

## Deviations from Plan

1. **[Rule 3] ImportScreen.tsx touched** (outside files_modified): widening `rejectReason` broke `REJECT_KEY[reason]` typing. One-line fallback maps the PDF reasons to the existing `unreadable` copy until plan 02.1-11 renders PDF-specific copy.
2. **Single commit for both tasks**: the gate, cleanup and stage changes are interleaved in one file, so the two tasks were committed together (2458b19) rather than separately.
3. **Gate wording**: `reviewGate()` returns `required: true` for every PDF; the hook exposes `{ required: count > 0, count }` so a fully reconciled PDF needs no tick, as the behaviour list requires.
4. **Period-less PDF with an entered closing balance**: the one ambiguous-column line stays `cannot-verify` (as in 02.1-09's pipeline test), so the gate there is `{ required: true, count: 1 }`, not `required: false`. The other 9 rows are `verified` and `reconcile.file` is `partial`. The fully reconciled no-tick case is proven on the year-end snapshot.
5. **Unmount cleanup** is asserted only as "does not throw" (state is unobservable after unmount); the cleanup is a `useEffect` cleanup calling `clearPdf`.
