## Pattern Assignments

### `supabase/functions/read-pdf-statement/index.ts` (route, request-response)

**Analog:** `supabase/functions/resolve-rate/index.ts` — the only existing Edge Function that is **client-invoked with the caller's own JWT** (`verify_jwt = true`), rather than pg_cron's shared-secret pattern (`fx-sync`, `fx-monitor`). `read-pdf-statement` is invoked directly from the app, so this is the correct auth shape, not `fx-sync`'s.

**Dual-client pattern to copy** (`resolve-rate/index.ts` lines 8-37):
```typescript
Deno.serve(async (req) => {
  if (req.method !== 'POST') return json({ ok: false, error: 'method' }, 405);
  const authHeader = req.headers.get('Authorization');
  if (!authHeader) return json({ ok: false, error: 'unauthorized' }, 401);

  const supabaseUrl = Deno.env.get('SUPABASE_URL')!;
  const anonKey = Deno.env.get('SUPABASE_ANON_KEY')!;
  const serviceRoleKey = Deno.env.get('SUPABASE_SERVICE_ROLE_KEY')!;

  // User-scoped client: RLS decides whether the caller may act on this object at all.
  const userClient = createClient(supabaseUrl, anonKey, {
    global: { headers: { Authorization: authHeader } },
    auth: { persistSession: false },
  });
  // Admin client: only used after the user-scoped check has already proven ownership.
  const admin = createClient(supabaseUrl, serviceRoleKey, { auth: { persistSession: false } });
  ...
});
```
For `read-pdf-statement`: the client uploads to a signed URL scoped to its own `auth.uid()`-prefixed path (D-04's Storage RLS), then invokes this function with `{ path, password? }`. The function should still open a `userClient` to confirm the path belongs to the caller (same IDOR discipline resolve-rate uses for `readPending`) before the `admin` client downloads/deletes the object — never trust the path string alone.

**Response envelope + error mapping** (`resolve-rate/index.ts` lines 5-6, 159-168; `resolveRate.ts` lines 69-75, 152-167):
```typescript
const json = (body: unknown, status = 200) =>
  new Response(JSON.stringify(body), { status, headers: { 'content-type': 'application/json' } });
...
let body: unknown;
try { body = await req.json(); } catch { return json({ ok: false, error: 'invalid-input' }, 400); }
const result = await resolveRate(deps, body);
return json(result.body, result.status);
```
Copy this shape verbatim for `read-pdf-statement`: `index.ts` stays glue only (env/client wiring, storage download/delete, calling `extractPdf`), all domain logic (page-cap check, password handling, scrub-before-log) lives in `extract.ts`'s pure core — exactly how `resolve.ts` holds all of resolve-rate's logic behind a `ResolveDeps` interface so it is Jest-testable with mocked deps.

**IN-B01 discipline (never echo the underlying error):**
```typescript
// resolve.ts lines 158-167
try {
  return await resolvePending(deps, transactionId);
} catch {
  return { status: 500, body: { ok: false, error: 'internal' } };
}
```
`read-pdf-statement` must do the same — a pdf.js internal error message could contain fragments of file structure; never forward `err.message` in the response body or in an unscrubbed log line (D-15).

For `extract.ts`: no deps needed for the pure extraction itself (RESEARCH.md's verified `extractPdf(bytes, password?)` is already dependency-free — it only calls `unpdf`), but the discriminated-union `ResolveResult`-style return type is the pattern to copy for `PdfExtractResult`/failure variants (`encrypted`, `too-many-pages`, `no-text-layer`), never a thrown exception for an expected failure mode.

**Verified extraction code** (RESEARCH.md, directly executed against real fixtures this session):
```typescript
// supabase/functions/read-pdf-statement/extract.ts
import { getDocumentProxy } from 'npm:unpdf@1.8.1';

export interface PdfExtractResult {
  pageCount: number;
  pages: { page: number; items: { str: string; x: number; y: number }[] }[];
  encrypted: boolean;
}

export async function extractPdf(bytes: Uint8Array, password?: string): Promise<PdfExtractResult> {
  let pdf;
  try {
    pdf = await getDocumentProxy(bytes, password ? { password } : {});
  } catch (err) {
    if ((err as { name?: string }).name === 'PasswordException') {
      return { pageCount: 0, pages: [], encrypted: true };
    }
    throw err;
  }
  const pages: PdfExtractResult['pages'] = [];
  for (let i = 1; i <= pdf.numPages; i++) {
    if (i > 25) break; // D-07 page cap enforced before spending more CPU
    const page = await pdf.getPage(i);
    const content = await page.getTextContent();
    pages.push({
      page: i,
      items: content.items
        .filter((it): it is { str: string; transform: number[] } => 'str' in it && it.str.trim() !== '')
        .map((it) => ({ str: it.str, x: it.transform[4], y: it.transform[5] })),
    });
  }
  return { pageCount: pdf.numPages, pages, encrypted: false };
}
```
`npm:` specifier import is a proven, in-production pattern in this repo — `fx-sync/index.ts` line 1 does the identical thing: `import { createClient } from 'npm:@supabase/supabase-js@2.116.0';`.

### `supabase/functions/read-pdf-statement/scrub.ts` (utility, pure)

**Analog:** `src/services/errors/scrub.ts` — copy this file's *discipline*, not its exact regexes (client scrubber targets error messages/stack frames; the server scrubber targets log lines/metadata about a statement).

**Pattern to copy** (`scrub.ts` lines 20-38, redaction-order discipline):
```typescript
/**
 * Redacts an error message down to technical, non-identifying content: emails, quoted
 * substrings (which routinely carry payee/item/account names), currency amounts and any
 * digit run of 4+, then truncates to {@link MAX_MESSAGE_LENGTH} characters.
 *
 * Redaction order is deliberate: each pass only ever narrows what a later pass can still see.
 */
export function scrubMessage(message: string): string {
  let result = message;
  result = result.replace(EMAIL_RE, '<email>');
  result = result.replace(DOUBLE_QUOTED_RE, '<str>');
  ...
  return result.slice(0, MAX_MESSAGE_LENGTH);
}
```
For the server scrubber (D-15): the allow-list must be **outcome, duration, page count, file size, layout id and error class only** — never text, amounts, names, file names or account numbers. Prefer an allow-list function (`buildLogMetadata(input): SafeLogMetadata`) over a redact-in-place function like the client's, since the server-side surface is narrower and easier to prove complete: only ever construct the log/Sentry payload from a fixed set of named, pre-validated fields, never from a free-text string that might carry statement content.

**Test to mirror:** the client scrubber's own `__tests__` directory (`src/services/errors/__tests__/`) plus RESEARCH.md's explicit requirement (IMP-03, D-15) for "an automated test that runs a sample statement through reading and asserts nothing from it appears in logs or error events" — write `noLeak.test.ts` the same way 02-32-PLAN.md's Task 3 already plans a no-leak test for `decodeText`/`sniffFormat` (grep-based assertion that no raw statement byte or string reaches a log call).

**Function shape to copy** (`fx_monitor_jobs.sql` lines 19-56, adapted):
```sql
create or replace function public.purge_stale_statement_uploads(p_older_than interval default interval '24 hours')
returns integer
language plpgsql
security definer
set search_path = ''
as $$
declare
  n integer;
begin
  delete from storage.objects
   where bucket_id = 'statement-uploads' and created_at < now() - p_older_than;
  get diagnostics n = row_count;
  return n;
end;
$$;

revoke execute on function public.purge_stale_statement_uploads(interval) from public, anon, authenticated;
grant execute on function public.purge_stale_statement_uploads(interval) to service_role;
```

**Schedule shape to copy** (`fx_monitor_jobs.sql` lines 115-128, simplified — no HTTP hop needed):
```sql
select cron.schedule(
  'statement-uploads-purge-hourly',
  '0 * * * *', -- hourly is comfortable margin inside the 24h backstop window (D-12)
  $$ select public.purge_stale_statement_uploads(); $$
);
```
Note this is *simpler* than both existing scheduled jobs (no `net.http_post`, no Vault secret, no shared-secret header) precisely because it needs no Edge Function round trip — call this out explicitly in the plan so it isn't over-built by copying the HTTP-hop machinery unnecessarily.
