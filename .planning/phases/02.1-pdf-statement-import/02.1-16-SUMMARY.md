# Phase 02.1 Plan 16: IMP-05 commit path Summary

Imports of any format (PDF, OFX, CSV) now store the statement's own conversion: the charged amount stays `original_amount`, the statement's foreign original goes to insert-only `stmt_orig_amount` / `stmt_orig_currency`, and separate FX fee lines link to their purchase with `fx_fee_of`.

## What was built

- **Task 1 (38657f2):** `NewTransaction` and `TransactionRow` gain the IMP-05 fields; the three insert-only keys are added to the insert list only; `TRANSACTION_COLUMNS` selects the four columns; the import chunk's optimistic row copies them and sets `conversion_source: 'statement'` when figures are present.
- **Task 2 (9d042af):** `buildPreview` runs `linkFxFees` over non-locked, non-duplicate rows and exposes `foreign` and `feeOf`. `toImportCommit` sets the statement figures only when the currency differs and signs match (mirrors the DB shape check), before any branch so the mark-paid fallback line carries them; the patch never does. Fee rows get `fx_fee_of` = the purchase's id, or, when the purchase became a mark-paid, are held in `ImportMarkPaid.feeLines`. `importFinalize` inserts held fees after `applyPatches` succeeds, on the C-WR-02 replay path and on the no-items path; a set-aside mark-paid re-points its fees to the fallback line. Held fee ids are in the import's inverse-of-inserts and counted once in `n`, so they share the single undo step. The failed-write `unrecordedLines` also include re-pointed fee lines.
- **Task 3 (93a2e02):** mapping step lists `foreignAmount` and `foreignCurrency` after Currency, with i18n keys; the Role type no longer excludes them.

## Deviations from Plan

- [Rule 2] `unrecordedLines` in the failed-write payload now also carries fee lines (re-pointed to the fallback line), otherwise a finalize that cannot run would lose held fees.
- The CSV fixture test only asserts the file prepares as CSV; the CSV foreign column roles are covered by engine tests (02.1-14/15), not re-driven end to end here.

## Known limitation / note

- D-36 (accepted): a kept mark-paid leaves the pending line without statement figures.
- A fee whose purchase lies in a different insert chunk could, in principle, be inserted before its purchase (FK `fx_fee_of`); linkFxFees prefers the row directly before the fee so the purchase normally precedes it. Not guarded here (chunkKeepingPairs only keeps transfer pairs together).
