Create `docs/decisions/statement-pdf-reading.md` with these sections (plain declarative prose, dated 2026-09-27):
1. **Decision** — PDFs are read server-side in the Supabase Edge Function `read-pdf-statement` using `unpdf@1.8.1` (pdf.js), in the existing production project (us-west-2), under the same Supabase DPA. D-02's on-device preference was weighed: the only on-device candidate returns plain text with no positions and would need a new native build; it is recorded under Deferred Ideas for revisit if a mature on-device library with text positions appears.
2. **Sub-processor cost (D-04)** — none: no worker service, no new vendor, no new DPA, no new region. `docs/dependency-register.md` needs no new row; its Supabase row gains a note at rollout (plan 02.1-12).
3. **Flow** — app uploads to private bucket `statement-uploads` at `<user id>/<random id>.pdf` (owner-folder insert only; no client can read, list or delete); the app calls `read-pdf-statement` with the path and, if needed, the password; the function reads, deletes the object in the same request on every outcome, and returns positioned text; the phone builds the StatementDraft and runs Phase 2's unchanged pipeline.
4. **Retention (D-10, D-11, D-12)** — no copy of any statement is kept, ever, in this phase; a stray upload (crash, closed app, dropped connection) is removed by the hourly `statement-uploads-purge-hourly` job once it is an hour old, so nothing survives two hours. **For Phase 10 (account deletion): there is no statement store; account deletion has nothing to purge for statements.** If a later phase adds "keep a copy", that phase must add its own deletion path.
5. **What the server keeps (D-13)** — nothing extracted from a statement; only the transactions a user commits, through the normal transaction path with RLS and FX stamping.
6. **Logs and error reports (D-15)** — server log line fields: fn, outcome, durationMs, pageCount, byteSize, removed, errorClass (closed list from the error's name). Never text, amounts, names, file names, paths, passwords or account numbers. The app sends no Sentry event from the PDF path. Both are enforced by tests (read.test.ts, readPdf no-leak test, engine noLeak.test.ts).
7. **Layout fingerprint (D-14)** — the `import_pdf_unread` analytics event: failed step, page band, and which column roles were found. No header text, no bank name (no bank templates exist yet, D-18, so nothing is detected), no amounts, names, dates, descriptions or account numbers; consent-gated.
8. **Passwords (D-21)** — sent with the read request over TLS, used once to open that file, never stored or logged.
9. **Not in scope** — OCR (D-28), AI reader (D-29), keep-a-copy, share-sheet entry, offline queueing, Free/Pro gating (Phase 9, which should weigh the server cost).
