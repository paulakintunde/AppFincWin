# Phase 02.1 Plan 08: pdfToDrafts Summary

Raw PDF rows and statement figures become Phase 2 `StatementDraft`s, and all six real extraction snapshots run through Phase 2's unchanged `inferProfile`, `convertDraft` and `reconcile` to their expected ledgers.

## Tasks

1. **pdfToDrafts + unit tests** - `77e4ed6`. 332-line `toDraft.ts`; every amount and balance goes through `parseNotatedAmount`; between-column and headerless amounts are placed via `balanceStep` / `learnDebitDirection` / `pickByDelta`; year questions, sections, stated figures, labels, warnings.
2. **Reader fixes** - `971069c` (deviation, below).
3. **Fixture flow + no-leak tests** - `56f0d56`. `fixtures.test.ts` (six `describe.each` blocks, multi-account two drafts 6 and 4 rows) and `noLeak.test.ts` (five corruptions, console spies, JSON leak scan, issue-code allow-list).

TDD note: the unit tests and implementation were written together and committed as one feat commit, so there is no separate RED commit for this plan (tdd gate warning).

## Deviations from Plan

**1. [Rule 1 - Bug] Label-cell figures were not read as statement figures** - `rows.ts` `lastNumeric` only looked for a separate numeric cell, so real "Previous balance 820.40" / "New balance 1,250.00" / "Opening balance 5,000.00" lines (one text cell) gave no opening/closing/limit. Now falls back to the tail token of the line text. Tests added in rows.test.ts.

**2. [Rule 1 - Bug] Page running header became a wrapped description** - multi-account page 2 starts with "Example Bank", which was appended to the previous section's last row. Continuation lines now only join a row on the same page (header and headerless modes). Tests added.

**3. [Rule 1 - Bug] Overlapping header runs fused** - credit-card header "Transaction date" (x 50-117) overlaps "Description" (x 110), so groupLines fused them, the header was not found and the statement fell to headerless mode with wrong signs. Runs overlapping by more than 1pt (`CELL_OVERLAP`) are now separate cells. Fixture left unchanged (reader fix chosen over regenerating the generator; the overlap is a generator column-width quirk but the tolerance is harmless for real PDFs). Test added in layout.test.ts.

**4. [Rule 3 - Blocking] depcruise no-circular** - importing `../../csv` barrel from toDraft created a cycle (csv -> statement -> pdf -> csv); imports `../../csv/inferFormat` directly.

No fixture or generator changes; no snapshots regenerated.
