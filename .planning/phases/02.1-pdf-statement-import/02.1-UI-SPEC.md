# Phase 2.1 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Platform note:** identical to `02-UI-SPEC.md` — React Native / Expo SDK 57, no CSS, no Tailwind, no shadcn. Styling is `StyleSheet` + the typed theme context (`src/theme/*`). All template fields assuming a web/shadcn stack are **N/A**, answered with the RN-equivalent.

**Extends, does not replace, `02-UI-SPEC.md`.** PDF is one more format adapter into Phase 2's single import pipeline (D-40): the same `ImportScreen`/`useStatementImport` state machine, the same format read-back, mapping-skip, reconciliation, duplicate, transfer and recurring-suggestion screens Phase 2 already built. This document specifies **only what a PDF adds**: a handful of new prompts and states slotted into the existing stage sequence, using only Phase 2's tokens, primitives, roles and copy voice. **No new colour, icon, spacing token, type size or component class is introduced anywhere in this document.** Where a state already exists in `02-UI-SPEC.md` (the "Can't verify" tag, the reconciliation sentence set, the format read-back, the multi-statement picker), it is reused verbatim and is not re-specified here.

**Open research dependency:** `02.1-CONTEXT.md` D-01 leaves the read location (on-device vs. a Supabase Edge Function / worker) to research. This document specifies **both variants** wherever they visibly differ — the upload notice, the offline message and the privacy line — and marks everything else as shared, so planning and execution are not blocked on that outcome.

**Phase 2.1 UI surface:** additions to the existing `ImportScreen` stage sequence only — a PDF branch of the file picker, an upload-consent notice (server variant only), a password prompt, an offline message (server variant only), a too-large-file message, an unreadable-layout message, a scanned-PDF message, a visible "reading" progress state, a multi-account section picker, a closing-balance prompt with its skip-confirmation, and a year-ambiguity question folded into the existing format-confirmation step. Nothing else in Phase 2's Record surface changes.

## Design System

| Property | Value |
|----------|-------|
| Tool | none — shadcn is not applicable to React Native (unchanged from `02-UI-SPEC.md`). |
| Preset | not applicable |
| Component library | none as a package. This phase adds three small composed screens/sheets — `PasswordPromptSheet`, `ClosingBalancePrompt`, and a `ReadingProgress` state view — each built entirely from Phase 2 primitives (`Sheet`, `Row`, `Pill`, the amount-entry field and `useAmountParser`, the existing tick/checkbox row, `OptionPicker`-style selectable rows). No new primitive class is introduced. |
| Icon library | none required — unchanged. The "reading" progress state uses the platform-native `ActivityIndicator` (React Native core), not a custom icon or SVG asset, tinted `accent`. |
| Font | Whatever pairing/accent the user has live-selected — unchanged; resolved through `useTheme()`/`textRole()`. |

**File picker:** the existing "Choose file" entry (`expo-document-picker`) now also accepts `.pdf`, sniffed by content (`%PDF-` header) alongside CSV/OFX/QFX (D-08). The file-picker helper line becomes format-agnostic — see Copywriting Contract — since each format's own size ceiling is now surfaced after the file is read, exactly as CSV's row-count ceiling already is, not pre-emptively.

**No new roles or sizes.** Every new copy element in this phase uses one of Phase 2's four existing roles:

| Element | Role |
|---|---|

| Body copy, helper text, the reading-state primary line | Body (15px/500) |
| Field labels, row sub-labels, the reading-state helper line ("This can take up to 10 seconds.") | Label (13px/600) |

## Color

**No new colours.** This document extends two of `02-UI-SPEC.md`'s existing reservation lists with explicitly named additions — it does not introduce a new role.

| Role | Value | Extended reservation (this phase) |
|------|-------|-------------------------------------|
| Accent | `accent` (user-selected, default `#1B4D3E`) | Adds, to the existing list: the password prompt's "Unlock" CTA, the upload notice's "Send and read" action, the closing-balance prompt's "Check balance" CTA, and the `ActivityIndicator` tint on the reading-progress view. Never used for the "Cancel"/"Skip" secondary actions, which render as plain text per the existing secondary-action convention. |
| Destructive | `danger` `#B4472A` | Adds, to the existing "row-count-exceeded message" reservation: the PDF too-large message (D-07), which is the direct page/size analogue of CSV's 5,000-row ceiling message and is styled identically — same role, same weight, no icon. |

Every other new state is plain `ink`/`inkMuted`/`inkFaint`/`fill1` text exactly as `02-UI-SPEC.md` already uses those tokens for informational (non-error) notes:

- The offline message (server variant), the unreadable-layout message and the scanned-PDF message are **not** danger-coloured — they reuse the exact plain-text treatment `02-UI-SPEC.md` already specifies for CSV/OFX's `unreadable` reject reason (Body role, `ink`/`inkMuted`, no icon, no colour-coding), because none of these are error states in the sense the row-count ceiling is; they are "this can't proceed, here's what to try instead" notes.
- The upload notice is a plain informational line (Body role, `ink`), not a warning — it is consent copy, not a risk flag.
- The multi-account section picker and the year-ambiguity candidate rows reuse the existing selectable-row visual treatment from the format-confirmation ambiguous-candidate list (no colour-coding beyond the existing selected/unselected row state already defined in `02-UI-SPEC.md`).
- The "Can't verify" tag on unreconciled PDF rows is the exact same `fill1`/`inkMuted` chip `02-UI-SPEC.md` already defines — reused verbatim, not restyled for PDF.

## Where the PDF Is Read — Both Variants

| State | Server variant | On-device variant |
|---|---|---|
| Upload-consent notice (D-05) | Shown once per PDF import, before the file is sent | Never shown |
| Offline message (D-06) | Shown when the device is offline and a PDF is picked; import cannot proceed | Never shown — PDF imports offline exactly like CSV/OFX |
| Privacy line (D-17) | Server-variant wording (see Copywriting Contract) | Existing Phase 2 wording, unchanged, already covers PDF |
| Reading progress (D-03) | Visible for the full round trip (upload, server read, response) | Visible for the on-device parse; likely shorter in practice, but the same UI applies since D-03's ~10s bar is the shared target for either path |
| Password prompt (D-21) | Same prompt; password travels with the upload over TLS and is discarded after reading (no UI difference) | Same prompt; password is used only to open the file locally (no UI difference) |
| Everything else (too-large, unreadable, scanned, account-section picker, closing-balance prompt, year-ambiguity, reconciliation, duplicates, transfers, recurring suggestions) | Identical | Identical |

This table exists so planning is not blocked on the D-01 research outcome: only the two rows marked "Never shown" / wording differences are conditional; every other row in this document ships regardless of which path research chooses.

## Focal Points

Each new surface is a small, single-purpose sheet or state. One element is its anchor; everything else is secondary.

- **Reading progress:** the indicator and its one line ("Reading your statement…") are the only anchor. There is no other content to compete with.
- **Upload notice:** the notice sentence is the anchor. "Send and read" is the one accent element; "Cancel" is plain text.
- **Password prompt:** the password field is the anchor, focused on open. "Unlock" is the one accent element.
- **Closing-balance prompt:** the amount field is the anchor. "Check balance" is the accent action. "Skip" is plain text and leads to the "I've checked these N rows" confirmation.
- **Account-section picker and year question:** the list of choices is the anchor. The question above it is the Sheet title, and helper text sits below as Label.
- **Offline, too-large, unreadable and scanned messages:** the message sentence is the anchor. The CSV/OFX pointer or next step follows as Body.

## Accessibility for New States

- **Reading progress.** The view carries `accessibilityLiveRegion="polite"` on the primary line so a screen-reader user is told reading has started and is not left silent for up to ~10 seconds; the `ActivityIndicator` carries `accessibilityLabel="Reading statement"`.
- **Password prompt.** The password field is `secureTextEntry`, labelled "Password" (not a bare icon-only lock glyph), and the wrong-password message is announced via `accessibilityLiveRegion="polite"` rather than only shown visually.
- **Upload notice.** The "Send and read" action's accessible name states the consequence in full — "Send this PDF to our server to read it" — matching the existing convention (transfer-suggestion cards, format-flip control) of naming what a consequential action does before it happens.
- **Offline / unreadable / scanned / too-large messages.** Each is a plain text block, read by a screen reader exactly as any other paragraph — no icon-only state exists to translate, matching `02-UI-SPEC.md`'s existing reject-reason accessibility pattern.
- **Account-section picker.** Each row's accessible name states the account label and line count in full ("Checking account, 42 lines"), not a bare "Section 1".
- **Closing-balance prompt and skip-confirmation.** The amount field uses the same accessible labelling as every other amount field in the app; the "I've checked these {n} rows" control carries `accessibilityRole="checkbox"` and its full sentence as the label, and the commit CTA's `accessibilityState.disabled` reflects the gate so a screen-reader user is told why the action is unavailable, not just that it is.
- **Year-ambiguity rows.** Each candidate row's accessible name is "Year {year}" in full, never a bare number, so a screen-reader user does not mistake it for an amount or a count.
- **General:** every new interactive element meets the existing 44px `touch-target-min` and `accessibilityRole="button"` conventions already established in `02-UI-SPEC.md` — nothing here needed a bespoke exception.
