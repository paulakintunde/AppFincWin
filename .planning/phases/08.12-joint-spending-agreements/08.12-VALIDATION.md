> Per-phase validation contract for feedback sampling during execution. Source: `08.12-RESEARCH.md` § Validation Architecture.

## Test Infrastructure

| Property | Value |
|----------|-------|
| **Framework** | Jest 30 + fast-check 4.10.1 (engine, `jest.engine.config.js`, 100% coverage folders); Jest 30 + RNTL (app, `jest.config.js`); pgTAP (`supabase/tests/database/NNN_*.test.sql`, local stack); Deno test (Edge Functions) |
| **Config file** | `jest.engine.config.js`, `jest.config.js`, `package.json` `test:deno` list |
| **Quick run command** | `npx jest -c jest.engine.config.js <touched engine path>` or `npx jest <touched app test file>` |
| **Full suite command** | `npm test && npm run test:engine && npm run typecheck && npm run lint && npm run depcruise && npm run check:right-answers && npm run check:cache-version && npm run lint:migrations` (+ `supabase test db` for touched suites, `npm run test:deno` when `alerts-deliver` changed) |
| **Estimated runtime** | quick ~20-60 s; full ~10-15 min |

---

## Sampling Rate

- **After every task commit:** the quick command for the touched module (no full local coverage per plan).
- **After every plan wave:** the full suite command above.
- **Before `/gsd-verify-work`:** full suite + `npm run test:crosscheck` + `npm run test:coverage` green.
- **Max feedback latency:** 60 seconds for the quick command.
