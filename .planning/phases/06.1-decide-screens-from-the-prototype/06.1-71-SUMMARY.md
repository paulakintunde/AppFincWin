## What changed

**Task 1 (FQ10, CN-9):**
- `monthFilter.ts` checks the params. `month` must be YYYY-MM with a month from 01 to 12. `why` must be one of `bill`, `pay`, `spending`, `late_start`, `month` or `recent`. Anything else is ignored, and an unknown code shows no banner (T-06.1-71-01).
- The Activity route reads `?month&why` the same way it reads `?debt`. Clear calls `router.setParams({ month: undefined, why: undefined })`.
- ActivityScreen sets the shared month once per arrival. Activity stays mounted as a tab, so `initialMonth` alone could not do it.
  - The banner shows above the list, only on the month it names and not while search is open.
  - Moving to another month drops the params, so the same link works again next time.
- Readiness fix (answer and Records) pushes `/activity?month=<item month>&why=<item kind>`.
- Records "Records for <last month>" pushes `?month=<previous month>&why=month`. "Add since" pushes `?month=<this month>&why=recent`. "Add as you go" (no records yet) still opens plain Activity.

**Task 2 (CN-10, OQ-71-1 B):**
- `RegionRow` sits on You under Home currency.
  - "Region" shows the user's own country, or "<Country>, from this phone".
  - "State or province" shows only when the country in force is the US or Canada.
  - Each opens a scrolling Sheet list. The country list starts with "From this phone".
- Writes:
  - Country: the existing `useUpdateMoneyPrefs().setRegion`.
  - State or province: the new `useSetRegionSubdivision`. It uses the same pattern as moneyPrefs: queued, `WRITE_SCOPE`, an optimistic update to `queryKeys.regionSubdivision`, and on rejection it puts the old value back (or re-reads it) and records a failed write.
  - Decide's Price step reads the same cache key, so its tax line updates at once.
- YouScreen: the `?focus=currencies` handling is now one helper that also covers `?focus=region`.
- PriceStep: the `set-region` link pushes `{ pathname: '/you', params: { focus: 'region' } }`. `grep -c "router.push('/you'"` returns 0.
- Region precedence is unchanged: `resolveRegion` still applies the user's own choice, then the device region, then the time zone. No IP lookup.

**Task 3 (CB-12, DN-6):**
- `AnswerWrites.setNoOverdraft(account, ownerId)` is bound in AnswerRoute. It calls `useEditAccount().edit({ ..., patch: { overdraft_limit: 0 } }, { stepId: newStepId(), ownerId })` and returns the step id, or null when no undo step was recorded.
- "No overdraft" now:
  - writes once per account while the fact still shows (T-06.1-71-02); the guard resets when the fact goes, so it can be answered again after an Undo
  - plays a light haptic and shows "Saved: no overdraft on <account>." with Undo
  - pushes nothing, so the user stays on the answer
- "Add limit" still opens `/accounts/<id>`.
- DN-6: the `account_use_question` Fix pushes `withFromAnswer({ pathname: '/decide/setup/records', params: { account } })`. The account id comes from the `account_use_unknown` notice. When only `fund_account_unknown` is present, it pushes `/decide/setup/net?from=answer`.
- RecordsSetup opens the accounts sheet once when `?account=` names an account it asks about, and lists that account first. Back uses `useLeaveItem`, which is `router.back()`, so it returns to the answer.

## Deviations from Plan

1. **[Rule 3 – scope, OQ-71-1 B] Files added to the plan before Task 2:** You files, the subdivision mutation and query, keys, the mutation registry and tests. Plan 79's file list overlaps none of them.
2. **[Rule 2] New data-layer write `useSetRegionSubdivision`.** `updateRegionSubdivision` existed only as a db function with no hook. It writes an existing, user-granted column. No schema change.
3. **[Rule 2] Extra links carry a month:** Records' "add since" (`why=recent`). The banner has two extra reason codes, `month` and `recent`, because those Records links have no readiness item kind.
4. **[Rule 1] The same link must work twice.** Leaving the banner's month drops the params. Without this, a second tap on the same link changes nothing (same params) and Activity would stay on the other month.
5. **[Rule 2] No overdraft fallback and double-tap guard** (T-06.1-71-02), plus the fund-only DN-6 route to Safety net.
