# Phase 06.1 Plan 82: Four device-check bugs before the Pixel 6 check

Owner-approved 2026-11-13 gap plan from the 06.1-61 device run. Screen-side only: no change under `src/engine`
(DECIDE_ENGINE_REVISION stays '06.6'), CACHE_SCHEMA_VERSION stays '9'. TDD: a failing test first for each bug.

## Tasks

1. **G-61-8 (red Maestro decide-waiver): "None" on the debts ask must always resolve it.**
   The engine asks about unrecorded debts whatever the `answered_no_debts_at` flag says, and the flag write is a no-op when the
   flag is already set, so "None" did nothing. The answer now leaves the `ask_debts_not_recorded` fact out once the flag is set
   (pure helper in `screens/logic/shownAnswer.ts`, applied to the evaluation the answer screen shows).
2. **G-61-11 (D21 doubled running costs): "Price and how you pay" shows the plan payment alone.**
   `Purchase.monthly` includes running costs (`runningMonthly`). The told line and the price step's plan summary use
   `planPaymentOf(purchase) = monthly - runningMonthly`; the verdict's own monthly figures stay the full monthly cost.
3. **G-61-3 (Not ready on a decided check for its own goal):** a decided check's answer drops readiness items for the Grow goals
   linked to it (`savings_goals.check_id`), recomputing `missing` and `ready` the way the engine does.
4. **G-61-10 (Save for it on an item that already fits):** when the engine's ready date is today or earlier, the goal card shows
   a new line instead of a same-day "Ready by", and the default amount is spread over twelve months like the no-date case.
   New string goes to plan 33's wording sign-off.
