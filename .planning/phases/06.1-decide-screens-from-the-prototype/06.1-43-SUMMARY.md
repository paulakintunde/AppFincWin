# Phase 06.1 Plan 43: Readiness answers reach the engine (G-1 part 1) Summary

Readiness answers are now stored as `decide_answers` rows of kind `readiness_waiver` and read back into `V3Inputs.waivers`. Skipped series lines reach the engine as `V3Inputs.skipped`. So an answer the user gives, or a line they skip, can now clear a named readiness item. A pure model, `readinessFixRows`, gives every item one fix and the answers the engine accepts for it. `EnvelopeAccountSheet` is the D-54 fix: it links an envelope to the account that holds it. No engine or database change was needed.

### Auto-fixed Issues

**1. [Rule 3 - Blocking] `V3AnswerLite.kind` widened in snapshot/v3/types.ts**

- **Fix:** Added `'readiness_waiver'` to the union. This file was not in files_modified.

**2. [Rule 3 - Blocking] Test file name**
- The plan names `src/data/mutations/__tests__/decideAnswers.test.ts`. The existing suite is `decideAnswers.test.tsx`, so the new cases went into that file.

**3. [Rule 1 - Copy key path] Envelope sheet keys**
- The plan's keys `decide.screens.sheets.envelopeAccount.*` would not resolve, because sheetsHome.ts is mounted at `decide.screens.sheetsHome`. The real keys are `decide.screens.sheetsHome.envelopeAccount.title` ("Which account holds {{envelope}}?") and `.none` ("No accounts yet.").

**4. [Rule 2 - Validation] readiness_waiver `at` checked**
- `shapeOf` throws RangeError when `at` is not YYYY-MM-DD, so the write fails before it is queued. Without this the database would reject it later.

**5. [Rule 1] Defensive branches in readinessFixes**
- If a bill or pay item lacks its series id or date, it offers no occurrence answer. The engine always sets both, so this case is tested but never reached in practice.
