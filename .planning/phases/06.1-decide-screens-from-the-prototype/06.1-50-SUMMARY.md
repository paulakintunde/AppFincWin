# Phase 06.1 Plan 50: Setup returns to one checklist, and the checklist has Back (G-4 part 2) Summary

Every setup item now returns to the checklist that is already open instead of stacking a new copy on top. So from an item, one Back leaves the item and one more Back leaves setup. The checklist also has a Back chevron in its top bar in every state, not only "Back to Decide" when all six are done.

## What changed

- `useLeaveToChecklist()` in SetupItemFrame.tsx returns `() => router.dismissTo(SETUP_HOME)`.
- All six items use it for the save path, "Save and close" and Back:
  - Pay, Bills, Debts, Net, Rules and Records.
  - Each `const leave = ...` is now the hook, called next to the other hooks, and every save handler's `router.replace(SETUP_HOME)` is now `leave()`.
  - Pay and Bills no longer need `useRouter`, so the import was dropped there.
- Toasts still fire before leaving. This includes plan 45's Records `stillOpen` toast, which stays first, and `leave` keeps its old behavior there.
- PaySetup edit is navigation only (3 lines), as plan 54 will rework that file.
- SetupChecklist has a top row with a `checklist-back` Pressable:
  - It uses the StepFrame/Row chevron (a rotated-border View pointing left, accent colour), so no icon library.
  - It has the a11y label `decide.screens.common.a11y.back` ("Back") and a 44 pt minimum target, and calls `onBack` in every state.
  - The all-done "Back to Decide" Pill is unchanged.
- SetupChecklistRoute needed no change: `onBack` already does `canGoBack ? back : replace('/decide')`.
- App stacks all run with `headerShown: false`, so there is no duplicate native header Back.
