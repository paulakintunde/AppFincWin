# Phase 06.1 Plan 64: Back returns to the answer you came from (H-3, FQ2) Summary

A step opened from the answer now carries `from=answer` and its Back, Android Back and "See the answer" pop straight back to that same answer (now re-judged). Every "go to Decide home" uses `router.dismissTo`, quick estimates from the answer go back to it, and the dead `setup/done` route is gone.

## What changed

**Task 1 (CN-4, CN-14), commit b4cb97fd**
- New `logic/decideNav.ts` (router passed in, no hooks): `goDecideHome(router, { focusCheck })` -> `dismissTo('/decide' | '/decide?focus=check')`; `backToCaller(router, fallback)`; `FROM_ANSWER = 'answer'`; `withFromAnswer(href)`; `isFromAnswer(param)`. 100% lines/branches/functions.
- `openNewCheck` (the answer's "New check") now dismisses to Decide home with the field focused instead of pushing a new copy.
- Past "Back to Decide" (empty state) uses `goDecideHome`.
- `app/(app)/decide/setup/done.tsx` deleted; its `Stack.Screen` and the routing-test entry removed. The `SetupDone` component and its test are kept (see Deferred).

**Task 2 (CN-1, DN-3, iOS swipe from 06.1-57), commit d6721a84**
- `useStepNav(id, step, flush)` in `check/useStepCheck.ts` reads `from` and gives `fromAnswer`, `to(step, dir)` (keeps `from=answer`), `back()` and `seeAnswer()`. Kind, Price and Costs steps (and their "still saving" screens) route Back, Next, the step bar and "See the answer" through it. StepFrame is untouched; its Android Back handler already calls the step's `onBack`.
- AnswerScreen: the four step links (price fix, Running costs, What you told, Costs that stop Add) push `withFromAnswer(stepHref(n, id, 'back'))`; "I'm not buying it" success and the answer Back fallback use `goDecideHome`.
- `app/(app)/_layout.tsx`: `gestureEnabled: false` on the three step routes.
- New `stepperBack.test.tsx` (8 tests): from=answer chevron Back flushes then calls `router.back` once (no replace/push); "See the answer" on steps 2 and 3 calls back, not push; Next keeps from=answer; DN-3 answer -> step 3 -> Android Back x3 never calls `BackHandler.exitApp` and ends on the answer (back) or Decide home (dismissTo); forward path step 2 Back replaces to step 1, step 1 Back dismisses to `/decide`, "See the answer" pushes.

**Task 3 (CN-5 b), commit e29adac4**
- `safeReturnTo.parseReturnTo` returns the safe path plus `'answer' | 'other'`; only `/decide/answer/<id>` after the existing allowlist counts as an answer (T-06.1-64-01).
- `decideNav.returnFromQuickEstimates`: answer below -> `router.back()`; answer with nothing below -> `dismissTo(answer)`; no or rejected return path -> `goDecideHome`; other allowed path (onboarding `/setup/history`) -> `dismissTo` (pops to it if below, otherwise takes this screen's place, as replace did). `QuickEstimatesRoute` has no `router.replace`.

## Deviations from Plan

1. **[Design detail] `useStepNav` instead of `useStepCheck` exposing `fromAnswer`.** AnswerScreen also calls `useStepCheck`, so the `from` param read and the Back rule live in a sibling hook in the same file (`useStepNav`, which returns `fromAnswer`). Same behaviour as the plan's bullet.
2. **[Rule 2] Next and the step bar keep `from=answer`.** Without this, a user who opened Kind from the answer and pressed Next would land on Price without `from`, and Back would walk the forward path instead of returning to the answer. Tested.
3. **[Design detail] `returnFromQuickEstimates` lives in `logic/decideNav.ts`**, so it is covered by `decideNav.test.ts` at 100% (the plan allowed the kind tests there). Non-answer allowed paths use `dismissTo` (the plan only named the answer and no-returnTo cases; the acceptance grep forbids `router.replace`).
4. **Test files touched beyond the list**: `stepper.test.tsx` (router mock gains dismissTo/back/canGoBack; step 1 Back now asserts dismissTo), `past.test.tsx` (asserts dismissTo), `decideRouting.test.tsx` (drops the deleted route). Two unused-import lint warnings fixed in the Task 3 commit.
