# Phase 06.1 Plan 77: After "I bought it" (H-14) Summary

"I bought it" now writes a **paid** day-one row on the date the Bought screen shows. That date is today by default and the user can change it, but never to a day after today. The writer and the screen both take today from the record context. Remove from decisions says which amount stays in the records and links to it. The Past detail shows the up-front amount as soon as the add is done.

## What changed

- **DC-3, root cause.** The plan pointed at `boughtWrite.ts`, but "I bought it" goes through `useGoAheadV3`, and `goAheadInputOfV3` in `decideGoAhead.ts` wrote `status: 'pending'` on every row. It also dated the day-one row with the engine's `purchaseDate`, which comes from the engine's own clock or the planned day. The fix:
  - Rows are now `localDate <= ctx.today ? 'paid' : 'pending'`, the owner's 2026-10-31 rule. Later instalments stay pending.
  - The day-one row is dated `ctx.date` (new, optional), held at `ctx.today`. Without a `ctx.date` it uses `ctx.today`.
  - The optimistic rows use the same `vars.rows`, so the optimistic status always matches what is written.
  - The `record_decide_go` call shape, its replay key and the one Undo are unchanged.
- `boughtWrite.ts` (`buildBoughtWrite`, used only by the dev harness) already used `ctx.today` for both the date and the comparison. I added the "date one day ahead" guard test there and made no code change.
- **Bought screen (OQ-77-2 A).** The Date row is now the record `DateField`. It starts on `today` (the shell's `rc.today`) even when the check was planned for a later day. A picked day after today is held at today. The chosen date goes to the writer as `ctx.date`, and the "Added" line shows it.
- **ActionRoutes.** No change was needed: it already passes `today={rc.today}`. The new routing test pins that the route takes today from the record context, not from the engine's purchase date.
- **DS-17.** The cause was still present after Task 1. "What your records show so far · Up front" read only the 30-day look-back checkpoint, so it showed a dash for 30 days after the add. It now shows the day-one amount the write added, read from this decision's live `written` `day_one` links. While those lines are being read it shows "Loading…", and with no such line it still shows the dash. Once the 30-day look-back is reached, its figure is used, as before. `usePastDecisions` now exposes `linesLoading`.
- **DC-4 (OQ-77-1 A).** When the up-front amount is known, the Remove confirm sheet says "The $12 in your records stays." For a plan it says "The $12 and its planned payments in your records stay." It also has an "In your records" row with a chevron. That row sets the shared Activity month to the record's month (`setSelectedMonth`) and opens `/activity`. When the amount is not known, the earlier copy is used. Nothing in the records is deleted.

## Deviations from Plan

1. **[Rule 1 - Bug] The live writer is `decideGoAhead.ts`, not `boughtWrite.ts`.** The fix went into `goAheadInputOfV3` and its tests (`decideGoAheadV3.test.tsx`), files the plan did not list. `boughtWrite.ts` was already correct and got only a guard test. Commits 5732bb6c and d20c4f10.
2. **[Rule 2] `usePastDecisions.ts` gained `linesLoading`** (not in the plan's file list). Without it, a record the user deleted would show "Loading…" for ever. Commit b00f55ba.
3. **Activity has no month route parameter.** "Pushes Activity with that month" is built with the existing shared month store (`setSelectedMonth` in `@/state/activityFocus`, the same store Home's Pay bills uses) plus `router.navigate('/activity')`.
4. The existing test "a dated purchase writes on that date" changed meaning on purpose (OQ-77-2 A): a check planned for later now writes today, paid.

## Known limits (not fixed)

- When the user changes the bought date, the plan's payment schedule stays on the engine's dates. Only the day-one row moves.
- `goAheadInputOfV3` does not skip a first payment dated today the way `buildBoughtWrite` does. This was already so before this plan and is out of scope.
- The "Up front" figure counts only links with role `day_one`. Older links with a null role show the dash until the look-back.
