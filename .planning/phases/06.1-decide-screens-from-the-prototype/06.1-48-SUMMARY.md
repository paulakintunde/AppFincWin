# Phase 06.1 Plan 48: Writes that land in seconds Summary

The persister wrapper now does its whole save (queued-write stringify, chunking, overflow clean-up, dev byte log, encryption) at most once per 1 s window and at once on background; every write leaves Sentry 'write' (settle) and 'net' (send) breadcrumbs with timings and no payload; and a cold-start restore refetches only stale active reads.

## What was built

**Task 1 (B-5) - throttled wrapper.** `createEncryptedPersister` keeps the latest client and schedules one trailing save after `throttleTime`; the base persister is created with throttle 0 (one throttle, not two). Saves run on a chain so they never overlap; `throttleTime <= 0` saves at once. The instance remembers how many overflow chunks it last wrote (`lastChunks`, starting `unknown`) and only reads overflow rows when an earlier save may have left rows past the new count. Stale overflow rows are now removed after the main row is written (a kill in between can no longer leave a main row pointing at removed chunks). New: `EncryptedPersister` type with `flush()` and `persistNow(client)`; exported `flushPersist()`. `removeClient` cancels a scheduled save. `startPersistOnBackground` (already registered in QueryProvider next to `persistOptions`) now calls `flushPersist()` on background/inactive, then on the next tick saves a fresh dehydrate via `persister.persistNow` (replacing the old second "immediate" persister instance). `CACHE_SCHEMA_VERSION` stays `'9'`; check:cache-version passes.

**Task 2 (F-2) - write timing.** `QueryClient` gets `mutationCache: new MutationCache({ onSettled })` adding `{ category: 'write', message: 'settled', data: { key, ms, status, failures } }`. `timeoutFetch` adds `{ category: 'net', message: 'write request', data: { method, table, ms, status } }` for non-GET/HEAD requests; `table` comes from the new `writeTableOf(url)` (segment after `/rest/v1/` or `/rpc/`, query string cut, else `'other'`); status is the HTTP status, `'failed'` or `'timeout'`. Timeouts and `RequestTimeoutError` unchanged.

**Task 3 (B-4) - restore.** `afterCacheRestore` calls `replay(qc)` first (never awaited, D-88) then `qc.refetchQueries({ stale: true, type: 'active' }).catch(() => undefined)` instead of `invalidateQueries()`. `count: 'exact'` on history reads kept deliberately (truncation guard).

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Correctness] Breadcrumbs wrapped in try/catch**
- **Found during:** Task 2
- **Issue:** a throw in MutationCache `onSettled` rejects the mutation, and a throw in timeoutFetch's `.then` would turn a good response into a failure. Telemetry must never fail a write.
- **Fix:** both `addBreadcrumb` calls are in try/catch.
- **Commit:** e7859e39

**2. [Rule 3 - Blocking] Tests that save then restore at once now pass throttleTime 0**
- **Found during:** Task 1 / final run
- **Issue:** with a trailing-only throttle, `persistClient` at the default 1 s returns before writing, so `persister.test.ts` `saveWith` and `offlineRead.test.tsx` seeding read an empty store.
- **Fix:** those test persisters use `createEncryptedPersister(undefined, 0)`. `offlineRead.test.tsx` was not in the plan's file list.
- **Commits:** 07686df8, 4bbbe67f

**3. [Design] Background save goes through the main persister**
- The plan said add an AppState listener next to `persistOptions`. One already existed (`startPersistOnBackground`, registered in QueryProvider), so it now calls `flushPersist()` and its next-tick save uses `persister.persistNow` instead of a second unthrottled instance. QueryProvider.tsx unchanged.

**4. [Rule 1 - Hardening] Overflow clean-up after the main row write**
- Stale overflow rows are removed after the base save, not before, so a kill between the two cannot orphan queued writes.
