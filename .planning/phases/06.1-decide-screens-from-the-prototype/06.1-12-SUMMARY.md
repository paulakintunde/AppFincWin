## Deviations from Plan

**1. [Rule 1 - Bug] CO-D-114 was not already true on main.** The builder dropped any account it could not convert (`balance === null -> []`), so `account_no_rate` could never fire. It now returns `{ id, balance 0, use null, noRate: true }`. The existing D-54 test was updated (the unrated account is now listed with noRate).

**2. [Rule 3] decide_may_use not added to SAVINGS_GOAL_COLUMNS** (the plan said to add it to the select). Plan 10 deliberately left it out until the push; adding it now would make every goal read fail against production. Only the `GoalSource` type has it (optional; absent = locked). **Plan 31 must add `decide_may_use` to SAVINGS_GOAL_COLUMNS with the push**, or the unlock never reaches the builder.

**3. Existing net size uses `useEditGoal`, not `save_goal_plan`.** A `save_goal_plan` edit with `series: null` stops the net's monthly record. The size-only direct patch (Grow's own label `safetyNetSizeSaved`) avoids that. Creation still uses `save_goal_plan` through `useSaveGoalPlan` as planned.

**4. Key names.** `queryKeys.decideHistory` already existed (row-derived month window), so the new read key is `decideCheckHistory`; the mutation key is `mutationKeys.decideHistory`. `safetyNetAnswer` and `decideAnswered` mutation keys are reserved only (the hooks compose Grow's and the setup keys).

**5. New db wrapper `src/db/netAnswerUse.ts`** (not in the plan's file list) for the RPC; `'decide_check_history'` added to `WriteEntity` and `sync.failedSheet.entity` in en.ts so failed writes can name it.

**6. Hook signatures** take the goal row / user and household (needed for household id, version and name) rather than bare ids; the goal name for a new net is passed in by the screen (`input.name`) because the data layer has no `t`.
