<objective>
G-1, part 1 of 3 (audit section E, rows C-1, C-2, C-4): the data side of "readiness that can finish". Today no code passes
`waivers` or `skipped` to the engine, so no answer the user gives can ever clear a readiness item, and nothing in Decide fixes
an unlinked envelope. This plan stores readiness answers, feeds them (and skipped lines) to the engine, adds the pure model that
says which fix and which answers each named item gets, and adds the envelope-account sheet (the D-54 fix).

Purpose: the Not ready card (plan 44) and the Records setup item (plan 45) can show named items that the user can actually clear.
Output: waiver key module, decide-answer kind, builder wiring, readinessFixes model, EnvelopeAccountSheet.

No migration: the `readiness_waiver` kind and key regex are already in production (migration
`supabase/migrations/20261030000200_decide_answers_readiness_waiver.sql`, caught up by 05.4-02 commit c8cbba25). No engine change:
the engine's readiness module already honours waivers and skipped occurrences (05.3-54, tested in
`src/engine/decide/v3/__tests__/readinessItems.test.ts`), so no right-answer cases and no revision bump are needed.
</objective>
