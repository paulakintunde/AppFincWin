# Phase 06.1 Plan 54: Pay ticks, checklist loading, honest setup rows Summary

Pay setup now writes `income_types` (pre-picked "Salary or wages" when pay was found, per GQ4), so Pay ticks as soon as the save lands, including the no-edit path from the device walk (DC-8). The page shows what Activity already knows, the amount and day are real fields, and a disabled Save says what is still missing. The checklist shows a loading line or the error card instead of "0 of 6 / Back to Decide", fills its bar from the done count on the first frame, and its Pay and Safety net rows say why.

## What changed

**Pay page (PaySetup.tsx)**
- "How are you paid?" with the six D-17 chips (multi-select; "No fixed income right now" stands alone). With no stored answer, "Salary or wages" is pre-picked only when a pay series or a found payer exists; otherwise nothing is picked.
- Save pay details adds `patch.income_types` whenever the picked set differs from the stored one (order-free compare). With found pay accepted as is and nothing stored, Save writes `{ income_types: ['salary_or_wages'] }`; it never ends with no write when Pay is not yet done.
- The set-aside row (FIN-20) reads the live chip selection, still empty by default.
- Found card: "Found in Activity", then "{{name}} · {{amount}}", then "{{ordinal}} of each month · {{account}}", with That's right / Change.
- Empty fields: MoneyInput `boxed` + `prefix="symbol"`; "Which day?" is a `DayPicker` (boxed row, opens a sheet of 1-31 chips, each at least 44 wide/high, read as ordinals).
- Change your pay sheet picks the payday from the same `DayGrid` (inline, no nested sheet).
- "It changes": each of the four ways has a sub-line under it.
- `NeedLine` under Save (frame footer): the first missing part, in order how paid, amount, day, account, way to count.

**Root cause of the missing found card (A-SU-4).** The audit account's pay was a live recurring series made in Activity with `income_kind` null (never marked as pay). The Pay page only looked for `income_kind === 'salary'`, and the records scan (`useIncomeContext.found`) skips rows linked to a series (`recurring_series_id !== null`), so 3 monthly arrivals produced neither a salary series nor a found payer, and the page fell to empty fields. buildV3Inputs already counts an untagged income series as pay. Fix: `unmarkedPaySeries()` picks the largest live, positive, untagged series (never a bill, saving, goal-linked, stopped or deleted one); it shows as found pay and is marked `income_kind: 'salary'` (counts_as kept, else 'available') through `usePatchSeriesAttributes` on Save; its step id joins the save toast's `stepIds`.

**Root cause of DC-8 / C-3.** `setupFactsFrom.hasPay` needs `inputs.profile !== null`, and `profileOf` returns null without `income_types`. Nothing on the Pay page wrote it, so a found-and-accepted pay with "About the same" saved only the pattern (or nothing), and Pay never ticked.

**Checklist (C-20, DS-20)**
- `useSetupFacts`: loading only while the settings query has no data yet; a settled `null` (no row) is read as every flag unanswered. `error` is true when `useDecideV3` is in error or the settings read failed with nothing cached; `retry` is `useDecideV3().refetch`.
- `SetupChecklist`: no items yet shows "Loading your setup…" (polite live region) or the shared `ErrorCard`; neither shows a count, a bar or "Back to Decide". Top-bar Back stays.
- DS-20: the checklist draws a still `ChecklistBar` from `doneCount` (same testIDs as the banner's). The banner's animated `SetupBar` is untouched (06.1-56 owns it).

**Rows (A-SU-2, A-SU-3)**
- `SetupFacts.payTypesSet?` and `netSavedMinor?` (optional, so other plans' fixtures still compile). Pay open: `payOpenHowPaid` when a pay series exists without income types, else `payOpenNoPay`. Net done: `{ savedMinor, amountMinor }` said as "{{saved}} in it · goal {{amount}}"; saved is `inputs.safetyNet.saved`, else the emergency fund, else 0.

## Deviations from Plan

1. **[Rule 3] Two out-of-list test files had one expectation each updated.** `payBills.test.tsx` (the found-pay save now also writes `income_types`) and `setupBanner.test.tsx` (old netDone wording). Neither was being changed by another plan (checked `git status`).
2. **[Rule 1] `need.pattern` replaced with `need.count`.** The pattern answer was never required for Save, so "Whether pay changes is still needed." could not be true. The real blocker after the pay itself is a missing way to count changing pay: "A way to count changing pay is still needed."
3. **Copy keys reused instead of duplicated.** Chips and heading use `income.paid.title` / `income.paid.option*` (the D-17 words already signed for the income profile); That's right / Change keep `pay.right` / `common.change`. The loading line is `setup.checklist.loading` (not `setup.loading`).
4. **Countable sub-line wording.** The steady sub-line first said "unspent money"; the screens copy guard bans "unspent" (D-56), so it reads "spare money".
5. **No-row reading (C-20).** A user with no `decide_settings` row now gets real progress (all flags unanswered, "Continue: Pay and payday"), not a lasting loading line; loading is shown only while the row has not been read.
6. **Pay type options are listed in PaySetup**, mirroring `PAID_OPTIONS` from `income/steps/PaidStep.tsx`, because importing that module pulls Supabase and auth into the page's test graph.
7. **Shared checkout on a feature branch.** `.git` is a worktree file and the branch is `feat/06.1-decide-screens` (not `worktree-agent-*`); committed there as the orchestrator directed, by explicit paths only.
