# Phase 06.1 Plan 18: Safety-net settings and first-answer gate Summary

Decide's safety-net settings screen (unlock behind a confirm, lock at once, animated padlock) and the first-answer gate (versioned intro card, then the one safety-net question) are built and tested.

## Tasks

1. Safety-net settings, unlock confirm, padlock - commit f46ee75f
2. First-answer gate (intro card then net question) - commit 3d97693f
3. Fix: inject write hooks via ports (depcruise), derive gate step in render (lint) - see git log (fix(06.1-18))

## Notes

- All copy reuses existing `decide.screens.safetyNet.*`, `legal.decideIntro.*` and `decide.v3.fact.net_none_start` keys; no new strings, so the shared copy guard file is untouched.
- The 48 px tile uses `width` plus `aspectRatio` (no `height:`), so the D-76 text-fit allowlist needed no new entry.
- "Unlock for answers" is a local outline Pressable (border, no fill), since Pill has no outline variant and shared primitives were not changed.
- Route `/decide/safety-net` (body in `src/shell/decide/SafetyNetRoute.tsx`) is gated like `/decide/settings` (decide_v3 plus DECIDE_SETUP_VISIBLE). It is not listed in `app/(app)/_layout.tsx` (headerShown is false by default), to avoid a same-wave edit conflict on that file.
- The padlock shackle swings about its left foot via Reanimated `useAnimatedProps` on an svg `G` (rotation, originX/Y, y). Not verified on a device; the jest tests check timing (one 220 ms change, none on first draw, none under Reduce Motion).
- `decide_may_use` is read defensively (`row.decide_may_use !== true` = locked). Until plan 31 adds the column to SAVINGS_GOAL_COLUMNS, the unlock cannot show as unlocked after a read; plan 31 must add it.

## Deviations from Plan

**0. [Rule 3] Write hooks are injected, not imported.** `fx-fetch-never-from-reads` (depcruise) forbids anything under `src/features/decide` from reaching `src/db/fxResolve`, and Grow's write hooks reach it through `transactionCache`. So `SafetyNetSettings`, `UnlockConfirm`, `FirstAnswerGate` and `NetQuestionSheet` take the writes as props (`NetUsePort`, `NetAnswerPort` in `screens/safetyNet/ports.ts`), and two new shell files bind them: `src/shell/decide/SafetyNetRoute.tsx` and `src/shell/decide/FirstAnswerGateBound.tsx`. **Plan 23 must mount `FirstAnswerGateBound` (not `FirstAnswerGate`) on the answer route.** The plan's grep criteria for `useSetNetAnswerUse` in UnlockConfirm/SafetyNetSettings (>= 1 each) and `useSafetyNetAnswer` in FirstAnswerGate therefore match in the shell files instead; the criterion `useSetNetAnswerUse` = 0 in firstAnswer/ still holds.

**1. [Rule 3] Plan said primary "Save safety net"; the existing signed copy is "Save and see the answer".** Used the existing key.

**2. [Rule 2] A failed read must not block answers.** `useFirstAnswerGate` treats a failed settings or goals read as "do not ask".
