# Phase 06.1 Plan 02: Stored check round trip for every Variant C field Summary

`parseCheckV2` now reads back running costs, closing percent, purchase date, what-it-replaces and the new D-21 quick-estimate lines, with caps and safe defaults. A fast-check property proves `parseCheckV2(JSON round trip of toStoredV2(c))` deep-equals `c` (Pitfall 1 closed).

No owner questions: D-12 and D-21 in 06.1-CONTEXT cover this plan.

## What was built

- **types.ts**: `QuickLine` union (expense, loan, savings, income), plus `CheckV2.quickLines?` with the D-21 comment. Type-only change.
- **inputsV2.ts**: helpers `exactMinorOf`, `localDateOf`, `everyOf`, `nameOf`, `listOf`, `runningCostOf`, `stopSourceOf`, `stoppedCostOf`, `saleOf`, `replacesOf`, `quickLineOf`. Caps: `MAX_RUNNING_COSTS = 12`, `MAX_STOPS = 8`, `MAX_QUICK_LINES = 8`, `MAX_NAME = 80`, `MAX_PAYMENTS = 600`. Each new key is set only when it was in storage, so older checks read back with no new keys. `toStoredV2` now writes `closingPercent` as decimal text. Before this, a bigint `closingPercent` would have made `JSON.stringify` throw.
- **Rules as built**: a running cost with a bad id, amount, cadence or start date is dropped. An end date before the start date becomes null. `on` defaults to true. A stop with a bad source is dropped. A sale with a bad amount or date becomes null, and an oversized `paysDebtId` becomes null. An invalid `purchaseDate` becomes null. `closingPercent` uses the same reader and cap as `taxPercent`. For quick lines, an unknown kind is dropped and the name is trimmed and cut to 80 characters. A one-off expense needs a date. A loan needs a monthly amount above 0 and 1 to 600 payments. Savings counts as usable only when stored as `true`. Income repeats every 0 or 1 months and needs a valid date. Lists are cut to their cap before they are read. A v1 or unknown-v payload still returns null.

## Deviations from Plan

1. **[Rule 1 - Bug] `toStoredV2` would have thrown on a check with `closingPercent`.** Percent is a bigint, which `JSON.stringify` cannot write. The plan said to convert it "if it is not already". It was not, so it is now converted the same way as `taxPercent`. Fixed in 2c503ea3.
2. **Purpose type unchanged (D-12).** The plan's behavior line says purpose is `'need' | 'want' | null`, but `CheckV2.purpose` is the existing `Purpose` (preset or custom), and the engine reads it for option order (05.4 D-41). Changing the type would be a breaking change outside this plan. The round-trip test instead covers null, `necessity` (need) and `nice_to_have` (want). Screens should map the "Need or want?" answer to those two presets.
3. **Test-data fix inside GREEN.** The RED commit's name-cut case had 78 spaces where it needed 79. Fixed in the GREEN commit along with an unused import.
