# Phase 06.1 Plan 62: Every tap shows it landed (H-1) Summary

A shared `usePressFeedback` helper puts a native Android ripple (drawn by the platform, so it shows even while the JS
thread is busy for seconds) and the app-wide iOS pressed dim on Pill, Chip, every SegmentedControl segment and every
answer and stepper row or link. Pill gains a `pending` state. Text links reach 52 dp tall. The answer's action bar now
pads with `insets.bottom`, so it sits above the Android nav bar. Both app shells take an opt-in `keyboardShouldPersistTaps`.

## What changed

- `src/ui/pressFeedback.ts`: `usePressFeedback('fill' | 'row')` returns `{ android_ripple, pressedStyle }`.
  Android: `{ color: fill6 | line4, borderless: false, foreground: true }` and no pressed style. iOS: no ripple and
  `{ opacity: PRESSED_OPACITY }` while pressed. `LINK_HIT_SLOP` is exported too.
- Pill: ripple and dim only when it is live. The new `pending` prop: opacity 0.5, `accessibilityState.busy`, presses
  ignored, same label, no spinner and no copy.
- Chip (light and dark tones) and SegmentedControl segments: ripple and dim. Read-only chips get neither.
- TabRootScreen and DetailScreen: `keyboardShouldPersistTaps?: 'handled' | 'always' | 'never'`, passed to the
  ScrollView. When it is absent, the ScrollView gets `undefined` (today's default). DetailScreen with `scroll={false}` has no ScrollView,
  so the prop does nothing there. No screen passes it yet. 56 and 58 will.
- ActionBar: `paddingBottom: insets.bottom + gapSm`. "I'm not buying it" has the link slop and the ripple.
- AnswerFrame: when no action bar shows (loading, error, not ready), the scroll content pads `screenH + insets.bottom`,
  so the legal link is never under the nav bar either. With the bar shown, the content padding is unchanged.
- AnswerTopBar: Back and New check get the link slop and the ripple. The When chips get the ripple, and the pay switch gets it through SegmentedControl.
- MoreDetailRows and WhatYouToldCard rows: ripple and dim. FactActions Fix links, ReadinessFixList fix links and the
  LegalBlock "can't see" link: link slop, ripple and dim.
- StepFrame: the Back chevron keeps its own 8 dp slop, which is larger than the link slop, and gains the ripple. "See the answer now" gets the
  link slop and the ripple. Next keeps the Pill feedback.

## Deviations from Plan

1. **[Rule 2 - Correctness] Ripple colour by surface.** The plan named `colors.fill6`. On the light controls (fill1 chips,
   secondary pills, transparent rows on surface), fill6 is almost the same colour as the background, so the ripple would not show.
   'row' feedback uses the existing `colors.line4` instead. 'fill' feedback (the accent pill and chips on the ink card) keeps fill6.
   Both are existing tokens. Files: src/ui/pressFeedback.ts. Commit adfa957b.
2. **[Rule 2 - Correctness] AnswerFrame bottom inset with no bar.** The bar pads itself. Without the bar (loading, error, not ready),
   the last link sat in the nav-bar area, so the scroll content now pads with the inset in that case only. Commit ed5559c1.
3. **[Rule 1 - Bug] Pill pending had to disable the Pressable.** Leaving the Pressable enabled with `onPress` undefined still let a
   test press reach the handler. Pending now sets `disabled`, and the announced state is `{ disabled: true, busy: true }`. Commit adfa957b.
4. `src/theme/layout.ts`: the only change is a doc comment on `touchMin` that points to LINK_HIT_SLOP. The value is unchanged.
