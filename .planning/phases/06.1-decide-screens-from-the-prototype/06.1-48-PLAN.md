<objective>
G-3 (audit F-2, B-4, B-5): writes that land in seconds. The persister wrapper runs `JSON.stringify(mutations)`, an AsyncStorage read
for overflow keys and (in dev) a 112 KB serialize on every cache event, before the base persister's 1 s throttle; logcat shows ~25
persists in 0.6 s. With plan 46 removing the rebuild storm, this removes the other big source of JS-thread load that delays writes.

Purpose: a write reaches the server within seconds (F-2: 40 to 52 s today on a warm emulator). Target confirmed on the Pixel 6 in
plan 51 (write settled under 5 s, measured by .maestro/decide-timing.yaml write_settle).
Output: throttled wrapper, background flush, write-timing breadcrumbs, tests.

Choices made here (no owner question needed, technical): keep the 1 s window (moving the work behind it is the main win; a longer
window adds risk for queued writes); no native AES module (a new native dependency would force a new native build; aes-js now runs
once per window instead of per event); keep `count: 'exact'` (only the first page of each history read asks for it, and it is the
truncation guard).
</objective>
