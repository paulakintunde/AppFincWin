## Re-review fixes

An independent re-review found three small bugs in this plan's work. Each got a failing test first, then the fix.

**A. Back-dating moved a payment date the user picked** (`src/data/mutations/decideGoAhead.ts`)
- Cause: da1e4d11 shifted the schedule's first payment by the Bought date's offset for every first-payment kind, including
  `deferred`, whose `firstDate` is the user's own date ("first payment on 15 Jan"). A purchase back-dated N days moved it N days
  earlier and could write never-made payments as paid.
- Fix: only `today` and `one_period` move; a `deferred` first payment keeps `sched.firstDate`. The `record_decide_go` call shape,
  replay key and single Undo are unchanged.
- Test: decideGoAheadV3 "a back-dated plan with a deferred first payment keeps the date the user picked" (rows stay 2026-11-20,
  2027-01-20, 2027-03-20, all pending; decision unchanged).

**B. Sheets ignored Reduce Motion on the JS-side slides** (`src/ui/Sheet.tsx`)
- Cause: `onFirstLayout` (added by a414b524), `keepEditing` and the open effect passed fixed `DURATION.sheetUp` /
  `DURATION.sheetDrag` / `DURATION.backdrop` to `withTiming`, so they did not use the reduced-motion duration the dismiss timer
  already uses.
- Fix: all three paths wrap their durations in `durationRef.current(...)` (useMotion's duration), as the rest of Sheet.tsx does.
  The worklet snap-back and slide-out in the pan gesture are left as they are (ReducedMotionConfig covers worklets on device).
- Test: new `src/ui/__tests__/Sheet.reducedMotion.test.tsx` (open + first-layout re-slide, refused-Back restore before and after
  the panel shows, and full durations when Reduce Motion is off).

**C. A legacy answer could survive an edit** (`src/features/decide/screens/answer/useAnswerEffects.ts`)
- Cause: an `answer_v3` stored before this plan has no `inputsKey`. It was replaced only when the inputs moved while the answer
  was open (`firstKey`). An edit made in the stepper before reopening became `firstKey`, so the stale answer was never replaced
  and Home kept saying "Changed since you looked".
- Signal check: there is no reliable one. `StoredSeenV3` has no timestamp, and `row.updated_at` moves on every write (draft saves,
  seen state, the answer save itself), so it cannot date an input edit against the answer.
- Fix (safest option): a legacy answer on a check that is not decided is stored again once, with the shown answer and its
  fingerprint. If the answer is the same, it only gains its fingerprint. If it differs, the case can't be told apart from a
  recompute on newer records. Replacing it at worst drops one "Changed" note about an answer the person is looking at right now.
  Keeping it would leave a stale answer that never heals. After that, the owner's rule holds: keep the first answer, replace only
  when the fingerprint moves, never once bought, waiting or passed.
- Tests: useAnswerEffects: legacy answer + stepper edit before reopen is replaced; matching legacy answer is stamped once;
  stamped answer kept on same-inputs reopen; decided check with a legacy answer untouched; legacy stamp then an edit stores both.
  The earlier test "an answer stored before fingerprints is kept on reopen too" was replaced: that behaviour was the bug.
