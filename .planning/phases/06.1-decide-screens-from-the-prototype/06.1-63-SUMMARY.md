# Phase 06.1 Plan 63: After a decision (H-2) Summary

I bought it, Save for it and Cash or installments now open in DetailScreen with a title, a Back and the safe-area insets. While data loads they show the answer's loading line. "Back to Decide" goes to Decide home. "Make the goal" shows that it is working, says so if it fails, and says whether a reminder was set. Compare goes back to the same answer. Removing a past decision asks first, using the confirm text that already existed.

## What was built

**Task 1: frames and loading-first routes (CB-4, CN-8, CN-7, CF-7, CB-9, CN-12; confirms DC-2, DN-7, DN-8, DS-22)**
- `ActionRoutes` decides what to show in this order: checks still pending → loading; checks failed with nothing cached → error card; check not in the list → `CheckNotFound`; engine loading → loading; engine error or no evaluation → error card; otherwise the screen. Loading and the error card both sit in `DetailScreen` with the screen's title. The loading state uses `AnswerLoadingBody`, the same "Working out the answer" line the answer screen shows.
- "Back to Decide" calls `router.dismissTo('/decide')` from the error card, from Added to records (Bought `onDone`, which RunningCostOffers' Done also uses) and from Goal made. "Back to the answer", shown when there is nothing to save for, stays `router.back()` through a new optional `onBackToAnswer` prop.
- `BoughtScreen` takes a new `accountsLoading` prop. While accounts load it shows "Loading your accounts…", not the no-account alert. Accounts that arrive later get the first one selected. Account names wrap to 2 lines (`numberOfLines={2}`).

**Task 2: Make the goal and Compare (CB-14, CF-6, CS-9, CN-13)**
- "Make the goal" sets `Pill pending` while it runs, and repeat taps are ignored. A thrown `saver.save` is caught: it shows the toast `save.failed` and the button stays live.
- Goal made shows "Reminder set for <date>." when the reminder is `'set'`, using the engine's `readyBy` (a date, or the 1st of its month, matching `readyByOf` in decideOutcome). It shows "Reminders are off." when the reminder is `'off'`, and nothing when it is `'none'`.
- `CompareContainer`: "See …" now calls `router.dismissTo({ pathname: '/decide/answer/[id]', params: { id, side } })`, and `router.replace` is gone. While checks load it shows the loading line in the "Cash or installments" frame.
- **dismissTo with params, as far as the code shows:** the existing AnswerScreen gets the new `side` prop. Before this change, AnswerScreen applied `side` only on mount: installments came from the initial sheet state, and cash from a once-only ref. With dismissTo, "See installments" would have reached the answer without opening the plan sheet. AnswerScreen now remembers the last side it applied: a later cash side pays once, and a later installments side opens the plan sheet. React Navigation's POP_TO replaces the params on the matched route, so `side` should update. **Plan 61 still has to confirm this on the device**, including that it takes one fewer Back to get home.

**Task 3: Past Remove asks first (CC-3)**
- Remove opens `ConfirmSheet` with `useDeleteDecision().confirmCopy(decision, writtenCount(links))`. That is the existing "Delete this decision?" title and the body saying what is kept. The cancel button reuses `decide.delete.keep` ("Keep it") and the confirm button reuses `decide.screens.past.detail.remove`. Confirm deletes once through the shared path, with its Undo toast. Cancel deletes nothing. `useDeleteDecision.ts` needed no change.

## New user-facing strings (en, `decide.screens.answerActions`)
- `save.reminderSet`: "Reminder set for {{date}}."
- `save.reminderOff`: "Reminders are off."
- `save.failed`: "The goal wasn’t made. Nothing changed."
- `bought.loadingAccounts`: "Loading your accounts…"

These were checked against the copy guards: none uses "advice", "recommendation", "you should", "free", "Skip" or "lend", none starts with "Pay", and none opens with an instruction verb. The frame titles reuse existing keys.

## Deviations from Plan

**1. [Rule 1 - Bug] AnswerScreen did not react to a side that changed after arrival**
- **Found during:** Task 2
- **Issue:** with `dismissTo`, Compare returns to the answer that is already mounted. That answer applied `side` only on mount, so "See installments" would no longer open the plan sheet, and a second pick did nothing.
- **Fix:** the boolean `sideDone` ref became the last applied side. Cash still updates through the effect. Installments opens the plan sheet through a render-time prop adjustment (`sideSeen` state), which keeps it clear of `react-hooks/set-state-in-effect`. Added a test to answerScreen.test.tsx, and changed the InstallmentPlanSheet mock so it renders a marker when visible.
- **Files (outside the plan list):** `src/features/decide/screens/answer/AnswerScreen.tsx`, `src/features/decide/screens/answer/__tests__/answerScreen.test.tsx`. Nobody else had them modified (checked with `git status`). Plans 64 and 66 change these files later.
- **Commit:** 509d27fd

**2. [Rule 3 - Blocking] detailSheets.test.tsx renders CompareScreen without a navigator**
- `DetailScreen` calls `useFocusEffect`, so the four CompareScreen tests threw "Couldn't find a navigation object". I added a DetailScreen mock that shows the title, following the pattern past.test.tsx uses. This file was outside the plan list. Commit eeea1eef.

**3. Frame title keys reused rather than added.** The plan said to reuse a key that means the same thing, so there are no `answerActions.frame.*` keys.

**4. Account auto-pick is derived, not an effect.** It behaves the same, and the test covers a late load and a pick that is no longer listed.

**Commit granularity:** Tasks 1 and 2 share SaveForItScreen.tsx, actions.test.tsx and answerActions.ts. Commit 1 holds the routes, Bought and Compare framing. Commit 2 holds all SaveForIt changes, including its frame, plus Compare navigation and the copy. So commit eeea1eef on its own refers to `bought.loadingAccounts` before 509d27fd adds it. Typecheck passes from 509d27fd onward.
