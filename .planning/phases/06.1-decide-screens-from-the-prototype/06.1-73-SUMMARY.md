# Phase 06.1 Plan 73: post-write JS storm (H-11b + DB-1) Summary

Measured where the time after a Decide write goes on the emulator dev build (React Profiler, CDP CPU profile, cache and
persister counters, JS-thread % per second), then fixed the confirmed data-layer and hidden-screen causes: one dehydrate
per persist window instead of one per cache event, and `freezeOnBlur` on the tabs and the outer stack. The largest cost,
Decide home re-rendering under the answer screen, is named with numbers as gap row G-73-1 for 06.1-74: the device targets
for write settle are not met yet.

## Fixes

1. **Persister (Task 2, allowed fix a).** `startThrottledPersist(qc)` replaces `persistQueryClient`'s subscription: cache
   events call `persister.persistLater(build)`; the dehydrate (`build`) runs once, inside the save the 1 s throttle
   schedules, with the same `dehydrateOptions` and buster. `persistNow`, the save on backgrounding and `removeClient` work
   as before (a pending build is dropped by both). `QueryProvider` keeps PersistQueryClientProvider's restore-once and
   `IsRestoringProvider` behaviour. The dev byte log no longer serialises a second time.
2. **Freezing (Task 3, allowed fix a).** `freezeOnBlur: true` in the tabs `screenOptions` and the outer stack
   `screenOptions`. Hidden tabs and screens two or more below the top stop rendering and render with the latest data when
   they come back. On Fabric, react-native-screens never freezes the screen directly below the top, so Back still shows it
   at once.
3. **Telemetry.** A 'write'/'start' crumb (key name, pending count) in `MutationCache.onMutate`; a 'persist'/'saved' crumb
   per save (serialise, encrypt and store ms, bytes, query and write counts). With the existing 'net' and settled crumbs
   every write now leaves start, send, settle and persist crumbs. Numbers and key names only.

Not applied, with reasons: (b) excluding rebuildable queries (OQ-73-1 not triggered); (c) invalidation (already per key
and active-only); (d) timers (not a cause); (e) write-queue scopes (no queueing seen: one write, no retries); (f) encrypt
timing (minor); Task 3 (b)/(c) Prepared keying and duplicate judge (prepare ran twice per session).

## Deviations from Plan

1. **[Rule 3 - Blocking] persisterBudget.test.ts updated (outside the file list).** Two tests counted every
   `addBreadcrumb` call; the new per-save 'persist' crumb broke them. They now read the over-budget crumb by message.
   `git status` showed no other plan changing the file.
2. **[Rule 1 - Bug] Probe logging was itself loading the thread.** The first probe logged every counter every 10 s (30-40%
   JS spikes in the idle samples). It now logs only the counters that changed, plus the Decide perf marks.
3. **Task 3 fix (a) partly applies.** The plan expected freezeOnBlur to stop covered Decide screens from rendering; on Fabric
   the screen directly below the top is exempt by design, so the main cost remains (G-73-1).
4. **Task commits are grouped by file.** `persister.ts` and `QueryProvider.tsx` carry both the Task 1 instrumentation and the
   Task 2 fix (commit a572fbdd); the two layouts carry both the Task 1 Profiler and the Task 3 freeze (commit b0854b8c).
5. **Maestro TIMING runs missing** (see above); the flow was fixed to wait for the settle.
6. **The revert check** for the regression guard was run on a throwaway copy that wired `persistQueryClientSubscribe` back
   in: 8 dehydrates (one per cache event) for its writes against 1 save, so `expect(dehydrates).toBe(saves)` fails without
   fix (a). The copy was deleted.
