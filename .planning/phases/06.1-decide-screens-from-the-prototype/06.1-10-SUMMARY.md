# Phase 06.1 Plan 10: Decide screens SQL Summary

One additive migration holds every new 06.1 store: the Decide-only safety-net unlock flag and RPC, the four answered stamps, the tax set-aside column, the owner-private check-history table, and the locked, up-front-only Save-for-it goal.

2. pgTAP, row types, undo labels, export manifest, purge doc - commit 98edf26b

## Deviations from Plan

**1. [Orchestrator override] Migration filename** - the plan's `20261110000100_decide_screens.sql` collides with Grow's file of that number. Used `20261111000100_decide_screens.sql`; the pgTAP header refers to it.

**2. [Rule 3 - Blocking] pgTAP number** - `96_*` was taken (Grow review fixes), so the test is `97_decide_screens.test.sql`.

**3. [Rule 3 - Blocking] Undo label keys live in `src/engine/undo/types.ts`, not `src/i18n/undoLabel.ts`.** `safetyNetUnlocked` and `safetyNetLocked` were added to `UNDO_LABEL_KEYS` there and to `en.undo.label`. undoLabel.ts reads them from en.ts and needs no change.

**4. [Rule 2 - Missing critical] apply_patches re-issued.** The unlock's undo step patches `savings_goals.decide_may_use`, which apply_patches did not allow. Added it as a system-key column plus its boolean type mapping. All other lines are copied unchanged. Not re-issued for the decide_settings columns, matching how `safety_net_locked` was handled.

**5. Purge job** - no change to `purge_deleted_decide_rows`: history has no soft delete and goes by cascade when a purged check is hard-deleted. Documented in `docs/ops/decide-purge.md` instead of adding a delete step.

**6. D-22 target** - the existing `goal.target` in the payload is the up-front amount (client-computed); the RPC bounds it to the check's stored `inputs.price` when that is a plain integer. `up_front_only` is read from `inputs.pay.mode = 'plan'`.

**7. `SAVINGS_GOAL_COLUMNS` not changed.** `decide_may_use` is on the row type as optional and read-only, but is not in the select list until the migration is pushed (plan 31), so a pre-push build cannot break goal reads. `DECIDE_SETTINGS_COLUMNS` does include the new settings columns; that read depends on the plan 31 push happening before the screens ship.
