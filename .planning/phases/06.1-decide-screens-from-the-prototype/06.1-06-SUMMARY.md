# Phase 06.1 Plan 06: sayResult Summary

sayResult is a pure, production renderer. It turns a v3 Result into lines of `{ key, text, code }` built from the engine's copy keys. It covers notices (unsaved_changes first), facts in engine order, the basis, the first caveat plus the large_for_month figure list and wrong-figure line, the next step, missing questions (values come from their MISSING_VALUE_SOURCE notice, with the D-62 fund variant), readiness lines, and the after-buy lead plus bought-on line.

Owner questions: none. Every gap could be settled from the engine tables and comments.

## Deviations from Plan

**1. [Rule 2 - Missing functionality] Two extra deps fields.** `today` decides between boughtToday and boughtOn, because Result has no asOf. `names.figure` names the missing figure in the save_vs_borrow 'ask' line, because there is no copy for a figure name. Both are additive; plan 14's hook supplies them.

**2. [Rule 1 - Bug] More variants and plain numbers than page.ts handles.** page.ts never picks ask_debts_not_recorded_*, tight_floor_user_line, earlier_money_from_savings or lean_bridge_net. It would also format counts (covered, times, payments, share) as money. sayResult follows the engine's comments for these. page.ts is not edited, as the plan says.

**3. [Rule 2] onMissing hook.** Throwing is the default, which the tests use. Production can drop the bad line instead of crashing the screen, and the code is still never printed.
