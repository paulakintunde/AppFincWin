# Phase 06.1 — Validation Strategy

> Per-phase validation contract for feedback sampling during execution. Source: 06.1-RESEARCH.md "Validation Architecture". Owner rule: no full local coverage run per plan; quick checks per plan, full suite at milestones.

---

## Test Infrastructure

| Property | Value |
|----------|-------|
| **Framework** | Jest 30 (jest-expo) + RNTL; fast-check 4.10.1; Maestro; pgTAP (`supabase test db`, CI) |
| **Config file** | `jest.config.js`, `jest.engine.config.js` (engine and crosscheck), Stryker config |
| **Quick run command** | `npx jest <touched folder>` (plus `npx tsc --noEmit` for engine files) |
| **Full suite command** | `npm run typecheck && npm run lint && npm run depcruise && npm run test:coverage` |
| **Estimated runtime** | quick ~30-90 s; full suite several minutes (milestone only) |

---

## Sampling Rate

- **After every task commit:** `npx jest <touched folder>`
- **After every plan wave:** `npm run lint && npm run depcruise` plus the wave's folders; engine waves add `npm run check:right-answers && npm run test:crosscheck`
- **Before `/gsd-verify-work`:** full suite green, mutation gate for engine changes, pgTAP in CI, Pixel text-fit + TalkBack pass, owner wording sign-off (D-08)
- **Max feedback latency:** 120 seconds per task
