# Phase 06.1 Plan 82: Four device-check bugs before the Pixel 6 check Summary

The answer screen now shows the engine's answer through one pure helper (`shownEvaluation`) that drops the debts ask once
"None" is answered and drops a decided check's own Grow goal from its readiness items; the plan payment is shown without the
running costs on the answer and the price step; and Save for it no longer shows a same-day "Ready by" for an item that already fits.

## Bugs, root causes and fixes

| ID | Root cause | Fix |
|----|-----------|-----|
| G-61-8 | The engine (`prepare.ts askDebts`) asks about unrecorded debts from the debts and accounts alone; it never sees `decide_settings.answered_no_debts_at`. "None" calls `useSetDecideAnswered`, which writes nothing (returns null) when the flag is already set, so nothing changed: the ask stayed and no toast showed. | `shownEvaluation` leaves `ask_debts_not_recorded` out of the facts when the flag is set. The answer reads `useDecideSettings`; the flag write patches that cache at once (onMutate), so the first "None" both saves and hides the ask, and Undo brings it back. |
| G-61-11 | `Purchase.monthly` includes the running costs' monthly share (`runningMonthly`); the told line "Price and how you pay" and the price step's plan summary printed `monthly`, so $411.17 + $323 showed as $734.17 while Running costs showed $323 again. | `planPaymentOf(purchase) = max(0, monthly - runningMonthly)` for the told line and `stepper.price.installmentsSummary`. Checked the rest: the verdict's "adds {{monthly}}" (monthly_short / low month) is the whole monthly cost and is not labelled as the plan payment, Full cost uses `planCard`, Costs that stop uses `runningMonthly`: these agree. |
| G-61-3 | Save for it makes a Grow goal with no account; D-54 makes every envelope with no account a readiness item, so the check's own answer became Not ready ("laptop (a Grow goal) has no account yet."). | For a decided check (bought, waiting, passed) the answer reads `useSavingsGoals`, takes the live goals whose `check_id` is this check, and `shownEvaluation` removes their `envelopes` readiness items, recounting `missing` and `ready` as `readinessOf` does. Other goals with no account still show Not ready. |
| G-61-10 | `readyDate(0)` returns today when the item already fits; `defaultMonthly` then used one month (the whole price) and the card said "Ready by" today. | A ready date on or before today counts as "fits now": the amount is spread over twelve months (as with no ready date) and the card says `goal.fitsNow`. The amount sheet no longer names today either. |
