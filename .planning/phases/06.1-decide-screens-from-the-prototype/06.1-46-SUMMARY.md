# Phase 06.1 Plan 46: One Decide calculation per data version Summary

All Decide hooks now share one settings source, one Prepared and one empty-check judge per data version. Pending-write count changes, draft saves and new checks no longer rebuild the snapshot, inputs or prepare. The unsaved notice is laid over at judge time and gives the same Result as a full rebuild.

## What was built

**Task 1 (B-1), commit 59f04d4e**
- `sharedSettingsSource(deps)` in `decideV3.ts` keeps one entry per snapshot source (WeakMap). It is keyed on the identities of the settings, answers and dismissals rows and on the live bridge id list (`liveBridgeCheckIds`, now exported from `settingsSource.ts`). Equal deps return the same `V3SettingsSource`, so `preparedV3(source, v3)` hits for every hook.
- `emptyCheckEvaluation(source, v3, unsaved = 0)` in `computeV3.ts` is cached on the PreparedEntry, so it is judged once per entry and count.
- `perfMark('decide.prepare:start' / ':end')` wraps the miss path of `preparedV3`.
- Test: 8 consumers under one QueryClient call `buildV3Inputs` once (`toHaveBeenCalledTimes(1)`), and every hook's `prepared`, `v3` and `evaluation` are the same objects (`toBe`). A save that changes only one check's `inputs` causes no rebuild. A check becoming bought rebuilds once for all 8 consumers.

**Task 2 (B-2, B-3, B-9), commit 79dea051**
- `useDecideSnapshot`: `source.unsavedWrites` is always 0, and the count is no longer a memo dep or shared-snapshot dep. The live count is returned on `DecideSnapshotState.unsavedWrites`.
- `withUnsaved(prepared, n)`: returns the same object when the count matches, otherwise a shallow copy with only `inputs.unsavedWrites` changed. `useDecideV3` returns `prepared: withUnsaved(held, n)`, so the per-keystroke judges in `useCheckEngine` carry the notice, and `evaluation: emptyCheckEvaluation(source, v3, n)`.
- The `paymentLinks` memo and the shared-snapshot deps key the checks read by a string signature of (id, kind) pairs, not by the rows.
- `useDecideLinks` uses `placeholderData: keepPreviousData`.
- History and upcoming reads use `staleTime: DECIDE_READ_STALE_MS` (5 * 60_000). The invalidation tests are unchanged and pass.
- Tests:
  - Equality: for a cash check (sofa) and a plan check (car), `judgeCheck(withUnsaved(prepare(inputs0), 2))` deep-equals `judgeCheck(prepare({...inputs0, unsavedWrites: 2}))`. The same holds through `computeV3`.
  - Pending count 0 -> 1 -> 0: no extra `buildV3Inputs`, and the notice shows only at 1.
  - A new check id: every consumer stays 'ready' while the new links key is pending.
  - A draft save keeps the snapshot source (no `buildDecideSnapshot`), and a kind change rebuilds.
  - A remount within the stale window does not refetch history or upcoming.
  - A waiting write leaves the source and its build untouched.

## Deviations from Plan

**1. [Rule 3 - Blocking] Allowed perfMarks in the D-53 import guard**
- **Found during:** Task 1
- **Issue:** `oneSource.test.ts` allows only listed imports in snapshot/v3 sources, so the planned perf marks in `computeV3.ts` failed it.
- **Fix:** Added `@/features/decide/perf/perfMarks` to the allowed list, with a comment. It is the dev-only timing harness: no storage, no data.
- **Commit:** 59f04d4e

**2. [Rule 1 - Correctness] `computeV3`'s `unsaved` parameter has no default**
- **Issue:** The plan said "default 0". That would have overwritten a count carried on the source, which breaks the existing APP-02 test in `computeV3Once` and changes the behaviour of direct callers.
- **Fix:** Left out, the Prepared's own count stands. Passed, it is laid over. `emptyCheckEvaluation` defaults to 0 because sources now always carry 0.

**3. Small extras outside the plan's file list**
- `liveBridgeCheckIds` is now exported from `settingsSource.ts`, so the bridge signature uses the exact same filter.
- `decide.test.tsx`: the D-127 test now asserts the new contract (count on the state, source untouched, no rebuild). Draft-save, stale-window and placeholder tests were added.
