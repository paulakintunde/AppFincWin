# Phase 06.1 Plan 80: Add, change and delete on Decide home's sheets Summary

Add rule now lists only kinds that are not already on the list, and says why "Add rule" is off. A saved "Something changed" item can be changed from its home line, with Undo. A one-off cost can have a name that home shows. Deleting a check gives "Deleted: <name>." with an Undo that brings the check back.

## What was built

**Task 1: Add rule (DC-7, DB-13, OQ-80-1 A). Commit 0d1bbe44.**
- `kindsOffered(doc)` in homeCardsModel returns the kinds in the sheet's order and leaves out Keep at least and Largest single purchase once either is on the list, even when switched off. Those rules are changed from their own row. The sheet no longer shows a greyed "Already added" row.
- A NeedLine sits under "Add rule" whenever the button is off below the cap. It reads "A kind and a value are needed.", or "A category is needed." once a category kind has a value but no category. At the cap, the existing cap line is the reason and no NeedLine shows.
- `commitRule` toasts now pass `undoLabel` (ruleAdded / ruleEdited / ruleRemoved). Before this, the toast host found no undo label for `addRule.toast`, `rule.savedToast` or `rule.removedToast`, so those toasts showed no Undo. The CRUD matrix had "Remove this rule … no undo".

**Task 2: Something changed and check delete (DC-10, DS-19, DC-9). Commit 936a2fc8.**
- Each saved change on home is one line, "Changed: …", with **Change** and **Reset** beside it (each at least 44 dp). Change opens the same sheet filled from the row through `changeFormOf`:
  - a one-off: its amount and its name;
  - pay: usual pay plus the stored difference;
  - a bill: the bill and the status its label names.
  - The date is today when the change is in this month, else the 1st of its month, because rows keep only a month.
- On Save, `changePatchOf` keeps only the fields that moved and sends them to `useEditChange().edit`. The toast reads "Changed: … Answers use it from …" with Undo (`changeEdited`). When nothing moved, the sheet closes with no write and no toast. In edit mode, dirty means "moved from the saved values".
- The one-off form has "Name (optional)" (max 40 characters). A typed name is stored in `decide_changes.name`, and home reads "Changed: Car repair $900". With no name, the row stores "One-off $9" and reads as before.
- The add, edit and reset toasts now carry `undoLabel` (changeAdded / changeEdited / changeDeleted). Before this, none of them showed Undo.
- Open-check Delete shows the new `openCheck.deleted` toast "Deleted: <name>." at once. It carries `undoLabel: 'decisionDeleted'` and `target: decide_checks/<id>`, so Undo goes through the label and row check (05.3-97) and clears `deleted_at`. The delete is a **soft delete**, so the check comes back with its inputs.
- The answer screen's "Deleted: <item>." toast had the same missing Undo. It is fixed in one place: `UndoToastHost`'s `DECIDE_TOAST_LABEL` maps `decide.screens.common.toast.deleted` to `decisionDeleted`. AnswerScreen.tsx is unchanged.

## Deviations from Plan

### Auto-fixed issues
1. **[Rule 1 - Bug] Toasts with a step but no Undo.** The rule toasts, the Something changed toasts and both check-delete toasts each recorded an undo step, but their text keys were not undo labels, so the host showed no Undo. Fixed with `undoLabel` params, plus one host map entry for the answer screen's key. Files: commitRule.ts, SomethingChanged.tsx, OpenCheckSheet.tsx, UndoToastHost.tsx. Commits 0d1bbe44 and 936a2fc8.
2. **[Rule 2] "A category is needed."** A second NeedLine string. Without it, a category rule with a value but no category would say "A kind and a value are needed.", which is wrong.
3. **[Rule 3] Tests outside the plan's list.**
   - homeCards.test.tsx and ruleSheets.test.tsx: the decideChanges mocks gained `useEditChange`; the ChangedChips case and the crossing toast params changed.
   - New homeUndoToasts.test.tsx: renders the real UndoToastHost with each new payload.
4. **Edit is limited to rows the sheet can rebuild** (`changeFormOf` returns null otherwise). This stops a Change from turning an older ongoing change into a one-off, or dropping its end month.
5. **Unnamed one-off detection matches the label template** (`isWrittenLabel`), not the exact formatted amount. A label saved as "One-off $9.00" still reads as no name when today's format gives "$9".

## Known limits (for 06.1-61 / later)
- Pay is stored as a difference from usual pay. If usual pay has moved since the save, Change shows the current usual pay plus the stored difference, and a save rewrites the difference against today's usual pay.
- A bill change whose bill is no longer listed, or was renamed, has Reset but no Change.
- The day of a change is not stored (month only), so Change opens on today or the 1st.
