# Phase 06.1 Plan 13: Answer action writes on v3 data Summary

Save for it, Not buying, I bought it and running-cost bills now run on v3 checks, each as one queued write with one Undo.

## Tasks

1. Save for it and Not buying (D-22) - commit 954397c6
2. I bought it from a v3 check; running costs as bills (ARC-24, APP-29) - commit 10c9ec7c

## What was built

- `useSaveForIt`: outcome 'wait', goal target from `saveForItTarget` (whole price for cash, `Purchase.dayOne` for a plan), one step id, returns `goalId`. Ready-by comes from `Result.readyBy` (a month becomes its first day). Existing `useWaitAndSave` is unchanged for callers (shared core).
- `useNotBuying`: 'pass' outcome with Undo and the `decide.screens.answerActions.notBuyingToast` toast.
- Reminder tap now opens `/decide/answer/[id]` (useNotificationObserver; the plan's "waitReminder" payload route lives there).
- `goAheadInputOfV3` + `useGoAheadV3`: cash writes one pending one-off row of `Purchase.whole` on `Result.purchaseDate`; a plan writes the up-front row (`dayOne`) plus a payment series from the schedule's first date (my share, with per-period and end fees), a separate final-payment row when it differs, and per-payment rows for cadences with no recurring frequency. One `record_decide_go` call, one step.
- `runningCostBillOf` / `useAddRunningCostBill`: one series per call, own Undo; `on: false` lines return null. No batch API.

## Deviations from Plan

**1. [Rule 3] Signature additions.** `goAheadInputOfV3(check, evaluation, accountId, ctx)` and `runningCostBillOf(line, itemName, categoryId, ctx)` take a ctx the plan did not list; the household, currency, time zone, label and id minting are not on the inputs. `useSaveForIt` takes `check` (a CheckRef) plus `v3` and `evaluation`.

**2.** The v3 go-ahead tests live in `decideGoAheadV3.test.tsx` (the old test file is the old-engine path, kept until 06.1-36). The jest pattern `decideGoAhead` runs both. The plan's LEDGER used-car check is built from the engine's own test fixtures (`checkPlan`), not a LEDGER file, which does not exist in the repo.

**3.** Undo of Save for it is server-side (one `p_undo_step` on the single RPC); the test asserts one rpc call carrying the step. No client `apply_undo_step` call is made here.
