# Phase 06.1 Plan 66: The answer shows the same parts every time (H-5) Summary

The answer now has one fixed shape. "What you told Decide" shows on every answer, whether the check came from home or the stepper. "Not ready" and "More needed" are now one layout with no count: "First: <item>", "More may follow once this is done.", then "What you told Decide", "I'm not buying it" and "Delete this check" (with Undo). "How you pay" and "When" show only with a verdict. The payday chip shows a real short date, or is hidden. A decided check shows "Bought on Nov 12." with a link to Past decisions, and no buy or save buttons. The first-answer gate sits over the answer frame, and a swipe counts as seen. A safety-net question put away unanswered comes back as one tappable line on the answer.

## Which engine status drove each not-ready layout (DS-2)

- **"Not ready yet" card** (owned by Finish setup): `result.readiness.ready === false`. AnswerFrame's old branch at line ~120 handled it.
- **"More needed" card** (verdict card with chip "More needed", Fix rows, options, More detail, I bought it / Save for it): `result.code === 'needs_input'` with readiness met. It fell through to the verdict branch, because only `readiness.ready === false` was caught.
- Now `isNotReady(result)` (AnswerFrame.tsx) catches both. A needs_input answer with no readiness row names its first missing figure, with its Fix link, as the "First:" item.

6. **A side=installments arrival waits for the gate.** The plan sheet is `visible={gated && sheet === 'plan'}`, so it never opens under the gate now that the gate renders over the frame.
7. **Existing tests updated to the new rules.** Changes: count titles become "First:"; one row where there used to be many; "Next payday" becomes the "Nov 20" chip; the told card is now on the home path; needs_input becomes the not-ready layout with one Fix.
