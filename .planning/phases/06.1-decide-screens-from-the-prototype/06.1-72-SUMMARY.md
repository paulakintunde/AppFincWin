# Phase 06.1 Plan 72: screen speed (H-11a, G-73-1, G-73-2) Summary

Perf marks now time the answer, stepper and setup-item mounts and every judge, and the owner's "make it lighter" decision
is applied without freezing: Decide home and the answer share one run of the Decide reads per screen. They ignore the
last-synced time, which changes on every fetch. Intl formatters and device locale reads are no longer rebuilt on every
render, and opening the answer no longer refetches the reads Decide home already holds. On the emulator dev build,
Check it to answer went from 18.8 s to 9.8 s and the write settled in 24.8 s, down from 98.4 s. Decide home rendered for
20.9 s under the answer, down from 58.1 s, and JS-busy time fell from 208 s to 80 s.

## Fixes applied

1. **G-73-2 Intl, done once and reused.** `deviceReadCache.heldRead` holds the device time zone, first locale and
   `useRecordContext`'s `today` for one second (a system change shows within a second). `useDeviceLocale` resolves once per
   locale, zone and override. `useMoneyFormatter` keeps the strings it made (per formatter, max 400), so a re-render with the
   same figures builds no `Intl.NumberFormat` or `DateTimeFormat`. The engine's formatters and `localDateIn` are unchanged.
2. **G-73-1 lighter Decide home, no freeze.** `DecideV3Scope` (tabs layout for `decide`, outer stack for every
   `decide/*` route) runs `useDecideV3` once per screen; every `useDecideV3` below reads that copy (same state, same cache).
   `useDecideV3` returns the same object while nothing changed. `useIsOnline` replaces `useSyncStatus` in Decide home, the
   answer and the first-answer gate (they only read `isOnline`).
3. **G-73-1(b) refetch burst.** Every Decide read uses `DECIDE_READ_STALE_MS` (5 min): the snapshot's reads, `useDecideV3`'s
   reads, and the answer's own accounts/categories/debts. Shared hooks take an optional observer `staleTime` and keep the
   60 s default elsewhere. Write invalidations still refetch at once (test in decide.test.tsx).
4. Not applied: `freezeOnBlur` changes (owner rejected option a; 73's freeze stays as it was), the stepper flush move (11 ms),
   and useSetupProgress (not this plan's file).

Expected Pixel 6 result for 06.1-74: the same causes apply on device, so T-4 (2,619 ms) and T-3 (write settle 11.7 s) should
drop roughly in proportion to the emulator (about 2x and 4x). T-1 (4,340 ms) and T-2 (3,629 ms) should drop less, because
their own mounts (0.55 to 0.65 s on the emulator) and the push remain. Confirm on a preview (release) build: the React DEV
cost in these profiles (`unstable_now` and `createTask`, 45 s self after the fixes) does not exist there.

## Deviations from Plan

1. **[Rule 3 - Blocking] Measured on a frozen worktree on :8082.** Plan 56's saves reloaded the app in the middle of a run,
   and 8081 belonged to another session's Metro. The worktree and its node_modules junction were removed afterwards.
2. **[Owner decision G-73-1] Files outside the plan's list:** useIsOnline.ts, deviceReadCache.ts, deviceLocale.ts,
   useRecordContext.ts, useMoneyFormatter.ts, the shared query hooks (optional staleTime), DecideHome.tsx (3 lines),
   AnswerScreen.tsx, useFirstAnswerGate.ts, cacheProbe.ts (perfDump), jest.setup.ts (hold off in tests).
3. **[Rule 3] Test mocks:** costsSummary.test mocks `usePerfMount`; routes, setup and shellNavigation tests mock
   `DecideV3Scope` as a pass-through (the layouts now import decideV3); four tests mock the new `useIsOnline`.
4. **DecideV3Scope uses a context-or-live hook** with an `eslint-disable` for rules-of-hooks. A component is always inside
   a scope or never (the scope lives in the layout), so the hook order is stable.
5. **One or two runs per state, not three.** Each emulator run took 10 to 20 minutes, with start-up ANRs. On the slow
   baseline the shared typing flow failed, so some baseline cells are missing.
6. **decide-timing.yaml** goes back to the tabs, then opens Decide home with `fincwin://decide`. On the emulator a Back press
   that lands late left the app, and a link alone does not leave a pushed screen.
