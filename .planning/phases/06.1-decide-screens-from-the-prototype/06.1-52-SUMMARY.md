# Phase 06.1 Plan 52: NeedLine, lenient money parse, no blank step Summary

Every disabled control on Decide home and the stepper now says why (shared NeedLine), money fields take "$150" / "1,200.50" and say "Digits only, like 1200 or 1,200.50." as soon as text cannot be read, a committed figure rests as "9,000", steps opened before their check is saved show "still saving" rather than a blank page, and the first-answer gate shows the offline card offline with nothing cached.

## What was built

- **useAmountParser**: strips one leading or trailing marker of the field's own currency before `parseAmount` (engine untouched). '£150' in a USD field and '$150' in a CAD field still fail (T-06.1-52-01). New `toDisplayText` groups in the region's marks (3/3 or lakh 3/2) by string maths and drops a zero fraction; it parses back by construction. The 'invalid' message is now the digits-only line.
- **MoneyInput**: `prefix="symbol"`, `suffix`, `onTextChange`; change-time errors; grouped rest text on blur (reported value unchanged).
- **NeedLine**: muted label line, polite live region, nothing for null.
- **Steps**: Kind, Price and Costs pass `pendingRows.find(r => r.id === id)` as the fallback row. With the create pending and no row, `StepStillSaving` draws the step frame with the "still saving" line. A truly missing check now shows `CheckNotFound` (before it was blank). Kind: "A kind is needed to go on." while Next is disabled. Price: 0 stays put on Next and See the answer with "A price above zero is needed." Costs: a cleared amount is held out of the stored check (never 0), shows "No amount yet.", is left out of the total, and returns in place once typed.
- **Home**: hint names the missing part (what / price / unread price / price above zero). `useNewCheck.start` returns `'loading'` when user or household is null (home then says "Your records are still loading."); a pending create stays `'unavailable'`.
- **Gate**: `useFirstAnswerGate` exposes `offline` (loading, offline, nothing cached) and `retry` (refetch settings and goals). `FirstAnswerGate` renders `OfflineCard` in that state.

## Deviations from Plan

1. **[Rule 3] Files outside the plan list.** `CheckCard.tsx` (the hint is drawn there, not in DecideHome; it gets `hint` and `onPriceText` props), `newCheck.test.ts` (the 'loading' and 'unavailable' results), `textFitMatrix.test.tsx` (its `decideChecks` mock needed `useCreateCheck`), new `check/StepStillSaving.tsx` (one still-saving frame for the three steps), `en.ts` + `copyStatus.ts` (digitsOnly under money.*, as the plan note directs). `useStepCheck.ts` and `stepper.ts` were not changed: the fallback already existed, and the copy keys went to common.ts per the plan's copy list.
2. **NeedLine inside the step content, not under StepFrame's button.** StepFrame is H-1's file in the same wave; adding a slot there would collide. The Kind and Price lines sit at the end of the step content. Plan 57/60 (layout) can move them under the button.
3. **Existing MoneyInput tests adjusted.** CR-D01's "the parser error waits for the blur" now checks that a half-typed grouping waits; the invalid-text test now matches /Digits only/ instead of /amount/.
4. **Error timing.** Only errors that more typing cannot fix show on change; ambiguous-separator still waits for blur, so typing "1,200" never flashes an error at "1,2".
5. **Cleared cost line (plan's stated fallback):** held in local step state, not stored as null (engine type is non-null). If the user leaves the step with the amount still empty, that line is dropped from the check.
