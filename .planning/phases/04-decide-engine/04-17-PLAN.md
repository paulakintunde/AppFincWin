<objective>
Build the D-44 day-by-day 90-day cash path as pure functions: the path without the purchase from the snapshot, the purchase's dated outflows, the lowest day of each path, the Phase 5 report and the `cash_dip` classification under the "one card per cause" amendment.

New plan, created 2026-10-15 for the engine depth expansion. It depends on 04-13 (`shareForCategory`) and 04-05 (`addDays`, `monthlyEquivalent`, types), so it runs in wave 4. 04-07 wires it into `prepareContext` (the path without the purchase) and `assessPlan` (the path with it and the `cash_dip` warning).

Two modelling choices D-44's text leaves open are taken from the non-interactive defaults recorded as **04-REPLAN-NOTES "2026-10-15 expansion", defaults 1 and 2 (both: needs user confirmation)**:
1. **Default 1 — the daily spread.** Undated spending (groceries and everything not in a confirmed series) and the minimum debt payments (debts have no dates in the snapshot) are spread evenly by day, so the path never overstates cash. Saving and investing contributions are not deducted: they are pausable (D-35) and usually stay inside the accounts cashOnHand already counts. The spread is computed in exactly one exported function, `spreadUndatedSpending(spreadMonthly, day)`; `buildCashPath` calls it and nothing else computes it.
2. **Default 2 — the `cash_dip` measure.** `cash_dip` carries the extra gap the dated flows add beyond the `cash` card: `max(0, reserve − lowestWith) − max(0, reserve − (cashOnHand − my day-one cost))`. The measure lives in exactly one exported function, `dipShortfall(input: CashDipInput)`, which already receives `lowestWithout`. The user's alternative from the notes — measure the dip only against the path without the purchase, `max(0, reserve − lowestWith) − max(0, reserve − lowestWithout)` — is therefore a one-function swap, with no boolean switch and no change to callers. The report always carries both `lowestWith` and `lowestWithout`.
