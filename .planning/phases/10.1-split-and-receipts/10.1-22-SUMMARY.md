# Phase 10.1 Plan 22: Receipt files in the data export Summary

Receipt files export as streaming ZIPs (`fincwin-receipts-<n>.zip`, split near 100 MB) with a `receipts.csv` in the first ZIP that maps each file to its line, fetched with the user's own session and shared through the system share sheet (Android: folder picker).

## Decisions

- ZIP 1 stays open until all downloads finish, so `receipts.csv` (which needs each file's final ZIP and missing state) is the last entry of the first ZIP; later ZIPs are closed as soon as the next starts. Only one file at a time is in memory.
- A new ZIP starts when the current one has reached the cap, so one ZIP can pass 100 MB by at most one file.
- If no file could be downloaded at all, the result is `offline` and nothing is shared (a ZIP with only a CSV is useless). A listing failure that looks like a network error is `offline`, else `failed`.
- The card is always shown: receipts have no entry in the feature registry (the registry test lists them as not level-gated).
- Receipts of a line the active view no longer shows are still exported, dated by when the file was added, with an empty line name.
- The CSV uses the existing `toCsv` from csvSerialize.ts (formula defusing and quote escaping included).
