# Phase 10.1 Plan 16: Decide and Insights inputs honour parts Summary

The builder scales a split line's parts to its home amount (largest remainder), drops each Savings outflow part (as a whole Savings line is dropped) and each Transfer part, and keeps the rest as one line with `parts` and a stable `categoryId`; shared split lines resolve each part to the viewer's builtin match and ignore member picks.

## Commits
- abc263f0 feat(10.1-16): Decide builder counts category parts, folding Savings and Transfer parts
- 5544493a feat(10.1-16): shared split lines show each part in the viewer's category

## Behaviour
- Unsplit lines: byte-identical path (new tests plus the existing suites pass).
- A split line skips the whole-line Savings check; each part is judged instead. Kept amount = sum of kept parts. One kept part gives a plain line (no `parts`); two or more give `parts` including the gap as a null-category part.
- `categoryId` = the line's category if a kept part has it, else the largest kept part (first on a tie).
- Shared: split rows (2+ parts) map `category_id` and each part through `res.category` (builtin match); the sources map gathers original ids; unchanged rows return the same object.
