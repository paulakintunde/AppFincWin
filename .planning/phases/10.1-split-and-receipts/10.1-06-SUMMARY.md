# Phase 10.1 Plan 06: Receipts storage model Summary

Private `receipts` bucket (5 MB; JPEG, PNG, WebP, PDF) with read and insert policies that follow line visibility, plus a receipts table, add/remove RPCs with the 5-receipt and 10-page caps, a purge queue filled by a before-delete trigger, service-role purge selectors and a 5-minute cron.

## Deviations from Plan

**1. [Rule 1 - Bug] Column name capture in storage policies.** The plan's policy text uses bare `name` inside `exists (select ... from transactions t ...)`. There `name` resolves to `transactions.name`, not the object name, so reads returned nothing and uploads were refused. Pgtap 132 caught it. Fixed by qualifying `objects.name` in both policies (and `foldername`/`extension` calls).

**2. [Rule 3 - Blocking] Existing table-classification tests.** Tests 102 (household_id table classification), 104 (realtime allowlist) and 106 (move-in table list) failed on the new table. Added `transaction_receipts` to each (derived from transactions; published; stays with household).

Extra helper functions `receipt_ext` and `receipts_queue_purge` were added (not granted to clients). `add_receipt` also returns `bad_type` for an unknown kind and `too_many_pages` for page_no outside 1..10.
