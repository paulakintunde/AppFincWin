## Deviations from Plan

1. [Plan arithmetic] The plan's behaviour line "typing 2500 in part 1 -> balance over 500" is wrong: 2500 + 2000 = 4500 of 5000, which is 500 left to place. The test pins left 500, and over 500 is pinned by raising part 2 to 3000.
2. [Rule 3] `CategoryPicker` gained an optional `title` prop (default unchanged) so the part picker can read "Category for part N".
3. [Rule 2] New copy key `split.part.amountFor` ("Amount for part {{n}}") so the amount field has its own accessible name apart from the category button (same label on both would be ambiguous). Added to splitReceipts/split.ts.
4. Part rows treat an amount of 0 or empty as "needs an amount" (the server rejects zero parts), so a first part that is "the rest" and reaches 0 also blocks Save.
5. Offline: the sheet closes as soon as the mutation is paused (queued), so the user is not held until a connection returns; the Undo toast only appears for a write that succeeds while the sheet is open (the sheet's mutate callbacks do not outlive it). The mutation's own onSuccess still refreshes the cache on replay.
6. "Every category" offered = active categories plus the system Transfer row (the lookup keeps system rows out of `active`); Settlement stays out.
7. The Remove-the-split block shows a "Keep as" Row (default: largest part) above the destructive link; confirmation uses ConfirmSheet with "Keep it" as the cancel action.
