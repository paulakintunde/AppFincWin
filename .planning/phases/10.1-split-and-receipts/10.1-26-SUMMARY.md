# Phase 10.1 Plan 26: Split by item, data and model Summary

A shared line's receipt can now be split between people item by item. Every item starts on the people of the line's usual split. Taking a person off an item or adding one updates each person's share at once, with tax, tip and discounts shared in proportion to each person's items (the engine's `itemShares`, which matches the server to the cent). Confirming sends only the items, their people and the extras to `set_split_by_item`. The server works the shares out again. The write waits in the offline queue, is version-checked, and shows "Split saved" with Undo, which sends the server's before-state to `restore_line_split`. If someone else changed the line first, confirm resolves `{ ok: false, reason: 'version_conflict', updatedBy }`, the hook's `conflict` reads "Sam changed this line. Review and save again.", and the draft is kept. A private line has no people at all (`people: null`, `members: null`) and only builds category parts.
