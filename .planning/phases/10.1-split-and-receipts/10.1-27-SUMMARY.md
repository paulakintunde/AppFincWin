# Phase 10.1 Plan 27: Split by item on screen Summary

On a shared line, the scan review now shows the "Split items between people" switch, which starts on. Every item gets one person chip per household member: avatar plus name, 44 tall, wrapping at large font sizes. A selected chip has the accent border and the checkIt glyph, so colour is never the only signal. Each chip is a checkbox with its checked state and a label such as "Sam, Oat milk". The last person on an item cannot be taken off; that chip is announced as disabled. "Split evenly as usual" shows on the first item only, using the rule word of the line's rule. Once any item differs from the usual people, "Back to the usual split" appears and resets every item.

Under the extras, three things are shown. First, the read-only note "Tax, tip and discounts are shared in proportion to each person's items." Second, "Each person's share": one row per member with the total and "{n} items · {extras} tax, tip and discounts". A member with no items shows "Nothing" and "No items". The card ends with "Total {amount}" and the Adds up / left to place / over badge. The totals line is a polite live region that speaks "Alex 18.70 dollars, Sam 5.50 dollars. Adds up" once the figures settle (600 ms). Third, "Where it goes": the parts built from the items, read-only, with the 'Tax and tip' part labelled. Its "Edit parts" link opens the category split sheet prefilled with those parts, together with the note "Editing the parts here stops the item split."

"Save split by item" is enabled only when the list can be confirmed and both the shares and the parts add up to the line total. A private line has no members, so it never shows a switch, chip, share card or "Where it goes".

On a shared line with a receipt, the line's detail has a "Split by item" row, shown only when household split by item and receipts are both on. It reopens the saved items with their people (`prefill`, no reading). If no items were saved yet, it reads the line's receipt the same way "Read this receipt" does.

Everyone on the line sees a notice card with the somethingChanged glyph: "Sam split this line by item", then one before → after row per person (for example "Alex, from $30.00 to $24.50"), and Undo. Undo goes through `useRestoreLineSplit`. It is offered on the newest split event only, and only while no settle-up covers the line. After an undo the newest card reads "Sam undid the split" and has no Undo. Plain split notices are unchanged.

## Deviations from Plan
1. **[Rule 2] The switch is a `ToggleRow` with the `household` glyph beside it**, not a `SegmentedToggle`. An on/off switch row is the app's existing control for this. SegmentedToggle would have needed new "Off"/"On" copy.
2. **[Rule 3] `MemberAvatar` gained size 36.** It had 28, 32 and 40 only, and the UI-SPEC asks for 36 on the totals rows. Chips use the existing 28.
3. **[Rule 3] `CategorySplitSheet` gained `initialParts` and `onSaved`**, so "Edit parts" opens on the parts built from the items and the review learns that the parts were saved. `onSaved` fires on Save and on "Remove the split".
4. **Edit parts semantics:** the split sheet saves the parts to the line itself. The review then turns the item split off, hides the people controls, keeps the note, and its button only closes. It does not write the item-derived parts again, which would overwrite the hand edit. Closing after that asks nothing. "Edit parts" shows only in existing mode and only at the split-line level (`splitLine`, level 3).
5. **The who-chips render under each ItemRow in ScanReview at full width.** They are not inside ItemRow, so they keep the full width at 320 dp.
6. **New `useScanPeople` hook:** current members in member order, with names from `useMemberLabel`. The usual people come from the stored split, or every member until it loads. The rule comes from `line.split_rule`. The people are put on the draft during render only while the draft is unchanged.
7. **New model helpers:** `fromStored` (prefill), `withMembers(..., { keepPeople })`, `onUsual`, `byItemReady`. **New in scanFiles:** `readingPages(groups)`, the "Read this receipt" page logic, used by the detail row when no items were saved. **New in data/mutations/itemSplit:** `latestItemSplitBefore` and `itemSplitBeforeFromEvent` (see decisions). keys.ts is unchanged.
8. **Undo from someone else's phone:** the household event carries only the split snapshot. Undo therefore restores the split and keeps the line's current parts and category. It clears `item_split` and sets `manual` = (rule is 'amount'). On the phone that made the split, the full server before-state is used, as long as the line has not changed since.
9. **Copy added** to `splitReceipts/scan.ts`: `scan.review.tax`/`tip` ("Tax", "Tip") and `scan.byItem.rule.{even,weight,amount,mine}` ("evenly", "by weight", "by amount", "to one person"). Also `nothing` ("Nothing"), `taxTipPart` ("Tax and tip"), `chipA11y`, `shareA11y`, and the plural pairs `shareSub_one/_other` and `personA11y_one/_other`, which replace `shareSub` so that one item reads "1 item". None of them say advice, recommendation or "you should".
10. **The "{name} has no items" save block** (UI-SPEC 6, for a rule that requires every person) is not built. A person with no items is always allowed. The plan's must-haves do not include the block, and the RPC does not ask for it. A zero-share person shows "Nothing" / "No items".
11. **TDD order:** each task's tests and code were written together and committed in one commit per task, as in 10.1-24, 25 and 26.
