# Phase 10.1 Plan 24: Receipt scan review Summary

The phone reads the receipt page by page and parses the pages as one receipt. The review then shows Store, Date and Total, the items with a likely category each, and tax, tip and discounts as their own rows. Unsure rows are marked "Check this" with a 96 x 96 crop of the receipt. If the figures do not add up, "Doesn't add up" says by how much, with "Use the receipt total" and "Use the items total". Nothing is written until confirm. Then a new line is inserted with its parts and the photos are queued as one receipt, or an existing line gets its parts (its total changes only on "Use the items total").

## Deviations from Plan
1. **[Rule 3] `AddTransactionInput.categoryParts`** (stored form) added to `useAddTransaction`, which passes it into the insert row and the optimistic row. The plan asked for this ("adding category_parts to the insert row").
2. **[Rule 2] Date order helper** `src/services/locale/dateOrder.ts` (`dateOrderFor(localeTag)`, read from Intl). There was no date-order reader in services/locale. ScanSheet passes `useDeviceLocale(rc.region).locale`, so the user's region override is respected.
3. **Model extras beyond the exact interface:** `ReviewImage` has optional `width` and `height`, which the crop needs. `fromParsed` ctx takes optional `pageOffsets` so each item's frame goes back to its page. `applyReceiptTotal(d, otherName)` takes the translated 'Other' name (default 'Other'). The helpers include `draftSignature`, used for the discard check.
4. **`useReadReceipt`** has a third state, `'stopped'`, and also returns `pageOffsets` and `pageSizes`. An optional `read` argument lets tests replace the reader (default `readOnDevice`). A page that throws or does not read is skipped. When no page reads, the outcome is unreadable.
5. **`useConfirmScan`** also returns `conflict` (from useSaveSplit), which the review shows. When the parts save is refused, `confirm` resolves to `{ ok: false, reason: 'conflict' }`. When the result is one category: on a split line the split is removed (keepAs that category); on a plain line `category_id` is set through the edit mutation. The `itemsToParts(` call lives in `scanModel.toPrivateSave`, which useConfirmScan calls. The key-link grep pattern therefore matches scanModel.ts, not useConfirmScan.ts.
6. **New-line category:** with no category of its own, the "Tax and tip" part takes the category of the largest item, so it is not left Uncategorised.
7. **Receipt files:** ScanSheet's `images` prop keeps the exact `{ uri, mime }[]` type. `toLocalFile` keeps `bytes`, `ext`, `width` and `height` when the caller passes the picked `LocalReceiptFile` objects. It completes a bare `{ uri, mime }` with the extension from the mime and `bytes: 0`. **10.1-25 should pass the picked files as they are**, so the outbox byte cap counts them. ScanSheet does not delete the picked cache files; the caller does that on close (as TransactionSheet does).
8. **"Try another photo"** calls a new optional `onRetake` prop, or `onClose` if the caller passes none. 10.1-25 wires it.
9. **Category chip:** `CategoryGlyph` only has the 36 and 48 tile sizes. The chip therefore uses the category's own `Glyph` at 16 plus the name in a fill1 pill, not "CategoryGlyph 24".
10. **"Check this" badge** is built inline (stateColors.tight pair, caution glyph, words). `Pill` has no glyph slot, and `StateBadge` has no caution shape.
11. **The crop is not tappable.** The plan said tapping it "opens the viewer at that spot", but ReceiptViewer has no zoom-to-region entry. The crop window is a square of 1.1 x max(line width, 3 x line height), centred on the line.
12. **Store and Total** are edited inline: a TextInput, and a MoneyInput for Total. Date uses the entry sheet's `DateField` with a Row trigger. The total can be edited only in 'new' mode; in 'existing' mode it changes only through "Use the items total".
13. **Dragging a dirty sheet down** uses the Sheet's own generic discard prompt. The "Discard" and "Cancel" buttons use the "Discard this receipt?" / "Keep editing" prompt.
14. **Copy keys added** to `splitReceipts/scan.ts`: `scan.review.defaultName` ('Receipt', the line name when no store was read), `scan.review.notRead` ('Not read'), `scan.review.discount` ('Discount'), `scan.item.name`, `scan.item.price` ('Price of {{name}}'), `scan.item.unnamed`, `scan.item.done`, `scan.item.a11y` ('{{name}}, {{amount}}, {{category}}'). None say advice, recommendation or "you should".
15. **TDD order:** tests and implementation were written together for each task and committed in one commit per task, not as separate RED and GREEN commits.
