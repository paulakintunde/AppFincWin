1. `.github/workflows/ci.yml`:
```yaml
name: CI
on:
  push:
    branches: [main]
  pull_request:
permissions:
  contents: read
concurrency:
  group: ci-${{ github.ref }}
  cancel-in-progress: true
jobs:
  checks:
    name: checks
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: 24, cache: npm }
      - run: npm ci
      - run: npm run lint
      - run: npm run typecheck
      - run: npm run depcruise
      - run: npm run check:ignores
      - run: npm run test:coverage
      - run: npm run verify:gates
      - name: Service-role key never referenced by client code (ENV-04)
        run: "! grep -rnE 'SERVICE_ROLE|service_role|sb_secret_' src app"
  secret-scan:
    name: secret-scan
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with: { fetch-depth: 0 }
      - name: gitleaks (full history)
        run: |
          docker run --rm -v "$PWD:/repo" ghcr.io/gitleaks/gitleaks:v8.28.0 git /repo --config /repo/.gitleaks.toml --redact --no-banner --exit-code 1
  rls:
    name: rls
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: supabase/setup-cli@v1
        with: { version: latest }
      - run: supabase db start
      - run: supabase test db
```
   The gitleaks binary runs through its official container image rather than gitleaks-action, because the action needs a paid licence on organisation-owned repos. Before committing, confirm the latest v8 tag on https://github.com/gitleaks/gitleaks/releases and pin that exact tag. Confirm whether the subcommand is `git` or `detect` for that version (v8.19+ uses `git <path>`; older uses `detect --source`).
2. `.gitleaks.toml`:
```toml
title = "FincWin gitleaks config"
[extend]
useDefault = true

[[rules]]
id = "supabase-secret-key"
description = "Supabase secret API key"
regex = '''sb_secret_[A-Za-z0-9_\-]{20,}'''

[[rules]]
id = "supabase-service-role-jwt"
description = "JWT whose payload carries role=service_role"
regex = '''eyJ[A-Za-z0-9_\-]+\.[A-Za-z0-9_\-]*InJvbGUiOiJzZXJ2aWNlX3JvbGUi[A-Za-z0-9_\-]*\.[A-Za-z0-9_\-]+'''

[[rules]]
id = "supabase-access-token"
description = "Supabase personal access token"
regex = '''sbp_[a-f0-9]{40}'''

[[rules]]
id = "posthog-personal-api-key"
description = "PostHog personal API key"
regex = '''phx_[A-Za-z0-9]{30,}'''

[allowlist]
description = "Documentation of key names only"
paths = ['''\.env\.example$''']
```
3. Run gitleaks locally through Docker, `docker run --rm -v "$PWD:/repo" ghcr.io/gitleaks/gitleaks:<tag> git /repo --config /repo/.gitleaks.toml --redact --no-banner`. It must report no leaks. If it flags a real secret in history, STOP and tell the user. Rewriting history needs a force-push, which the workspace rules block, so the key must be rotated instead.
4. Do not stop or restart the local Supabase stack here. Plan 00-09 may be using it in parallel. The `supabase db start` + `supabase test db` sequence is proven by the first CI run in Task 2.
