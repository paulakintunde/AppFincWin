# Phase 0 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Platform note:** FincWin is React Native / Expo SDK 57 (iOS + Android), not a web app. There is no CSS, no Tailwind, no shadcn. Styling is `StyleSheet` + a typed theme context (RESEARCH.md Architecture Patterns). All "Design System" template fields that assume a web/shadcn stack are marked **N/A** below and answered with the RN-equivalent instead. The colour, type and layout tokens in this contract are pulled **verbatim** from `BUILD-PROMPT.md` §2 and `FincWin United.dc.html`, which CLAUDE.md's "Design fidelity" constraint declares canonical and closed — no new colours, gradients, shadows or icon sets may be introduced, in this phase or any other.

**Phase 0 UI surface (per CONTEXT.md D-10–D-25):** welcome/sign-in screen (Apple + Google), analytics opt-in prompt, a minimal "You" settings screen (identity, accent switcher, font-pairing switcher, analytics toggle, sign out, live Supabase connection check), sign-out confirmation when writes are unsynced, the update-required screen, and the typed i18n catalogue + safe-area shell + reduce-motion behaviour that every later screen inherits. Nothing from Phase 1+ (five-tab shell, transaction entry, Decide, etc.) is in scope here.

## Platform-Specific Components (Phase 0 additions to the template)

| Component | Spec | Source |

Label is Apple's own localized "Sign in with Apple" — not free copy, not translated through the app's own i18n catalogue. Must not be recoloured, outlined, or have its logo altered — Apple HIG requires the official button, unmodified except corner radius. | CONTEXT.md D-12, D-11 |
| Continue with Google button | Custom button following Google's branding guidelines (not the raw Google-supplied button asset), restyled to match the prototype's outline pill: `border:1.5px solid #E5E2D7`, `border-radius:999px`, `padding:15px 0`, label `Continue with Google`, weight 600, size 14.5px, colour `#14150F`. | Both buttons render on both platforms | Apple button shows on Android too (D-11) — tapping it runs Supabase's web OAuth flow via the Apple Services ID, not the native ceremony. Visually identical button, different flow underneath; no visual distinction needed between the two paths. | CONTEXT.md D-11 |
| Apple button pre-enrolment state | Apple Developer Program enrolment (ENV-10) has an external clock and may not have cleared when this phase ships on Android. Claude's discretion (CONTEXT.md): keep the button visible but disabled (reduced opacity, e.g. `opacity: .4`, no press feedback) with a one-line note beneath ("Apple sign-in arrives once our developer account is verified") rather than hiding it — keeps the layout honest and avoids a layout jump when it activates. Config-flag driven, not a code branch per build. | CONTEXT.md Claude's Discretion |

**Token exception (document so the DSG-02 checker doesn't flag it):** Apple's black button and Google's brand mark are the **single sanctioned exception** to "colours drawn only from the documented token set" (DSG-02). Both are governed by their respective platform's brand guidelines, not FincWin's token set, and must render as those guidelines specify even though the colours (Apple's pure black, Google's multicolour "G") aren't in the token list.

## Spacing Scale

**Exception to the generic 8-point scale:** CLAUDE.md's Design Fidelity constraint fixes BUILD-PROMPT.md §2's layout values as canonical and closed — screen padding, header offset and sheet padding are **exact pixel values from the prototype**, not a generic 4-multiple scale, and several of them (22, 30) are not multiples of 4. Do not round them to the nearest 8pt-scale value. The table below is the literal set Phase 0 screens use.

| Token | Value | Usage |
|-------|-------|-------|
| screen-h | 22px | Horizontal padding on the welcome screen, You screen, consent screen |
| card-pad | 16px | Interior padding for the "You" screen's settings-row cards and the sheet field block |
| header-top | `insets.top + 21` (≈68px on the 402×874 reference device) | Top offset for the first header block — **never hardcode 68px**, always derive from safe-area insets (DSG-03) |
| sheet-pad-bottom | 30px | Bottom padding on any bottom sheet (analytics consent, if presented as a sheet rather than full screen) |
| sheet-corner-pad | 22px | Sheet's own top/side interior padding, distinct from screen-h |
| group-gap | 18px | Vertical gap above each settings-row group heading on the You screen |
| row-pad | 14–16px | Vertical/horizontal padding inside each settings row |
| gap-sm | 8–9px | Icon-to-label gaps, inline button gaps (e.g. Google mark to label) |
| gap-md | 12px | Avatar-to-name gap, row internal element gaps |
| pill-pad-v | 15–16px | Vertical padding inside all pill buttons (sign-in CTAs, consent buttons) |
| touch-target-min | 44px | Minimum tappable height for icon-only controls (back button, dismiss ×) — standard accessibility exception, applies regardless of visual size |

Exceptions: 22px and 30px are canonical prototype values, not 4-multiples — kept exactly per Design Fidelity (DSG-02/03/04). No other exceptions.

## Typography

**Exception to "2 weights only":** BUILD-PROMPT.md §2's canonical type scale uses weights 400/500/600/700/800 across the whole app — a closed set, not open to new weights, but wider than the generic 2-weight guidance. Phase 0 screens use exactly **3** of them. Declaring more here would violate DSG-02's "documented token set only" in the other direction (inventing new weights), so the 3 below are locked for this phase's screens.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Display (wordmark) | 34px | Archivo Black's inherent black weight (font choice, not a numeric weight token — other pairings render this role at their own bold-equivalent weight) | 1.0 |
| Heading (screen title, e.g. "You" name) | 26px | 700 | 1.16, letter-spacing -.01em |
| Body (row labels, button labels, consent copy) | 15px | 500 | 1.5 |
| Label (meta text, group headers, secondary copy) | 13px | 600 | 1.4, letter-spacing .11em on all-caps group headers only |

Font sizes actually rendered across Phase 0's four screens (welcome, consent, You, update-required): **34, 26, 15, 13** — 4 sizes, matching the contract's 3–4 requirement. Do not introduce a 5th size (e.g. do not shrink error text below 13px — reuse the Label role).

## Color

**Exception to strict 60/30/10:** FincWin's token set (BUILD-PROMPT.md §2) is a closed palette assigned by semantic role, not a literal three-colour split — but it does map cleanly onto the 60/30/10 shape below for Phase 0's screens.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `canvas` `#FBFAF7` | Full-screen backgrounds: welcome screen, You screen, update-required screen |
| Secondary (30%) | `surface` `#FFFFFF` | Settings-row group cards, the analytics-consent sheet (if sheet-presented), the account-field block |
| Accent (10%) | `accent` `#1B4D3E` default (user-selectable: `#1F3A5F` navy, `#7A4B2A` rust, `#3E5C6B` slate) | Reserved **only** for: the accent-swatch selection ring on the theme switcher, the analytics-toggle "on" fill, the "connected to Supabase" success indicator dot, the "Share usage" consent button fill, and the focus ring (`2px solid accent`, `2px` offset). **Not** used on the Apple/Google sign-in buttons — those use their own brand colours (see Token exception above) |
| Destructive | `danger` `#B4472A` | Reserved **only** for: the "changes not yet saved" sign-out warning text/icon, the account-field error text (`acctErrText` pattern), and the update-required screen's blocking-state accent if one is used |

Accent reserved for: theme-switcher selection ring, analytics-toggle "on" state, connection-check success indicator, "Share usage" button fill, focus ring. Never the sign-in buttons, never body text, never decorative.

Secondary token detail: `ink-muted` `#6E6A5E` for secondary/body-adjacent text (tagline under wordmark, row sub-labels), `ink-faint` `#767161` for tertiary/help text (footer notes), `fill` `#F1EFE8` for the toggle-off track and the inactive-state chip background (e.g. current-account pill on the signed-out-style layout).

## Copywriting Contract

Voice: declarative, not prescriptive — never "advice", "recommendation", "you should" (this rule governs Decide-tab copy specifically, but the same plain/declarative register applies project-wide per CLAUDE.md). British-ish spelling, typographic apostrophes (`'` not `'`). Per CONTEXT.md D-16, welcome-screen copy is **user-supplied and not yet final** — placeholder i18n keys below are explicitly marked. Per D-20, consent/settings/error copy is Claude-drafted in the prototype's voice and awaits user review before being treated as final; it is not user-owned in the same blocking sense as D-16.

| Element | Copy |
|---------|------|
| Wordmark (fixed, not a copy decision) | "FincWin" — `Archivo Black` (or the active pairing's display face), 34px |
| Welcome tagline — **AWAITING USER COPY (D-16)** | i18n key `auth.welcome.tagline` — placeholder: `[one line under the wordmark — user to supply]`. Do not invent final copy; ship the placeholder key so the screen renders and is swappable. |
| Apple sign-in button | Apple's own localized string ("Sign in with Apple") — not sourced from FincWin's i18n catalogue, not editable |
| Google sign-in button | "Continue with Google" — fixed per D-12, matches Google's own verb convention |
| Apple button, pre-enrolment disabled state | "Apple sign-in arrives once our developer account is verified." — i18n key `auth.apple.pendingEnrolment` |
| Analytics consent — heading | "Share anonymous usage?" |
| Analytics consent — body | "Helps us see where the app is confusing — never your amounts, payees or account names. Change this anytime in settings." |
| Analytics consent — primary CTA | "Share usage" |
| Analytics consent — secondary choice (equal weight, D-17) | "Not now" |
| Primary CTA (You screen actions) | "Sign out" (row label); confirmation flow below |
| Empty state | Not applicable — Phase 0 ships no data-list screens (Activity and friends arrive in later phases) |
| Error state — sign-in failure | "Sign-in didn't go through. Try again." |
| Error state — connection check | "Not connected — check your internet connection." |
| Destructive confirmation — sign out, unsynced writes exist (D-15) | "{n} changes not yet saved. Signing out clears the encrypted cache and everything queued on this device." Actions: "Cancel" / "Sign out anyway" |
| Destructive confirmation — sign out, nothing unsynced | No confirmation dialog; sign out proceeds immediately (friction only when something would actually be lost) |
| Update-required screen — heading | "Update needed" |
| Update-required screen — body | "This version is behind. Update FincWin to keep using it." |
| Update-required screen — primary CTA | "Update now" (deep-links to the platform store listing; no skip/dismiss option — this is a blocking screen) |

**Explicitly forbidden, project-wide per CLAUDE.md:** "Your figures stay on this device" or any variant — the prototype's signed-out copy at `FincWin United.dc.html` line 2945 is false under FincWin's cloud-first architecture and must not be ported into any Phase 0 screen (D-15).
