<task type="auto">
  <name>Task 2: Generate the Apple client secret, enable the Supabase Apple provider, flip the flag, build iOS</name>
  <files>scripts/apple-client-secret.mjs, docs/ops/auth-providers.md, docs/dependency-register.md</files>
  <read_first>

  <action>
1. `scripts/apple-client-secret.mjs` (Node ESM, only `node:crypto` and `node:fs`): reads APPLE_TEAM_ID, APPLE_KEY_ID, APPLE_SERVICES_ID and APPLE_P8_PATH from env. It builds header `{alg:'ES256', kid}` and payload `{iss: teamId, iat: now, exp: now + 180*24*3600, aud: 'https://appleid.apple.com', sub: servicesId}`, signs with `crypto.sign('sha256', data, { key: p8, dsaEncoding: 'ieee-p1363' })`, prints the JWT to stdout and the expiry date to stderr. It never writes the JWT to disk.
2. For dev and prod, run `curl -X PATCH https://api.supabase.com/v1/projects/<REF>/config/auth -H "Authorization: Bearer $SUPABASE_ACCESS_TOKEN" -H "Content-Type: application/json" -d '{"external_apple_enabled":true,"external_apple_client_id":"<APP_ID>,<APPLE_SERVICES_ID>","external_apple_secret":"<JWT>"}'`. The bundle ID covers native iOS ID tokens; the Services ID covers the Android web flow. Verify with GET.
3. `eas env:update` (or delete and create) `EXPO_PUBLIC_APPLE_SIGNIN_ENABLED=true` in development, preview and production, and set it to `true` in `.env.local`.
4. `eas build --profile development --platform ios`. This is interactive for Apple credentials the first time: let EAS generate the distribution certificate and provisioning profile, and include the registered XR. Then run `eas credentials -p ios` to confirm the profile includes the Sign in with Apple entitlement (Pitfall 3). Install on the XR from the build page's QR/link.
5. Update `docs/ops/auth-providers.md` (Apple section: Services ID, Key ID, Team ID as identifiers only, the redirect URLs, the secret regeneration command `node scripts/apple-client-secret.mjs`) and the register: Apple Developer Program provisioned; Sign in with Apple provisioned with "client secret expires YYYY-MM-DD, regenerate and PATCH both projects before then". Also add the renewal to the Blocker/Notes column.
  </action>
  <verify>

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-00-20-01 | I | SIWA .p8 key | mitigate | Stored outside the repo (`*.p8` gitignored); the script reads it at run time; the JWT is printed, never written |
| T-00-20-02 | D | Client-secret expiry (6 months) breaks Android Apple sign-in | mitigate | Expiry date in the register with a regeneration command; renewal reminder |
| T-00-20-03 | S | Token audience confusion | mitigate | Supabase client_id list restricted to our bundle ID + Services ID |
| T-00-20-04 | T | Stale provisioning profile missing the entitlement | mitigate | Capability enabled on the App ID first; `eas credentials` inspection after build (Pitfall 3) |
| T-00-20-05 | I | Apple private-relay email handling | accept | Stored as provided in the caller-only-readable profiles row (RLS) |
