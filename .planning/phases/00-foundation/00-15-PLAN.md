<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| native identity SDK -> app | ID tokens from Apple/Google |
| app -> Supabase Auth | Tokens exchanged for sessions; server verifies |
| system browser -> app deep link | Android Apple flow returns via fincwin://auth-callback |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-00-15-01 | S | Apple ID-token replay | mitigate | Fresh 256-bit nonce per attempt; hashed to Apple, raw to Supabase; GoTrue verifies the nonce and signature (never verified client-side) |
| T-00-15-02 | S | Google ID-token replay where the SDK lacks nonce support | accept | Token is short-lived (1h), audience-bound to our client IDs and verified by GoTrue; nonce used whenever the installed SDK supports it; documented in auth-providers.md |
| T-00-15-03 | S | Authorization-code interception on the Android deep link | mitigate | PKCE (`flowType: 'pkce'`): the code verifier never leaves the device, so an intercepted code is useless |
| T-00-15-04 | T | Open redirect | mitigate | Supabase `uri_allow_list` restricted to `fincwin://auth-callback` |
| T-00-15-05 | I | Loss of Apple name/email | mitigate | Written before sign-in resolves; persisted locally and retried on failure; never overwritten with null (ACC-03) |
| T-00-15-06 | I | Google web client secret | mitigate | Only in .env.local and Supabase config via Management API; never in git or the app bundle |
</threat_model>
