  <name>Task 1: Install Android Studio (SDK, JDK, emulator) and create an AVD</name>
  <read_first>
    - .planning/phases/00-foundation/00-RESEARCH.md (Environment Availability: Android SDK/adb/JDK missing)
  </read_first>
  <action>Human-only: a GUI installer plus the SDK/AVD wizards. Installing software needs approval under the workspace rules.</action>
  <what-built>The Expo SDK 57 project from 00-02 is ready to build natively. The machine has no Android SDK, adb or JDK yet.</what-built>
  <how-to-verify>
    1. `winget install Google.AndroidStudio` (or download from developer.android.com/studio). Run the setup wizard with the Standard install, which adds the SDK, platform-tools, emulator and a bundled JDK.
    2. Android Studio -> More Actions -> SDK Manager -> SDK Platforms: install the latest stable Android API that Expo SDK 57 targets (see https://docs.expo.dev/versions/latest/ for the compile SDK). SDK Tools: tick Android SDK Build-Tools, Command-line Tools (latest), Emulator, Platform-Tools.
    3. Device Manager -> Create device -> Pixel 8 (or similar) -> the same API image (x86_64, Google APIs or Play) -> Finish, then start it.
    4. Set user environment variables: `ANDROID_HOME=%LOCALAPPDATA%\Android\Sdk`, `JAVA_HOME=C:\Program Files\Android\Android Studio\jbr`. Add `%ANDROID_HOME%\platform-tools` and `%ANDROID_HOME%\emulator` to PATH. Open a new terminal.
    5. Confirm `adb devices` lists `emulator-5554 device` and `java -version` prints 17 or newer. Reply "ready".
  </how-to-verify>
  <acceptance_criteria>
    - User replies "ready" after `adb devices` shows a running emulator
  </acceptance_criteria>
  <resume-signal>Type "ready" or paste the error</resume-signal>

  <action>
1. Verify the toolchain: `adb devices` shows a `device`; `java -version` prints 17 or newer; `echo $ANDROID_HOME` is non-empty.
2. `npx expo run:android`. This prebuilds `/android` (gitignored), compiles the debug dev client with expo-dev-client, installs it on the emulator and starts Metro. On a Windows long-path error, enable long paths (`git config --system core.longpaths true`, plus the `LongPathsEnabled` registry key via an elevated prompt, which needs the user) and record it.
3. Confirm the app launched: `adb shell dumpsys activity activities | grep -i <android.package from app.config.ts>` shows a resumed activity. Take a screenshot with `adb exec-out screencap -p > "$TMPDIR/fnd02-boot.png"` (outside the repo) and check that the FincWin wordmark renders on the #FBFAF7 background.
4. Record the debug keystore SHA-1 for Google OAuth (plan 00-15): `keytool -list -v -keystore "$USERPROFILE/.android/debug.keystore" -alias androiddebugkey -storepass android -keypass android | grep SHA1`. Write it into docs/dev-setup.md under "Debug signing SHA-1". A debug SHA-1 is not secret.
5. Write `docs/dev-setup.md` with these sections: Prerequisites (Node 24, Android Studio + SDK + AVD, JDK 17 via Android Studio jbr, Docker Desktop, Supabase CLI via Scoop, eas-cli); Environment variables (ANDROID_HOME, JAVA_HOME, PATH entries); Daily loop (`npx expo start --dev-client` once the dev client is installed; `npx expo run:android` after any native/config-plugin change); "Expo Go is not used: Apple/Google sign-in, secure store and PostHog need a development build"; iOS loop (EAS development build to the iPhone XR, blocked on Apple enrolment, plan 00-20); Debug signing SHA-1.
  </action>
