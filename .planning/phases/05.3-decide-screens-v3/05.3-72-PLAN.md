<objective>
Give an unrealistically large price a clear "too big" message instead of checking it.

Root cause (gap 6, cited): `priceProblem` (src/features/decide/v3/model/draftStatus.ts line 13) only knows 'priceNeeded'. The
amount parser accepts anything up to MAX_ABS_AMOUNT_MINOR (10^13 minor units, $100 billion; src/engine/money/types.ts line 20),
and the engine only reports `exceeds_range` when its bigint maths overflows (judge/purchase.ts line 152), which $10 billion does
not. So "Coffee · $10,000,000,000" was accepted, saved and checked. The UI-SPEC (line 305) requires "a price above the engine
range: the exceeds_range text" inline under the price.

The range (planner's PROPOSAL; the owner decides in Task 0 before it is hard-coded): the ceiling is 100 x the top band edge of the user's home
thresholds (`HomeThresholds.bandEdges[13]`, $5,000,000 in USD, so $500,000,000), clamped to MAX_ABS_AMOUNT_MINOR; with no band
edges (source 'missing') it is 100,000,000,000 minor units. It follows the home currency because the band table does.

Output: the ceiling, the message, the refusal, tests.
</objective>
