# Phase 05.3 Plan 102: Offline status from the online state Summary

"Offline, will save" now shows only when the app is offline; a save queued behind another write while online reads "Saving…".

## What changed

- `src/data/sync/writeQueueState.ts`: `isOfflinePaused(m, online)` and `isQueuedBehind(m, online)`.
- `draftStatus` takes `{ status, offlinePaused, pending }` and returns `saved | saving | offline | notSaved`. `saveStatusOf(mutations, online)` in `useV3CheckDraft` reads the online state via `useSyncExternalStore(onlineManager)`.
- `useCheckWritesSettled`: a save queued behind another write while online is not settled. The offline test is made at render, not in the `useMutationState` filter, because going offline fires no mutation-cache event and the filter result would otherwise stay stale (found by the offline half of the test).
- `check.ts`: `saving: 'Saving…'`.
- Test mocks of `@tanstack/react-query` in CheckScreen, checkMatrix and useV3CheckDraft tests gained an `onlineManager` stub.

## RED evidence

`offlineFlap.test.tsx` on the pre-fix code: `reads a save queued behind another write as saving, not offline` failed with `Expected: "saving"  Received: "offline"` (the save was `pending` with `isPaused: true` while online), and the useCheckWritesSettled case failed with `Expected: false Received: true`.

## Check it with a busy queue (Task 2)

Check it not reproduced with a busy queue. With a never-resolving WRITE_SCOPE write ahead and the app online: a new check whose create is queued commits within one press (`commit` returned true via the `pendingRows` optimistic row, answer saved once), and for an existing check with a stale cached price the draft's price follows the typed 7,000 and commit returns true. No change was needed in `useV3CheckDraft.commit`. These are hook-level tests; CheckScreen and `useCheckV3` were not edited and are covered by their existing tests. The false NetInfo "not reachable" side is left to 05.3-103's device recorder. No `OPEN:` items.
