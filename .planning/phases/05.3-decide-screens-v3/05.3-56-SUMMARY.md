# Phase 05.3 Plan 56: Readiness answers write through undoable mutations Summary

One hook, `useReadinessAnswer`, turns each readiness chip into exactly one existing undoable write (mark paid, skip, or a `readiness_waiver` save in owner-private `decide_answers`) with a named toast, and tells the card whether the write landed.

## What was built

- **decideAnswers.ts**
  - `AnswerInput` gains `{ kind: 'readiness_waiver'; waiver; at }`. `shapeOf` maps it through `waiverAnswerShape` (05.3-54), so the key regex matches the 05.3-61 database check.
  - `save(a, label?, onSettled?)` and `remove(row, label?, onSettled?)`. `label` is `{ key: UndoLabelKey; name?: string | null }`. It rides in the insert, update and remove vars, names the undo step (`labelParams.name` only when a name is given), and is recorded as `labelKey` in failed-write records (ids and label only, never an amount). With no label the steps stay `answerSaved` / `answerRemoved`.
  - `onSettled` is wired through `mutation.mutate(vars, { onSuccess, onError })`.
- **Undo labels**: nine keys appended to `UNDO_LABEL_KEYS` (all match `undo_log.label_key ~ '^[a-zA-Z]{1,40}$'`), with the plan's exact named and unnamed copy in en.ts.
- **useReadinessAnswer** (`src/features/decide/v3/ready/`)
  - `markPaid`: finds the line in `source.rows`, then `source.upcomingRows`, of this household; calls `markPaid(row, userId, today)` once; toasts `markedPaid` with the step id (null step id: no Undo); settles true.
  - `skip`: skips only when the row has `recurring_series_id` (B1). Otherwise saves a `didnt_happen` waiver (`no_pay` for a pay item) for the item's series and date.
  - An uncached `lineId` opens Activity, writes nothing, never throws.
  - `waive`: one `save` with `{ kind: 'readiness_waiver', waiver, at: today }` and the per-kind label; month waivers are named with `useV3Format().month`. A null result shows no toast. A thrown RangeError (malformed waiver) settles false.
  - `open`: Activity via `router.navigate('/activity')`, Envelopes via `pushOnce(ENVELOPES_HREF)`.
  - No user or household: no-op, settles false.
  - `clearWaiver`: `waiverAnswerFor` on the cached answers, then `remove(row, { key: 'readinessAnswerCleared', name })` with a toast. No row: nothing.
  - No analytics events. Nothing writes `recurring_dismissals`.

## Deviations from Plan

### Auto-fixed / added

**1. [Rule 2 - Correctness] Already-answered line writes nothing**
- markPaid on a line already `paid`, or skip on one already `skipped`, makes no write and no toast, and settles true (same as a null save). Avoids a needless version bump and a misleading Undo.

**2. [Rule 2 - Security, T-05.3-56-01] Household check on the cached line**
- A cached row whose `household_id` differs from the current household, or that lacks `version` / `local_date`, is treated as not cached and opens Activity.

**3. [Rule 2 - Correctness] Skip with no series and no item series/date**
- If the line has no series and the item carries no `seriesId` or `date` (so no valid waiver can be built), the hook opens Activity instead of writing.

### Interpretations

- **Mocking style**: the tests replace `@/data/mutations/transactions` and `@/data/mutations/decideAnswers` with `jest.mock` factories returning spies, rather than `jest.spyOn` on the live modules. Same intent (pin the calls on the source modules) without loading Supabase env.
- **markPaid/skip onSettled**: `edit` always enqueues the write; a null step id only means no undo step. So these settle true after enqueue, as the plan's interface note allows.
