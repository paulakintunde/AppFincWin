<objective>
Wire the client to the 4-arg server function and fix the wrong-currency, unlinked plan pot.

Root causes (cited):
- Gap 1 currency: `useBoughtContext` (src/features/decide/v3/record/useBoughtContext.ts line 42) sets `currency: cash.currency` (the everyday account's currency, GBP on the test account). `V3RecordProvider.planIt` passes `currency: ctx.currency` with `goalTarget = purchase.whole`, which is in the HOME currency (USD). The pot is stored as GBP 300.00 and shown converted back to USD: $401.03. The same mislabel reaches Record as bought: `buildBoughtWrite` writes `original_currency: ctx.currency` while its amounts are home-currency (`src/data/mutations/boughtWrite.ts` lines 107, 136, 182), and line 369 even passes `ctx.currency` as `homeCurrency`, which shows the intended meaning.
- Gap 1 link: `useWaitAndSave` builds the goal with no account (src/data/mutations/decideOutcome.ts `DecideWaitGoal`), so readiness's `envelopeItems` names it "Not linked to an account".
- Gaps 2 and 8: `recordOutcomeUndo` records a client step that the server can never apply (see 05.3-66 objective).

Output: the mutation sends `p_undo_step`; the plan pot carries `account_id` and the home currency; bought rows are labelled in the home currency.
</objective>
