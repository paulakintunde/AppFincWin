# Phase 05.3 Plan 113: Own kinds bring their base kind's cards (UAT gap 32) Summary

An own kind now shows the cards of the built-in kind it counts like. A "Bike" that counts like Vehicle shows "Car costs to consider" and the vehicle card note. A "Flat" that counts like Property shows the Home costs card, the Property card note, and "Asked under item costs above." on the major-asset card. A removed or unknown own kind shows the same cards as General, which is how the engine already treats it.

## What was done
- **Task 1:** added `src/features/decide/v3/model/itemBase.ts` with `itemBaseOf(ref, own)`. A preset returns itself. A live own kind returns its stored base. Any id not in the rows returns `'general'`. This repeats the engine's `resolveItemType` rule, because the barrel-only depcruise rule blocks a deep import. Tests cover every preset, live own kinds, missing ids, and parity between `liveCustomOptions(raw).itemTypes` and the row shape from `useOwnOptions`. The file has 100% statements, branches, functions and lines.
- **Task 2:** LayerStack calls `useOwnOptions()` and memoises `itemBaseOf(check.itemType, own.itemRows)`. It passes the result as `itemBase` to PaymentPlanCard, ItemCostsCard and MajorAssetCard. The costs gate is now `costsPresetOf(check, itemBase)`. Each card takes an optional `itemBase?: V3PresetItemType` and falls back to `itemBaseOf(check.itemType, NO_ROWS)`. None of the three cards checks `itemType.kind === 'preset'` any more. No engine files changed. Per D-18, the last three cards still only store their answers.

## Deviations from Plan
1. **[Rule 1 - outdated test] `src/features/decide/v3/layers/__tests__/ItemCostsCard.test.tsx` changed (not in files_modified).** Its case "a stored non-preset type has no card" assumed the old behaviour, where an own kind gets no costs card. Under the engine's rule that this plan adopts, an own kind with no rows counts as General, and General asks cost questions. That case now checks that an own kind with no `itemBase` shows "Extras to consider", and that with `itemBase="vehicle"` it shows "Car costs to consider". I also added a case for a kind with no cost questions (`rent_bill`), so the "no card" path is still tested. Commit 4eba7457.
2. **[Rule 1 - test fact] itemBase.test.ts preset count:** the plan said "nine presets", but `V3_ITEM_TYPES` has 12 (it also holds rent_bill, loan_repayment and cash_equivalent). The test checks that every value in `V3_ITEM_TYPES` maps to itself and does not assert an exact count.
3. **[Rule 3 - typecheck] itemBase.test.ts** indexed `refs[0]`, which `noUncheckedIndexedAccess` rejects. Fixed with named refs in ef7c95d2. This is a separate test-only commit, made after the GREEN commit, because typecheck only runs in the Task 2 verify.
4. **Behaviour note:** before this plan, MajorAssetCard hid the legal and moving fields for every own kind. Now an own kind based on General, or a removed one, shows both fields, the same as the General preset. This is what the plan intends ("renders exactly as General").
