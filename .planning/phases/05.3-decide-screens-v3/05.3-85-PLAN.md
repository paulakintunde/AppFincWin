<objective>
Two minor UAT gaps on the check and answer:
1. Step 22: "Pressing Check it straight after typing a price checks that price" — the device briefly showed "More needed / A price is needed first".
2. Step 0.24: "The confidence sheet closes after Ask again" — it stayed open.

Root cause 1: `useV3CheckDraft.commit()` (src/features/decide/v3/check/useV3CheckDraft.ts) calls `flush()`, which only *queues* `useSaveCheckDraft().save(...)`. That mutation runs in `WRITE_SCOPE` (src/data/mutations/decideChecks.ts, `setMutationDefaults(mutationKeys.saveCheckDraft)`), so its `onMutate` cache patch waits behind any earlier write in the scope (often the draft's own create). `CheckScreen.onCheck` then pushes the answer route at once, and `AnswerScreen` evaluates `useCheckV3(id)` from the cached row, whose `inputs` still lack the price, so the engine returns needs_input / no_price until the queued save reaches onMutate.

Root cause 2: `ConfidenceSheetV3`'s Ask again `Pressable` calls only `onAskAgain?.(row)`; AnswerScreen wires it to `clearWaiver(...)` and nothing sets `confOpen` false.

Output: synchronous cache patch on commit; sheet closes on Ask again; tests.
Coordination: do not edit src/data/mutations/decideChecks.ts or AnswerScreen.tsx here (other gap plans touch them).
</objective>
