<objective>
Keep the band and the layer list when a periodic check is not complete yet.

Root cause (gap 4, cited): `buildResolved` (src/engine/decide/v3/judge/purchase.ts lines 157-182) returns `nothing(missing)`
as soon as `plan_count_missing`, `plan_rate_missing`, `first_payment_not_chosen` or `pause_interest_not_answered` is found,
BEFORE it computes `whole`, the item-type specs, `bandOf` and `layersFor` (lines 184-219). With no Purchase, `judge`
(judge.ts lines 437-438) sets `band = null` and `layers = []`. CheckScreen (line 60-61) and LayerStack (lines 53-54) read
`purchase?.band ?? result.band`, so choosing "Periodic payments" hides the band chip, the purpose and value questions and the
car costs card (and gap 3 means the plan could never be completed).

Fix: compute a preview `{ band, layers }` from the price, tax, fees, share and item type before the plan-field return, carry it on
PurchaseBuild, and let judge fall back to it. Same functions (`bandOf`, `layersFor`), so the preview can never disagree with the
built Purchase.

Output: engine change with tests; 100% coverage.
</objective>
