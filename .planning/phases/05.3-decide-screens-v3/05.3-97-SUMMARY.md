# Phase 05.3 Plan 97: Saved-plan delete Undo targets its own step Summary

A toast's Undo now reads the step it is about to replay and refuses, with "Nothing was undone...", when the step's label or touched rows are not the ones the toast was shown for. The device sequence (save A, save B, delete B, Undo at 1 s) is a regression test in four variants.

## Root cause

**No variant reproduced the device failure.** All four variants pass: base, queue paused, queue busy and sheet. In every one, `apply_undo_step` is called exactly once with B's delete step id, A stays a saved plan with its goal live, and B comes back with no failed write. Specifically, the late-replay ("queue paused") variant did NOT fail: a paused `undoStep` for A's `planSaved` step replays through `resumePausedMutations` when the user asked for it, runs once, and does not make B's Undo apply any other step.

So the client path `useDeleteDecision.deleteDecision` -> `showToast({stepId})` -> `UndoToastHost.onUndo` -> `undoStep` mutationFn -> `applyUndoStep` carries the right id in a clean run. The device cause is not in those files under the conditions tested. Remaining unexcluded candidates, which a device run with logging would decide: a stale step id on the toast from an earlier code path (the Record sheet or a persisted paused undo from an installed build, which the variants cannot construct), or the 05.3-102 pause/queue states on the device. What this plan delivers is the guard that makes the symptom impossible to apply silently: `fetchUndoStepMeta` plus the label and touched-row check in `src/data/mutations/undo.ts` (`undoStep` mutationFn). Whatever step id reaches it, a step for another row or another label applies nothing and says so.

Caveat on ordering: the base variant ran once with the guard already in the tree (the guard does not alter the correct-id path). I did not re-run it against pre-guard source.

## Accomplishments

- Device-sequence tests with a fake server that keeps versions, row state and undo_log steps (replay gives `already-undone`, a wrong id visibly reverts A).
- `ToastState.target`, `UndoVars.expect`, `fetchUndoStepMeta(client, stepId)`, `UndoRunOutcome` with `'mismatch'` (toast `undo.wrongStep`, History refreshed, no failed write).
- `useDeleteDecision`, the `SavedPlanRow` unfinished delete and `RecordSheet.onUndo` pass their check id; the host passes `expect` for single and group Undo.
- `'not-found'` now also refreshes History.

## Old persisted paused undoStep mutations

Handled by the label guard (preferred option in 5c), proved by `undoExpect.test.ts` ("a persisted undo with no expect ... wrong label refuses, right label applies"). Scope: only Decide check labels (`planSaved`, `notBuyingSaved`, `decisionWritten`, `decisionDeleted`, `checkDeleted`, `checkCleared`) read the step first; every other undo is sent as before with no extra read, so the other toasts are unchanged (the plan's "no target keeps today's behaviour" line). Tradeoff: a persisted old undo can only be caught on label, not on touched rows.

## Deviations from Plan

**1. [Rule 3 - Blocking] Variants split into one file each.** With four `it`s in one file, the second and later tests never rendered their `Harness` (the previous test's hook object was reused, so saves went to a finished QueryClient). The queue, version chains and in-flight map are module state. Variants live in `savedPlanDeleteUndoToast.{,paused.,busy.,sheet.}test.tsx` over a shared `savedPlanToast.harness.tsx`. Consequence: `grep -c "it("` on the main file prints 1, not 4; the family has 4.

**2. [Rule 1 - existing tests] Fakes updated for the new read.** `undo.test.tsx` and `savedPlanDeleteUndo.test.tsx` fakes now answer the step-meta read; `RecordSheet.test.tsx` expects `expect: { entityId: 'c1' }` on the sheet's Undo.

**3. Sheet variant is minimal.** It asserts that, after plan A's save and no queued sheet undo, the B Undo applies only B's step. A real RecordSheet render for A was not built; the sheet's `stepId` reset on hide is read from the code (RecordSheet clears `stepId` when not visible), not exercised.
