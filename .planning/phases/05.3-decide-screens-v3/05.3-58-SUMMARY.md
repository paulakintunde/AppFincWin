# Phase 05.3 Plan 58: The asking not-ready card Summary

The not-ready card now asks instead of blocking. It renders 05.3-57's `notReadyGroups` under their months, and each chip writes its answer once through 05.3-56's `useReadinessAnswer`, with Undo. The owner's September gaps (pay, Netflix, Lunch still Expected) and the October spending gap (last Oct 14) are each one tap.

## What was built

- **NotReadyCard.tsx**
  - Same props, so HomeScreen and AnswerScreen are unchanged. The analytics effect, the onReady effect, the `notReadyRows(...).length` empty check and the card styles are kept.
  - `notReadyGroups(readiness, thisMonth, useRecordContext().today)`.
  - Each group shows its heading (label role, inkDim). Then each item shows:
    - one accessible View whose label is `itemA11y`, with money read through `moneyA11y`. It holds the title (label), the status (body s13_5, inkDim) and the question (body);
    - a wrapping row (`flexDirection: 'row', flexWrap: 'wrap'`) of chip Pressables, each with role button, its visible label and `accessibilityState { disabled }`;
    - the quiet link (label in inkMuted, minHeight touchMin).
  - The group's month link comes last. A line1 divider sits between items.
  - Formatting uses `useV3Format`: money, moneyA11y, month and date. Envelope names are joined with ', ', and the `{{month}}` chip/link params are formatted with `month`.
  - W3: `pending` is a set of keys, `item|<view.key>` or `month|<group.key>`, stored with the readiness it was made under. A new readiness object clears every key, and `onSettled(false)` removes its own key.
- **Tokens only**: pill style reused (radii.pill, line4, cardPad, touchMin), inkMuted for links, line1 dividers, the gapSm and gapMd spacings.

## Deviations from Plan

### Interpretations

1. **Pending clear without useEffect.** The plan said "clear the set in a useEffect keyed on readiness". The card instead stores the readiness next to the keys and treats a different readiness as an empty set. The observable behaviour is the same (the test re-renders with a new readiness object and every chip is enabled again). It avoids a set-state-in-effect under the React Compiler lint and an extra render with stale disabled chips.
2. **Open actions are not pending.** "I'll record it", "Open Activity" and "Open envelopes" navigate and write nothing, so they never disable the chips. Otherwise a user who came back from Activity without recording would find the item stuck until readiness changed.
3. **Formatter in tests.** Both suites mock `useV3Format` with a deterministic formatter in the new `notReadyKit.ts` (`$16,199.42`, `3 Sep`, `11 dollars and 99 cents`). The real hook reads account, category and series queries that need the Supabase env. Assertions are on the full formatted strings the card builds.
4. **Answer hook mocked with jest.mock**, not jest.spyOn. The hook imports Supabase-backed modules, so it cannot load in Jest without env. This is the same approach 05.3-56 used.
5. **HomeScreen.test.tsx** also mocks `useRecordContext`, because the real card now reads `today` from it, and that module imports the Supabase client. AnswerScreen.test.tsx already mocked it.
6. **Code-only ordering test** now asserts the item groups' labels and the 'Open Activity' / 'Open envelopes' buttons. The old single-row button label (`title. reason. button`) no longer exists because the item text and its buttons are now separate TalkBack stops.
7. **notReadyKit.ts** (test fixtures) is a new file not listed in files_modified.
8. **[Rule 3 - Blocking] Four more suites render the real card.** AnswerAsk.test.tsx, answerStates.test.tsx, answerMatrix.test.tsx and homeMatrix.test.tsx now mock `useReadinessAnswer`. homeMatrix also mocks `useRecordContext`. None of their assertions changed. They are not in files_modified. Commit da9b148c.
