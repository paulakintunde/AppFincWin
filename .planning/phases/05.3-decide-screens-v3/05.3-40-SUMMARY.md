# Phase 05.3 Plan 40: Layer cards A Summary

The purpose block (D-10 order, emergency follow-up), the payment plan card and the item costs card are live on the Check screen through a LayerStack mounted in `PurchaseRoute`'s `renderLayers`; `CheckScreen.tsx` is untouched.

## What was built

- **LayerStack** shows cards from `Purchase.layers` via `layerVisibility`, in canonical order, each in `RiseIn`. Hidden cards are only hidden: no edit is called, stored answers stay (I43). Saved regular payments come from `useRecurringSeries` and `useCategoryLookup` (live series only, exact builtin category key).
- **PurposeBlock**: "What is this for you?", six presets in D-10 order, 2 columns (1 under rule S), 44 high, ink fill when selected, nothing selected by default. The emergency tile shows when the engine's `canUseEmergency(purpose)` is true.
- **PaymentPlanCard**: Weekly / Every 2 weeks / Monthly, length chips 12 to 84 plus Custom (sets `termMonths`, clears `count`), `RateInput` (empty = null, typed 0 = 0%, over 100 refused with the last value kept and the warning shown), down payment to `pay.deposit` only, set-up fee, "More fees" (per payment, end), optional quoted payment, "A loan length is needed.", live summary tile from the engine schedule, "See the whole plan: {total} in total" link, card note by item type.
- **ItemCostsCard**: preset questions via `costFields` (amounts empty, never filled), "Sales tax or levy (%)" percent to `taxPercent` with the hint "about {amount}" computed by the engine's `salesTaxOf`, yes/no answers and the tax due date stored under `L4.<id>` layer answers, no deposit field. Saved-payment offer with "Use it" (fills only on press).
- **costPrefill** (100% coverage) and **percentText** (100%).

## Deviations from Plan

**1. [Rule 3 - Blocking] `salesTaxOf` exported from the v3 barrel.** The tax hint must be the engine's figure ("the UI never multiplies a percentage") and the depcruise rule allows only the barrel. Added one export to `src/engine/decide/v3/index.ts` and the pinned list in `barrel.test.ts`.

**2. [Rule 1 - correctness] costPrefill maps only insurance_monthly and home_insurance, and only on exact frequency match.** `fuel_monthly` omitted (builtin Transport is not fuel). `utilities_change` omitted (a change is not the existing bill, so prefilling would give a wrong number). `home_insurance` is a yearly question so it reads a yearly series and uses a new `prefillYear` copy key ("a year") instead of "a month". No conversion or rounding is done.

**3. Announcement.** The plan's LayerStack test asked LayerStack to announce "Purpose questions added". CheckScreen (05.3-24) already announces "{layer} questions added" from the same layer list, so repeating it would double-speak; LayerStack tests assert visibility instead.

**4. Figures are not line-clamped.** "Figures one line" is met by wrapping-safe layout without `numberOfLines` (the text-fit guard bans clamps); the matrix test passes with `clampCount: 0`. No fitAllow entries were needed; `fitAllow.ts` exists with empty lists.

**5. Tax due date field** (tuition/tax preset `due_date`) is a plain ISO text field (`YYYY-MM-DD`), stored under `L4.due_date` only when valid; there is no date picker in the kit yet.

## Known limitations

- Custom item types and custom purposes are not wired (the settings source carries no custom options, per 05.3-24 hand-off); a custom item type shows no costs card.
- The card-rule note is shown on the payment plan card only, not repeated at the foot of the costs card.
- `renderLayers` does not pass a read-only flag; decided checks ignore edits in `useV3CheckDraft`.
