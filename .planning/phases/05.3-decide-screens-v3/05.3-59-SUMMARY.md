# Phase 05.3 Plan 59: The answer names the answers it rests on Summary

When a result rests on the user's own readiness answers (readiness.waived, this month's paid-by-other dues, or always-other series), one quiet note under the hero names them ("Netflix counted as paid by someone else." or "Rests on 2 of your answers.") and opens the confidence sheet. There each answer is listed once with how it was counted and its own "Ask again", which undoes it through 05.3-56's clearWaiver.

## What was built

- **waiverNote.ts** (pure, `src/features/decide/v3/model/`)
  - `waiverRows(waived, paidByOther, alwaysOther, thisMonth)` builds one `WaiverRow` per waiver (key = kind plus its fields). `paidByOther` entries become `paid_by_other` (series + date) or `always_other` waivers. Each `alwaysOther` series becomes an `always_other` row, even when it is in neither waived nor paidByOther (the blocker case: October's Netflix recorded paid).
  - `effectKey`: `notCounted` for a paid_by_other row dated in thisMonth, `alwaysNotCounted` for every always_other row (D-31), else null.
  - Each row has `textKey` (sheet text), `shortKey` (note text), `params` (name / date / month, unformatted), `waiver` and `name`. A null name leaves `params.name` out, and the UI uses `WAIVER_UNNAMED_KEY` ("A payment").
  - `waiverNote(rows)`: null for none, `note_one` with `params.text = { key: shortKey, params }` for one, `note_other` with `count` for more.
- **Copy** (`decide.v3.ui.confidence.waiver.*`): the plan's exact strings, plus `always_other_short`. Nothing says the figures still include the bill.
- **ConfidenceSheetV3**: new optional props `waivers`, `format` and `onAskAgain`. After the reasons, with a line1 top rule, comes the heading (label role, inkDim), then each row: one accessible text View (row text, plus the effect line in s13_5 inkDim; label "text. effect"), followed by its own `Ask again` Pressable (role button, label "Ask again: {{text}}", minHeight touchMin, inkMuted). With no waivers the sheet is exactly as before. Exports `waiverText(t, f, key, params)`.
- **AnswerScreen**: computes rows from `result.readiness?.waived`, `evaluation.month.paidByOther ?? []`, `evaluation.month.alwaysOther ?? []` and `evaluation.month.month`. It renders the note as a quiet Pressable (label role at meta size, inkMuted, minHeight touchMin, marginTop gapSm) right after the hero inside the Rise wrapper, and passes rows, `f` and `onAskAgain = (w) => clearWaiver(w.waiver, w.name)` to the sheet. The confidence level and chip are unchanged. Tokens only.

## Deviations from Plan

### Interpretations

1. **always_other_short added.** The plan's copy list has only `paid_by_other_short` for the note. With a single always-other answer, the long text would read "Netflix: counted as always paid by someone else.". The new key reads "Netflix counted as always paid by someone else.", matching W8. It passes all the guards.
2. **WaiverRow gains `shortKey`, and waiverNote's `note_one` carries `params.text = { key, params }`.** The interface said `params: { text }` "where the card renders text from the row's textKey". The note needs the short form, so the row names its own short key, and the screen resolves it with the same `waiverText` helper the sheet uses.
3. **The sheet takes callbacks, not the hook.** ConfidenceSheetV3 takes `onAskAgain` and `format` instead of calling `useReadinessAnswer` / `useV3Format` itself. Both hooks read Supabase-backed queries, so the existing ConfidenceSheetV3 tests would have needed new mocks. AnswerScreen owns `clearWaiver(waiver, name)`, and its test spies on the mocked hook module (`mockClearWaiver`), as the plan asks.
4. **Fixture dates.** The plan's example row is 'Netflix, 3 Sep' with the notCounted line. notCounted applies only to the current month (2026-10 in the fixtures), so the tests use Netflix on 3 Oct for the effect line and Lunch on 21 Sep for the no-effect row.
5. **answerKit.tsx changed (not in files_modified).** `fullEv` accepts `readiness.waived` and a `month` override, and the kit exports `PBO_NETFLIX`, `WAIVED_LUNCH` and `READY_WITH`. Existing callers are unaffected.
6. **AnswerScreen.test.tsx's useReadinessAnswer mock** now routes `clearWaiver` to a module-level `mockClearWaiver` spy. No existing assertion changed.
7. **answerMatrix's useCheckV3 mock** returns a second stable value (two answers, fair confidence) while `mockWaivers` is true. The original cells use the original value unchanged.
