# Phase 05.3 Plan 13: Record as bought write path Summary

A pure v3 builder for Record as bought (rows, series, debt, decision from Purchase and Result only), a replay-safe `useRecordBought` mutation on `record_decide_go`, and a context plus shell provider so the record sheets reach it, Plan it and Not buying without touching the write layer.

## What was built

- `buildBoughtWrite`: day-one row (negative, one_off, category from purchase, only when dayOne > 0); a payment series for the instalment (weekly, fortnightly, monthly, quarterly, yearly; other cadences are refused); a different final payment becomes its own row after a shorter series; a `debts` row (my share of financed, apr text, minimum payment, secured, term months for monthly); a monthly running_cost series. Every amount goes through `myShareOf` (the engine's own share rounding, newly exported from the v3 barrel) and `assertSafeInteger`. Refusals (no purchase, no cash account, no debt category when financed, non-safe amounts, unmappable cadence, row/series caps) are tagged so `isBoughtRefusal` tells them from bugs.
- `useRecordBought`: ids and step id minted once; a second tap for the same check while one is pending returns null and sends nothing; a refusal returns null; tracks `decide_recorded {outcome:'bought'}` once. `canRecord` is a dry run.
- `registerRecordBoughtMutations` is wired into `registerMutationDefaults`, so a rehydrated paused write replays with the same ids.
- `V3RecordProvider` supplies `RecordMutationsContext` (inert default, stable value): every action saves `answer_v3` via `useSaveCheckAnswer` first.
- `coolingOffAt` moved to `coolingOff.ts`; decideGoAhead re-exports it, decideOutcome imports it directly (no decideGoAhead import left).

## Deviations from Plan

1. **[Rule 3 - Blocking] BoughtContext location.** Plan had recordMutations.ts `import type` from boughtWrite; depcruise failed on it (fx-fetch-never-from-reads follows type imports). The interface now lives in recordMutations.ts and boughtWrite.ts imports and re-exports it. The "only import type lines" acceptance check holds trivially (no import at all).
2. **[Rule 2] `aprText?: string | null` added to BoughtContext.** Neither Purchase nor Schedule carries the rate, but the debts row needs apr text; the caller supplies it.
3. **Failed-write label key not wired.** `recordFailedWrite` has no label-key field and `decide.v3.ui.record.failedBought` does not exist yet; the failure path reuses the existing `decide.toast.outcomeFailed` refusal toast and the standard failed-writes entry (entity decide_checks). A later copy plan can add the dedicated key.
4. **planIt reminder.** `reminderOn: false` passes `readyBy: null` to `useWaitAndSave` (no reminder), so ready_by is not stored in that case; month-only ready-by is stored as the first of that month.
5. Extra test file `boughtWrite.hook.test.tsx` (hook behaviour) beyond the plan's file list; the half-share golden test relies on allocate giving the extra cent to member 0.
