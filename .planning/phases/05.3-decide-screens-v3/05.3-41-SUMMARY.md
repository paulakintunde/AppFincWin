# Phase 05.3 Plan 41: Answer screen and route Summary

The Answer screen is assembled from the built parts: header, notices, hero or not-ready card or in-place question, refund tile, funding strip, facts, assumptions, needs-input card, links and the fixed action bar, behind `/decide/answer/[id]`.

## What was built

- **Route:** `app/(app)/decide/answer/[id].tsx` validates the id (`isUuid`, else `V3NotFound`), then `AnswerRoute` wraps `AnswerScreen` in `V3Gate` and `V3RecordProvider`. The route is not registered in `_layout.tsx` (plan 43 owns that).
- **Header:** the round back control ("Back to the check"), the "{Item} · {price}" title as one "Change details" button back to the check, and the "B{n}" badge with the label "Band {n}".
- **Question registry:** `renderQuestionBody` maps all seven question codes and throws a `RangeError` for any other code.
- **Screen:**
  - Not ready (D-52): `NotReadyCard` replaces the hero, with no verdict, strip, facts or bar, and "Last saved answer: {chip}, {date}" when a stored answer exists.
  - Asking (D-07/D-08): `AskCard` replaces the hero and the strip, facts and bar give way to "Your answer is saved as you go." After the last answer the hero rises in (fade and lift, reduced-motion aware) and focus moves to it.
  - Decided (D-13): stored answer line, "Changed since you saved" when the live code differs, and only Check again and Check another price.
  - Open checks: `AnswerActionBar` opens `RecordSheet` for bought, plan and not-buying; `aprText` comes from the stored plan rate for financed purchases.
  - A recompute keeps the last answer on screen with the hero marked busy.
  - `decide_answer_shown` fires on first show and on each code change, never while not ready or asking.

## Required toast fix

`AskCard` now owns the one Undo toast. `askToastKey` gained `unspentConfirmed`, `incomePatternSaved`, `expectedIncomeSaved` and the unexplained "Saved" key (`decide.v3.ui.check.saved`, via the new `askToastText`). The four 05.3-33 bodies no longer toast; they only call `onSaved(stepId|null)`. Their tests assert no toast, and `AskCard` tests cover the new keys.

## Notes for the owner and later plans

- No separate "recorded" state was built on the screen: the record sheet is the confirmation (05.3-27). The sheet's `onClose` is the same for "Not yet" and "Back to Decide", so the screen decides whether to leave from the row status. If the cached row does not update immediately after a write, the user stays on the (now decided) Answer view instead of returning to the Decide tab. Worth a check on device.
- A decided check shows the live hero beside the stored answer line. If the owner prefers the hero to show only the stored answer, that is a small change in `AnswerScreen`.
- "Check again" on a decided check starts a new check and opens its answer (same as the refund tile).
- Plan 43 must register `decide/answer/[id]` in the Stack.
- Pre-existing lint warning in `NoticeTiles.tsx` (unused `radii`) left alone.
