# Phase 05.3 Plan 78: Delete a saved plan, then Undo

After Save the plan / Not buying the app records the check and pot versions the server wrote, so a delete pressed before any refetch is sent with the right versions and its Undo works.

## Delete-undo app cause
Confirmed as the plan predicted. `decideOutcome.ts` never called `recordWrittenVersion`, and its success only invalidated. The delete (`useRemoveDecision` -> `editCheck` goal branch in decideChecks.ts) resolves expected versions with `resolveExpectedVersion`, which only knows this device's recorded writes. With the cached check at version 1 and the server at 3 (answer save + outcome), the forward `apply_patches` was sent with 1 and conflicted. The reproduction test failed on exactly that (check expectedVersion 1, expected 3).

## Changes
- `decideOutcome.ts`: `DecideOutcomeVars.baseVersion` (the cached check version, passed from `useWaitAndSave` / `usePass` via an optional `version` on `CheckRef`). After the RPC, `recordWrittenVersion('decide_checks', checkId, [base, base + 1], checkVersion)` and, for a Wait goal, `recordWrittenVersion('savings_goals', goalId, [1], goalVersion)`. `onSuccess` patches the cached check and goal rows to those versions (existing invalidations kept).
- `decideChecks.ts` and `useRowActions.ts`: unchanged; the cause was not there.
- Test `savedPlanDeleteUndo.test.tsx`: real QueryClient and write queue, a fake server that keeps versions and refuses stale `expectedVersion`; asserts forward versions (check 3, goal 1), inverse versions (4, 2), the `apply_undo_step` call, and no failed write.
