<objective>
UAT gap (step 75 item 2, major), part 2 of 3: offer the user's own item types and purposes on Check a purchase, and let the user add them there.

Root cause: `ItemTypeChips` defaults `custom` to an empty list and `CheckScreen` never passes one; `PurposeBlock` calls `purposeOptions(check.purpose, NO_CUSTOM)` with a hard-coded empty list (05.3-24 / 05.3-40 known limits). Storage comes from 05.3-81.

Design choice (Claude's discretion): the options are created where they are used, on the check, through a small sheet; managing them (rename, delete) is 05.3-84. To keep `CheckScreen.tsx` untouched (other gap plans edit it), `ItemTypeChips` and `PurposeBlock` read the options themselves through `useOwnOptions()`.

Output: hook, sheet, chips and purpose block wired, copy, tests.
</objective>
