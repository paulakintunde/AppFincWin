# Phase 05.3 Plan 04: Snapshot-layer additions Summary

Pure snapshot additions for the 05.3 screens: pending-write count, one-pass `computeV3Many`, refund-stripped evaluation for D-13, check id through `reanswerSaved`, foreign-currency v2 conversion, and a property proof that extras sales_tax/deposit change nothing.

## What was built

- `buildV3Inputs(..., pendingWrites = 0)` sets `unsavedWrites`; negative, fractional or NaN counts throw RangeError. `computeV3` and `reanswerSaved` pass it through (`unsaved_changes` notice and confidence reason appear above 0).
- `computeV3Many(source, v3, rows, pendingWrites)` builds the snapshot and inputs once; each entry deep-equals `computeV3(..., id)`. Empty list gives an empty map and builds nothing.
- `stripRefunds` (pure, non-mutating) clears `refundOf` on every line; `computeV3WithoutRefunds` evaluates the same stored check on those inputs.
- `reanswerSaved(prev, source, v3, inputs, checkId = null, pendingWrites = 0)`.
- L-09 `foreignV2` in `checkOf`: a stored v2 check with a foreign currency converts price, one-off fees, extras, plan deposit/trade-in/quoted payment/fees and value amounts at the latest stored rate (integer minor units); no rate gives `price: null` (needs input).
- Property tests (200 runs each): extras sales_tax/deposit leave code, split and day-one unchanged; taxPercent > 0 raises `whole`; plan deposit > 0 lowers `schedule.financed`. The fixture uses a fully set-up person (unexplained answer and steady income confirmed) so the verdict is real, not needs_input.
