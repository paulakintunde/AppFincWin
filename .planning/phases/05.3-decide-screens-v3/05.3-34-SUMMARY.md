# Phase 05.3 Plan 34: Refine check-in Summary

The refine home card and review screen: every choice is an explicit, undoable write through the 05.2 hook the matching setup step uses; "keep" writes nothing.

## What was built

- **useRefine** builds `RefineInput` (setup done date, rough flag from `rough_as_of`, override date, last shown, snooze, unmarked regular-payment candidates, card habits) from the cached reads and calls `refine()`. `snoozed` is true while the stored Later date is in the future.
- **useRefineChoices** has an exhaustive `INTENTS` table (every `RefineCardKind`, typed and tested) saying which of a card's two buttons is the write. Writes reuse: series amount edit ('Pay updated' / 'seriesEdited'), `useSaveSetupStep` (everyday, steady amount, month marks), `useUnspent.confirm`, `useConfirmRegularCandidate` and `useAddDismissal` (new regular), PotSheet (saving bucket "Change it"), `openDebtSheet` (card not paid in full). Each write shows the Undo toast; analytics carry kind and choice only.
- **RefineCard**: accentTint1, radius 26, 18/20 padding; Review pushes `REFINE_HREF`; Later snoozes to today + 14 days through `useStampRefine.snooze` with an Undo toast.
- **RefineScreen / RefineItemCard**: header "k of n checked", dashed inkSoft1 to solid line2 borders, status chips, radio buttons, polite status announcement, "Done for now" until all are checked then "Done". Opening stamps `refine_last_at` once.

## Deviations from Plan

1. **[Rule 3 - Blocking] Series writes go through the setup sheet registry.** `useEditSeriesFrom` / `useSetSeriesStatus` reach `db/fxResolve`, which depcruise `fx-fetch-never-from-reads` forbids from `features/decide`. Added `updateSeriesAmount` and `pauseSeries` to `SetupSheetActions` (default: return null), registered in `src/shell/decide/SetupSheetHost.tsx`, and `RefineRoute` calls `useSetupSheetHost()`. `useEditSeriesFrom.editFrom` gained an optional `labelKey` (default 'seriesEdited') so the pay edit records 'payUpdated'. Existing `setupSheetHost.test.tsx` now mocks the series mutations and covers the two actions.
2. **[Rule 1] Card list is frozen on open.** Opening stamps `refine_last_at`, after which `refine()` reports nothing due (30-day gap); without freezing, the cards would vanish mid-review.
3. **Intent order.** `saving_bucket` lists "Looks right" first, so its intents are `['keep','update']`; the plan's "keep/update" wording is honoured by intent, not button position. For `card_not_paid_in_full` and `under_logged_month`, "Looks right" is the write (open the card sheet; leave the month out) and "Keep it" writes nothing.
4. `everyday_override_expiring` has no suggested figure, so "Use {{amount}}" shows the current figure and re-stamps `everyday_override_at` to today.
5. Documented in the plan: Later uses the stored snooze write (not a local preference).

## Known gaps (not stubs)

- **card_not_paid_in_full cannot fire yet:** the app stores no per-statement paid-in-full history, so `cardStatements` carries each card's stated habit with an empty history. The choice path is built and tested.
- `pay_stopped` "Lower it" pauses the pay series from today (user-led); `changing_income` is not emitted by the engine, its write is the steady amount.
- `RefineCard` is not mounted on the home screen (plan 39) and `decide/refine` is not registered in the layout Stack.Protected block (plan 43).
- Sheet-opening choices (saving bucket Change it, card Looks right) mark the card Updated on open; the sheet makes its own undoable save.
