# Phase 05.3 Plan 17: Check edit model Summary

Pure, immutable edit functions for the draft CheckV2, so each answer has one storage place: sales tax in `taxPercent`, deposit in `pay.deposit` (withExtra refuses both, M-08), L2/L6/L7 answers in value fields or `layerAnswers` only (D-18), and a plan kept in `L3.plan` across once/plan switches (I43).

## What was built

- `checkEdits.ts`: all twelve edits. Amounts must be non-negative safe integers, counts 0..600, useYears 0..200, percent 0..9999, otherwise RangeError. `withDeposit`/`withPlan` throw outside plan mode. `withPurpose` clears emergency when the purpose cannot use it; `withEmergency(true)` throws then. `withLayerAnswer` validates the key through `layerOfAnswerKey`; `undefined` removes.
- `costFields.ts`: preset questions in order minus `modelled_elsewhere` ids; `majorAssetFields` hides L6 legal/moving when the preset asks closing_costs/moving_costs (property gives both false, vehicle both true).
- `draftStatus.ts`: `draftStatus` and `priceProblem`.

## Verification

- `npx jest src/features/decide/v3/model` with coverage: 53 tests pass, 100% on all four measures for the three new files. Round-trip property uses 300 runs (JSON and in-memory); a second property proves no edit sequence puts sales_tax/deposit in extras.
- `npm run typecheck` clean; `npm run depcruise` no violations.
