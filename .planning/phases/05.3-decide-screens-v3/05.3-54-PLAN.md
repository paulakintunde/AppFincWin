## Research findings (2026-10-30, kept for the record)

(a) Can the app already say "this occurrence didn't happen"?
- `recurring_dismissals` / `dismissedKeys` mean "this payee is not regular" (offerKey, no date). They cannot say "this occurrence didn't happen".
- transactions.status is 'pending' | 'paid' | 'skipped', and a skipped row needs a series.
- Undoable mutations already exist: `useMarkPaid` and `useSkipOccurrence` (src/data/mutations/transactions.ts).
- Gap: buildV3Inputs drops skipped lines, while readiness builds its dues from the schedule. So skipping a bill does not settle its gap today. Fixed by `V3Inputs.skipped` (here, 05.3-55 and 05.3-63).

(b) Bills paid by another household member
- fetchTransactionsInRange filters by household_id only, so every member's rows are in the snapshot.
- settle() accepts a series-linked paid line, or an unlinked line with the same sign inside the amount band.
- So a bill another member marks paid or records already settles. Waivers are only needed for payers outside the app, or for untracked accounts.

(c) Where to store the answers
- No existing column fits:
  - counts_as is for pay only.
  - end_reason would end a real bill.
  - UnusualStep rebuilds month_marks.
  - income_types 'none' would throw away a real pay type.
- Owner decision D-28: waivers go in owner-private decide_answers (owner-only RLS; created_by cascades on account delete).
- This needs one migration (05.3-61) to widen decide_answers' kind and shape checks, and an owner-gated push (05.3-62).
- recurring_dismissals is NOT used: it is readable by the whole household and keeps rows after a member leaves.

```ts
export type ReadinessItemKind = 'bill' | 'pay' | 'spending' | 'late_start' | 'envelopes';
export interface ReadinessItem {
  readonly kind: ReadinessItemKind;
  readonly code: ReadinessCode;
  readonly month: YearMonth;          // envelopes: the asOf month
  readonly seriesId: string | null;   // bill, pay
  readonly envelopeId: string | null; // envelopes
  readonly lineId: string | null;     // a pending line of the SAME series for this occurrence, else null (B1)
  readonly name: string | null;       // pending line name, else series or envelope name, else null
  readonly amount: MinorUnits | null; // pending line amount, else series amount; null for spending, late_start, envelopes
  readonly date: LocalDate | null;    // bill/pay: due date; spending: newest paid everyday (null if none); late_start: earliest line date in that month (null if none); envelopes: null
}
export type ReadinessWaiver =
  | { readonly kind: 'paid_by_other'; readonly seriesId: string; readonly date: LocalDate }
  | { readonly kind: 'didnt_happen'; readonly seriesId: string; readonly date: LocalDate } // only when no same-series pending line exists to skip
  | { readonly kind: 'no_pay'; readonly seriesId: string; readonly date: LocalDate }       // same rule
  | { readonly kind: 'always_other'; readonly seriesId: string }
  | { readonly kind: 'income_elsewhere' }
  | { readonly kind: 'nothing_to_add'; readonly month: YearMonth; readonly at: LocalDate }
  | { readonly kind: 'month_complete'; readonly month: YearMonth; readonly at: LocalDate }
  | { readonly kind: 'start_from'; readonly month: YearMonth };
export type ReadinessWaiverKind = ReadinessWaiver['kind'];
export interface WaivedItem { readonly item: ReadinessItem; readonly by: ReadinessWaiverKind; readonly waiver: ReadinessWaiver }
export interface SkippedOccurrence { readonly seriesId: string; readonly date: LocalDate }
export interface Readiness { readonly ready: boolean; readonly missing: readonly ReadinessCode[]; readonly items?: readonly ReadinessItem[]; readonly waived?: readonly WaivedItem[] } // always set by readinessOf; optional so UI fixtures stay valid
```

      - When nothing matches: lineId null, name = series.name ?? null, amount = the series amount.

    - Ordering of items and waived: month (prev, then ym, then envelopes), then kind (late_start, pay, bill, spending, envelopes), then date, then seriesId or envelopeId. Plain string order, never localeCompare.
    - missing = sorted unique codes of the remaining items. ready = items.length === 0.
