## Research findings (recorded for D-24, 2026-10-30)

(a) What "this occurrence didn't happen" looks like today.
- `recurring_dismissals` / `V3Inputs.dismissedKeys` do NOT express it. A dismissal is "this payee is not a regular payment", keyed by the detector's offerKey (name|currency|sign). It hides a candidate series and has no date.
- transactions.status is 'pending' | 'paid' | 'skipped' (migration 20260926000200). A constraint requires a skipped row to belong to a series. The materialiser never recreates a skipped occurrence.
- Existing undoable mutations in src/data/mutations/transactions.ts: `useMarkPaid().markPaid(row, ownerId, today, adjust?)` (status 'paid', date = due date or today if earlier, undo label 'markedPaid') and `useSkipOccurrence().skip(row, ownerId)` (status 'skipped', undo label 'skipped').
- Gap: buildV3Inputs drops skipped lines (`if (l.status === 'skipped') return [];`), but readiness builds bill dues from the series schedule. So a skipped bill today still shows as unpaid, and skipping cannot settle a readiness item. This plan adds `V3Inputs.skipped`; 05.3-55 fills it.
- decide_answers has a 'pay_arrival' kind (key '<series>:<date>', bool), but its kind and shape are fixed by CHECK constraints. Adding kinds would need a migration, so it is not used for waivers.

(b) How a bill paid by another household member counts today.
- fetchTransactionsInRange filters on household_id only (no created_by), so the Decide snapshot holds every member's rows on live accounts. readiness's paidLines and settle() match a due by a series-linked paid line, or by an unlinked paid line with the same sign and amount within AMOUNT_TOLERANCE_DIVISOR, dated within the series window.
- So a bill another member marks paid, or records with a matching amount, already settles it. Waivers are needed only when the payer is outside the app, or pays from an untracked account, or nobody records it.

(c) Where the answers can be stored without a migration.
- recurring_series.counts_as ('available' | 'kept', pay only) and end_reason ('stopped' | 'paused') do not fit. Ending a series would remove a real bill from the forecast.
- decide_settings.month_marks (jsonb) holds month typicality, and UnusualStep rebuilds it keeping only 'out'/'half' values, so other keys would be wiped. income_types 'none' would throw away a real pay type.
- recurring_dismissals takes any payee_key of 1 to 200 characters, is soft-deletable (Undo works), has add and remove mutations with undo steps, and already carries a namespaced per-person answer: 'not-pay:<uid>:<key>' (05.2-66, "No migration", the matcher trusts created_by). The waivers follow that pattern. **No migration is needed.** The undo label_key column accepts any 1 to 40 letter key, so new undo labels need no migration either.

```ts
export type ReadinessItemKind = 'bill' | 'pay' | 'spending' | 'late_start' | 'envelopes';
export interface ReadinessItem {
  readonly kind: ReadinessItemKind;
  readonly code: ReadinessCode;
  readonly month: YearMonth;          // envelopes: the asOf month
  readonly seriesId: string | null;   // bill, pay
  readonly lineId: string | null;     // the pending line for this occurrence, else null
  readonly name: string | null;       // pending line name, else series name, else null
  readonly amount: MinorUnits | null; // pending line amount, else series amount; null for spending, late_start, envelopes
  readonly date: LocalDate | null;    // bill/pay: due date; spending: newest paid everyday date (null when none); late_start: earliest line date in that month (null when none); envelopes: null
}
export type ReadinessWaiver =
  | { readonly kind: 'paid_by_other'; readonly seriesId: string; readonly date: LocalDate }  // "Someone else paid it"
  | { readonly kind: 'didnt_happen'; readonly seriesId: string; readonly date: LocalDate }   // "It didn't happen" when no pending line exists to skip
  | { readonly kind: 'no_pay'; readonly seriesId: string; readonly date: LocalDate }         // "No pay this month" when no pending line exists to skip
  | { readonly kind: 'always_other'; readonly seriesId: string }                             // "Someone else always pays this"
  | { readonly kind: 'income_elsewhere' }                                                     // "My money comes from elsewhere"
  | { readonly kind: 'nothing_to_add'; readonly month: YearMonth; readonly at: LocalDate }   // "Nothing else to add"
  | { readonly kind: 'month_complete'; readonly month: YearMonth; readonly at: LocalDate }   // "<Month> is complete as it is"
  | { readonly kind: 'start_from'; readonly month: YearMonth };                              // "Start Decide from this month" (late start)
export type ReadinessWaiverKind = ReadinessWaiver['kind'];
export interface WaivedItem { readonly item: ReadinessItem; readonly by: ReadinessWaiverKind; readonly waiver: ReadinessWaiver } // the waiver that settled it (first in precedence), so the UI can name and clear it
export interface SkippedOccurrence { readonly seriesId: string; readonly date: LocalDate }
export interface Readiness { readonly ready: boolean; readonly missing: readonly ReadinessCode[]; readonly items?: readonly ReadinessItem[]; readonly waived?: readonly WaivedItem[] } // items/waived: always set by readinessOf; optional so existing UI fixtures stay valid
```
