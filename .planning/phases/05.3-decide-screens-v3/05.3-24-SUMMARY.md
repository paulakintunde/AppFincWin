# Phase 05.3 Plan 24: Check a purchase core Summary

The v3 Check screen core: a route that validates its id and focus, an autosaving draft hook, and the item/price, band chip, item-type and how-pay controls with a fixed "Check it" bar that writes the stored answer only on press.

## What was built

- **Route** `/decide/purchase/[id]`: `isUuid` else `V3NotFound`; only `focus=price` passes; body wrapped in `V3Gate`.
- **useV3CheckDraft(id)**: state starts from `emptyCheck()` or the stored row; first edit calls `useCreateCheck` once (kind buy, `toStoredV2`, furthestStep 1) and fires `decide_check_started` (no properties); later edits debounce 400 ms into `useSaveCheckDraft`; flushes on unmount and on app background; holds the first edit until account ids resolve; `commit(result)` is the only caller of `useSaveCheckAnswer` (`seenOf(result)`); decided checks ignore edits. Save status comes from the newest create/save mutation via `draftStatus`.
- **CheckScreen**: header with save status (only offline / not saved announced), focusing body title, `ItemPriceFields` (3:2, stacked under rule S, price focus + select for D-19 through the MoneyInput ref), `BandChip` (polite live region keyed on band number, 150 ms settle, compact range from `HomeThresholds`), `ItemTypeChips` (General default, retired type read-only), `PayToggle`, `renderLayers` slot, reassurance tile (hidden on `no_setup` or not ready), fixed bar with the reason above a disabled `Check it`; revealed layers announced politely.
- Edits go through 05.3-17 `withPrice / withItemType / withPayMode`.

## Deviations from Plan

- **[Rule 3] `useLooseT.ts` added**: typed i18n keys reject keys assembled at run time (band layer words, item-type labels, save status). A 10-line helper mirrors `useDynamicT`. No copy keys were added; all `decide.v3.ui.check.*` and `band.*` keys already existed.
- **Price focus** uses `inputRef` + `focus()` + `setSelection` instead of editing the shared `MoneyInput` (avoids touching a file other plans may edit).

## Known Stubs / hand-off

- Custom item types: `customLabels` is empty (settings `custom_options` is not wired by the settings source yet), so only presets plus a stored retired type show. The chip row already supports custom labels via the `custom` prop.
- Evaluation is null until the draft row exists in the checks cache (created on the first edit), so the band chip and Check it wait for the first edit to land; before that the chip is hidden.
- "Price above the engine range" inline text (`exceeds_range`) is not shown on this screen; only the price-needed reason is (above the bar, per UI-SPEC item 8).
- `renderLayers` args: `{ check, evaluation, edit }` for 05.3-40 / 05.3-42.
