## Findings the planner must act on (found while mapping)

1. **`readiness.missing` order and `verdictTable` keys:** the UI view-models import only from the `@/engine/decide/v3` barrel (depcruise `decide-engine-barrel-only`). `verdictRowFor`, `VERDICT_TABLE`, `NOTICE_KEYS`, `FACT_KEYS`, `MISSING_KEYS`, `READINESS_KEYS` live in `src/engine/decide/v3/copy/verdictTable.ts` and `decideCopy.test.ts` imports them by relative path, which is allowed only in tests. Confirm each is in `v3/index.ts` and `v3/__tests__/barrel.test.ts` before a feature file uses it; add the missing ones there first (Wave 0).
2. **`useDecideV3()` evaluates an empty check (`computeV3(source, v3, {})`, `src/data/queries/decideV3.ts:88`).** The per-check hook (`useCheckV3(checkId)`) must be a sibling that copies the read composition (lines 61-89) but passes the check's `inputs` and `checkId`. The `resultFor*` delegates drop `checkId` (`computeV3.ts:63-65`), so call `computeV3` directly.
3. **`guard_decide_check` only locks `inputs, name, furthest_step, kind` on a decided check** (`20261016000100_decide_tables.sql:55-76`). A new `answer_v3` column is NOT locked by it, so the client can write the stored answer on a decided check with a plain column update. No guard change is needed. The insert/update grants (lines 93-96) must be restated with the new column.
4. **`answer_v3` shape:** D-16 says "the six answer codes". `reanswerSaved(prev: SeenV3 | LegacyState | null, ...)` and `changeSinceLooked` take a `SeenV3` (`{v:3, code, variant, readyBy, unspentAfter, lineFacts}`), not a bare code. A `text` column with a six-code CHECK gives the chip and "Last saved answer" but cannot give "Changed since you saved" reasons. A `jsonb` column holding `SeenV3` with `check (answer_v3 is null or answer_v3->>'code' in (...))` is the safe superset. Planner picks; the pgTAP file must cover whichever is chosen. Do not derive from `verdict_at_decision` (D-16).
5. **Existing v3 engine files:** `src/engine/decide/v3/month/refunds.ts` and `refine.ts` and their tests already exist (05.2). D-13's "strip the refund links" builder is the only new pure piece; the shadow generator has a test-only `withoutRefundLinks` (`__tests__/shadow/generateNearLine.ts`) to copy from.
6. **D-12 basis mismatch is real:** `judge.ts:97 readyMonth(month, price, unspent)` is called with `p.dayOne` and `available.unspent` (lines 152, 171, 180), while `futures.ts:insteadFutures` calls `buyLater` with `purchase.whole` and `funds.unspent.available ?? value`. A property test must assert equality at lever 0 across the shadow histories.
