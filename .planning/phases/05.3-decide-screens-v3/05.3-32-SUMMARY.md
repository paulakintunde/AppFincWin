# Phase 05.3 Plan 32: In-place question card and first three bodies Summary

The Decide question card (D-07/D-08) plus account-use (with fund variant), pay-arrival and low-month-cover bodies, all saving through the 05.2 undoable mutations with Undo.

## What was built

- **AskCard**: surface card (radius 26, cardPadLg, line2 border), eyebrow "One thing first", the catalogue question (money, account name, date and month formatted via useV3Format), the body, and "and 1 more question" / "and N more questions". The View carries the group label "Question k of n. {question}". Focus moves to the question on mount and when the question changes; after a save with more queued, the next question's arrival is announced "Saved. {next}"; with none left, `onDone()`. Each save: Undo toast (when the step id is not null) and one `decide_question_answered { missing }`.
- **Toast labels** (`askToastKey`): accountUseSaved, emergencySaved (fund variant), payArrivalSaved, answerSaved (everything else, including 05.3-33's bodies unless it adds more).
- **AccountUseBody**: four rows; Everyday and Savings save at once; A mix and Kept for one thing open the 05.2 second views in the card with Back / "Save account use". Fund variant: radio list of accounts from `useEmergencyFundForm('sheet')` and "Save fund account" (useSaveEmergencyFund with the D-04 linkUse).
- **PayArrivalBody**: saves `{kind:'pay_arrival', seriesId, payDate, arrived}` from `question.pay`; null pay disables both buttons.
- **VolatileCoverBody**: saves `{kind:'volatile_cover', checkId, covers}`; shows the "only your answer" note.

## Deviations from Plan

**1. [Rule 3 - 05.2 file touched, as the plan allowed]** `src/features/decide/setup/AccountUseSheet.tsx`: the body was only reachable inside its Sheet, so it was extracted into an exported `AccountUseFields` (props `account, balance, onSaved, onCancel, onDirtyChange, inline`). The Sheet now wraps it and passes the same behaviour (save, toast, close). `inline` mode: Everyday/Savings save at once, no Keep/Save row on the first view, second views read Back / Save account use, and the toast is left to the caller. 05.2 setup tests (accountUse, emergencyFund and the rest of setup/) still pass.

**2. [Design] Toast ownership**: the plan text puts the toast in AskCard's onSaved but lists a per-body undo-label assertion. The card shows the toast; body tests assert `onSaved(stepId)` and `askToastKey(question)`; AskCard.test asserts the toast payload.

**3. [Design] focusNode.ts**: focus is a small helper module so the test can observe it (findNodeHandle returns null under the test renderer).
