# Phase 05.3 Plan 19: Strip, facts, copy picker, assumptions Summary

Four pure view-models for the answer screen: a funding strip built from Result.split, a facts card, a notice/fact copy variant picker that guarantees D-11, D-46 and D-48 wording, and the assumptions line.

## What was built
- `copyPick.ts`: `noticeCopy`, `factCopy`, `OVER_RATE_TEXT = '999'`. Rate '9999' or 'above_max' reads `implied_rate_over` with 999; count 1 reads `_one`; lean-month figures read `_one` / `_over` with the absolute amount (integer negation); UI variants for income_from_expected, month_heading_short, line_crossed, emergency_used. Discriminator keys and nulls are dropped from params.
- `assumptions.ts`: `decide.v3.ui.answer.assumptions` (or `assumptionsTyped` on rough_figures) with `{amount: month.erest, date: last day of month}`.
- `funding.ts`: `fundingStrip` for one-off splits, fits_month left-after, not_yet uncovered, monthly_short, payday and periodic fits; null for needs_input. Returns an extra `uncovered` field.
- `factRows.ts`: figure rows for the seven figure facts, sentence rows via `factCopy`, quoted_differs tone warn, a coveredBy row at the end for not_yet with readyBy.

## Verification
- `npx jest src/features/decide/v3/model` with coverage: 12 suites, 81 tests, 100% on all model files.
- Tests named D-11, D-46, D-48 pass, including the May / -87000 case; a contract property checks every returned key resolves in en.ts and every param is a declared value key.
- Strip property tests: parts never negative and sum to the drawn total.
- `npm run typecheck` clean; `npm run depcruise` clean.
- No copy keys were changed, so the i18n guard tests are unaffected (the guard run was started but not awaited).

## Deviations from Plan
- TDD RED and GREEN were committed together per task (two commits), not as separate test and feat commits.
- Strip text equivalent: the model returns heading and parts only; the UI composes the spoken sentence from them with formatMoneyA11y.
- The `coveredBy` row has no `subKey` because the params for `coveredBySub` are not defined in this plan. The UI plan can add it.
- Factrow label keys under `decide.v3.ui.factRow.*` (monthLeftAfter, unspent, unspentFrom, emergencyUntouched, emergencyUsed, rebuild, envelopeUsed, unspentHeldBack, lowMonth, lowMonthMonthly) are asserted by exact string; they and the `decide.v3.ui.answer.*` keys are not in this base's en.ts and resolve later in 05.3-44.
