# Phase 05.3 Plan 116: Reachability grace for the online gate Summary

A short Supabase reachability blip on a working connection no longer pauses the write queue. A pure, timer-injected online gate (`src/data/sync/connectivity.ts`) makes a failed probe count as offline only after 10 s, while a lost connection is still offline at once. onlineManager and the `[sync-diag]` log use the same gate.

## Tasks

1. **Pure connectivity predicate and online gate.** Commits 3d51037a (test) and 1ff7b74e (feat).
   - `netClass(s)` returns `'offline'` when isConnected is false, `'unreachable'` when isInternetReachable is false, and `'online'` otherwise. null counts as online, so the app does not flash offline at boot.
   - `UNREACHABLE_GRACE_MS = 10_000`.
   - `createOnlineGate(setOnline, timers)` returns `{ update, isOnline, dispose }`.
     - online: cancels the timer and sets online at once.
     - offline: cancels the timer and sets offline at once.
     - unreachable while online: starts a single 10 s timer. Repeat reports do not restart it.
   - The module imports nothing from React or NetInfo.
2. **onlineManager and the sync log use the gate.** Commit 6fb162f4.
   - The NetInfo listener feeds `gate.update(state)`. It replays writes and refetches only when the report itself is `'online'`.
   - The focus path's `NetInfo.refresh()` result goes into the same gate. The error branch still resumes as before.
   - The TanStack cleanup disposes the gate. `resetOnlineManagerForTests` disposes it and sets it to null.
   - `recordOnlineChange(source, state, online, head)` logs `net: netClass(state)` and the gate's `online` value. It dedupes on the (net, online) pair, so the device log still shows every blip.

## Deviations from Plan

1. **[Rule 1 - test bug] Type error in Task 1 test.** `fns[0]()` failed tsc (possibly undefined). The fix asserts `fns` has length 1 and calls `fns[0]?.()`. It is committed together with Task 2.
2. **[Rule 3 - test harness] AppState subscription in onlineManager.test.ts.** The new grace describe block spies `AppState.addEventListener` to return `{ remove }`. Without it, re-registering the focus listener inside one suite throws on `undefined.remove()`. Production always gets a real subscription, so production code is unchanged here.
3. Behaviour detail: if every TanStack subscriber unsubscribes, TanStack runs the cleanup, which disposes the gate. The module still holds a reference to it for the focus path. A disposed gate keeps working; dispose only cancels a pending timer. The next subscribe creates a new gate.

No files outside `files_modified` were changed.
