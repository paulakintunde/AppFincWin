# Phase 05.3 Plan 18: Hero, action bar and confidence models Summary

Pure view-models for the answer hero (one mapping table filling every verdict placeholder from the Evaluation), the action bar (one primary per row) and the confidence chip, proven by a golden test over all engine cases rendered through real en.ts.

## What was built

- `hero.ts`: `heroModel` takes keys from `verdictRowFor(code, variant)` and fills month, left, lowMonth, short, fromMonth, after, date, months, readyMonth, monthly, used. Fallback bodies `notCoveredNoDate` and `emergencyNoRebuild` when the engine has no value. Also `heroHaptic` (warning for not_yet, monthly_short, emergency_use on first appearance or code change) and `answerShownProps` (code, variant or 'none', band; no money).
- `actionBar.ts`: left is always "Record as bought"; fits_* and emergency_use make it primary; payday makes "Remind me {date}" primary; not_covered makes "Plan it" primary; monthly_short makes "Save the plan" primary; needs_input has zero primaries and `helpInBody: true`.
- `confidence.ts`: hidden when firm; "Rough, from your figures" when `rough_figures` is a reason; one key per reason.

## Verification

- hero.golden.test: 75 engine cases (scenarios22, extra-d18, refunds, variable-income) render title, chip and body through i18next with real en.ts; no `{{`, `undefined` or `NaN`.
- Unit tests at 100% coverage on the three files; `npm run depcruise` clean; `npm run typecheck` clean.

## Deviations from Plan

No other deviations. No copy keys were added; all `decide.v3.ui.*` keys already existed.
