## Deviations from Plan

**1. [Rule 3 - Blocking] No setState inside useEffect for the reset.** The plan said to clear `justAdded` in a `useEffect`. The repo's lint rule `react-hooks/set-state-in-effect` fails that as an error. Instead, both components clear it while rendering (`if (justAdded !== null && live.some(c => c.id === justAdded.id)) setJustAdded(null)`), which is React's documented way to adjust state when inputs change. The behaviour is the same: the label is dropped as soon as the cache lists the id. Files: ItemTypeChips.tsx, PurposeBlock.tsx (commit 3f2f4ea7).

**2. [Test fix] PurposeBlock expectation.** The first draft expected `own.add` to get the untrimmed name. OwnOptionSheet already trims before calling onSave, so the test now expects `'For the kids'`.

No files outside files_modified were touched. useOwnOptions.ts is unchanged (05.3-120 owns it).
