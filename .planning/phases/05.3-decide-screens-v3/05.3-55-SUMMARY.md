# Phase 05.3 Plan 55: Readiness fed from real Decide data Summary

The owner's private readiness answers, the skipped occurrences in the source rows, and the row names now reach V3Inputs through settingsSourceOf and buildV3Inputs. No new query was added. On the owner's evidence source (asOf 2026-10-30), computeV3 now names all four gaps: the pay, Netflix and Lunch in September, each with its pending lineId, plus October spending dated Oct 14.

## What was built

- **settingsSource.ts / types.ts:** `V3SettingsSource.waivers?: ReadinessWaiver[]`, filled with `waiversFromAnswers(input.answers)`. The answers come from `useDecideAnswers(userId, householdId)`, which is owner-scoped, and RLS also requires created_by = auth.uid(). `SettingsSourceInput` and its callers did not change. `V3AnswerLite.kind` already listed `'readiness_waiver'` (05.3-54). Only the comment was updated.
- **buildSnapshot.ts (type only):** `SnapshotRow` and `SnapshotSource.series` gain `Partial<Pick<..., 'name'>>`. `GoalSource` gains `name?: string | null`.
- **buildV3Inputs.ts:**
  - `nameOf` turns an empty or missing name into null. `V3Series.name` comes from the recurring_series row, `V3Line.name` from the transaction row, and `Envelope.name` from the savings_goals row.
  - `skipped` comes from `source.rows` with status 'skipped', a non-null recurring_series_id and a null deleted_at, using local_date (W2). `months` is unchanged, and a test checks this.
  - The return gains `waivers: v3?.waivers ?? []` and `skipped`. `withoutMoney` spreads the settings, so waivers survive CR-03. payArrivalsOf, expectedIncomeOf and heldBridgesOf already filter by kind, and a test now proves they ignore readiness_waiver rows.
