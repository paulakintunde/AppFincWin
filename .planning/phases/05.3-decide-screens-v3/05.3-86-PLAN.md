<objective>
UAT gap (step 39, minor): "Back from a check returns to Decide home in one step." On the device each Change details + Check it added two history entries, so Back walked through every earlier answer and form, then left the app.

Root cause: every hop between the check and its answer is a `router.push` through `pushOnce`:
- `CheckScreen.onCheck` (src/features/decide/v3/check/CheckScreen.tsx): `pushOnce(answerHref(id))`;
- `AnswerHeader` title press "Change details" (src/features/decide/v3/answer/AnswerHeader.tsx): `pushOnce(purchaseHref(checkId))`;
- `AnswerScreen` `anotherPrice` / `checkAgain` (src/features/decide/v3/answer/AnswerScreen.tsx): `pushOnce(purchaseHref(newId, { focus: 'price' }))` / `pushOnce(answerHref(newId))`.
The outer Stack therefore grows check, answer, check, answer, ... and the back history (`BackHistoryProvider.goBack` -> `stackBack` -> `router.back()`) pops one screen per press.

Fix: these four hops replace the current screen (`router.replace`) instead of pushing. The back history already copes: a replace is observed as a same-depth transition, and the next `router.back()` pops to home, where `popTo` drops the stale entry (src/shell/backHistory/backHistoryReducer.ts).
Output: `replaceOnce`, four call sites, tests.
Coordination: CheckScreen.tsx and AnswerScreen.tsx may also be edited by group A gap plans (66-79); change only the lines named here.
</objective>
