# Phase 05.3 Plan 43: Entry-point wiring Summary

Every Decide entry point now reaches the v3 screens for accounts with `useDecideAccess().v3`, and lands on Coming soon for everyone else. `DECIDE_V3` and `DECIDE_OPEN` stay false.

## What changed

- `app/(app)/_layout.tsx`: new `<Stack.Protected guard={access.v3}>` block with decide/purchase/[id], answer/[id], plan/[id], instead/[id], worked, help/[id], refine, decisions, envelopes. The old `guard={DECIDE_OPEN}` block is untouched. The notification observer is enabled by `access.v3 && consentAnswered(...)`.
- `app/(app)/(tabs)/decide.tsx`: ladder `!v3 ? (loading ? V3Skeleton : ComingSoon) : HomeScreen`; the DevShadowExport block is verbatim.
- `app/(app)/(tabs)/_layout.tsx`: `DecideShellHost` mounts only when `access.v3`.
- `DecideShellHost`: the quick action runs `openV3NewCheck()`.
- `useNotificationObserver`: a reminder tap pushes `answerHref(id)`; id validation is unchanged.

## Tests

- `entryGate.test.tsx`: with v2, the nine routes are guarded false, the observer is off, the old check route stays under a false guard (and `DECIDE_OPEN` is false), the tab shows Coming soon, no `newCheck` quick action registers, and a deep link to each of the nine routes redirects to `/decide`. With v3, the reverse.
- `tabRoot.test.tsx`: Coming soon / skeleton while loading / HomeScreen / DevShadowExport.
- `oneAnswer.test.tsx` (criterion 1): with the real `useChecksV3` and `useCheckV3` over faked read hooks and the demo source, the home list code, the code behind the Answer hero chip and useCheckV3's code are equal for a waiting check, an open draft and a check carrying a volatile-cover answer.
- Updated: `useNotificationObserver.test.tsx` (answer href), `DecideComingSoonScreen.test.tsx` (mocks the v3 home and profile), `decideSetupPage.test.tsx` (the Decide-tab block moved to tabRoot.test).

## Deviations from Plan

1. **[Rule 3 - Blocking] YouScreen not edited.** You > Add already shows only quick actions that are registered, and `DecideShellHost` (the only registrant of `newCheck`) is now gated on `access.v3`, so the New check item is absent without a change to YouScreen. entryGate asserts no `newCheck` registration under v2.
2. **[Rule 3] Existing tests adjusted** for the new tab-root imports (they pulled in Supabase env config through the real HomeScreen/useProfile).
3. oneAnswer renders the real `AnswerHero` model (`heroModel`) and `savedPlanRow` model rather than mounting the whole AnswerScreen and SavedPlanRow, which need the record, router and mutation providers; the codes come from the same hooks those screens call.
