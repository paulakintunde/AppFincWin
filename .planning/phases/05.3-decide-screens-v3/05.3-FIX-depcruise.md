# 05.3 fix: readiness writes broke `fx-fetch-never-from-reads`

**Kind:** Rule 3 deviation fix (blocking: `npm run depcruise` failed). No plan file.
**Introduced by:** 05.3-56 (useReadinessAnswer), 05.3-58 and 05.3-59 (its callers).

## Problem

`npm run depcruise` failed the rule `fx-fetch-never-from-reads` ("read hooks and the engine (incl. Decide) must not reach
the fetch door, even through another module"). The chain was:

`src/features/decide/v3/ready/useReadinessAnswer.ts` -> `src/data/mutations/transactions.ts` (useMarkPaid,
useSkipOccurrence) -> `transactionCache.ts` -> `src/db/fxResolve.ts`.

NotReadyCard, HomeScreen and AnswerScreen (Ask again) reached it through useReadinessAnswer.

## Fix

The same split as the record writes (05.3-13 V3RecordProvider / RecordMutationsContext):

- `src/shell/decide/ReadinessAnswerProvider.tsx` (new): the old hook body, unchanged, as a private
  `useReadinessAnswerWrites()`, plus `ReadinessAnswerProvider`. The provider hands one stable context value whose calls
  read the latest render through a ref, as V3RecordProvider does.
- `src/features/decide/v3/ready/useReadinessAnswer.ts`: now types (`ReadinessAction`, `ReadinessSettled`,
  `ReadinessAnswer`), `ReadinessAnswerContext` and the `useReadinessAnswer()` consumer only. It imports no mutation. With no
  provider mounted the default is inert: an answer settles `false` and Ask again does nothing, matching the
  RecordMutationsContext convention (no dev throw).
- Mounted where the routes are composed in the shell:
  - `src/shell/decide/v3/AnswerRoute.tsx`: `V3Gate > V3RecordProvider > ReadinessAnswerProvider > AnswerScreen`.
  - `src/shell/decide/v3/HomeRoute.tsx` (new): `ReadinessAnswerProvider > HomeScreen`. `app/(app)/(tabs)/decide.tsx`
    renders `<HomeRoute />` in the v3 branch instead of `<HomeScreen />`.
- The consumer kept its module path, so every `jest.mock('../ready/useReadinessAnswer')` in the screen tests already points
  at the new consumer and needed no change.
- `useReadinessAnswer.test.tsx` moved to `src/shell/decide/__tests__/ReadinessAnswerProvider.test.tsx`. It renders the
  consumer inside the provider, so it tests both, and gains one case: the consumer with no provider writes nothing,
  shows no toast, does not navigate and settles every answer false.

No behaviour, copy or engine changes. DECIDE flags unchanged (false).
