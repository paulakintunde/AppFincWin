<objective>
Stop the sticky Decide header covering rows and links, and stop content sliding under the status bar (UAT gap 31).

Root cause (verified): TabRootScreen (src/shell/screen/TabRootScreen.tsx) renders the compact header as a sibling AFTER the ScrollView, and CompactHeader (src/shell/header/CompactHeader.tsx) is `position: 'absolute', top: 0` with `pointerEvents='auto'` once visible, so it overlays whatever content has scrolled under it and takes those taps. Between scroll 0 and the threshold (`compactThreshold` in useTabRootChrome.tsx) nothing paints the status-bar area, so the large header scrolls under the status bar.
Design (Claude's discretion, layout only, existing tokens): an opt-in `compactInFlow` mode used by Decide v3 home only:
- a fixed backdrop View of height `insets.top` (`colors.canvas`) above the ScrollView;
- the compact header rendered IN FLOW between the backdrop and the ScrollView while visible (no absolute position; its own top padding without the inset);
- when it appears or disappears, the scroll offset moves by its measured height in the same frame (scrollTo, animated false) so the content does not jump;
- hysteresis: show above the threshold, hide below threshold minus the header height, so the compensation cannot flip it back.
</objective>
