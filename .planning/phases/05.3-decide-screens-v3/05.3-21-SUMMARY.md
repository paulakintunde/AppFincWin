## How D-12 lever 0 is handled (hand-off from 05.3-05)
- `explore` is called on the judge basis: `price = purchase.dayOne`, `unspent = max(0, funds.unspent.available ?? value)`, `answerWaits: true` when the code is `not_yet`.
- One-off purchases: no adjustment. Explorer month at lever 0 equals the answer's ready month (tested over every not-covered variable-income golden, which includes the seasonal earner Ines).
- Plan purchases (`purchase.monthly > 0`): the model computes the whole-month offset between the answer's ready month and the explorer's lever-0 month, shows the answer's month as the head, and applies the same offset to the slider result at every other lever (never earlier than next month; months count shifted the same way). So slider 0 always equals the answer, and moving the slider still moves the date by the explorer's own steps.
- Tests: `D-12 slider 0 equals the answer` (all not-covered goldens; asserts at least one seasonal and one plan purchase were checked) and `D-12 plan-purchase goldens stay anchored...` (head stays the answer's month with a lever on; more cut is never later).
- Seasonal picture: result key `decide.v3.ui.instead.thenSeasonal` (month only); steady: `...then`. A zero-month result also uses the month-only key.

## Deviations from Plan

**1. [Rule 1 - Bug] Total includes running costs.** The plan says the total row equals PlanCard.total and also that the mix (with running) sums to the total. PlanCard.total excludes running costs, so both cannot hold when running > 0. The screen lists a running-costs row above the total, so `total.amount = PlanCard.total + running x months`, and the exact lender-comparable figure is exposed as `planTotal === PlanCard.total` (tested, and `total.amount === PlanCard.total` when there are no running costs). Mix parts sum to `total.amount`. The UI-SPEC total label "Total over n months" therefore matches the rows shown.

**2. [Rule 3 - Blocking] Extra optional inputs.** planModel takes optional `rate` (the typed rate) and `deposit`, since neither is on Purchase or PlanCard. The rate is also taken from a quote's implied rate when none was typed. The down-payment row appears only when there is a deposit; it is part of the price and is not added to any total. Zero-valued tax/fees, interest and running mix parts are omitted. `cadenceWord` has a fourth value `other` for cadences with no catalogue word.

**3. Deposit zero figure.** `zeroFigure` is the 0% view's interest given up (0 for a one-off purchase; the avoided loan interest for a plan stream), with the whole 0% view exposed as `zeroView`.
