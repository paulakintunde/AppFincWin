<objective>
UAT gap (step 61, minor): "Other records shown during the walkthrough read correctly": the refund detail reads "Kind: Refund to Groceries" with status Paid; the line "pay … $83,823.64 / $84,149.21 below the pay on record" looks wrong; figures drift slightly with FX after reloads. (The fourth item, the New pot sheet account picker, is 05.3-87.)

Root cause 1 (status Paid): `rowTag` (src/engine/activity/tags.ts) sets `outflow = row.original_amount < 0 || refund`, so a refund, which is money in (positive original_amount), is tagged like spending: 'paid' when settled, 'due'/'overdue' when pending. `statusActionFor` (src/features/record/activity/detailRows.ts) uses `flowOf`, which returns 'out' for every refund (src/engine/activity/filters.ts, D-03: refunds never count as income), so the action reads "Mark as paid". The direction for the status word must come from the sign; flowOf stays as it is (D-03 still holds for the figures).

Root cause 2 (Kind copy): `activity.detail.kindRefund: 'Refund to {{category}}'` (src/i18n/locales/en.ts line ~860) reads as if the money went to the category.

Root cause 3 (pay line): `pay_capped_expected` (en.ts line ~3534) says "{{capped}} below the pay on record", but `capped` (src/engine/decide/v3/cash/path.ts, "Total pay withheld by the D-35 expected-income caps") is the TOTAL held back over the 90-day path, not a monthly gap, so a monthly pay of about $16,000 shows "$83,823.64 below". Copy fix only; the engine figure is correct.

Root cause 4 (FX drift): not a bug in the maths. Pay series and account balances in another currency are converted at the latest stored rate (src/features/decide/snapshot/conversion.ts `makeConverter` -> `convertLatest`), and `useFxLatest` refetches after an hour, so a new day's rate moves the figures slightly (the two pay lines above differ by 0.4%, a normal day's GBP/USD move). The old screens showed this as basis notes (05-42 D-37, `source.conversions`); the v3 screens never show it. Fix: say it on "How this was worked out".

Coordination: WorkedScreen.tsx and decideV3Ui/worked.ts are likely edited by group A plans (always-pays bill listing, last-day everyday). This plan adds one import and one JSX line to WorkedScreen.tsx and puts its copy in a new decideV3Ui/rates.ts.
</objective>
