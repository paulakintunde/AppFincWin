<objective>
UAT gap (step 24, cosmetic): "Money figures and band labels are formatted the same way everywhere." On the device "$150,055,124.01 breaks across two lines in 'What could I do instead?'; band labels mix '$100–$500' and 'US$20k–US$50k'."

Root cause 1: `useV3Format.money` (src/features/decide/v3/shared/useV3Format.ts) returns `heroAmountText(formatMoney(...)).text`. With the default limit of 10 characters, any longer amount ("$150,055,124.01" is 15) gets a zero-width space after each group separator (src/features/decide/v3/shared/heroAmountText.ts), which is a deliberate line-break point. Every v3 screen that prints `f.money(...)` (titles, FutureCard figures, sentences) can therefore break a long number. CONTEXT: "no numbers breaking across lines". The only intended break-at-separator user is the hero, and `MonthBarCard` already calls `heroAmountText` itself.

Root cause 2: `BandChip.edge()` (src/features/decide/v3/check/BandChip.tsx) formats a plain edge with `fmt.money` (the shipped formatter, "$500") but a compact edge with `new Intl.NumberFormat(locale, { style: 'currency', currency, maximumFractionDigits: 0 })` using the device locale, which in en-CA renders USD as "US$20". Two formatters, two symbols.

Output: unbreakable money text, a one-line shrink on FutureCard figures, one formatter for band edges, tests.
</objective>
