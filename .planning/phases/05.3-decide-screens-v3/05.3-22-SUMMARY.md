# Phase 05.3 Plan 22: Worked-out and refine models Summary

Pure view-models for "How this was worked out" (rows sum exactly to monthLeft) and for the refine home card, card list and 12-kind choice table.

## What was built

- `workedModel(ev, inputs, names?)`: six rows (pay, regular, loans, saving, everyday so far, still to come) with `deduct` flags, result row, last-six-months list with normal/half/out states, typical, basedOn, largest (only with 3+ months used), and the regular-payments list with an empty flag. Property test: rows always sum to `monthLeft`; Sam case gives 42500.
- `refineModel`: `REFINE_CHOICES` for all 12 `RefineCardKind` values, `refineHomeCard` (eyebrow three/new, body `_one`/`_other`, snooze and empty handling), `refineCards` (kicker/title/body keys, params, choices). Accepts either a `RefineResult` (`triggers`) or a single `trigger`.

Choice keys are full `decide.v3.ui.refine.*` keys that exist in the refine copy (a test checks each exists). No new copy was added.

## Deviations from Plan

**1. [Rule 1 - plan assumption wrong] Loan source.** The plan said loan minimums are part of billsPaid + billsDue. In `month/model.ts` debt minimums are in `setAside`, so the loans row is the sum of `debts[].minimum` (clamped to setAside) and saving is the remainder. Rows still sum to monthLeft.

**2. V3Series has no name.** `workedModel` takes an optional `names` map (series id to display name) and falls back to the id. The caller (screen plan) supplies names. Pay row `date` param is the confirmed pay series anchor date ('' when none); the UI formats it.

**3. Per-month left fallback.** When `incomePicture.months` has no entry, left is paid income-type lines (income, other_in, refund) minus paid out-type lines (spending, debt_payment, saved_invested, other_out), integer adds of absolute amounts. Only full past months are listed. "Half-logged" is a `half` mark or a `month_looks_under_logged` notice for a month not in monthsUsed.
