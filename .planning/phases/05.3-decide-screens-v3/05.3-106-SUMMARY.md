# Phase 05.3 Plan 106: Expected income question names the right month

The engine now lists which future months have no expected income (`uncoveredIncomeMonths`, exposed as `Evaluation.uncoveredIncome`), the "Expected money in for {Month}" question names the first of them, and "and N more" counts the rest. UAT gap 23, income part, is closed.

## Owner decision (Task 1)

future-only (owner, 2026-10-31, asked by the orchestrator before execution). Decide never asks expected income for the current month, only for months still to come. The current month is already worked out from money in so far plus pay still due (`payCapsOf`).

## What changed

- `needsInput.ts`: exported `uncoveredIncomeMonths(inputs, month, purchase)`; the D-35 rule drops the current month (the asOf month, the same one `dependsOnMonths` always includes). `needsInput` adds `expected_income_needed` exactly when the list is non-empty.
- `evaluate.ts`: `Evaluation.uncoveredIncome?` filled in `evaluateOnce` (carried through the stricter-of-two reading).
- `ask.ts`: `params.month` is the first listed month, `months` is the list, and `params.months` is its length. Falls back to this month when the list is absent (hand-built fixtures).
- Tests: existing D-35 tests updated to the new rule (this-month-only purchases no longer ask; scheduled purchases touching later months do); new helper tests (36-payment plan from 2026-11-30 starts at 2026-11; a confirmed 2026-11 moves the start to 2026-12; steady, no picture, no purchase give []); new `askExpectedIncome.test.ts` across a month boundary.
