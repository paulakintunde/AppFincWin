<objective>
A successful settings save no longer wipes a queued settings change from the cache (UAT gap 35, minor; cache part).

Root cause (05.3-UAT.md round 3): both decide_settings mutations write the server row straight into the cache on success (decideSetup.ts:176-179, decideSettings.ts:78-81) without re-applying edits still queued behind them. Each file's onError already rebuilds "server row + queued edits", but only from its own mutation key.
Output: one queued-patch helper over both keys, used in onSuccess and onError of both mutations, and a reproduction test. The chip's local fallback label is 05.3-118.
