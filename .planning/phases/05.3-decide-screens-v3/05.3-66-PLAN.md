Root cause (gap 2, cited): Plan it and Not buying record their undo step from the CLIENT
(`src/data/mutations/decideOutcome.ts` `recordOutcomeUndo` -> `recordUndoStepSafely` -> `insertUndoStep`). Clients can only
insert `id, label_key, label_params, ops` (20260926000500 `grant insert (...)`), so the step has `allow_system_keys = false`.
Its ops patch `decide_checks.status / decided_at / verdict_at_decision / wait_monthly / ready_by / cooling_off_at`, which
`apply_patches` allows only when `fincwin.undo_replay` is on (20261028001100 line 81 `v_system`, line 176). `undo_replay`
(20261030000100) turns the resulting 22023 "patches unknown column status" into a `conflict`, the client records it as a
"changed elsewhere" failed write (`src/data/mutations/undo.ts` `recordRefusal`) and the banner counts it (gap 8).
Record as bought works because `record_decide_go` writes its own step server-side with `allow_system_keys = true`
(20261016000300 line 344).

Root cause (gap 1, server half): `record_decide_outcome` (20261021000100 lines 244-249) inserts the Wait goal with no
`account_id`, and readiness requires every envelope to be linked (`src/engine/decide/v3/readiness.ts` `envelopeItems`),
so Decide turns "not ready" after every Save the plan.

Output: one additive migration with a new 4-argument overload, proven by pgTAP 78. No production push here (05.3-67).
