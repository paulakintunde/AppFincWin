# Phase 05.3 Plan 47: Undo for Plan it and Not buying Summary

Plan it and Not buying each record exactly one undo step through the existing apply_patches / undo_log path (no SQL), and the record sheet's done step offers Undo beside Back to Decide for all three outcomes.

## How it works

- `record_decide_outcome` returns only a status, so the step is built client-side after the RPC lands: the check's fresh version is read, and for Plan it the created goal's version too. Inverse ops: the check back to `status open` with decided_at, verdict_at_decision, wait_monthly, ready_by and cooling_off_at null (apply_patches allows these columns in undo replay), plus a goal soft-delete in the same step. Recorded with `recordUndoStepSafely` (queued on failure). A step that cannot be built never fails the saved decision.
- Step id is minted at call time. `save` resolves `{ reminder, stepId }`; `pass` returns the step id. An in-flight guard per check id means a double tap writes once and returns the same step id.
- New undo labels `planSaved` ("Plan saved · name") and `notBuyingSaved` ("Not buying · name"), with unnamed variants, added to UNDO_LABEL_KEYS, en.ts and the pinned label test (no existing key fit).
- Sheet: Undo uses the same `useUndo` path as the toast. On undo for Plan it / Not buying it also calls `cancelCheckReminders(row.id)`. Reconcile would clear a stale reminder for a reopened check eventually; this does it at once.
