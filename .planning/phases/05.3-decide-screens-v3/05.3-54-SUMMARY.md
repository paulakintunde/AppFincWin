# Phase 05.3 Plan 54: Named readiness items, waivers and skips Summary

readinessOf now returns named gap items (kind, code, month, series or envelope, same-series pending lineId, name, integer amount, date), settles them from the user's waivers and skipped occurrences into a `waived` list, and a pure waiverKeys module fixes the owner-private `readiness_waiver` decide_answers format.

## What was built

- **Types** (`src/engine/decide/v3/types.ts`): `ReadinessItemKind`, `ReadinessItem`, `ReadinessWaiver`, `ReadinessWaiverKind`, `WaivedItem`, `SkippedOccurrence`. `Readiness` gains optional `items` and `waived`. `V3Inputs` gains optional `waivers` and `skipped`. `V3Series`, `V3Line` and `Envelope` gain optional `name`. All are exported through the barrel's existing `export type * from './types'`, so barrel.test.ts needed no change.
- **readiness.ts**: split into `pastMonthItems`, `currentMonthItems`, `envelopeItems`, plus `namedGaps` (B1) and the waiver layer.
  - B1: lineId comes from one `settle()` call over pending lines with a non-null seriesId. Since settle only pairs a linked line with its own series, this equals the per-series run. A same-amount one-off never gives a lineId.
  - Skips become `skip|<series>|<date>` linked lines in the same settle call as the paid lines (bills), and settle pay occurrences. A skip of an unknown series is ignored.
  - Waivers with `at > asOf` are ignored. Precedence: start_from, month_complete, income_elsewhere, always_other, paid_by_other, didnt_happen, no_pay, nothing_to_add; then the latest `at`; then canonical JSON. This does not depend on input order.
  - The current-month spending clock counts a fresh nothing_to_add or month_complete `at` (within NEEDS_INPUT_ENTRY_AGE_DAYS).
  - Envelopes are never waived.
  - Sorting is plain string order on month, kind rank, date, then id.
- **waiverKeys.ts** (`src/features/decide/snapshot/v3/`): exports `READINESS_WAIVER_KIND`, `READINESS_WAIVER_KEY_RE` (the exact 05.3-61 regex), `waiverKeyOf`, `waiverAnswerShape`, `waiversFromAnswers` and `waiverAnswerFor`. It uses `import type` only.
- **decideAnswers.ts**: `DecideAnswerKind` gains `'readiness_waiver'` (type only).
