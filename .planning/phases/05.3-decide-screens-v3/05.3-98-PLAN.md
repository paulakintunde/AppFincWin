<objective>
Remove the one-live-copy rule on reopened checks so "Check again" and "Check another price" work every time (UAT gap 21, blocker).

Design decision (planner, recorded here as the gap asked): option (c), change the index with a migration.
- (a) reuse or replace the live copy is wrong for D-19: "Check another price" must be a NEW check, and the live copy is often already decided (a saved plan), so reusing it would reopen or overwrite a decision.
- (b) set reopened_from only on the first copy loses the link D-19 says every copy carries, and the D-13 refund line and the home list both read it.
- (c) drop `decide_checks_reopened_once` (20261021000100, IN-B05). It was added so two devices could not each reopen one Past decision; the v3 screens deliberately allow many copies, and the lists' "Check again" keeps opening an existing open copy on the client (05.3-100). The non-unique `decide_checks_reopened_from_idx` (20261016000100) stays for lookups.
The push is plan 05.3-99 (owner OK first). The client in 05.3-100 works before the push (it follows the server's redirect) and after it.

Output: one additive-safe migration and pgTAP 80.
</objective>
