<objective>
UAT gap (step 75 item 1, major): "The 'card not paid in full' refine card can show". The owner said the known limit from 05.3-34 is not OK.

Root cause: `src/features/decide/v3/refine/useRefine.ts` builds `cardStatements` with `paidInFull: [] as readonly boolean[]` for every card, because the app keeps no per-statement history. `refine()` (`src/engine/decide/v3/month/refine.ts`, the `card_not_paid_in_full` loop) needs `REFINE_CARD_UNPAID_STATEMENTS` (2) trailing `false` flags, so the card can never fire.

Smallest sound design (no migration): derive the history from the card account's own records. A card debt row carries `account_id`; the snapshot source already holds the last 12 months of lines (`rows`, `upcomingRows`), every account's current paid balance in its own currency (`balances`) and the accounts. Walking the balance back from today gives the amount owed at each month end; the payments (positive lines) into the card in the two following months show whether that was paid off. Month ends stand in for statement dates; the two-month window absorbs any statement day (a statement closing on the 15th is due around the 10th of the next month, and the month-end balance also holds spending from after the statement, which the following statement's payment covers).

Purpose: the refine check-in can ask again when a "pays in full: yes" card carries a balance (UP §6 "When a card's balance is not paid in full for 2 statements, the setup answer 'pays in full: yes' is shown as a question again").
Output: a pure engine function with 100% branch coverage and the hook wiring.
</objective>

```typescript
export interface CardLedgerInput {
  readonly asOf: LocalDate;
  /** The card account's paid balance today in its own currency. Negative = owed. */
  readonly balanceNow: MinorUnits;
  /** The card account's paid lines in its own currency, any order. Spending negative; payments and refunds positive. Must hold every paid line dated after fromMonth's first day. */
  readonly lines: readonly { readonly date: LocalDate; readonly amount: MinorUnits }[];
  /** The first month whose end can be walked back to (the first month the lines fully cover). */
  readonly fromMonth: YearMonth;
}
const PAYMENT_WINDOW_MONTHS = 2;
export function cardPaidInFullHistory(input: CardLedgerInput): readonly boolean[]
```
Algorithm (all sums in BigInt, result flags only):
1. `last = addYearMonths(yearMonthOf(input.asOf), -(PAYMENT_WINDOW_MONTHS + 1))` (on 2026-10-31: 2026-07, whose window Aug..Sep has ended).
2. For each month M from `fromMonth` to `last` inclusive (none when fromMonth > last): `end = M-<daysInYearMonth(M)>`; `windowEnd = last day of addYearMonths(M, PAYMENT_WINDOW_MONTHS)`; `after = Σ amount of lines with date > end`; `balanceAtEnd = BigInt(balanceNow) - after`; `owed = balanceAtEnd < 0n ? -balanceAtEnd : 0n`; `paid = Σ amount of lines with amount > 0 and end < date <= windowEnd`; push `owed === 0n || paid >= owed`.
3. Guard the walked balance with `minorFromBigInt(balanceAtEnd, 'cardPaidInFullHistory')` once per month so an out-of-range value throws (refine.ts uses the same guard).
Export `cardPaidInFullHistory` and the type `CardLedgerInput` from `src/engine/decide/v3/index.ts` (one added line next to the `refine` export) and add `'cardPaidInFullHistory'` to the pinned export list in `src/engine/decide/v3/__tests__/barrel.test.ts`.
