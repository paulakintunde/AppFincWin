# Phase 05.3 Plan 119: records_look_behind honours "this month is up to date" Summary

The Decide judge now leaves out "Your records look behind this month" when the user answered, within the last NEEDS_INPUT_ENTRY_AGE_DAYS (10) days and no later than asOf, that the current month is up to date (`month_complete`) or has nothing to add (`nothing_to_add`). This is the same rule readiness already uses, and it closes UAT gap 36.

## What changed

- `needsInput.ts`: new internal `currentMonthAnswered(inputs)`. It is true when a waiver is `month_complete` or `nothing_to_add`, its `month` is `yearMonthOf(asOf)`, `at <= asOf`, and `daysBetween(at, asOf) <= NEEDS_INPUT_ENTRY_AGE_DAYS`. It runs only inside the band/e branch, as the last condition guarding `out.add('records_look_behind')`. The 5.4.3 header line notes the skip. No new imports (`daysBetween`, `yearMonthOf`, `NEEDS_INPUT_ENTRY_AGE_DAYS` were already imported).
- `needsInput.test.ts`: new case "05.3-119 (UAT gap 36)". It checks that fresh `month_complete` and fresh `nothing_to_add` skip the line. Last month's answer still asks. An answer exactly at the 10-day limit still counts; one day past it asks again. An answer dated after asOf is ignored. The other waiver kinds (paid_by_other, didnt_happen, no_pay, always_other, income_elsewhere, start_from) change nothing. When a stale and a fresh answer are both present, the fresh one counts.
- `needsInput.waiver.property.test.ts` (new): a fast-check property with 300 runs. It generates bands 0-7, logged pace, e or null, newest-line age or none, pay present or not, day one, and up to 6 waivers of any kind, month and date (-40..+5 days around asOf). For every case, `needsInput` with waivers is a subset of `needsInput` without them.
