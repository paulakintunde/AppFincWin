## Task 1: Stryker baseline (informational, PARTIAL)

Two things blocked the first runs and were fixed (deviations below). Then:

- Whole scope (v3 plus 5 shared files): 8,204 mutants, 5,449 of them static (64%). The first full run (static mutants included) was stopped; static mutants each re-run the whole suite (about 4 minutes of test time each), so that run cannot finish on this machine. Initial dry run of 2,672 tests took 6 to 13 minutes.
- Per the plan's 60-minute rule the baseline was cut to `judge/*.ts` with `--ignoreStatic` (2,034 mutants listed for the folder). After 1 hour of mutation: **695 of 2,034 tested (45%), 2 survived, 2 timed out**, so 693 of 695 tested mutants were caught (about 99.7%). Rate was about 12 mutants per minute (2 test runners); the tool estimated another 1h 13m.
- NOT recorded: a whole-engine score, killed/no-coverage counts, and the top-10 survivor files. Stryker only writes its JSON/HTML report at the end of a run, and I stopped it at the one-hour box, so `reports/mutation/mutation.json` does not exist (the plan's automated check `test -f reports/mutation/mutation.json` fails for that reason). The two survivors are not identified by file.
- **The nightly CI run on Linux is the authoritative baseline** (per the owner's instruction). Suggested CI invocation: `FC_RUNS=10 npx stryker run --ignoreStatic` first, then without it on a long runner.
- `break` is unchanged: `grep -c "break: 0" stryker.config.mjs` returns 1.

## Task 2: Reviewed diff

- `corpus()`: 22 invented people (9 golden + 13 audit) x 5 checks (cash at 60, 500, 2,000, 9,000; one 48-month plan at 9,000, 7.9% APR, first payment one period) plus 200 seeded generated histories (seed 0x051d) = 310 keys (`persona:<id>:<price>:<mode>`, `gen:<i>`).
- `answers.json`: baseline recorded from the current engine (code, variant, afterBuyMonth per key). `changes.json`: empty ledger.
- `reviewed.test.ts` fails when any engine answer differs from `answers.json` (lists key, approved, current), when a ledger entry lacks a fix ID, a 20+ character reason or `approved: true`, or names a key not in the corpus. A probe edit of one `answers.json` value failed the test; revert passed.
- `write.test.ts` runs only with `REVIEWED_WRITE=<FIX-ID>`.
- `scripts/reviewed-diff.mjs --write <FIX>` appends unapproved entries and writes `reports/reviewed/<FIX>.html` (Before -> After in plain labels, grouped stricter / looser / same answer with different detail, with totals). `--approve <FIX> --reason-file <path>` (lines `key: reason`, colon then space, because keys contain colons) fills reasons, approves entries that have a 20+ character reason, and rewrites `answers.json` only if every changed key has an approved entry; otherwise it exits 1 and leaves `answers.json` alone. Tested end to end with a throwaway fix ID and reverted.

## Task 3: Retire legacy-answers.json as an oracle

## Deviations from Plan

**1. [Rule 3 - Blocking] Stryker could not parse a mutant in readiness.ts**
- Found during: Task 1. Stryker rewrote `(item.date as LocalDate) <= w.at` to `item.date as LocalDate < w.at`, which does not parse (26 SyntaxErrors), so the dry run failed.
- Fix: a typed constant `const billDate: LocalDate = item.date as LocalDate; return billDate <= w.at;` with an `if (item.kind !== 'bill') return fresh(w.at)` guard. Behaviour unchanged; readiness tests pass.
- Commit: 5881a5dd.

**2. [Rule 3 - Blocking] Initial test run timed out at Stryker's 5-minute default**
- Fix: `dryRunTimeoutMinutes: 45` and `ignorePatterns` (coverage, reports, caches, .planning, android, ios, .expo) in `stryker.config.mjs`. `break` untouched.
- Commit: 5881a5dd.

**3. [Scope] Baseline reduced to judge/ and partial** (see Task 1). Run flags were CLI-only (`--ignoreStatic`, `--mutate`, `--reporters progress-append-only,...`); not committed to config.
