Step 1 revision (2026-11-05), checked against D-52..D-125 and the plan 28 / 37 / 38 builds:
- The engine side of ENG-14 is already built (05.4-15): `V3Inputs.recordsAsOf`, month/freshness.ts (`records_synced` in the first 7 days with records synced at most 3 days before), the `records_out_of_date` caveat (D-119) and `Result.recordsAsOf`. This plan only feeds it. No engine file changes.
- Offline on the 1st: the real blocker is in `src/data/queries/decide.ts`, not buildV3Inputs. The history and upcoming query keys carry the month range, so on the 1st the new keys have nothing cached and, offline, Decide stays "loading" forever. The fallback moves to useDecideSnapshot (placeholderData from last month's keys, rolled forward by a pure helper in the 100% snapshot folder). buildV3Inputs is pure and receives rows; it gets only the recordsAsOf pass-through.
- `lastServerFetchAt(q: Query)` already exists in persister.ts and falls back to dataUpdatedAt (needed by dehydrate). A new `serverFetchTimeOf(queryHash): number | null` with no fallback feeds recordsAsOf, so an optimistic write never makes records look fresh.
- Which reads set recordsAsOf, and whether the oldest or newest wins: OWNER Q1 (the original text said "latest"; the threat register says a stale answer must never look fresh).
- Typed errors: the write side already has them (`classifyWriteError` in src/data/sync/writeErrors.ts; `NotFoundError` is thrown only after the server answers and a re-read finds no row; a failed re-read throws DbError). The grep found no place on the v3 path that turns a network failure into "not found"; the old screen's `useCheckDraft` 'not_found' needs a row seen and then gone from server data (05.5 deletes that screen). So nothing is replaced; the new read classifier feeds useDecideV3's `errorKind` for the 08.1 card. RequestTimeoutError extends TypeError, so errors.ts stays dependency-free.
- Cache bump reason corrected: the v3 Result / Evaluation is never cached (decideV3.ts, bigint). The bump is for cached row shapes 05.4 changed (listed in must_haves). The shape hash therefore reads the cached shapes (every `*_COLUMNS` select list in src/db, src/db/rows.ts, src/data/keys.ts), not the engine's types.ts, which would force a cache wipe on every engine edit.
- `check:cache-version` is already registered in package.json (05.4-01) but its script file is missing (found in plan 37). This plan writes it, plus a `node --test` file (plan 32 pattern; Jest ignores scripts/).
- Persister tests live in src/data/__tests__/persister.test.ts (there is no src/data/cache/__tests__).
- D-113 / APP-02 data side: buildV3Inputs passes `unsavedWrites: 0`, so the "Some changes are not saved yet" note (plan 28) can never show in the app. Whether this plan wires the queued-write count: OWNER Q2.
- D-114: the silent drop of accounts with no rate stays until 05.5 (named follow-up); this plan must not change it.
</revision_note>
