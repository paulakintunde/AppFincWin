# Phase 05.4 Plan 35: Stored inputs reach the v3 engine. Summary

The stored data added in 05.4 now reaches the v3 engine inputs. That covers account kind, overdraft limit and rate, debt due day, the interim safety net (protect, size, lock, with saved = the emergency fund), fact lines on, and the state or province. Debts reach the engine for quick-estimate and no-record users too. A stored plan keeps its home-loan mark.

## What was built

**Accounts (FIN-03, ARC-25, D-144)**
- Kinds map as follows: checking becomes checking, savings stays savings, and cash, investment, other and any unknown kind become other.
- The overdraft limit is converted from the account's currency at the latest stored rate, rounded down. If no rate exists, the account has no limit.
- The rate is passed as stored. A null or unreadable rate stays null, and no default is ever used.

**Debts (FIN-04, D-43)**
- `dueDay` must be 1..31; anything else is null.
- A card's debt carries the card account id, so its due day is read from the live card row on that account.
- The old builder now also returns its debt list on every result kind (`debtRecords`, additive). The v3 inputs read it for logged, quick-estimate and no-record users. Old-engine answers are unchanged.

**Safety net (FIN-01, D-33, D-35, D-61)**
- No settings row gives `safetyNet: null`, so the engine defaults apply.
- Otherwise the net reads: protect = column is not false; size = the column, or null (the starter); saved = the emergency fund, or 0; locked = column is not false.
- An old cached row without the columns reads as the defaults.
- CR-03: when the settings money is in another currency, the size is dropped. Protect and locked are kept.

**Fact lines (D-08)**
- Always `true` for now. The switch's storage and screen are in 08.1.

**State or province (D-19, D-20, D-142)**
- There is a new required snapshot read, `regionSubdivision`, using `fetchRegionSubdivision` and query key `['region-subdivision', userId]`.
- `buildV3Inputs` passes the value when a country is resolved and the code matches `^[A-Z0-9]{1,3}$`. Otherwise it passes null.
- The country itself is unchanged: `getDeviceRegion` resolves it from the user setting, then the device region, then the time zone. IP is never used.
- The cache lock was updated at version 3 with no bump.

**Need or want (D-41)**
- The stored v2 `purpose` already reaches `Purchase.purpose`. A test now pins it.

**Home-loan mark (D-39c, D-143)**
- `parseCheckV2` keeps `pay.housing` only when it is true. Any other value is left out, so an unmarked plan reads exactly as before.
