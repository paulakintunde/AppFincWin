<step_1_findings>
Step 1 (2026-11-06, on d7b42122) measured the problem before any build. The step-1 report has the detail; the plan relies on these facts:

- Scope (D-32): 76 files, **13,949 mutants** (local `stryker run --dryRunOnly`). 05.4-08's figure of 8,204 is out of date; the engine has grown since.
- **No complete mutation run has ever finished**, on CI or locally. There is no whole-engine score. The only figure on record is 05.4-08's partial: judge/ only, 695 of 2,034 tested, 2 survived, 2 timed out, after 1 hour on Windows. The cut-off CI parts also show few survivors (1-24 per part at 21-60% done), which suggests the score will be high, but that is not a score.
- Why `mutation-changed` never completes (48 CI runs on this branch: 28 cancelled, 19 failed, 1 running, 0 passed):
  1. "Changed files" means changed since `main`. On a phase branch 359 commits ahead, that is 56 of the 71 v3 files, so every push asks for a near-full run.
  2. `concurrency: ci-<ref>` with `cancel-in-progress: true` cancels the whole run on each new push.
  3. Runs that are not cancelled hit `timeout-minutes: 90` at 21-60% of their part (GitHub shows a timeout as "cancelled"). A part tests about 4-9 mutants a minute (2 test runners per 4-core runner; the TypeScript checker takes the other 2). judge.ts alone is 1,923 mutants, one part, about 4-5 hours.
  4. Parts are balanced by line count, not mutant count, so they are uneven.
  5. Stryker writes `.stryker-cache/incremental.json` only when a run finishes, so the cache is never saved and every push starts from zero.
  6. Some runs fail in Stryker's first test pass because the branch had real failing tests at that commit (table.test SO-10/SO-11 on d17121f9; an I9 property counterexample on b32d8e40). Both predate later fixes; the I9 seed does not reproduce on HEAD.
- `nightly.yml` is **not on `main`**, so its schedule has never fired and `gh workflow run nightly.yml` returns 404 (Pitfall 8's "merge the nightly early" never happened). It is also one job with a 340-minute cap, far short of a full run.
- The repo is public, so standard GitHub-hosted runner minutes are free; the Free plan runs at most 20 jobs at once; one job may run at most 6 hours.
- The bar differs: CONTEXT QA-04 says 90%; ROADMAP success criterion 4 says 95%. D-174 settles it.
</step_1_findings>
