<revision_note>
Revised 2026-11-05 (step 1) against the code after plans 06, 13, 28, 33 and decisions D-1..D-127:
1. The route is added to app/(app)/_layout.tsx inside its own `Stack.Protected guard={harnessEnabled()}` (outside the DECIDE_OPEN guard, which would hide it); the route also redirects to Home (the Decide tab is closed while DECIDE_OPEN is false, so "redirect to the Decide tab" is replaced). The "linked from nowhere" grep excludes that registration.
2. Gate split: the Record-as-bought harness is `__DEV__` only. It writes real rows to the one production database, and a perf build may be installed on a phone that is not a dev phone. The engine harness shows under `__DEV__` or `EXPO_PUBLIC_PERF=1`.
3. `record_decide_go` refuses a check that does not exist, is not the caller's, or is not open. The harness therefore first creates an open check (useCreateCheck, client uuid), waits until it saves, then calls `useRecordBought().record`. The sample is a financed purchase with one running cost, so it writes a day-one row, a payment series, a running-cost series and a debt (the old "two running-cost bills" did not match buildBoughtWrite, which writes one running-cost series).
4. perfMarks keeps only the last 30 samples and is a no-op without EXPO_PUBLIC_PERF=1. The engine harness times each call itself with performance.now(), computes p50/p95 over all 200 (nearest rank, the same as perfMarks' statOf), and also emits `judge:start`/`judge:end` marks so perfReport and `adb logcat` see the last 30. 20 untimed warm-up calls first; 3 runs.
5. The heavy account generator from prepare.test.ts uses test helpers, which app code must not import. A new app-side `heavyAccount.ts` builds the same shape (12 months x 120 lines, 20 series, 6 debts, 4 accounts) directly as V3Inputs, plus the shadow sample checks ($60, $500, $2,000, $9,000 car cash and plan). Engine source is untouched.
6. APP-04 here is the engine share only (fix plan section 4: "the engine part of each key press"). Whole key press, 300 ms and Decide Home open need the Variant C screens and move to 08.1. The old plan's "cold open of Decide Home" step is removed (the old Home is unreachable).
7. Harness labels are developer strings held as constants (jsx-text-only i18n lint), never in en.ts or the copy table; declarative wording only.
8. Maestro flows run against one production database: they sign in as the account the owner picks and undo what they add (Undo toast or History), so no test rows stay.
9. Checks follow the owner policy of 2026-11-05: lint, typecheck, `jest --findRelatedTests` on changed files, reviewed:diff; no full test:coverage; no engine branch check (engine unchanged).
10. Owner answers needed before build: see the step-1 report (device for the robot flows, sign-in account, how the Pixel 6 timing build is made, Pixel 6 availability, APP-04 scope).
</revision_note>
