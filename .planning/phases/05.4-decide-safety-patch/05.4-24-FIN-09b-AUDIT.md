## The rule as built

- **Opening balance** (afterBuy.ts openingBalance): the everyday money now (spending accounts less pots) less this month's money in
  so far, plus this month's money out so far (paid lines dated this month; own transfers are neither), plus card and loan minimums
  already gone with no line to show them (debts.ts paidUnrecorded: a stated paidThisMonth, DB-10; a due day already past; a minimum
  the month sets aside that the balance no longer needs). Pay counts only once it has arrived, so pay the month expects but has not
  received never looks like an overdraft (D-52; the first build read "month-end account less this month's figure" and the crosscheck
  found that misreading for irregular earners).
- **Carried overdraft** = an opening below 0. It comes off this month's figure (MonthModel.monthLeft) first, in every reading, so
  Home (homeFigure), every answer's afterBuy, the ladder's room for this month, the overspent notice and the D-65 tier all read the
  same reduced month ("it uses this month up": only what is left of this month can go toward a purchase). Money carried in above 0
  changes nothing (QE-09).
- **The answer says so:** fact overdraft_carried_in { month (last month), amount }: "{{month}} ended about {{amount}} overdrawn. That
  is paid back from this month first." (D-106 and the copy guard green). The review page shows "Owed from last month (D-86)".
