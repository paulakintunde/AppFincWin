Whether the 4 tester accounts are real people with months of their own records decides whether this round means anything: a new or thin account answers needs_input on every sample (surprise 4). Owner question D-160.

6. **Answer names on the page.** The page shows the app's own chip text, not raw codes. A .mjs script cannot import the TS engine, so `scripts/shadow-labels.json` maps `code|variant|once` to the chip text (once = a one-off sample: s60, p500, l2000, c9000_cash; verdictRowFor reads tight differently for one-off and plan answers). A jest test builds the same map from `verdictRowFor` and `src/i18n/locales/en.ts` and fails on drift ("run SHADOW_LABELS_WRITE=1 ...").

Rule 1 now follows D-115 (a plain Fits never takes the month below 0; any other fit below 0 was already below 0 or carries a caution). Rule 3 ("cheaper gets a stricter answer") uses CODE_PRECEDENCE order (lower index = stricter, as the invariant tests do) on the four cash samples only; the two plan samples differ in rate and length, so they are not compared. The script keeps a copy of CODE_PRECEDENCE, and its node test reads `src/engine/decide/v3/constants.ts` as text and fails if they differ.
8. **Revision.** The current revision is read from `src/engine/decide/v3/shadow/revision.ts` source text (today '05.4.1'). Later 05.4 plans may bump it (D-146); the phones then run again on their next open and the report is per revision. Surprise 2 (changed since the previous revision) applies only when `--previous <rev>` is given; the first run has none.
9. **Currency.** Rows carry minor units in the tester's own currency without the code (D-147). The report reads `decide_settings.currency` for each reporting user (read-only, same query) to show whole units with the code; when it is missing, it shows minor units marked "minor units".
10. **Withdrawal and deletion.** RLS gives testers insert only, no select or delete, so a tester cannot remove their own rows. Rows go with the account (on delete cascade). What happens when someone says "stop" is owner question D-162; the runbook writes the steps.
11. **Update apply timing.** Preview builds use checkAutomatically ON_LOAD; an update downloads on one open and applies on the next cold start. Testers are asked to open the app, close it fully, and open it again, while online.
12. **Recording.** Consent replies are kept by the owner, outside the repo. The repo records tester numbers, dates and counts only (no IDs, emails or names), in the SUMMARY and PRODUCTION-LOG.
13. Per-plan checks only (no full test:coverage); `node --test` for scripts, targeted jest for the label guard.
