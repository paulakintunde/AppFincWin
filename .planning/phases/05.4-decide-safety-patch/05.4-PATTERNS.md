### Engine property tests (`invariants/*.test.ts`)

**Analog:** `src/engine/decide/v3/__tests__/invariants/answer.test.ts`

Header and imports (lines 1-30): file header lists invariant ids; each property title starts with its id so the index finds it.
```typescript

import { loadPersons, personById, toV3Inputs } from '../golden/adapter';
import { checkOnce } from '../helpers/fixtures';

const RUNS = { numRuns: 60 };
```
Core pattern (lines 47-57): the title starts `I<n> ...`, fixed seed, "never better" via `codeRank` (lower = stricter).
```typescript
it('I1 thin data is never better: ...', () => {
  fc.assert(
    fc.property(inputsArb, checkArb, (inputs, check) => {
      const a = evaluate(thin, check).result;
      const b = evaluate(treatedFull, check).result;
      expect(codeRank(a.code)).toBeLessThanOrEqual(codeRank(b.code));
    }),
    { ...RUNS, seed: 0x0540 }
  );
});
```
**Apply to every Theme A property** ("a lower balance never gives a better answer", "adding tax never makes an answer better", "$0 net equals off", D-24 pin). Use distinct fixed seeds per test (Stryker stability). For Stryker, read `numRuns` through one shared helper (env `FC_RUNS` / `STRYKER_MUTATOR_RUNNER`) instead of the literal `RUNS`.

**Invariant index** (`invariants/index.test.ts` lines 12-45): `IDS = Array.from({ length: 43 }, ...)` and regex `TITLE = /(it|test|describe)(\.each\([^)]*\))?\(\s*['"`]I(\d+)\b/g`. New properties register by extending the length (I44+), or adding a parallel `T05_4` id list, so a missing test fails by name. Scans `v3/` and `snapshot/v3/` and `decideCopy.test.ts`. If new test folders live outside these (e.g. `rightAnswers/`), they are still under `V3`, so covered.

**Arbitrary construction** (`invariants/arbitraries.ts` lines 1-40): inputs are built from golden persons then perturbed with a `Tweak` record (`fc.record({...})`); `mu = (n) => minorUnits(n)`; `codeRank = CODE_PRECEDENCE.indexOf`. Extend `Tweak` for overdraft limit, safety net, running cost, tax percent rather than inventing a second generator. New codes must be added to `CODE_PRECEDENCE` in `v3/constants.ts`.
