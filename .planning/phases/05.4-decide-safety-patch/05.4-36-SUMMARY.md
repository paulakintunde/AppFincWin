# Phase 05.4 Plan 36: the quiet shadow run

**What this plan does:**
- A tester who said yes (profiles.decide_shadow) gets a quiet check on their phone. It runs 6 fixed sample purchases against their own records, once per engine version.
- Only the answer, a short list of codes and numbers rounded to 2 significant figures leave the phone.
- Nothing is shown on screen, nothing waits on it, and Decide stays off for everyone.
- People who are not testers never load the Decide data for this.

## Rules as built (plain words)

- **Samples (D-12, D-147).** s60, p500, l2000, c9000_cash, c9000_plan, f1200_plan.
  - They are 60, 500, 2,000, 9,000 (cash), 9,000 (48 monthly payments at 9.9%, first payment one period out) and 1,200 (12 monthly payments at 0%).
  - Each is in whole units of the tester's home currency, scaled by its minor-unit exponent: £60 is 6000, ¥60 is 60.
  - Tax is included, there are no fees, the share is personal and there is no purpose.
  - A test checks that no invented person is asked for a price or a plan figure.
- **What a row carries (D-10).**
  - code and variant.
  - reasons: the codes, each prefixed with its list: m: missing, d: readiness, r: reasons, f: facts, c: caveats, n: notices. They keep that order, repeats are removed, and the list is cut at 12.
  - figures: only numbers, each rounded to 2 significant figures (ties away from zero; never -0). The fixed keys come first: am, aum, ab, s.<source>, band, rbm, ready, cut. Then each fact's numbers as `<fact>.<key>` in the order emitted. That stops at 24 entries or 1,100 characters of JSON (the column limit is 2048 bytes).
  - Every string is dropped. So is every key named like an id, name, account or category, matched by word: accountId and other_account_overdrawn.amount are dropped, "paid" is kept. The free_help name never leaves.
- **When it runs (D-13, D-146).** The run happens once per DECIDE_ENGINE_REVISION ('05.4.1').
  - revision-lock.json holds the sha256 of three things:
    - answers.json;
    - every approved right-answer case (id, fixture, expected);
    - shadowRun on every reviewed-corpus input (the invented people and the 200 generated histories), with all 6 samples.
  - Any change fails with "bump DECIDE_ENGINE_REVISION". Rewrite the lock after a bump with `REVISION_WRITE=1 npx jest src/engine/decide/v3/shadow/__tests__/revision.test.ts`. It refuses to record a new hash under the old revision.
  - Probe: one saved answer was edited by hand and the test failed with that message. The edit was then undone.
- **On the phone (runShadow).**
  - decide_shadow off: nothing runs.
  - The "already sent" mark `fincwin:decide-shadow-sent:<revision>` exists: nothing runs. Sign-out wipes it.
  - Offline: it skips the run, and the host runs it again when the phone comes back online.
  - Records not up to date (D-145): the first try's day is stored in `fincwin:decide-shadow-wait:<revision>`. It waits on each app open until 7 days have passed, then sends with ready = 0 and the d: codes.
  - Otherwise it sends one insert of 6 rows, then sets the mark. A 23505 (already sent) counts as success.
  - A refused insert: no mark, `captureFailedWrite({ entity: 'decide_shadow_runs', kind: 'insert', code })`.
  - Anything else: `captureError(new Error('decide shadow run failed'), { area: 'sync' })`.
  - Nothing is thrown, and no amount goes to Sentry.
- **Where it is mounted.** `DecideShadowHost` is in `app/(app)/(tabs)/_layout.tsx`, always mounted, next to the DECIDE_OPEN-gated DecideShellHost.
  - DecideShellHost was not usable: it mounts only when Decide is open.
  - The host renders null.
  - Only when profile.decide_shadow is true does it mount the inner runner, which calls useDecideV3. It then waits for 'ready' inputs and an idle moment (scheduleIdle).
