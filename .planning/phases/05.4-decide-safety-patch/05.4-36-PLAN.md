<revision_notes>
Step 1 revision (2026-11-05) against the code after plans 30-38 and 46-57:

1. **Mount point.** DecideShellHost is mounted only when DECIDE_OPEN is true (tabs layout), so a runner there would never run while Decide is off. A new `DecideShadowHost` is mounted unconditionally in `app/(app)/(tabs)/_layout.tsx` (every signed-in user with an account). It reads `decide_shadow` from useProfile and only then mounts an inner part that calls `useDecideV3()`, so people who are not testers never load the Decide reads.
2. **Profile read.** `useProfile` selects `decide_v3` but not `decide_shadow`. `decide_shadow` is added to PROFILE_COLUMNS and the Profile type (optional). The column is in production (20261103000400, pushed in 05.4-31), so the select is safe.
3. **Variants guard.** Since the plan was written, 20261103000900 (D-62, D-63) and 20261103001000 (D-65) widened the variant CHECK to 15 values. The guard reads the LAST migration that defines `decide_shadow_runs_variant_check`, not 000500. **Production has only 000100..000700**; 000800..001000 are files only. A tester whose answer is extra_savings, month_already_short or a month_short_* tier would have the whole 6-row insert refused (23514). The runner treats that like any failed insert (no mark, tries again next app open), so nothing breaks; but those files must be pushed before 05.4-42 switches any tester on. Written into the SUMMARY as a note for 05.4-42.
4. **Code list.** Result codes overlap across lists (pay_gap and tax_not_included are both reasons and notices; debt_due_day_assumed is a reason and a fact). Each code is prefixed with its list (m:, d:, r:, f:, c:, n:) so 05.4-42's report can tell them apart. The cap keeps "reasons before facts", with missing and readiness codes ahead (they explain an ask or a not-ready answer).
5. **Figures.** Defined exactly: am (afterBuy.month), aum (afterBuy.usualMonth, when not null), ab (afterBuy.before), s.<source> (each funding segment), band, rbm (months from asOf to the ready-by month), ready (1 or 0), cut (codes cut), then numeric fact values as `<fact>.<key>` in emitted order up to 24 entries. Every number is rounded to 2 significant figures (all numbers, not only money: stricter). Rounding uses Number.prototype.toPrecision(2) (exact on safe integers, ties away from zero: 1250 -> 1300, -1250 -> -1300) instead of BigInt.
6. **Samples per currency.** `shadowSamples(currency)` scales the whole-unit prices by the currency's minor-unit exponent (currencyExponent), per D-147.
7. **Revision hash.** Hashing only answers.json and approved cases would miss engine changes that add or change lines without moving a headline (05.4-38 added free_help with 0 headline changes). Per D-146 the hash can also cover the rounded shadow rows. Hashing runs in the test only (node crypto); engine source stays pure.
8. **Mark key.** `fincwin:decide-shadow-sent:<revision>`: under the fincwin: prefix, so the sign-out wipe clears it and a different tester on the same phone runs again.
9. **Error reports.** A failed insert goes to `captureFailedWrite({ entity: 'decide_shadow_runs', kind: 'insert', code })`; anything else to `captureError(new Error('decide shadow run failed'), { area: 'sync' })`, a fixed message, so no amount ever leaves in an error.
10. Verification follows the per-plan checks (no full test:coverage).
</revision_notes>
