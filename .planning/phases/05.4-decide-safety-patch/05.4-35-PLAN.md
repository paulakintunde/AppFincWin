<revision_note>
Step 1 revision (2026-11-05), against the code after plans 31, 33, 34 and 40 (and d17121f9, which moved plan 34's dev harness to
src/features/devHarness; this plan touches none of those files) and decisions up to D-141.

What changed and why:
1. Region: the original Task 2 called resolveRegion inside buildV3Inputs. The country is already resolved in the data layer
   (src/data/queries/decide.ts: getDeviceRegion(rc.region) -> resolveRegion) and passed as source.region; buildV3Inputs is pure and
   cannot read the device. Revised: keep source.region; add `regionSubdivision` and `profileRegion` to SnapshotSource; a new read
   in useDecideSnapshot fetches profiles.region_subdivision (fetchRegionSubdivision exists; no change to src/db/profile.ts, whose
   comment keeps the money-prefs read unchanged). New query key -> keys.ts changes -> `npm run check:cache-version -- --update`
   (no bump: version 3 has not shipped). The read is a required snapshot read like the other 16 (Decide waits for it), so an
   answer never flips from "no tax" to "tax" when it lands.
2. Account kind mapping: the DB kinds are cash, checking, savings, credit, investment, loan, other (20260924000300). credit and
   loan stay out (they are debts). checking -> 'checking'; savings -> 'savings'; cash and other -> 'other'; investment -> Q3.
   'current' and 'card' are never produced (no such stored kind; cards are debts).
3. Overdraft limit currency: the plan passed the stored limit as is. It is in the account's currency, so it is converted like the
   balance, rounded down (cautious).
4. Card due day: a card's debt in the old builder has the card ACCOUNT id, so `debtRow.get(d.id)` misses the card's debts row and its
   due_day. The due day is looked up by debt id, else by the card's debts row on that account.
5. D-43 for quick estimates: buildV3Inputs only fills debts on the logged path today, so a quick-estimates user's card never reaches
   the engine. The old builder exposes its debt list on every result kind (new additive field); buildV3Inputs reads it for all kinds.
6. Safety net: decide_settings now also has safety_net_locked (D-61, migration 20261103000800); it is wired too. V3SettingsSource
   gets three optional fields; settingsSourceOf copies them. Old cached rows without the columns read as protect on, size null,
   locked (the column defaults).
7. Fact lines: decide_settings has no fact-lines column; factLines is passed as true (D-08 default on). The switch's storage and
   screen are 08.1.
8. Purpose (D-41): already flows through parseCheckV2; a test pins it. Home-loan flag (D-39c): parseCheckV2 drops pay.housing, an
   engine adapter gap no plan covers -> Q2.
9. Checks: per the orchestrator, per-plan checks only (depcruise, lint, typecheck, findRelatedTests, check:cache-version, the 100%
   branch check on src/engine/decide only if engine source changes, reviewed diff). The full test:coverage is not run here.
10. autonomous: false — stops for owner questions (step 1) and for D-14 after the build.

Not in this plan (recorded for later, no change now):
- essentialCategoryIds (ARC-07) and tightLine (FIN-07): nothing stores them yet (08.1 screens).
- V3Debt.seriesId / joint / paidThisMonth: no stored source wired through the old parse path; 05.5 (D-16 decouple).
- safety_net_size is not converted by the home-currency change migration (20261029000200 predates it). Nothing writes it until
  08.1; 05.5 moves the net to its owner (D-33) and must convert it there.
- D-114: accounts with no exchange rate are still dropped silently until 05.5.
- parseCheckV2 also drops runningCosts, closingPercent, purchaseDate and replaces (BO-05); no screen writes them yet (see Q2).
