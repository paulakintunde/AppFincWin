# Phase 05.4 Plan 33: Decide's data layer offline on the 1st, an honest records date, build once, read-error kinds, cache version guard

**What this plan does:**
- On the 1st of a month (or any day this month's reads have not landed yet), Decide builds from last month's saved reads instead of waiting forever offline. The engine's freshness rule (05.4-15) then decides what it may say.
- The answer carries a true "records up to" date: the oldest real server read among past entries, upcoming entries and balances. It is empty when not known, never "today".
- The data is built and prepared once per change; each check (each key press, in 08.1) only runs the check part.
- The "Some changes are not saved yet" note can now show: the builder counts the writes still waiting to send.
- A failed read has a kind (network, not found, server, forbidden, conflict). A network failure never reads as "not found".
- The saved-data version goes from 2 to 3, and CI now fails if a saved shape changes without a version change.

## Rules as built (plain words)

- **Offline fallback (APP-01):**
  - The history and upcoming query keys include this month's dates, so on the 1st they have nothing cached.
  - useDecideSnapshot gives both reads `placeholderData` from last month's keys, through `rollForward`: history keeps rows from this month's `from` to `to` (last month's history plus last month's upcoming rows now inside the window); upcoming keeps last month's upcoming rows from this month's `upcomingFrom`.
  - Placeholder data is never written to the cache and never persisted (the December query stays 'pending'; tested). It needs both of last month's reads; otherwise Decide waits and names the missing reads.
  - When this month's read lands it replaces the fallback.
- **Records date (APP-06, D-126):**
  - `serverFetchTimeOf(queryHash)` reads the server-fetch map only. `lastServerFetchAt` keeps its dataUpdatedAt fallback for the 30-day persist rule.
  - recordsAsOf = local day (rc.timeZone) of the oldest of the three fetch times, using last month's hashes while the placeholder shows. Null when any is unknown or the time zone is bad. A manual cache write never moves it (tested).
  - The memo is keyed on each read's dataUpdatedAt, so a refetch that returned equal data still moves the date.
  - buildV3Inputs: `recordsAsOf: source.recordsAsOf ?? null`.
- **Unsaved count (D-127):** `useMutationState({ status: 'pending' })` counted on the source; buildV3Inputs takes a whole positive count, anything else as 0. With one waiting write the answer gains the unsaved note first and is otherwise identical (tested).
- **Build once (ENG-13, APP-03):** `preparedV3` keeps { built, inputs, prepared } in a WeakMap on the source, up to 4 settings / uses variants per source. computeV3 calls `judgeCheck(prepared, check)`. useDecideV3 now builds once (it used to build the inputs twice).
- **Read-error kinds (APP-10):**
  - network: TypeError (the 15 s RequestTimeoutError is one), AbortError, DbError status 0 or no code and no status.
  - not_found: 404, PGRST116, NotFoundError. forbidden: 401, 403, 42501, PGRST301..303, no session. conflict: 409, VersionConflictError. Everything else: server.
  - Decide hooks expose `errorKind` (null unless status is 'error') and `missingReads` (read names) for the 08.1 card.
  - Grep result: no place on the Decide path turned a network failure into "not found". The write classifier is unchanged. The old screen's useCheckDraft 'not_found' needs a row seen and then gone from server data (05.5 deletes that screen).
- **Cache version (APP-07):**
  - CACHE_SCHEMA_VERSION 3 for the 05.4 row shapes (accounts.overdraft_rate, debts.due_day, decide_settings safety_net_* and custom_options). A version 2 blob keeps its queued writes and drops its queries (tested).
  - `check:cache-version` hashes every `*_COLUMNS` / `*_COLUMN` constant in src/db, src/db/rows.ts and src/data/keys.ts (line endings normalised). It passes only when the hash and the version both equal the lock. `--update` rewrites the lock.
  - Probe: adding a column to DEBT_COLUMNS failed the check ("persisted shapes changed: bump CACHE_SCHEMA_VERSION ..."); revert passed.
- **D-114 untouched:** buildV3Inputs still drops accounts with no exchange rate (~line 413); 05.5 sends them.
