# Phase 05.4 Plan 16: reasons replace Rough / Fair / Firm Summary

**The v3 engine no longer has a confidence level. Each answer carries its reasons with their numbers, sorted by a fixed weight table, each with a declared audience; at most one next step; and a plain basis such as "Based on 2 of the 3 months of records Decide looks for." With no complete month of records the answer also carries the fact "No full month of records yet." A guard test fails on the old level type or a quoted rough / fair / firm outside a dated allowlist of old files. The reviewed diff shows 0 changed answers, so there was no D-14 popup.**

## What changed

- **Reasons (FIN-25 / ENG-10).** `confidence/reasons.ts` replaces `month/confidence.ts` (deleted). `REASON_WEIGHT`: user_said_cover 10, quick_estimates 20, few_months 30, unspent_drifted 40, pay_missed 50, close_to_line 60, early_in_month 70, under_logged 80, unspent_stale 90, unsaved_changes 100, provisional_rates 110, no_setup 120. Every weight is different, so there are no ties. Each `ReasonItem` carries its numbers: few_months {used, lookedFor}, early_in_month {day, from}, under_logged {logged, usual}, unsaved_changes {count}, unspent_stale {days}, unspent_drifted {value, suggested}, pay_missed {count, amount} (integer sum through BigInt), user_said_cover {monthly, months}.
- **Audience (ENG-18).** `REASON_AUDIENCE`: user_said_cover, quick_estimates, few_months, pay_missed, close_to_line = 'answer'; the rest = 'detail'. An exhaustive `Record<ConfidenceReason, true>` in the unit test means a new code must be added to both tables before the test compiles.
- **Basis (UX-04 / CMP-F12).** Quick estimates alone: `{ kind: 'quick_estimates' }`. Fewer than 3 months: `{ kind: 'partial', used, lookedFor: 3, upTo }`. Otherwise, if no 'answer' reason: `{ kind: 'records', months, upTo }` ("Based on 4 months of your records, up to Oct 29."). With an answer reason: `{ kind: 'records_with_reason', months, upTo, reason }`, the top one by weight. `upTo` is `recordsAsOf ?? asOf`.
- **Next step.** `pickNextStep`: the top-weighted reason that has a fix the user can make, or null.
- **Judge.** The four places that lowered the level to rough (drifted unspent, quick estimates, missed pay, your own word) and the stale-unspent cap now add the matching reason with its numbers. `MonthlyPart.capRough` became `saidCover: { monthly, months } | null`.
- **stricterOf (D-42).** The code is compared by CODE_PRECEDENCE only (LEVEL_RANK is gone). `mergeConfidence` takes the union of the reasons (the chosen reading's numbers first) and builds the basis from the smaller reading (fewer months; quick estimates on either side win).
- **no_full_month.** `prepare()` sets `noFullMonth` when no month before this one is marked full in the months as given (never the all-full reading). `judgeCheck` then appends the fact `no_full_month`. QE-01 and QE-13 carry it; QE-02 (2 full months) does not.
- **Copy.** en.ts `decide.v3.basis.partial` "Based on {{used}} of the {{lookedFor}} months of records Decide looks for.", `basis.records` "Based on {{months}} months of your records, up to {{date}}.", `basis.quickEstimates` "Based on your quick estimates, not your records.", `basis.recordsWithReason.{user_said_cover, quick_estimates, pay_missed, close_to_line}`, `nextStep.*` (six sentences, stated as facts), `fact.no_full_month` "No full month of records yet.". `basisCopy.test.ts` checks that each sentence's placeholders match `BASIS_VALUE_KEYS`. The v3 banned-word test (`should`, `you can`, `safe`, ...) and the new CMP-F12 check pass.
- **Invariants.** I45 (reasons sorted by REASON_WEIGHT, each with its table weight, at most one next step that names a carried reason; seed 0x0545, fcRuns(200)). I46 (a fits answer with any 'answer' reason never carries the clean records basis; seed 0x0546, plus a fixed D-48 "yes" case). IDS length 46. The old level properties (I1, I25, I7, D-42 thinning) now compare `restsOn()` (a test-only order on the basis) and reason codes. The golden fixtures' old three-word `confidence` expectations are read through `goldenLevel()` (test-only, the old rule exactly), so those fixtures did not need edits.

## Deviations from Plan

1. **[Rule 1 - Correctness] A fourth basis kind, `records_with_reason`.** The plan lists three kinds, but I46 cannot hold with them: with 3+ months, your own word or a missed pay would get the clean sentence. The fourth kind names the top 'answer' reason, with its own copy. Commit 8820a3b5.
2. **[Rule 3 - Interpolation] Copy uses `{{used}}`, `{{lookedFor}}`, `{{months}}`, `{{date}}`.** The plan's text writes single braces, but i18n placeholders are double braces everywhere in en.ts. So the plan's literal grep for `{used}` returns 0, and the double-brace grep returns 1. Commit 8820a3b5.
3. **[Rule 3 - Convention] The fact key is `decide.v3.fact.no_full_month`**, not `noFullMonth`: FACT_KEYS and the copy contract use the code as the key. Commit 8820a3b5.
4. **[Rule 1 - Plan behaviour] no_full_month on asks too.** The first version left it off needs_input answers. QE-01 answers needs_input today, and the plan requires its facts to include no_full_month ("whatever the reason codes"). Commit 8820a3b5.
5. **[Rule 3 - Blocking] knownRed QE-02 removed, and QE-01 / QE-13 re-tagged, in the Task 1 commit**, not Task 2. The ratchet fails as soon as QE-02 passes, and the re-tags live in the same file. Commit 8820a3b5.
6. **[Rule 3 - Harness] `pick()` reads confidence reasons** (see the orchestrator note). The case expected blocks are untouched.
7. **`close_to_line` is declared but not emitted.** No "tight" or "close to the line" rule exists in v3 yet. FIN-07 (05.4-21) defines it, and it has a weight, audience, basis copy and no next step ready.
8. **Barrel additions** (not in the plan): `REASON_WEIGHT`, `REASON_AUDIENCE` and the four copy key tables, so 08.1 screens can order and word reasons without reaching into engine internals. Pinned in barrel.test.ts.
9. **TDD order.** Tests were written alongside the implementation in the same commit, not as a separate failing commit first.
