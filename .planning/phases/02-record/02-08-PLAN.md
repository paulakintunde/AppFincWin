1. `public.materialise_series(p_series_id uuid, p_today date default null) returns setof uuid` — lock the series (`for update`, `deleted_at is null`, return nothing if absent). `v_today := coalesce(p_today, (now() at time zone s.time_zone)::date)`; `v_through := public.recurring_horizon(v_today)`, capped at end_date; `v_floor := greatest(coalesce(s.materialised_through + 1, s.anchor_date), s.anchor_date)`. Loop n from 0: stop at occurrence_count, at n > 5000 (hard guard), or when the date passes v_through; for dates >= v_floor insert `(gen_random_uuid(), s.household_id, s.account_id, s.created_by, s.amount, s.currency, date, s.time_zone, s.name, s.category_id, s.payment_type, 'pending', s.id, date)` into transactions (columns id, household_id, account_id, created_by, original_amount, original_currency, local_date, time_zone, name, category_id, payment_type, status, recurring_series_id, occurrence_date) `on conflict (recurring_series_id, occurrence_date) where recurring_series_id is not null and deleted_at is null do nothing returning id` and `return next` each new id. Finally, only if v_through > coalesce(materialised_through, '-infinity'): `perform set_config('fincwin.system_restamp', 'on', true); update public.recurring_series set materialised_through = v_through where id = s.id; perform set_config('fincwin.system_restamp', '', true);` (bookkeeping: no version bump, no updated_by change).
2. `public.materialise_recurring() returns integer` — for each series with deleted_at null and (end_date is null or end_date >= current_date - 1), count rows from materialise_series(id). Return the total.
3. `public.create_recurring_series(p_series jsonb, p_anchor_transaction_id uuid default null, p_link_transaction_ids uuid[] default '{}') returns jsonb`:
   - household from p_series must be in `public.user_household_ids()` else raise 42501; a series id that already exists in the same household returns `{"status":"already-applied","series_id":…}` (replay-safe), in another household raises 42501.
   - If p_anchor_transaction_id: lock that transaction (same household, deleted_at null, recurring_series_id null, else raise 22023); anchor_date := its local_date.
   - Insert the series with created_by = auth.uid(); `materialised_through` = the anchor/linked rows' latest local_date when rows are being linked, otherwise `greatest(anchor_date, date_trunc('month', today-in-tz)::date) - 1` (a new series never back-fills past months as overdue).
   - Link: update transactions set recurring_series_id = series id, occurrence_date = local_date for the anchor plus `distinct on (local_date)` rows of p_link_transaction_ids that are in the household, not deleted and not already linked; collect `{id, version}`.
   - inserted := array of materialise_series(series id) ids (version 1 each).
   - Return `{"status":"applied","series":{"id","version","before":null},"inserted":[…],"soft_deleted":[],"linked":[…]}`.
4. `public.edit_recurring_series_from(p_series_id uuid, p_expected_version integer, p_patch jsonb, p_effective_from date) returns jsonb`:
   - Lock series; missing or deleted -> `{"status":"not-found"}`; not a household member -> raise 42501; version mismatch -> `{"status":"conflict","conflict":{"entity":"recurring_series","id","updated_by","record_name": name,"builtin_key":null,"reason":"changed"}}`.
   - Allowed patch keys: name, amount, currency, account_id, category_id, payment_type, freq, anchor_date, end_date, occurrence_count — any other key raises 22023.
   - before := jsonb object of the old values of exactly the patched keys (plus anchor_date when it is changed implicitly).
   - Update the series with explicit per-column `case when p_patch ? 'col' then (p_patch->>'col')::type else col end`; when freq changes and anchor_date is not in the patch, set anchor_date := p_effective_from; set materialised_through := least(coalesce(materialised_through, p_effective_from - 1), p_effective_from - 1) in the same statement (one version bump).
   - Soft-delete `status = 'pending' and deleted_at is null and occurrence_date >= p_effective_from` rows of this series (never paid, never skipped, never earlier), collecting `{id, version}` (Pitfall 2).
   - inserted := materialise_series(id).
   - Return applied with series `{id, version (re-read), before}`, soft_deleted, inserted, linked [].
5. `public.end_recurring_series(p_series_id uuid, p_expected_version integer, p_end_date date) returns jsonb` — same checks; p_end_date < anchor_date raises 22023; before := `{end_date, occurrence_count}` old values; update end_date; soft-delete pending rows with occurrence_date > p_end_date; return applied with inserted [] and linked [].
6. Grants: revoke execute on all five from public, anon; `grant execute on function public.create_recurring_series(jsonb, uuid, uuid[]), public.edit_recurring_series_from(uuid, integer, jsonb, date), public.end_recurring_series(uuid, integer, date) to authenticated;` materialise_series and materialise_recurring: revoke from authenticated too, grant to service_role only.
