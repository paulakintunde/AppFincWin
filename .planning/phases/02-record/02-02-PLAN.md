```typescript
export type Delimiter = ',' | ';' | '\t';
export const MAX_IMPORT_ROWS = 5000; // D-18: data rows, header excluded
export type TokenizeError = 'empty' | 'unterminated-quote' | 'stray-quote' | 'too-many-rows';
export type TokenizeResult =
  | { ok: true; rows: string[][]; delimiter: Delimiter }
  | { ok: false; error: TokenizeError; line: number };
export function detectDelimiter(text: string): Delimiter;
export function tokenize(text: string, opts?: { delimiter?: Delimiter; maxDataRows?: number }): TokenizeResult;
```
- Strip a leading byte-order mark (U+FEFF, written in code as the escape sequence backslash-u-FEFF) — decodeText already removes it, this keeps tokenize safe for any caller. `detectDelimiter` counts ',', ';', '\t' outside quotes on the first logical line and returns the most frequent (ties: ',' then ';' then '\t'; zero of all: ',').
- Single pass state machine over characters: fields, current row, `inQuotes`, `line` counter (1-based physical line of the row start). A quote is only legal at field start (opens quoting) or, inside quotes, as '""' (literal quote) or closing quote followed by delimiter/EOL/EOF; any other quote -> stray-quote. EOF inside quotes -> unterminated-quote. Treat '\r\n', '\n' and '\r' as row ends outside quotes; inside quotes keep them verbatim in the field.
- Skip rows whose every cell is '' after trimming. Pad rows shorter than the first row with ''.
- Count data rows (rows after the header); the moment the count exceeds `opts.maxDataRows ?? MAX_IMPORT_ROWS` return too-many-rows with the current line (stop scanning — do not tokenize the rest).
- Never trim cell contents (mapping trims later). Never throw or log cell content (typed errors with line numbers only — RESEARCH Security extension V7).

```typescript
import type { NumberNotation } from '../money';
export type DateFormat = 'YMD' | 'DMY' | 'MDY';
export type DateFormatGuess =
  | { kind: 'certain'; format: DateFormat }
  | { kind: 'ambiguous'; candidates: DateFormat[] }
  | { kind: 'none' };
export type DecimalMark = '.' | ',';
export type DecimalMarkGuess = { kind: 'certain'; mark: DecimalMark } | { kind: 'ambiguous' };
export type NotationGuess =
  | { kind: 'certain'; notation: NumberNotation }
  | { kind: 'mixed-grouping'; notation: NumberNotation }
  | { kind: 'ambiguous'; candidates: [NumberNotation, NumberNotation] };
export function parseCsvDate(raw: string, format: DateFormat): string | null;
export function inferDateFormat(samples: readonly string[]): DateFormatGuess;
export function inferDecimalMark(samples: readonly string[]): DecimalMarkGuess;
export function inferNumberNotation(samples: readonly string[]): NotationGuess;
export function notationFor(mark: DecimalMark): NumberNotation;
```
Rules:
- `parseCsvDate`: trim; drop a time part after 'T' or after a space followed by `\d{1,2}:`; split on `/`, `-`, `.` or single spaces into three parts; a part that is an English month name or 3-letter abbreviation (jan..dec, case-insensitive) is the month regardless of format; 2-digit years map to 2000+yy; 4-digit years must be 1900..2100; assemble per format; return the zero-padded 'YYYY-MM-DD' only if `isValidLocalDate` accepts it, else null.
- `inferDateFormat`: for each candidate format count samples that parse; drop candidates that fail any non-empty sample; if exactly one remains -> certain; if YMD remains it wins (4-digit leading year is unambiguous); if DMY and MDY both remain -> ambiguous ['DMY','MDY']; none -> none. Ignore empty samples.
- Sample cleaning (shared by the two number inferences): strip leading/trailing spaces, sign characters (- + U+2212 U+2013), parentheses, currency symbols (single-char `\p{Sc}` test), 3-letter codes and DR/CR/D/C/OD tokens at either end; normalise U+2019 to "'" and NBSP/U+202F to ' '.
- `inferDecimalMark`: on cleaned samples — if it contains both '.' and ',' the LAST one is the decimal mark (certain); if it contains only one kind and that separator is followed by exactly 1 or 2 digits at the end -> that mark (certain); followed by exactly 3 digits -> no evidence; conflicting certain votes across samples -> the majority, ties -> ambiguous; no evidence at all -> ambiguous.
- `inferNumberNotation`: decimal from inferDecimalMark (ambiguous -> `{ kind: 'ambiguous', candidates: [notationFor('.'), notationFor(',')] }`); group = the non-decimal separator seen between digit groups in the cleaned samples (',' '.' ' ' "'"), defaulting to the opposite mark when none is seen; grouping = 'indian' when any sample's integer part shows a 2-digit group before the final 3-digit group (e.g. '12,34,567'), 'western' when any shows 3-digit groups beyond the first group ('1,234,567'), and `{ kind: 'mixed-grouping' }` (with the western notation) when both appear.
- `notationFor`: '.' -> { decimal '.', group ',', grouping 'western' }; ',' -> { decimal ',', group '.', grouping 'western' }.
The device locale is never read here. Add `export * from './inferFormat';` to the barrel if Task 1 did not. Commit `feat(02-02): implement CSV date and number-notation inference`.
