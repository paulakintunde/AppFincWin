<open_questions_answered>
Decision "Open for planning" item 3, what a balance shows when no stored rate exists yet for a pair:
- The pair's latest rate is EUR->A and EUR->B from `fx_latest_rates` (any age, frankfurter-v2 preferred on the same date). If either leg is missing, `latestPerEur` returns null and `homeAmountFor` / `projectionHomeAmount` return null. That code already exists and stays as is: no estimate, no fallback, no fetch.
- Month totals already count such rows as unconverted and show `activity.totals.unconverted` ("{{count}} line(s) waiting for a rate"). Unchanged.
- AccountBalanceBlock today hides the home figure silently when it is null. NEW: show `accounts.inHomeWaiting` = 'Waiting for a rate' in the same meta style, without RateAttribution (there is no rate date to show). This reuses the existing "waiting for a rate" wording and is declarative per CLAUDE.md's voice rules.
- The account's own-currency balance is always shown; only the converted figure waits.
- Decide (Phase 4, not built) inherits this contract: an amount whose pair has no stored rate is unconverted, never estimated, and Decide never fetches. This plan's dependency-cruiser rule is the guard. Phase 4 planning must carry the "waiting for a rate" state into its verdict copy.
Production note: fx_rates already holds every quote fx-sync stored from 2026-09-24 to 2026-10-07, so on rollout no currency that existed in the old picker lacks a latest rate. "Waiting for a rate" can only appear for a currency nobody has used yet, until its first line, account or import fetches it.
</open_questions_answered>
