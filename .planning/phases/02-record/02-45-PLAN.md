<objective>
Ship a fixed ISO 4217 currency list inside the app (pure data under `engine/money`) and make it the picker's only ISO source. The `currencies`-table query and the "only currencies with a live rate" filter go away.

Purpose: decision item 1. The 2026-10-07 outage (an empty picker for every user) came from the picker depending on the server `currencies` table and on `fx_latest_rates`. With the list in the app, that class of bug cannot happen.
Output: an engine data module + tests, a server-parity test, a simplified currencyOptions, deleted currencies query/db module, adjusted tests.
</objective>

<open_questions_answered>
- Decision "Open for planning" item 1, client side. Readers of `currencies`: only `src/db/currencies.ts` -> `useCurrencies` -> `useCurrencyOptions`. Readers of `fx_latest_rates`: `useCurrencyOptions` (the live-rate filter, removed here), `AccountBalanceBlock`, `activity.ts` totals, `useStatementImport`, `provisional.ts` (offline provisional stamp). All but the first are conversion reads and keep using `useFxLatest` unchanged (decision item 5). `useCurrencyOptions` itself feeds the picker, `AccountSheet`, `TransactionSheet`, `AccountBalanceBlock`/`useBalanceSummary` (exponent lookup), `useDeviceHomeCurrencyDefault` (region suggestion check) and `useAddCustomCurrency` (code-collision check). All of them keep the same `CurrencyOption` shape, so none needs a change.
- Exponents: `currencyExponent()` (engine) stays the single source. The data file's `exponent` is a literal checked against it by test, and SQL `currency_exponent()` is already mirrored by 07_money_rounding_mirror. The Decide engine is not built yet (Phase 4). It must read exponents from `engine/money` and rates from the cached latest rates. Plan 02-48 enforces "never fetch".
- What the list contains (planner choice, "a fixed ISO 4217 list"): the ISO 4217 active codes that are circulating currencies (drop fund/unit codes BOV CHE CHW CLF COU MXV USN UYI UYW and the precious-metal/SDR/testing codes XAG XAU XBA XBB XBC XBD XDR XPD XPT XSU XTS XUA XXX), intersected with the currencies Frankfurter v2 can price (`GET https://api.frankfurter.dev/v2/currencies` on the snapshot date, keeping entries whose end_date is null or within 30 days of the snapshot date, the same rule as the 2026-10-07 fix). EUR is always included. A code Frankfurter cannot price would leave every line in it "rate pending" forever, so it is left out. The `ISO_CURRENCY_LIST_AS_OF` constant records the snapshot date. The list is updated with app releases (decision item 1).
- `CurrencyOption.rateDate` stays in the type for custom currencies (`as_of`). ISO options always carry `null`: the picker has no dependency on any rate.
</open_questions_answered>
