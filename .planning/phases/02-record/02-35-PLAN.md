    - consistent ledger in file order -> file 'all-verified', every row 'verified', orientation 'as-is'
    - the same ledger newest-first -> orientation 'reversed', all verified (never sorted by date)
    - perturb one amount by δ != 0 -> exactly one link fails ('cannot-verify' on that row) and every other row verifies; file 'partial'

    - blank balances on random rows -> rows between two balanced rows verify by segment

```typescript
export type RowCheck = 'verified' | 'verified-as-group' | 'cannot-verify' | 'no-balance';
export type FileCheck = 'all-verified' | 'partial' | 'none-in-file' | 'ends-only-mismatch';
export interface ReconcileRow { amount: number | null; balance: number | null; localDate: string | null; availableDelta?: number | null }
export interface ReconcileResult { orientation: 'as-is' | 'reversed'; rows: RowCheck[]; file: FileCheck; verifiedLinks: number; failedLinks: number }
export function reconcile(rows: readonly ReconcileRow[], stated: { opening: number | null; closing: number | null }): ReconcileResult;
```
Algorithm (all sums as `BigInt`, compared as bigint):
1. For each orientation (file order, reversed): walk consecutive balanced rows i < j (only unbalanced rows between). Check `B[j] − B[i] = Σ amt(i+1..j)`; for availableDelta files use Σ availableDelta instead of balances. A passing segment marks rows i+1..j 'verified'; a failing one marks them pending-fail. Before the first balanced row: if stated.opening is present, treat it as B[−1]. Count verified links.
2. Choose the orientation with more verified links; ties -> the one whose dates are non-decreasing more often (date-ascending), then 'as-is'.
3. Same-day jitter: for each failing segment, if the whole same-localDate block containing it has boundary balances with `B_end − B_start = Σ block`, mark the block's rows 'verified-as-group'.
4. Stated opening + closing: check `opening + Σ amt = closing`. If there are no running balances at all: match -> all rows 'verified' (file all-verified); mismatch -> all rows 'cannot-verify', file 'ends-only-mismatch'. With running balances present, a failing ends check adds no extra flags beyond the failing links (it is reported by the links).
5. Rows never covered by any balance or stated figure -> 'no-balance'. File: no balances and no stated figures -> 'none-in-file'; every row verified/verified-as-group -> 'all-verified'; else 'partial'.
6. A row whose amount is null makes its segment fail.
Results are indexed in the ORIGINAL row order regardless of the chosen orientation. No `>= 0` checks. Barrel: append `export * from './reconcile';`. Commit test then feat.
