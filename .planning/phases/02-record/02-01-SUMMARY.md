## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] Fixed `jest.config.js`'s `testMatch` so Jest can find any test file at all inside this worktree**
- **Found during:** Task 1, first attempt to run `npx jest src/engine/recurring` to confirm RED
- **Issue:** Every `npx jest` invocation reported "No tests found... 241 files checked... testMatch: ... - 0 matches" — for every folder, not just this plan's. Root cause: this worktree lives at `.claude/worktrees/agent-<id>/`. Jest's `testMatch` normalization (`jest-config`) escapes `rootDir` for glob-safety, then `jest-util`'s `replacePathSepForGlob` converts backslashes to forward slashes for every backslash *except* one immediately followed by a regex-special character — including `.`. Since the worktree path contains `\.claude\worktrees\...`, that one backslash survives, producing a mixed-separator glob (verified via `npx jest --showConfig`) that matches zero of the 241 candidate files on Windows. This is an environment-level bug, not caused by this plan's own changes, but it blocked verifying every task in the plan, including running the plan's own literal `<verify>` commands.
- **Fix:** Changed `testMatch` from `['<rootDir>/src/**/*.test.ts?(x)', '<rootDir>/supabase/functions/**/*.test.ts']` to `['**/src/**/*.test.ts?(x)', '**/supabase/functions/**/*.test.ts']` — anchoring with `**/` instead of the `<rootDir>` token sidesteps the broken substitution entirely (the existing `testPathIgnorePatterns` still excludes `node_modules`).
- **Files modified:** `jest.config.js`
- **Verification:** Ran the plan's own exact `<verify>` commands (`npx jest src/engine/recurring`, then with `--coverage --collectCoverageFrom=... --coverageThreshold=...`) and they now match and run correctly. Ran the full repo suite afterward (`npx jest`, no path filter): 77 suites now discovered (previously 0), 1328/1329 tests passing — confirming the fix is correct and introduces no regressions.
- **Committed in:** `e02d180` (Task 1 commit, alongside the RED fixture/test) and `8b4b468` (Task 2, comment/coverage-bucket follow-up edit to the same file)

**2. [Scope Boundary] Logged, did not fix, a pre-existing flaky test found while verifying the fix above**

- **Issue:** `src/features/you/__tests__/YouScreen.test.tsx` › `YouScreen identity › renders the user's full name and email sub-label` failed with `Exceeded timeout of 5000 ms for a test`. This is a Phase 1 (money-core) test, untouched by this plan, and out of scope per the Scope Boundary rule.
