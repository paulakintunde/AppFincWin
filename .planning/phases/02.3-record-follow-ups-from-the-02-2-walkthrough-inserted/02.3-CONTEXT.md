# Phase 02.3: Record follow-ups from the 02.2 walkthrough - Context

**Gathered:** 2026-10-12
**Status:** Ready for planning

<domain>
## Phase Boundary

Six requests from the Phase 02.2 device walkthrough, on existing Record surfaces. No new top-level feature:

- **REC-26:** after a statement is parsed, choose between reconciling it against entries already made and loading it as new entries.
- **REC-27:** categorise manual entries from the description, with a user-editable rules list.
- **ACC-14:** the signed-out screen offers "Continue as <previous account>" or "Use a different account".
- **REC-28:** the entry sheet's amount is a compact field, and the number keypad opens only on tap.
- **REC-29:** the entry sheet's account picker has "Add account", which returns with the new account selected.
- **REC-30:** bulk "Add to list" in the entry sheet, up to 30 per type, editable, kept as a draft, saved in one step with one Undo.

Out of scope:
- The Phase 3 shell rework: bottom-sheet migration, tabs, FAB, back history.
- Any new import format.
- Any change to the duplicate engine's rules.

</domain>

<decisions>
## Implementation Decisions

### Import: reconcile vs new entries (REC-26)
- **D-01:** The choice is asked **after the file is read** and the format is confirmed, just before review.
  - The prompt can state the overlap, e.g. "This statement overlaps 24 lines you already have".
  - It applies to PDF, CSV, OFX and paste-free statement imports. Paste-a-list is not a statement and keeps its current flow.
- **D-02:** **Reconcile mode leads with missing lines.**
  - Statement lines with no match in the app are listed, flagged as missing, and added on approval.
  - Lines already recorded collapse into one summary row ("18 already recorded").
  - *(Revised 2026-10-12, see D-23)* App lines absent from the statement are also shown, read-only, in a collapsed section.
- **D-03:** In reconcile mode the missing lines **start ticked**. The button reads "Add N lines", and the user can untick any line.
- **D-04:** **New-entries mode keeps today's duplicate check.**
  - Every line loads.
  - Likely duplicates stay flagged "Possible duplicate" and unticked (REC-16 `findDuplicates`, unchanged).
- **D-05:** Both modes keep the rest of the existing pipeline unchanged: transfers, pay-match, refunds, fee links, the review gate for unverified rows, and the single import undo step.

### Auto-category and rules (REC-27)
- **D-06:** **The category is guessed as you type** in "What is it for?".
  - When the description matches, the Category row fills in and carries a small "suggested" tag. Choosing another category clears the tag.
  - A category the user picked by hand is **never** overwritten.
  - Editing an existing transaction does not re-guess unless its category is empty.
- **D-07:** **The app learns automatically.**
  - The user's most recent category for a description is reused, using the same learned map as import (`buildLearnedMap`).
  - Precedence: **user rules > learned map > built-in keyword rules > Income default for money in > none.**
- **D-08:** **Rules are managed at You → Categories → Rules.**
  - The user can add rules such as "contains *Tesco* → Groceries", and edit or remove them.
  - When the user overrides a suggestion, the app offers to make it a rule: "Always use Groceries for Tesco?" (one tap creates the rule; dismissing it does nothing).
- **D-09:** **Matching is "contains a word."**
  - Case- and accent-insensitive, using `normaliseDescription`.
  - Whole-word matches beat part-word matches, and longer keywords beat shorter ones.
- **D-10:** User rules can target any active category, custom ones included. The current `DEFAULT_KEYWORD_RULES` only target builtins.
- **D-11:** Rules apply to manual entry and paste. They also feed the import category guess, in the same precedence order.

### Faster entry sheet (REC-28, REC-29, REC-30)
- **D-12 (REC-28):** **Compact amount field.**
  - A single "Amount" line sits under the Money out / Money in / Transfer chips. Tapping it slides up the in-app number pad.
  - Tapping elsewhere or pressing Done hides the pad.
  - A **new entry opens with the pad closed**, so the description and other fields are visible without scrolling.
  - This builds on the `activeField` model from quick 261010-kpe.
  - Cross-currency transfers keep their second amount line in the same compact style.
- **D-13 (REC-29):** **"Add account" from the picker.**
  - The account picker ends with "Add account", which opens `AccountSheet` over the entry.
  - On save the user returns to the entry with the new account selected, and nothing already typed is lost.
  - This follows the ImportScreen `onSaved(id)` pattern. On a transfer, "Add account" works for both From and To.
- **D-14 (REC-30):** **The list sits under the form.**
  - "Add to list" sits beside Save. It validates the entry, appends it to a list at the bottom of the sheet ("3 in list · £142.50") and clears the form for the next entry.
  - Tapping a listed item edits it in the form; swiping removes it.
  - "Save" writes the current entry (if valid) plus every listed item **in one step with a single Undo**.
- **D-15:** **The list can mix types,** up to **30 of each type** (money out, money in, transfer). Each item is tagged with its type. When a type reaches 30, "Add to list" is disabled for that type with a declarative note.
- **D-16:** **What "Add to list" carries over:**
  - It **keeps the account, date and type**.
  - It clears the amount, description, category, note and toggles.
- **D-17:** **Draft persistence.**
  - The list is saved on the phone as a draft.
  - Opening Add again offers "You have N unsaved entries — Continue / Discard".
  - Cancel with items asks before discarding.
  - Signing out clears it: the key uses the `fincwin:` prefix, so it is covered by `wipeDeviceData`.
  - The draft is per user and per household, and is never synced to the server.

### Sign-in account chooser (ACC-14)
- **D-18:** **What is remembered after sign-out:**
  - Only the **display name, email and provider** (Google or Apple).
  - No tokens and no financial data.
  - Device data is still wiped on sign-out as today. This identity is stored **outside** the `fincwin:` wipe prefix, as a single small record.
- **D-19:** **"Continue as <name>" is one tap.**
  - It signs back into that Google account without the picker when Google allows it (silent / previous sign-in), and falls back to the picker otherwise.
  - "**Use a different account**" always opens Google's account list: call `GoogleSignin.signOut()` / clear the cached Google account first.
- **D-20:** **"Not you? Remove"** on each tile clears that remembered account. Deleting the FincWin account removes it from the list.
- **D-21:** *(Revised 2026-10-12)* **Up to 3 recent accounts are remembered**, most recent first, each tile with its own "Remove". A 4th account signing in drops the oldest. Same fields as D-18 (name, email, provider; no tokens). Originally "only the last one"; the user brought the multi-account option into scope.
- **D-22:** **Apple** follows the same tile when its sign-in is enabled. It is disabled today (`EXPO_PUBLIC_APPLE_SIGNIN_ENABLED`); build the provider-neutral shape now.

### Added 2026-10-12 (brought into scope after the first pass)
- **D-23 (REC-26):** In reconcile mode, **app lines in the statement's period that are not on the statement** appear in a **collapsed section below**: "In the app but not on this statement (3)".
  - Read-only: the import never changes or deletes them. Tapping one opens its detail.
  - The period is the statement's stated period, else the first–last row dates (02.1 D-24 handling).
  - Lines the matcher already linked or excluded (duplicates, pay-matched, matched transfers) are not extras. Pending or scheduled lines count only if paid or received.
  - The planner defines the matching tolerance so near-date or near-amount entries don't show as false extras (reuse `findDuplicates` matching in reverse).
- **D-24 (REC-27, household rules):** Each rule is **Shared (household)** or **Just me**. **Any household member** can add, edit or remove a shared rule; changes go through the normal undo/history so who changed what is visible.
- **D-25:** **Precedence:** the user's own rule > shared household rule > learned map > built-in keyword rules > Income default > none.
- **D-26:** A shared rule **points to a category by name and kind** (e.g. "Groceries", expense). For each member it resolves to their active category with that name; if they have none, the rule is skipped for them and shown in Rules as "not in your categories". Personal rules point at the user's own category id.
- **D-27:** **Rules are stored server-side.** Personal rules are owned by the user; shared rules are scoped to the household with household-member RLS (the same membership checks as other household data). New migration and pgTAP; rules sync across devices.

- **D-28 (REC-30, user 2026-10-12, UI-SPEC A4):** **The bulk list allows repeating entries.**
  - A listed item can carry Repeats like a single entry, and counts as 1 item toward its type's 30.
  - Saving the list creates each series with the other rows under the one Undo.
- **D-29 (ACC-14 / REC-26 / REC-27, user 2026-10-12, UI-SPEC A3, A9, A12):**
  - The one-tap "Always use … for …?" rule is **Just me**.
  - The reconcile/new choice is **always shown**, including "0 lines overlap".
  - The tile keeps the wording **"Not you? Remove"** on its own line.

- How the reconcile "missing" decision reuses `findDuplicates` output: missing = not matched.
- The draft storage key format and the schema version for the draft.
- The haptics already in the app for the new actions (Add to list, Remove).

## Existing Code Insights

### Reusable Assets
- `src/engine/categorize/guessCategory.ts`: `normaliseDescription`, `buildLearnedMap`, `guessCategory`, `DEFAULT_KEYWORD_RULES`. Extend with user rules and the precedence from D-07.
- `src/engine/statement/duplicates.ts` `findDuplicates`: reconcile "missing" = rows without a match.
- `src/data/mutations/batchInsert.ts` `insertRowsAsOneStep`: chunked insert with one undo step, already used by clone-month and paste. Template: `src/data/mutations/pasteLines.ts`. It needs per-row account, currency, status and fields, plus a new batch label.
- `src/features/record/accounts/AccountSheet.tsx`: `mode {kind:'new'}` and `onSaved(id)`, as already used inline by `ImportScreen.tsx:152-159`.
- `src/features/record/activity/activityViewPrefs.ts`: AsyncStorage JSON prefs pattern for the draft.
- `src/services/auth/google.ts`: Google sign-in (`configure`, `signIn`, `signInWithIdToken`). `hasPreviousSignIn`, `signInSilently` and `signOut` are not used yet.
- `src/services/storage/wipe.ts` `wipeDeviceData`: removes `fincwin:`-prefixed keys. The remembered identity must deliberately live outside that prefix (D-18).

### Established Patterns
- **Entry sheet** (`src/features/record/entry/TransactionSheet.tsx`): one sheet for out, in and transfer. Pickers are siblings driven by `picker: PickerKey`. `activeField` drives keypad visibility.
- **Pickers** (`src/features/record/entry/pickers/AccountPicker.tsx`, `CategoryPicker.tsx`) are plain `Sheet`s of `Row`s.
- **Import review** (`ReviewStep.tsx`, `useStatementImport.ts`): rows start `included: duplicate === null`. The "Possible duplicate" tag already exists.
- **Copy** goes in the typed i18n catalogue `src/i18n/locales/en.ts`, guarded by the copy voice test.

### Integration Points
- A new **user category-rules table**: a migration with RLS/owner, a pgTAP test, and db/queries/mutations, managed on the Categories screen.
- The **reconcile/new choice** sits as a new import stage between format confirmation and review in `useStatementImport.ts`, rendered in `ImportScreen.tsx`.
- The **WelcomeScreen** gains the remembered-account tile. The remembered identity is written on sign-in success and kept on sign-out.

</code_context>
