# Phase 02.3 Plan 19: Entry list wiring Summary

New entries can be listed, edited, removed and saved together through `useBulkAdd` with one Undo ("Added n entries"); the list draft is resumed, kept on accidental close and asked about on Cancel.

## What was built
- `EntryListFooter`: Add to list (secondary) beside Save (primary), cap note, finish-current error, plus `listSummaryText` shared with the screen-reader announcement.
- `TransactionSheet` (new entries only): `useEntryList`, `EntryList` below the footer, `validateCurrent` shared by Add to list and list saves, `addCurrentToList` (clears per D-16, resets Repeats/origin/offer, closes the pad), `saveWithList` (oldest first plus the form entry when it has content; partial invalid form blocks with the finish-current message), `editItem`/`loadItem` with the replace prompt, resume / cancel-with-items ConfirmSheets. Sheet swipe-down / back still calls `onClose` directly so the draft survives.
- Tests: new `TransactionSheet.list.test.tsx` (23 tests) and a `@/data/mutations/bulkAdd` mock in the five existing sheet test files.

## Deviations from Plan
- Tasks 1 and 2 touch the same file and were committed together in one commit (87f643d) rather than two.
- `save()` was not refactored onto `validateCurrent`; the single-save path is byte-for-byte unchanged and `validateCurrent` is a separate helper used by the list paths (keeps single saves provably unchanged).
- Scroll-to-top after Add to list was skipped: `SheetScroll` does not forward a ref and `Sheet.tsx` is outside this plan's files (plan allows skipping).
- `categoryNameOf` now falls back to the active category list when the id is missing from `byId`.
- Save is also disabled when the list holds a transfer and the transfer category has not loaded (otherwise `useBulkAdd` would throw).
- Tests use real timers with `waitFor`/`findBy` rather than fake timers. The 30-cap case is seeded from a stored draft instead of 30 typed adds.
