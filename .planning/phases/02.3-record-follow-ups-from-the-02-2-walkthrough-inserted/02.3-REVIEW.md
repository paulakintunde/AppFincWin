# Phase 02.3: Code Review Report

**Scope:** `git diff 3ed62b4 c2dd26c -- src app supabase`, 67 non-test files, read against the tests and the phase context.
**Result:** no critical or high findings. Six medium and eight low.

## Areas that held up

- **Engine boundary:** `src/engine/**` (entryList, categorize, statement/extras, undo) imports only from other engine modules. Nothing reaches into db, state, services, ui or react.
- **Money:**
  - `buildEntryListWrite` signs amounts from integer minor units.
  - `summarise` never adds across currencies and ignores transfers.
  - `prefillAmountInText` goes through `convertMinor` (BigInt, half-up) with `Math.abs` on a parsed minor value.
  - No float arithmetic anywhere in the new money paths.
- **category_rules RLS and grants:**
  - Policies, column grants and the `fill_category_rule` and `guard_category_rule` triggers are sound.
  - Ownership and household are server-set. Scope, owner and household are immutable.
  - Personal insert and update require a non-system category the caller owns.
  - Anon has nothing, and there is no delete grant.
- **record_entry_list:**
  - Security definer with `search_path=''` and fully qualified references.
  - The replay check runs before row checks.
  - It requires every id to be a live, own, version-1, unseries'd row in a household the caller belongs to, with 1..200 unique ids.
  - Anchors must be unique members of `p_row_ids`.
  - All-or-nothing, with a single `undo_log` row.
  - Execute is revoked from public and anon.
- **apply_patches and undo_log_fill:** the `category_rules` additions (allow-list, column list, type map, scope checks, category ownership check, already-applied branch) mirror the table RLS. The 42501 raise is correct.
- **Rule edit and remove replay:** `acceptIfAlreadyApplied` compares timestamps by instant, so the client-ISO `deleted_at` does not produce a false conflict.
- **Remembered accounts privacy:**
  - Stored under `fincwin-identity:`, outside the `fincwin:` wipe prefix, as intended.
  - Never passed to analytics, `captureError` or logs.
  - Stored in AsyncStorage, not SecureStore.
- **Local onUndo toast:** in-memory only, never serialised, and `restore()` is guarded by the mounted and epoch refs.

## Medium

### MD-01: Learned map can suggest an archived (or system) category in the entry sheet
**File:** `src/features/record/useGuessContext.ts:62-69`, consumed by `src/features/record/entry/TransactionSheet.tsx:96-108`
**Issue:**
- `buildLearnedMap` is fed every categorised row name with no filter on category state. Personal and shared rules are resolved against active, non-system categories only.
- Scenario: the user archived "Coffee", and an older row named "Costa" still points at it. They type "Costa". `guessCategory` returns `source:'learned'` with the archived id, and the effect writes it into `state.categoryId`.
- The Category row shows "Uncategorised" with a "Suggested" sublabel, because `categories.active.find` misses it. Save then writes the archived category id.
- The same applies to a learned id that is a system category such as Settlement. The import and paste paths share the same context.

**Fix:** drop learned entries whose id is not in the eligible set.
```ts
const eligible = new Set(memberCategories.filter(c => c.active && !c.system).map(c => c.id));
const learned = useMemo(() => buildLearnedMap(
  (namesQuery.data ?? []).filter(n => eligible.has(n.category_id)).map(...)), [namesQuery.data, memberCategories]);
```
Alternatively, validate the guessed id against `categories.active` in `applyGuess`.

### MD-02: Rule offer for an existing exact keyword fails silently while a success toast and Undo are shown
**File:** `src/features/record/entry/categorySuggest.ts:49`, `src/features/record/entry/TransactionSheet.tsx:305-319`
**Issue:**
- `ruleOfferFor` suppresses the offer only when a personal rule has the same keyword and the same category (`hasRuleFor`).
- Scenario: the user has the personal rule "netflix" -> Subscriptions, types "Netflix", gets Subscriptions as `suggested`, and picks Entertainment. An offer for the same `keyword_norm` with a different category is shown.
- Accepting hits `category_rules_personal_keyword` (23505). `insertCategoryRule` finds no row with that id and rethrows. `onError` removes the optimistic row and records a failed write, with no user feedback.
- Meanwhile `acceptOffer` has already toasted "Rule added" with Undo.

**Fix:**
- In `ruleOfferFor`, return null (or an "update rule" offer) when any personal rule has the same `keywordNorm`.
- Alternatively, show the toast only after success.

### MD-03: Reconcile "extras" are computed from a fetch window narrower than the statement period
**File:** `src/features/record/import/useStatementImport.ts:433` (range) versus `:579-583` (period)
**Issue:**
- `stored` is fetched for `[firstRowDate-2d, lastRowDate+2d]`, but `statementPeriod` prefers the stated `periodStart` and `periodEnd`.
- Scenario: the statement is 1-31 Mar and its first and last lines are 5 Mar and 28 Mar. App lines on 1-2 Mar and 31 Mar are never fetched, so they cannot be reported as "in the app but not on the statement". The feature then reports fewer extras than exist, with the period it claims to cover.

**Fix:** fetch `{ from: min(range.from, period.from), toInclusive: max(range.toInclusive, period.toInclusive) }`, or compute the period first and use it for the range read.

### MD-04: `existingChecked` is true when the range read failed and any unrelated cached query array exists
**File:** `src/features/record/import/useStatementImport.ts:455-462`
**Issue:**
- `cachedArrays` is every array under `transactionsRoot` (any month, any account, plus derived arrays). Its length being greater than 0 enables Reconcile with the "overlap" claim.
- Scenario: offline, with only another month cached. The overlap count is 0, so every line shows as "missing". Committing in reconcile mode re-imports lines that already exist.
- Reconcile exists to prevent exactly that.

**Fix:** set `existingChecked` only when `rangeRead.ok`, or when cached month queries cover every month in `[range.from, range.toInclusive]`. Otherwise show the "unchecked" copy.

### MD-05: Bulk save can leave committed rows with no undo step while telling the user "Nothing was changed"
**File:** `src/data/mutations/bulkAdd.ts:96-117` (mutationFn), `:222-241` (onError)
**Issue:**
- The rows are inserted in one request and `record_entry_list` runs afterwards.
- If the RPC is refused with a permanent error (22023 or 42501, class `rejected`), the rows stay on the server with no undo step.
- `onError` shows `undo.batchRefused` ("That batch couldn't be saved. Nothing was changed.") and removes them from the cache, so they reappear after the invalidate.
- Transient errors retry correctly (insert is idempotent and the RPC replays). The permanent case is the gap.

**Fix:** on a rejected RPC, soft-delete the just-inserted ids via `apply_patches`, or fall back to `recordUndoStepSafely` with `inverseOfInserts`. Otherwise change the copy so it does not claim nothing changed.

### MD-06: Draft validation allows a cross-currency transfer without a received amount, and the save path then silently reuses the sent amount
**File:** `src/engine/entryList/draft.ts:75-80` and `src/data/mutations/bulkAdd.ts:82`
**Issue:**
- `parseItem` accepts a transfer whose `toCurrency` differs from `currency` with `amountInMinor === null`. It also accepts a transfer with `toCurrency === null`.
- `buildEntryListWrite` uses `item.amountInMinor ?? item.amountMinor`. A corrupted or stale draft saves 100 GBP -> 100 JPY as a real transfer.
- `buildTransferLegs` only rejects a same-currency mismatch. The draft is the only untrusted input here, since `itemFromForm` always supplies the figure, but the engine comment promises strict validation.
- A null `toCurrency` throws a `TypeError` from the `save` handler, which crashes the sheet.

**Fix:**
- In `parseItem`, for transfers require `toCurrency !== null`, require `amountInMinor !== null` when `toCurrency !== currency`, and require null otherwise.
- In `buildEntryListWrite`, throw instead of falling back to `amountMinor` when currencies differ.

## Low

### LW-01: Remembered accounts are not removed on account deletion, and Apple is never handled
**File:** `src/features/auth/rememberedAccounts.ts:7`, `src/services/auth/google.ts:91`
**Issue:**
- Email and name outlive sign-out by design. `forgetGoogleOnAccountDeletion` is exported but has no caller (the comment says Phase 10).
- It covers only Google. Apple entries have no deletion path.
- Until Phase 10 wires it, the in-app deletion does not purge this PII (GDPR erasure).

**Fix:**
- Add a provider-agnostic `clearRememberedAccounts()` and call it from the deletion flow.
- Track the wiring as a Phase 10 acceptance item.

### LW-02: `amountInManual` is never reset when the transfer currencies change
**File:** `src/features/record/entry/TransactionSheet.tsx:195`, `:273-289`
**Issue:**
- After the user keys a received amount, `amountInManual` stays true.
- `withToAccount` and `withAccount` keep `amountInText` for a cross-currency to cross-currency change. The figure in the old currency is silently kept and saved.
- If the pair becomes same-currency, `dropStaleAmountIn` clears the text. Switching back to a cross-currency pair then leaves the field empty with no prefill.

**Fix:** reset `setAmountInManual(false)` (and clear `amountInText`) whenever `state.toCurrency` or `state.currency` changes. Do this in the picker `onSelect` handlers, not in an effect.

### LW-03: Undo of a rule removal can fail with a raw unique violation
**File:** `supabase/migrations/20261012000200_category_rules_patches.sql` (Phase B update), `src/engine/undo/inverse.ts`
**Issue:**
- Scenario: remove rule "tesco", add a new live "tesco" rule, then Undo the removal.
- Restoring `deleted_at = null` violates `category_rules_personal_keyword`. 23505 propagates out of `apply_patches` as a generic error instead of a structured conflict.

**Fix:** in `apply_patches`, for `category_rules` ops that clear `deleted_at`, pre-check for a live rule with the same scope key and return `status:'conflict'` (reason `changed`, `record_name` = keyword).

### LW-04: `useFxLatest().data ?? []` gives the prefill effect a new dependency every render
**File:** `src/features/record/entry/TransactionSheet.tsx:196`, `:289`
**Issue:**
- While rates are undefined, `[]` is a new array each render, so the effect re-runs every render. The guard `s.amountInText === next ? s` prevents a loop.
- The effect still does wasted work and is fragile.

**Fix:** use a module-level `const NO_RATES: readonly FxLatestRow[] = []`.

### LW-05: The Sheet slide animation can flash the sheet fully open on re-open
**File:** `src/ui/Sheet.tsx:62-67`
**Issue:**
- `slide` keeps its end value 0 after the first open. On re-open (the same component instance, `visible` toggled), the first frame renders at translateY 0 and only the passive effect resets it to `height`.
- The sheet can paint fully open for one frame, then jump down and slide up.

**Fix:** reset the value when closing (`if (!visible) slide.setValue(height)`) or use `useLayoutEffect`. Consider honouring reduce-motion.

### LW-06: `continueDraft` can push the list above the per-type cap
**File:** `src/features/record/entry/useEntryList.ts:117-123`
**Issue:**
- Items added while the resume prompt is pending are merged with all stored items unchecked. Per-type counts can exceed `LIST_CAP_PER_TYPE`.
- It does not break the 200-row limit (maximum about 120 rows), but it breaks the stated cap and `canAdd`.

**Fix:** fold the stored items through `addItem` and report the overflow in `dropped`.

### LW-07: Extras detail for a transfer leg and stale extras after edit
**File:** `src/features/record/import/ExtrasDetail.tsx:37`, `src/features/record/import/ReviewStep.tsx`
**Issue:**
- `counterpartAccountId: null` is hard-coded, so deleting a transfer leg from the extras list shows the transfer-delete confirm with an empty destination account name.
- After an edit or delete in the detail sheet, `state.extras` and `extraRows` are not refreshed, so the row stays listed.

**Fix:** resolve the counterpart from `row.transfer_id`, or exclude transfer legs from extras. Drop extras whose rows are deleted.
