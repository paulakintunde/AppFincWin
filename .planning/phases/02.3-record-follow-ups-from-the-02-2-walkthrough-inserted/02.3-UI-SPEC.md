# Phase 02.3 — UI Design Contract (Record follow-ups)

> Visual and interaction contract. Generated by gsd-ui-researcher, to be verified by gsd-ui-checker. Baseline: `02.2-UI-SPEC.md` (approved 2026-10-09), `02.1-UI-SPEC.md`, `02-UI-SPEC.md`, `00-UI-SPEC.md`. Product decisions: `02.3-CONTEXT.md` D-01..D-27 (locked). Technical seams: `02.3-RESEARCH.md`.

**Platform note:** React Native / Expo SDK 57. No shadcn, no CSS. Styling is `StyleSheet` + `useTheme()` / `textRole()` from `src/theme/*`. **This phase adds no colours, no type sizes, no radii, no spacing values, no icons, no gradients and no shadows.** Every surface below is composed from `src/theme/tokens.ts`, `layout.ts`, `typography.ts` and the existing primitives in `src/ui/` (`Sheet`, `SheetHeader`, `Row`, `Pill`, `Chip`, `ConfirmSheet`, `EmptyState`, `Keypad`, `SwipeRow`, `ToggleRow`, `CategoryGlyph`, `ToastView`) plus the import helpers in `src/features/record/import/importUi.tsx` (`T`, `Heading`, `Actions`, `Tag`, `SuggestionCard`). Where this document says "reuse", the executor must not re-style.

**Scope surface (what this phase touches):**
1. Import (`import/ImportScreen.tsx`, `ReviewStep.tsx`, new `ReconcileChoice.tsx`): the "check for missing / add as new" step and the reconcile review (REC-26).
2. Entry sheet (`entry/TransactionSheet.tsx`, `pickers/AccountPicker.tsx`, new `EntryList.tsx`, `useEntryDraft.ts`): compact amount + keypad on tap (REC-28), suggested category + rule offer (REC-27), Add account (REC-29), Add to list + draft (REC-30).
3. Categories (`categories/CategoriesScreen.tsx`, new `RulesScreen.tsx`, `RuleSheet.tsx`): Rules list and add/edit sheet (REC-27).
4. Welcome (`auth/WelcomeScreen.tsx`, `GoogleSignInButton.tsx`): recent-account tiles and "Use a different account" (ACC-14).

Nothing else changes. The Phase 3 shell rework (bottom-sheet migration, tabs, FAB, back history) is out of scope; it carries these surfaces over later.

## Interaction Contract

### 1. Import: check for missing lines, or add as new (REC-26; D-01..D-05, D-23)

**Where:** a new import stage `choose-mode`, after the format is confirmed (and after mapping for CSV) and before review, for **CSV, OFX/QFX and PDF**. Paste-a-list never shows it. Rendered by `ReconcileChoice` inside `ImportScreen`'s `StageView`, in the same un-sheeted step layout as `FormatStep` (heading, body, rows, `Actions`).

**1a. Checking state** (the existing-entries read and duplicate pass run first, RESEARCH Pattern 3):
- `ActivityIndicator` (accent) + Body line "Checking against your entries…" with `accessibilityLiveRegion="polite"`. Same layout as `ReadingProgress`. No Back during this state; Cancel stays available.

**1b. The choice:**
- Heading (Sheet title): "Choose how to add this statement"
- Body sentence (Body, `ink`): "This statement overlaps {count} lines you already have." (singular "1 line"); when the overlap is 0: "0 lines overlap with entries you already have."
- The choice is **always shown**, including at 0 overlap (user decision 2026-10-12).
- Two `Row`s, each with a sub-label and a chevron; **tapping a row proceeds** (one tap, no separate Continue):

| Row | Label | Sub-label |
|-----|-------|-----------|
| Reconcile (listed first) | "Find what's missing" | "Adds only lines that aren't recorded yet" |
| New entries | "Add every line" | "Likely duplicates are flagged and left unticked" |

- `Actions` below: "Back" / "Cancel" (secondary pills, existing keys). Back returns to the stage that preceded (format or mapping); Abandon mapping treats `choose-mode` like `format`.
- **Existing entries could not be read** (offline with no cache, or a failed read): the overlap sentence is replaced by "Your existing entries couldn't be checked, so nothing can be matched yet." and the reconcile row is shown disabled (`accessibilityState.disabled`, 0.4 opacity, as the disabled Google button) with sub-label "Needs your entries to load. Try again when you're online." "Add every line" stays available.

**1c. New-entries mode** = today's review exactly (D-04): every line listed, duplicates unticked with "Possible duplicate", commit "Import {n} transactions". No visual change.

**1d. Reconcile review** (same `ReviewStep` FlashList, same row anatomy, same tick, same footer gate, same `matches` continuation):
- Heading (Sheet title): "{count} lines aren't recorded yet" / "1 line isn't recorded yet". The balance reconciliation sentence and rates-pending note keep their place under it.
- **Missing rows first**: every unmatched line, **ticked by default** (D-03), each carrying the `Tag` "Missing" (`fill1` / `inkMuted`) beside its category chip. Category chip, issues and "Can't verify" behave exactly as today. The user can untick any row.
- **Near-match hint** (display-only, RESEARCH A10, `EXTRA_NEAR_WINDOW_DAYS = 3`): when a missing row pairs with an extra of equal amount within 3 days, both rows get a Label-role `inkMuted` line under the tags: on the missing row "Might be the same as {name} on {date}", on the extra "Might be the same as the statement line on {date}". The missing row **stays ticked**; the hint never changes a default.
- **"Already recorded" summary row** (after the missing rows, `groupGap` above): one `Row` "{count} already recorded" with a chevron, collapsed by default. Tapping expands the matched statement lines beneath it in today's row anatomy, **unticked**, with the existing "Possible duplicate" tag replaced by "Already recorded" (same `Tag`). A user can tick one to add it anyway (same override the new-entries mode allows). Tapping the row again collapses it. Hidden when the count is 0.
- **Extras section** (last, `groupGap` above): a disclosure `Row` "In the app but not on this statement ({count})", collapsed by default, hidden when 0. Expanded: a Label-role `inkMuted` note "The import leaves these as they are." then one row per extra: name (Body, `ink`), date (Label, `inkMuted`), signed amount (Body; normal sign rules), **no tick**, row `accessibilityRole="button"`. Tapping opens the existing transaction **detail sheet** (02.2 section 5) unchanged. Render at most 50 rows expanded, then a `Row` "Show {n} more" that appends the next 50.
- **Commit:** when there are no transfer/pay matches, the primary pill reads "Add {n} lines" / "Add 1 line" (accent), disabled at 0 ticked. With matches, today's "Continue" flow is unchanged and the final commit keeps today's label. Success toast and the single import undo step are unchanged ("Imported {n} lines").
- **Nothing missing:** heading becomes "Everything on this statement is already recorded." (Sheet title), no missing rows, the summary and extras rows still render, and the actions are "Close import" (secondary, closes the import, nothing is written) / "Back".

**Focal point:** the missing rows. The summary and extras rows are deliberately quieter (plain rows, collapsed).

### 2. Entry sheet: compact amount, keypad on tap (REC-28; D-12)

- The 44px `AmountDisplay` block is replaced by **one compact field** directly under the Money out / Money in / Transfer chips (new entries) or at the top (edit).
- Field: `Pressable`, `minHeight` 44, `fill1` fill, radius `radii.card / 2` (13, the existing input style), padding 16 horizontal / 8 vertical, 1.5px border (transparent at rest, `accent` while the keypad is open). Content: left, the value in Sheet title role (`ink`; transfers `↔ ` + `inkDim`) or the placeholder "Amount" (Body, `inkFaint`); right, the currency code (Label, `inkMuted`, display only; currency is still changed through the Currency row).
- **Keypad visibility** (`activeField: 'amount' | 'text' | 'none'`):
  - A **new entry opens with the keypad closed** (`'none'`). **Edit also opens closed.** (Assumption A1.)
  - Tapping the amount field opens the existing `Keypad` directly below it (`'amount'`), dismissing any OS keyboard first.
  - A right-aligned text button **"Done"** (Label 13/600, `ink`, 44x44 hit) sits on the row under the keypad; it closes the keypad (`'none'`).
  - Tapping any other control (text field, picker row, chip, toggle, date) closes the keypad. Tapping blank sheet space closes it.
  - The OS keyboard hiding (`keyboardDidHide`) sets `'none'`, **never** `'amount'` (RESEARCH Pitfall 3; protects the 261010-kpe fix).
- **Cross-currency transfer:** two compact fields stacked, placeholders "Amount sent" and "Amount received" (existing keys `record.sheet.field.amountOut` / `amountIn`); the keypad types into whichever was tapped and the open field shows the accent border. The cross-currency note keeps its place under them.
- Errors (amount parse failures, "Both sides of a transfer…") render directly under the field in Label role `danger`, as today.
- Haptics: unchanged (`hapticSelection` per key).

### 3. Entry sheet: suggested category and the rule offer (REC-27; D-06..D-08)

- **Guess as you type:** on every change of "What is it for?" (debounced 250ms), when the category was not picked by hand, the Category row fills with the guess and shows the `Row` sub-label **"Suggested"** (Label, `inkMuted`). Precedence is the engine's (D-25). When the guess is "none" the row returns to "Uncategorised" with no sub-label.
- A category chosen in the picker is a **hand pick**: the sub-label disappears and typing never changes it again in this sheet. Editing an existing transaction never guesses unless its category is empty (D-06).
- **Rule offer** (D-08): when the user **replaces a suggested category** with a different one and the description is non-empty, a `SuggestionCard` (`fill1`, radius `card`, padding 16) appears directly under the Category row:
  - Text (Body): "Always use {category} for “{keyword}”?" where keyword = the trimmed description as typed, cut to 60 characters (Assumption A2).
  - `Actions`: **"Make it a rule"** (secondary pill) / **"Not now"** (secondary pill).
  - "Make it a rule": creates a **Just me** rule in one tap (user decision 2026-10-12), removes the card, fires `hapticLight`, and shows the toast "Rule added · {keyword}" with Undo. The entry itself is unaffected and still needs Save.
  - "Not now", choosing yet another category, or saving without answering: the card disappears and nothing is stored.
  - Not shown when a rule with the same keyword and category already exists, in transfers, or in Add-to-list edits of the same description twice in one session (offered once per description per sheet).
- Accessibility: Category row label "Category, {category}, suggested from the description"; the card is `accessible` with the full question as its label, its pills are buttons.

### 4. Account picker: Add account (REC-29; D-13)

- `AccountPicker` ends with a `Row` **"Add account"** (dense, chevron, `ink`) after the account rows, always shown (never removed by `excludeId`), in the Account, From account and To account pickers.
- Tap: the picker closes, then the existing `AccountSheet` (`mode {kind:'new'}`, title "New account") opens over the entry sheet on the next frame (avoid stacking two Modals in one tick).
- **Save** in AccountSheet: returns to the entry sheet with the new account selected in the side that asked (Account, From or To), its currency applied as `withAccount` / `withToAccount` do, and the toast "Account added · {name}" (existing undo label). Nothing typed is lost.
- **Cancel / dismiss** AccountSheet: returns to the entry sheet with the picker closed and the previous selection unchanged.
- For a transfer, if the new account is created from To while it would equal From, the same-account error copy applies as today ("Pick two different accounts.").

### 5. Entry sheet: Add to list, the list, and drafts (REC-30; D-14..D-17)

Only **new** entries offer the list. Editing an existing transaction or transfer shows today's footer unchanged.

**5a. Footer buttons** (replace the single full-width Save):
- One row, gap 8: **"Add to list"** (secondary pill, left, flex 1) and **Save** (accent primary pill, right, flex 1).
- Save label: list empty: today's labels ("Save expense" / "Save income" / "Add transfer"). List non-empty: "Save {count} entries" / "Save 1 entry", where count = listed items + 1 when the form has an amount typed.
- "Add to list": runs the same validation as Save, including the Repeats checks (errors appear in place, as today). On success: the entry joins the list, the form clears **amount, description, category (and its Suggested state), note, payment type, Automatic, Refund and Repeats** (Repeats resets to "Doesn't repeat"), and keeps **account, date, type, currency and status**; the keypad stays closed; the sheet scrolls to the top; `hapticLight`; screen readers hear "{name} added to the list. {summary}" via a polite live region.
- "Add to list" **disabled** (with `accessibilityState.disabled` and the note as its hint) when:
  - the current type already has 30 items. Note under the buttons (Label, `inkMuted`): "The list holds 30 money out entries. Save them to add more." (money in / transfer variants below).
- **Save with a list:** if the form is untouched (no amount and no description), Save writes the list only. If the form has content and is valid, it is written with the list. If the form has content but fails validation, nothing is written, the field errors show and a Label `danger` line under the buttons reads "Finish or clear this entry to save the list."
- Save writes everything **in one step with one Undo** (`insertRowsAsOneStep`, label `addedMany`), **including every repeating series** carried by listed items or the current entry (see 5d). Toast: "Added {count} entries" with Undo (ordinary 3.2s). Haptic: `hapticSuccess` (bulk commit precedent). The draft is cleared. Per-row cap warnings are **not** raised for list saves (Assumption A5); a single save keeps its cap toast.

**5b. The list section** (below the footer buttons and any notes, `groupGap` above, still inside the sheet's scroll):
- Header line (Label 13/600, `ink`, `accessibilityRole="header"`): the summary.
  - Single currency, only money out (or only money in): "{count} in list · {total}" (e.g. "3 in list · £142.50").
  - Single currency, both directions: "{count} in list · {out} out · {in} in".
  - Transfers are counted but never added to a total. Transfers only, or more than one currency: "{count} in list".
- Item rows (`SwipeRow` wrapping a dense `Row`-style line, `line1` separators), newest first:
  - Left: name (Body, `ink`, one line, ellipsis). Transfers: "{from} → {to}".
  - Sub-label (Label, `inkMuted`): "{type} · {category or 'Uncategorised'} · {date}" where type is "Money out", "Money in" or "Transfer" (existing chip words). Transfers: "Transfer · {date}".
  - Right: amount (Body). Money out plain `ink`; money in "+" in `accent`; transfers `↔ ` in `inkDim` (02.2 rules).
  - Repeating item: a second sub-label line (Label, `inkMuted`) under the first: "Repeats monthly", "Repeats every 2 weeks, until 12 Mar 2027" or "Repeats monthly, 6 times" (frequency words from the existing `record.recurring.frequency.*` keys). Non-repeating items have no second line.
- **Tap an item** = edit it: it leaves the list and loads into the form (type chip, amount, name, category without the Suggested tag, account, date, note, flags, and its Repeats value into the existing `RepeatsField`). If the form already holds a **valid** entry, that entry is first added to the list. If the form holds an **invalid partial** entry, a `ConfirmSheet` asks: body "Clear what's in the form to edit this one?", actions "Keep typing" (secondary) / "Clear and edit" (primary). (Assumption A6; its "Clear and edit" primary is accent.)
- **Swipe left** reveals the `danger` zone with the word "REMOVE"; a full swipe removes the item from the list (`hapticLight` from `SwipeRow`). No confirm and no toast (the item was never saved). No swipe-right action.
- Accessibility: each row label "{type}, {name}, {amount}, {date}", plus ", {repeat sub-label}" for repeating items; `accessibilityActions`: `activate` = "Edit", custom "Remove from list".
- Restored items whose account is archived or deleted are dropped on load, with a Label `inkMuted` line at the top of the list: "1 entry was left out because its account is no longer available." / "{count} entries were left out…".

**5c. Draft persistence and prompts:**
- The list is written to the device as a draft on every change (debounced). Key `fincwin:entry-draft:v1:{userId}:{householdId}` (inside the wipe prefix; RESEARCH Pattern 4). Never synced.
- **Resume prompt:** opening a **new** entry while a draft exists shows a `ConfirmSheet` over the freshly opened entry sheet:
  - Title: "You have {count} unsaved entries" / "You have 1 unsaved entry"
  - Body: "They were kept on this phone from last time."
  - Actions: **"Discard entries"** (secondary, left) / **"Continue list"** (accent primary, right).
  - "Continue list" loads the list under the form. "Discard entries" deletes the draft. Dismissing the prompt (swipe or back) counts as **Continue list** (no data loss).
- **Cancel with items:** tapping the sheet's "Cancel" while the list has items shows a `ConfirmSheet`:
  - Title: "{count} entries aren't saved yet" / "1 entry isn't saved yet"
  - Body: "Keep the list on this phone for next time, or discard it."
  - Actions: **"Keep for later"** (secondary) / **"Discard list"** (destructive `danger`).
  - Dismissing this prompt returns to the entry sheet.
- **Accidental close** (sheet swiped down, Android back) with items: no prompt; the sheet closes and the draft is kept (resume prompt next time).
- Signing out wipes the draft (prefix). The draft is per user and household.

**5d. Repeating entries in the list** (user decision 2026-10-12, reverses draft assumption A4):
- A listed item can carry Repeats exactly like a single entry: the `RepeatsField` stays visible whether or not the list has items, for money out and money in (transfers have no Repeats today, unchanged).
- **Cap:** a repeating item counts as **1** toward its type's 30, whatever number of occurrences its series later creates. The "Save {count} entries" count also counts items, not occurrences.
- **Save:** each repeating item becomes its first transaction plus its series, created in the same write as every other row, and the whole save is still **one Undo** (the anchor-is-new pattern of the single save, D-24 amendment, applied per item inside the `addedMany` step). Undo removes every row, every series and every occurrence it materialised. The toast stays "Added {count} entries".
- **Draft:** the repeat value (frequency, end rule) is stored with the item and restored with it.
- **Validation:** the existing Repeats errors ("Use a whole number from 1 to 1000.", "The end date is before this entry's date.") block "Add to list" just as they block Save.

### 6. Categories → Rules (REC-27; D-08..D-11, D-24..D-26)

**6a. Entry point:** on the Categories screen, a `Row` directly under the title: label **"Rules"**, sub-label "{count} rules" / "1 rule", or "Fill in a category from the description" when there are none; chevron. Pushes the Rules screen (route chosen by the planner, e.g. `/categories/rules`).

**6b. Rules screen** (`Screen scroll`, same header treatment as Categories: Sheet-title-role title "Rules", `accessibilityRole="header"`):
- Helper (Label, `inkMuted`): "When a description contains a rule's word, its category fills in. Your own rules come before shared ones."
- Primary pill **"Add rule"** (accent), placed as "Add category" is on Categories.
- Section **"Just me"** (Label, `inkMuted`, header role), then section **"Shared with household"**. A section with no rules is omitted. Within a section, rules sort A–Z by keyword.
- Rule row (`Row`, rowPad 15, chevron, tappable to edit):
  - leading: `CategoryGlyph` of the target category (its colour key and first letter);
  - label: the keyword as typed (Body), e.g. "Tesco";
  - sub-label (Label, `inkMuted`): the category name, e.g. "Groceries".
  - Shared rule whose category doesn't resolve for this member (D-26): leading `CategoryGlyph` with the `slate` swatch and the stored name's first letter; sub-label "{name} · not in your categories" (`inkMuted`). The rule is skipped for this member's guesses.
  - Accessibility label: "Description contains {keyword}, category {category}, {Just me | Shared}" plus ", not in your categories" when unresolved.
- **Empty state** (`EmptyState`, both sections empty): heading "No rules yet." body "Add one, like “Tesco” to Groceries, and that category fills in whenever a description contains the word. Built-in matches still apply."
