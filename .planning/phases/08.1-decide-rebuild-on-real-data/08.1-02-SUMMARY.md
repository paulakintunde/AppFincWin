# Phase 08.1 Plan 02: Expected lines, sale, payoff and goal close in one Decide save Summary

**record_decide_go now writes an 'expected' kind of monthly line, the sale money in, the old loan's payoff and a goal close in one transaction with one undo step, reusing Grow's sale steps through one shared private function.**

## What was built

- **Migration `20261123000100_decide_go_expected_sale_goal.sql`** (not pushed; plan 16 pushes):
  - `recurring_series.amount_kind text not null default 'exact'` with a check of `exact | expected`. `create_recurring_series` and `edit_recurring_series_from` carry and validate it (22023 on a bad value); `apply_patches` allows it (key list and type map) so undo of an edit restores it. These four function bodies are the 20261122000300 bodies with only the marked 08.1-02 lines changed.
  - `grow_check_sale_legs` (leg shape) and `grow_sale_and_payoff` (sale line, final payment, payoff of both series, debt restore, undo ops), private, revoked from public/anon/authenticated. `record_debt_sale` now calls them; its other behaviour and error text are unchanged.
  - `record_decide_go` (uuid[] body and the p_rows overload): new `p_sale`, `p_payoff`, `p_goal_close` (jsonb, null = not ticked). Payoff names its loan (`debt_id`, `expected_version`); the loan must be the caller's, in the check's household, not already paid off, at the expected version. `goal_close` is `{goal_id}` and refuses with `record_decide_go: goal_not_linked` (22023) unless the goal is the caller's, live, in the check's household and `check_id = p_check_id`. Undo ops: links, debt, rows, sale/payoff ops, series inverses, goal reopen, check restore. Replay of the step id still returns already-applied first.
- **pgTAP 112** (44 assertions): expected stored / plain reads exact / invalid refused; nothing ticked writes nothing; Decide writes the same two lines and loan state as Grow's record_debt_sale on an identical loan; payoff-only ends the loan's series and undoes; other household's loan, stale version, bad shape refused; goal closes, goal_not_linked for an unlinked goal and for another person's goal (leaving no sale behind); one big save (row + expected series + ended series + sale + payoff + goal close) is one undo step and one Undo reverses all of it; replay writes nothing twice.
- **Client**: `RecurringSeriesRow.amount_kind` (read defaults to 'exact' for a row from an older server), `NewRecurringSeries.amount_kind?`, `'amount_kind'` in `RECURRING_SERIES_PATCH_KEYS`; `recordDecideGo` takes `sale`, `payoff`, `goalClose` (sent as `p_sale`, `p_payoff`, `p_goal_close` only when given); exported `DecideGoSale`, `DecideGoPayoff`, `DecideGoGoalClose`, `DECIDE_GO_GOAL_NOT_LINKED`, `isDecideGoGoalNotLinked`.

## Deviations from Plan

### Auto-fixed / decisions

**1. [Rule 3 - Blocking] Local stack is shared, so `supabase db reset` / `supabase test db` were not run.** The single local Postgres container (`supabase_db_cohmcbdfgqmiwykztrdg`) is shared by every parallel worktree agent; a reset would have wiped their state. Instead each pgTAP file was run through `psql` inside `begin; <migration>; <test file>` with the file's own final `rollback`, so nothing persisted. Same assertions, same engine, no reset.

**2. [Rule 1/3] Old 7-arg `record_decide_go` overloads are dropped and replaced by 10-arg ones with defaults.** Adding a defaulted overload beside the old one would make every existing 7-arg call ambiguous. Existing pgTAP 56, 60, 99 still call with 7 args and resolve to the new function.

**3. [Rule 2] The p_rows overload (the one the client really calls) was extended too**, not only the uuid[] body the plan names, and passes the three arguments through.

**4. [Rule 2] Shape validation for the sale leg** (`grow_check_sale_legs`) is shared and also covers a payoff naming no loan, differing loans on sale and payoff, equal leg ids, owner/household/paid-off/stale-version checks on the loan.

**5. Wait-then-bought caveat (for plan 07, not a defect here).** `record_decide_go` only accepts an `open` check, and goals made by Wait are linked to the check through `savings_goals.check_id`. If a goal's originating check has already moved to 'waited', the UI must call the save with the check that is open and linked; `goal_close` requires `check_id = p_check_id` exactly. If plan 07 needs a goal linked to an earlier check, widen the link rule there.

## Deploy-order note (important for plan 15/16)

`RECURRING_SERIES_COLUMNS` now selects `amount_kind`. Any client build or OTA that includes this commit reads that column, so **the migration must be pushed before this client ships**, or `fetchRecurringSeries` will fail against production. The three new RPC arguments are only sent when ticked, so the save itself stays compatible with the old server until then.
