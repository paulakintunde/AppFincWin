# Phase 08.1 Plan 12: Household purchase is shared money Summary

A purchase checked with scope Household is now recorded as one shared line at its full amount (and shared bills for its running costs), using Phase 8's own split and owing rules. Just me is written exactly as plan 09 wrote it.

## Commits
- 02f75473: Task 1, engine `Purchase.full`, writer, migration, pgTAP, tests
- 8a5212b9: Task 2, Bought screen sub-line, copy, test

## What was built
- **Full amounts from the engine.** The writer only had my share (`Purchase.whole`/`dayOne`), so a household row could not be exact. `Purchase.full?: { whole, dayOne }` is set in `judge/purchase.ts` only when the share splits more than one way; personal and "mine" rules leave it absent (their `whole`/`dayOne` already are the full amounts). No new branch logic beyond the one spread; `purchase.ts` stays 100% branch (all 156 v3 engine suites).
- **Writer (`goAheadInputOfV3`).** When `check.share.kind === 'household'`: the day-one row is `full.whole` (cash) or `full.dayOne` (plan), payment series use the lender's full amount (no `myShareOf`), running-cost bills and expected lines are written at their (already full) amount; every row and series carries `is_shared: true`. No `myShareOf` on household rows. Just me unchanged. The account is just the account: joint or personal gives identical rows.
- **Server (new additive migration `20261125000500_decide_go_shared_rows.sql`).** The jsonb-rows overload of `record_decide_go` accepts an optional `is_shared` key on a row and inserts it. Phase 8's `share_on_insert` then applies the household's split rule, the household-currency stamp and the stored split; a household of one, debt-linked or goal-linked line stays personal there. Series already read `is_shared` (Phase 8 D-16), so no change. Any other extra key is still refused.
- **Owing.** The save makes no owing row. Phase 8 reads owing from shared lines and splits on a personal account; a joint account is not tracked (D-17). Nothing here changes those rules.
- **Bought screen.** `label`-role, `inkMuted` sub-line directly under the title, before the "no money moves" line and the card holding the "Bought on {{date}}." line. Household only. Amount row shows the full amount written.

## Deviations from Plan

**1. [Rule 3] Engine change (`Purchase.full`) and migration added.** The plan lists neither; both are required (the engine did not expose full amounts, and the server refused `is_shared` in `record_decide_go` rows). Both additive and optional. Migration is a file only (see below).

**2. [Rule 3] `DecideGoRow` type.** `NewTransaction & { is_shared?: true }` in `db/decideOutcomes.ts`, so `NewTransaction` (used by direct-insert writers that have no `is_shared` grant) is not widened.
