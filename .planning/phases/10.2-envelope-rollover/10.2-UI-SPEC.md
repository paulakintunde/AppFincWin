# Phase 10.2 (Envelope rollover) - UI Design Contract

> Visual and interaction contract for the rollover switch, and for every place a category limit shows once rollover is on. Built only from the app's own tokens (`src/theme/*`) and primitives (`src/ui/*`). Follows the 10.1-UI-SPEC format. Sources: 10.2-CONTEXT D-01..D-08 (locked), 10.2-RESEARCH surfaces S1-S16 and open questions O1-O6, CLAUDE.md design fidelity and compliance, prototype `FincWin United.dc.html` (feature row L3258, Insights limit rows L5275-5279, You switch and toasts L5359; `rolloverFor` L6969-6973 is superseded and not ported). Where this file and the prototype differ, this file wins on tokens; CONTEXT wins on behaviour. Choices CONTEXT did not settle are listed in "Owner to confirm" at the end.
>
> **Governing rule: with rollover off, nothing on any screen changes.** Every new element below renders only when `rollover_since` is set (D-01, D-07). The one exception is the Features list row (section 9).

## Color

Only `src/theme/tokens.ts`. No gradients, no extra shadows, no new hexes. `inkFaint` never sits on the page tone.

| Role | Token | Usage |
|------|-------|-------|
| Dominant (60%) | Page tone (`pageTint`, `canvas` fallback) | Behind sheets; Activity under the strip |
| Secondary (30%) | `surface` white rows and cards, `fill1` for the limit card and the Activity strip | Limit card, strip, notes |
| Accent (10%) | `colors.accent` | Listed below |
| Destructive | `stateColors.short` text with a word | **None used.** "Turn off rollover" is a text button in `ink` weight 600; the confirm sheet is the safeguard, and an over-limit month is not a destructive state |

Accent reserved for: the switch track when on (existing `ToggleRow`), the primary button in a sheet when enabled, the text link "Open Categories". Nothing else.

State colours, always with a glyph and words, never alone:

| Mark | Token | Rule |
|------|-------|------|
| Over the limit | `warn1` text (#8A5A1B, the `stateTight` text) with `stateOverCap` glyph + "over by $X" words | Existing rule (Confirmed Decision 4: a limit breach is amber, never red). Used in the Categories sub-label, the limit card, the strip and the Insights line |
| Under the limit | `inkMuted` | Plain words, no state colour |
| Carried line | `inkMuted` | Neutral in both directions. "+ carried" is not green and "- over" is not red: a carry is a figure, not a verdict |

**Limit bar (tokens only).** `ProgressBar` `thin`, `tone="ink"` in every state. The fill never changes colour; the over state is carried by the words and the `stateOverCap` glyph beside the bar. The bar is a single track whose length stands for the **larger** of the effective limit E and the plain limit L (`max(E, L)`). A tick (`tickPercent`) marks where the **other** one sits:

| Case | Track length | Tick | Meaning |
|------|--------------|------|---------|
| E = L (no carry, or first month) | L | none | plain bar |
| E > L (a carried surplus) | E | at `L / E` | the tick is the plain limit; the stretch beyond it is the carried amount |
| E < L (an overspend carried) | L | at `E / L` | the tick is where this month's limit ends; the stretch beyond it is the amount taken off |
| E = 0 | L | none | words carry the meaning: "$0 of $0 this month" |

Fill = `min(100, spent / max(E, L))` percent, clamped by `clampPercent`. Spent above the track fills to 100 and the words say "over by". The bar is an aid: its `accessibilityLabel` carries the full sentence (see Accessibility). It animates its fill on first view only, per `ProgressBar`; Reduce Motion draws it at final width.

## Layout and Screen Contracts

Terms: **L** plain limit, **E** effective limit for the month (plain plus carried, clamped 0..2L), **C** = E - L carried (can be negative). With rollover off E = L and no screen below shows anything new.

**Primary anchor:** on the limit card and the Activity strip, the effective limit amount (`bodyStrong`) is the one focal point; the over-limit glyph and words are second. Everywhere else the existing row hierarchy is unchanged.

### 1. You: the switch (D-01, D-06)

Placed in the You group that holds the data settings (prototype: You > Data), as `tiled('rollover', <RolloverRow />)` after `weekStart`, gated by the Features registry at level 3. Hidden rows leave no gap.

- `ToggleRow`: label "Envelope rollover"; sub "What is left of a limit carries into next month. So does an overspend." Value off by default.
- **Note line** under the row (`label`, `inkMuted`, `step.tight` above), shown only while on: "Started in {month}. The first carry is at the end of {month}." (D-05; `{month}` is the long month name of `rollover_since`, localised.)
- **No-limit hint**, shown while the user has no category with a limit, on or off: `info` glyph + "No category has a limit yet." and a text link "Open Categories" (accent, 44 tall). The switch still works.
- **Turning on:** no confirmation (nothing is lost). The switch writes `rollover_since = this month` through the existing prefs mutation (optimistic, rolled back with the existing failed-write toast if refused). Toast (existing `ToastView`, `hapticTap`): "Rollover is on. This month's result carries into next month."
- **Turning off (D-06):** the switch does not flip first. `ConfirmSheet`: title "Turn off rollover?", body "Limits go back to their plain amounts now and carried amounts are dropped. Turning it on again starts fresh.", buttons "Turn off rollover" and "Keep it on" (equal weight, stacked full width at large font scale, 52 tall). On "Turn off rollover": the switch flips, `hapticTap`, toast "Rollover is off. Limits are back to their plain amounts." No Undo action on this toast (see Owner to confirm 2).
- Offline: the toggle works as a queued write (paused mutation). The row note shows existing `SyncStatusLine` wording if the write is waiting; nothing new.

### 2. Categories list (S2-S4)

Rows unchanged in structure (`Row`, `leading` glyph, chevron). For a category **with a limit**, with rollover on:
- Sub-label line 1 keeps today's wording with E in place of the plain limit: `categories.usage.ofCap` "{spent} of {cap} this month", or `ofCapOver` "..., over by {over}" in `warn1` with `stateOverCap` glyph (existing tone rule). Example: "$420 of $580 this month".
- **Carried line** as a second sub-label line under it (`label`, `inkMuted`, `step.hair` below), only when C is not zero: "$500 + $80 carried from October" or "$500 − $50 over in October". Row grows to its content (min 64).
- No bar on list rows (the list stays compact and identical in rhythm to today).
- **E = 0:** "$0 of $0 this month" in `inkMuted` when nothing is spent (not the over state; see note below), and "$12 of $0 this month, over by $12" in `warn1` once something is spent.
- **Loading** (past months not yet read): show the `used` wording ("Used 4 times this month"), no limit figure, no carried line; the limit wording fades in (`FadeIn` 0.15 s) when ready. Never show the plain limit first and then change it. The over-limit toast is suppressed until the chain has loaded.
- Categories without a limit, system rows, archived rows: unchanged.

Engine note for the planner (visible behaviour): today `categoryUsage` treats `spent >= cap` as over, so E = 0 with nothing spent would read "over by $0". The UI contract is: over requires `spent > 0` when E = 0. Spending exactly E elsewhere keeps today's behaviour (O6).

### 3. Category sheet: limit field and the "This month" card (S8, D-08, mid-month rule)

The sheet keeps editing the **plain** limit: the field, its label "Monthly cap" and its helper text are unchanged. When rollover is on and the category has a limit, a `LimitCard` sits **above** the field (`step.section` below it):

`LimitCard` (`fill1`, `radii.card`, padding `step.card`, gaps `step.tight`):
1. `label` `inkMuted`: "This month" (on the right, the month name when the sheet is opened from a past context; today it is always the current month, so omit).
2. `bodyStrong`: the effective limit E ("$580"), with the words "limit this month" in `label` `inkMuted` beside or, at large scale, under it.
3. Carried line (as section 2), only when C is not zero.
4. Explainer (`label`, `inkMuted`), only in clamped cases, previous-month figures from the chain:
   - cap case: "{month} had {left} left. A limit carries at most one month's worth."
   - floor case: "{month} went over by {over}. A limit takes off at most one month's worth."
5. First-month line (`label`, `inkMuted`), only when the chain starts this month (switched on this month, or the limit was set or changed this month): "The first carry is at the end of this month."
6. `ProgressBar` thin (rules in Color) with `animate` only on first view, then the spend line: `categories.usage.ofCap` / `ofCapOver` with E. Over state: `stateOverCap` glyph + "over by $X" in `warn1`.
7. Unconverted note (`info` glyph + `label` `inkMuted`), only when a past month the carry rests on has lines with no converted amount: "Some of {month} isn't counted yet, so this figure can change."

**Limit change (research O1, recommended rule):** when rollover is on and the user edits the limit field to a value different from the stored one, and the category currently has a non-zero carry, a helper line appears under the field (`label`, `inkMuted`, `info` glyph, live region polite, `useSettledLabel` 600 ms): "Changing the limit starts carrying again from this month." When the field is cleared (limit removed) and the category currently has a non-zero carry: "Without a limit there is nothing to carry. Setting one later starts fresh." No extra confirmation and no extra toast: the existing category-edit Undo restores both columns. When there is no carry to lose, no helper shows. The same helper shows in the Decide `AddRuleSheet` / `RulesSetup` limit editor (it writes the same limit).

New category with a limit: no card until the chain has a first month; after saving, the card shows the first-month line.

### 4. Entry-sheet category picker and over-limit toast (S5, S6)

- **Picker rows:** the same sub-label as the Categories list **line 1 only** (effective figure, "$420 of $580 this month"). No carried line, so picker rows stay at today's height.
- **Over-limit toast:** existing string `categories.cap.overToast` "{category} is over its cap by {amount}" and existing `hapticWarn`, with E as the limit and the amount over E. Fires on the save that takes spend from under E to at or over E, as today (`crossesCap`).
- **E = 0:** the first spend in that category in the month crosses a $0 limit, so the toast fires: "Groceries is over its cap by $12". (Planner: `crossesCap` must treat `spentBefore <= 0` and `spentAfter > 0` as crossing when the limit is 0.)
- **While loading:** no toast, no sub-label limit figure (as section 2).

### 5. Activity: per-month badge and category view (S7, D-08)

- **Row badge** `appLife.status.overCapBy` ("over by $X") is unchanged in look and wording. It fires on the row that pushes that category's running total in **that row's month** past **that month's** effective limit. Months before the chain start use the plain limit, as today.
- **Category view strip** (`LimitStrip`): when Activity is filtered to exactly one category that has a limit, rollover is on, and the view is a single month, a strip appears as the first item of the list (it scrolls away; the header bands are untouched). `fill1`, `radii.card`, padding `step.card`:
  - line 1: category name (`bodyStrong`) and "$580 limit" (`label`, `inkMuted`); wording `categories.rollover.limitThisMonth` "{amount} limit this month" when the viewed month is the current one, otherwise `categories.rollover.limitInMonth` "{amount} limit in {month}".
  - line 2: the carried line (omitted when C = 0).
  - line 3: the `ProgressBar` and the spend line "{spent} of {E}", over state as in section 3.
  - A range of several months, or several categories chosen: no strip (badges still apply per row).
- The strip is a summary, not a control (no tap target). Reduce Motion: no fade.

### 6. Insights category rows (S12, D-08; new surface)

Insights shows no limit today. In "Where it went" (`WhereItWentSection` > `CategoryRow`), the existing bar is a **share-of-spend** chart (`chartPalette`) and stays exactly as it is. The limit is added as **text under the bar**, never as a second bar.

Shown only when rollover is on, the view is a **single month** (not the 6-month, 1-year or all ranges), and the category has a limit:
- `label` `inkMuted` line: "Limit {E}" then, in the same line, either "{amount} under the limit" (`inkMuted`) or `stateOverCap` glyph + "Over by {amount}" (`warn1`). At large font scale the two parts wrap onto two lines; the glyph stays with "Over by".
- Carried line below it (same wording as section 2), omitted when C = 0.
- Months before the chain start show "Limit {L}" (plain) and no carried line.
- A tap on the row still opens Activity on that category (unchanged). The limit text adds no new tap target.
- Header summary: the existing "Where it went" header gains no new count (the prototype's "N envelopes over cap" is not carried; Insights copy avoids judgement words).
- Strings use the `insights.rollover.*` keys. The Insights copy guard bans "tight", "good", "bad", "strong", "steady", "poor", "healthy", "best", "better", "optimal", "should", "advice"; none of the strings below use them.

### 7. Decide (S9-S11b, D-07)

The engine and every Decide answer are unchanged with rollover off. With it on, only the limit **value** fed to the check changes; Decide's spare money is never touched and a carried amount is never shown as money to spend.

- **Money rules card and rules setup rows** (`MoneyRulesCard`, `RulesSetup`): a capped category's row keeps showing the **plain** limit as its value (it is the user's rule). When E differs from L, a sub-label line is added: "{E} limit this month" (`decide.rollover.limitThisMonth`, `label`, `inkMuted`). When E equals L, nothing is added.
- **Purchase check in that category:** the existing crossed-line sentence is unchanged; the limit figure inside it is E (so the user reads "$580 limit this month" where the sentence names the limit). The planner confirms how `line_crossed.limit` renders; if the sentence needs the words "limit this month", that is a copy-layer change, not an engine change.
- **No carried line in Decide.** Decide says only "{E} limit this month". It never says "carried", "unspent", "overspent", "room", "you can" or "should".
- **If the carried amounts cannot be loaded** while rollover is on: the check falls back to the plain limit and the answer carries one `info` line "Carried amounts did not load, so the plain limit is used." (Owner to confirm 7.)
- Decide copy guard: the strings below sit under `decide.*`, so the decide set applies (banned list in `src/i18n/copyGuard/rules.json`; `limits` apply to `decide.screens` keys: at most 25 words and 3 numbers per string).

### 8. Household and privacy

No new UI. Categories and limits are per user: a member sees only their own limits and carries, never a partner's (`shared_line_categories` returns no limit). A shared line's part counts toward the **member's own** category (07 D-33). The You switch is per user. Nothing about a partner's rollover appears anywhere.

### 9. Features list row (S14, level 3)

A new row in the Features list: name "Envelope rollover", area "Planning", level 3 (Planning area, "Full picture"), glyph `stateOverCap`. Sub-line: "Leftovers and overspends carry into next month". (The prototype's "What you did not spend carries into next month" no longer describes the behaviour, because overspends carry too, D-02.) It follows the same lock, unlock and tap behaviour as the existing `caps` row. It is registered in `featureRegistry.ts` and `09-LEVEL-MAP.md` §1 item 6 together (amend "No" to "Yes, level 3, built in 10.2").

## Right-answer strings (from 10.2-RESEARCH cases; L = $500, USD, English locale)

| Case | Line shown | Sub-label / extra |
|------|-----------|-------------------|
| Leftover carried (Oct spent $420) | "$500 + $80 carried from October" | "$0 of $580 this month" |
| Overspend carried (Oct spent $550) | "$500 − $50 over in October" | "$0 of $450 this month" |

Planner: `detailKit.f.month` returns month and year, so add a month-name-only helper (research A1: grep `monthLabel|formatMonth` first). The carried figure is the net carry into this month, even when it built up over several months; the label still says "from <previous month>" (D-08).

## Interaction and Motion

- One motion at a time (06.2 kit): `FadeIn` 0.15 s for the limit wording appearing after load, `FadeSwap` 0.15 s when the carried line or figures change after an edit, `ProgressBar` fill on first view only.
- Reduce Motion (`useReduceMotion`): no fade, no bar animation; instant.
- Haptics (`expo-haptics` async API only): `hapticTap` when the switch changes and when the confirm sheet confirms; `hapticWarn` on the over-limit toast (existing). None on the helper lines.
- Switching off flips the switch only after confirmation; the switch rests off until then.

## Accessibility

- **Switch:** role `switch` with state; label "Envelope rollover"; hint "Carries what is left of each limit, or what went over, into next month." The since-note is read after it.
- **Categories row:** one label for the row, in spoken money and words, never symbols: "Groceries, 420 dollars of 580 dollars this month, 500 dollars plus 80 dollars carried from October." Over: "..., over by 20 dollars." `categories.rollover.a11y.carriedFrom` "{{limit}} plus {{carried}} carried from {{month}}"; `a11y.overIn` "{{limit}} minus {{over}} over in {{month}}" (the visible "−" is not read as a symbol). Uses the same spoken-money helper as the existing `usageSubLabel` rows.
- **Bar:** `ProgressBar accessibilityLabel`: "Limit used: 420 dollars of 580 dollars, 72 percent. Plain limit 500 dollars." The tick is not a separate stop.
- **Limit card, strip, Insights line:** the figures, carried line and explainer read in order as one group; over state reads "over by X" (the glyph is decorative, hidden from the reader).
- **Limit-change helper:** `accessibilityLiveRegion="polite"`, spoken once settled (`useSettledLabel`, 600 ms).

A short line under the limit box warns before you save, and Undo brings the old carry back. The other choice (keep the carried dollars across a limit change) needs more stored data.
2. **No Undo button on the "rollover is off" message.** The "Turn off rollover?" question already warns you first. Recommended: no extra Undo, to avoid asking twice. If you want one, it is cheap: Undo would put back the start month, so every carried number returns exactly. Turning the switch on by hand instead starts fresh, as D-06 says.
3. **Counting split lines and shared lines the same way everywhere.** Once Phase 10.1 lands, a split line counts each part toward its own category. Recommended: Categories, Activity, Insights and the carry all use one counting rule, so they cannot disagree. Side effect: for someone with split or shared lines, a category total may differ slightly from today's figure.
4. **Insights shows a limit line only for a single month, and only when rollover is on.** Recommended: yes. Long ranges (6 months, a year, all) mix months with different limits, so no limit line there. With rollover off, Insights stays exactly as it is today.
