<objective>
Remove duplicate payment candidates (F-07) and let a "Not regular" answer be reversed (F-09).

Root cause of F-07 (code read, proved by Task 1's fixture): detectCandidates groups by `offerKey|accountId` (engine recurring.ts:168) and each row id lands in one group only, so equal `key` + `anchorDate` on two candidates means two accounts, each with its own rows on the same dates. useRegularCandidates builds `id: `${candidate.key}|${candidate.anchorDate}``, which then collides (LogBox: `bookshop|USD|-1|2026-08-30`). Whether the owner's two Bookshop accounts are genuine payments or an import duplicate cannot be told from code (no database access in planning or execution); the re-walk checks it in Activity. So the fix makes the ids unique and names the account, and collapses only true duplicates (same ids). The fix stays in the hook (no engine change).
F-09: the Not regular MarkButton disables once marked and nothing removes the dismissal. useRemoveDismissal already exists (05.2-15).
Output: hook dedupe and ids, a clear action on the card, tests.
</objective>
