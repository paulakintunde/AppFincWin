# Phase 05.2 Plan 30: Activity income card, income tags and refund tags Summary

Activity now shows the "How are you paid?" card, income-type chips with a once-only payer question (one batch, one Undo), and two-way "Refund of" / "Refunded" tags, all hidden unless the Decide switch is on.

## Tasks
1. HowArePaidCard + 14-day device-local dismissal (6b29f69c). Shown only with switch on, `income_types` missing and not dismissed; "Not now" writes a `fincwin:activity:incomeCardDismissedAt:<userId>` timestamp; the offerCard slot is now a fragment of the card and SeriesOfferCard.
2. IncomeTagChip + IncomeTagSheet (2e897381, 97e8d6e2). Earlier payments are shown as a count before Save; Save makes one `useTagIncome.tag` call and one toast with Undo.
3. RefundTag + ActivityRow/ActivityScreen wiring (7ded85dc). Chip and tags render under the row's text, outside the row Pressable so they stay reachable by screen readers; unflagged rows keep their old structure.

## Verification
- `npx jest src/features/record/activity`: 34 suites, 354 tests passed.
- `npm run typecheck` clean; eslint 0 errors on changed files (two pre-existing `require()` warnings in ActivityRow.test).

## Deviations from Plan
- **Standalone route not present.** "Set it up" pushes `/decide/setup?mode=standalone` as specified, but no such route exists in `app/` yet; the stepper host/route is not part of this plan. Until it exists the button navigates to a missing route. The Done toast "Income setup saved" belongs to that host.
- **Refund link in the income sheet is prop-gated.** "It’s a refund of a purchase" renders only when `onRefundLink` is passed. ActivityScreen does not pass it yet because RefundPickerSheet is plan 05.2-33; 33 should wire it.
- **Refund tags see only the loaded rows.** Tags are computed from the rows in the list (`itemRows`). A refund whose purchase is in another month gets no tag, and a purchase's "Refunded x" counts only refunds loaded alongside it. Earlier payments for the payer question are fetched across all months (name search, exact payer key kept).
- **Toast choice.** On with more than the payment itself tagged: "Tagged {n} payments from {payer}"; On with only this payment: "Saved for future payments from {payer}"; Off: "Income type saved". The singular "Tagged 1 payment" key is unreachable by this rule.
- **Chip wording.** "reinvested, not counted" is used for kept Dividends; other kept income uses "kept, not counted".
- Existing `ActivityRow.test.tsx` and `CalendarView.test.tsx` gained a `useDecideAccess` mock (v3 false); no assertions changed.
- Not wired here: the transaction detail "Income type" row and the series sheet rows named in the UI-SPEC (not in this plan's files).
