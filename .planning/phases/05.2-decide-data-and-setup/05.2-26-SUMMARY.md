# Phase 05.2 Plan 26: Account use Summary

Account-use list, shared sheet and setup step, plus a gated "What this account is for" row on the account edit screen. Suggestions from the account type are shown only and are never stored until the user confirms them.

## Commits
- 60945e3e: suggestion helper, AccountUseSheet, AccountUseList (task 1)
- 326176c7: AccountUseStep and the account edit row (task 2)

## What was built
- `suggestUse(kind)` is pure: checking and cash suggest Everyday; savings and investment suggest "Savings I don't touch"; other, credit and loan give null.
- `AccountUseList` lists non-archived money accounts (not credit or loan). Unanswered rows get a dashed border. Suggested rows show "Everyday?" and "Suggested". "These look right" saves all guesses in one `useSaveAccountUses` batch. Nothing is written before that, or before a row is changed in the sheet. It reports `allConfirmed` to its parent.
- `AccountUseSheet` has four radio cards. "A mix" opens a second view in the same sheet: a CheckRow per envelope with "In {other}" or "Moves from {other}", then "Anything else set aside here?". "Kept for one thing" opens "Which one?" (Emergency fund or an envelope). It shows a soft warning when the use is changed away from emergency on the account the fund follows. One `useSaveAccountUse` call writes the use and the placements, then shows the "Account use saved" toast with the step id. A dirty sheet uses the shared Sheet discard confirm.
- `AccountUseStep` follows the step contract. Continue is held until every money account has a stored use (reason: needed). `save()` returns `{ stepId: null }`.
- `AccountSheet` gets an `AccountUseRow`. It renders only for an existing account when `useDecideAccess().v3` is true and the kind is not credit or loan. The queries sit in an inner component that mounts only after those checks.

## Deviations from Plan
1. [Rule 3 - Blocking] `accounts.test.tsx` needed mocks for `useDecideAccess`, `@/data/mutations/accountUse` and `@/data/queries/decide`. Importing the new row pulls in `useProfile` and the Supabase client, which throw without an env. No assertion changed and all 35 existing tests pass.
2. [Spec adaptation] The current answer on the edit row is shown as the Row's second line (`sublabel`), with "Not set" in warn1 when empty, instead of as a right-hand value. A long answer would not fit beside the label at 320 dp or font scale 2.0. I did not add a tone prop to the shared `Row`.
3. [Limitation] The saved amount on envelope rows in the mix view is `opening_saved` only. Tagged transfer lines are not summed, because that needs the past-decisions context. This is display-only and nothing computed depends on it.
4. Renamed `useLabelKey` and `useText` to `labelKeyOfUse` and `describeUse`. The hooks lint rule flagged them as hooks, and they are not.
5. The sheet header cancel uses the existing `record.sheet.cancel` key. No new copy keys were added; all copy was already in en.ts.
