<objective>
Make "Not my pay" a per-person answer (WR-02). Re-verified in code, and the claim holds: `notPayMatcher` (src/features/income/notPay.ts) reads every member's live not-pay rows from the household `recurring_dismissals` list, and `useIncomeContext` applies it to the household's transactions. Income setup itself is per user (decide_settings is keyed by user). So one partner's "Not my pay" on the other's salary hides that salary from the other's own setup.

Plan 05.2-66 chose household scope and accepted this as T-05.2-66-03. The owner has now decided to fix all review findings, so this plan replaces that choice. Reasoning: "my pay" is about one person, and the answer only hides a guess, so scoping it to its author takes nothing away from anyone else.

Key format: a per-user filter alone is not enough. The live unique index is `(household_id, payee_key, direction)`, so B's own "Not my pay" on the same payer would hit 23505 if A had already answered. The key therefore carries the user id: `not-pay:<uuid>:<candidate key>`. Rows in the old format (05.2-66, written on the owner's device) still count, but only for their `created_by`. They need no data change.

IN-01 (info, trivial, same file): cut by code point. The incomeTagModel.ts half of IN-01 is not in any plan's files and is left as optional.
</objective>
