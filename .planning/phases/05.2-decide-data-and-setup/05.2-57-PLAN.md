<objective>
Stop the persisted query cache overflowing Android's CursorWindow (F-11), and make sure a bad row never takes the write queue down with it.

Root cause analysis to confirm in Task 1: LargeSecureStore stores `iv:hex(ciphertext)` in one AsyncStorage row, so the stored size is about twice the serialised JSON. 05.2 added household-wide reads (the 6-month `offer-history` read used by the pay and regular steps, `refund-links` / `refund-purchases`) on top of the Decide history, so a large household passes 1 MB of JSON and the row passes 2 MB. On the next start AsyncStorage.getItem throws "Row too big to fit into CursorWindow" outside LargeSecureStore's try, persistQueryClientRestore removes the client, and any queued offline writes in that blob are lost.
Output: a key filter, a byte budget that never drops mutations, a safe read, tests with a measured fixture.
</objective>
