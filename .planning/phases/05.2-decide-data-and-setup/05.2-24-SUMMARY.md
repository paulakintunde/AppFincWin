## Behaviour
- **Regular**: candidates are computed on the device from six months of records (never stored). State comes from the caches: a live series of the same payee = Regular, a dismissal = Not regular, neither = "Not marked" (dashed border, warn1 words). Counter "{n} of {m} marked", the unmarked line while any row is unmarked, three buttons in one row from 360 dp / scale 1.3 and stacked below. Each mark saves at once with its own Undo toast (`paymentMarkedRegular` / `paymentDismissed`). Next always works; `save()` returns `{ stepId: null }`. Empty state and quick-pick sheet.
- **Loans**: live, not paid-off debts with Balance / Minimum / APR (FigureStrip), "due the {day}" from the linked series, Yes / Sometimes / No chips on cards only, written on save through `useSetDebtPaysInFull` (last step id returned, one toast).
- **Saving**: Fixed / Flexible ChoiceCards per saving series (none preselected, skip = fixed), seven bucket chips, bucket cards with swatch dot and two MoneyInputs (stacked below 360 dp), readiness line, total line (empty / equal / less) and the D-22 tile (warnTint, D-23 line, "Lower a bucket" scrolls to and focuses the largest bucket's Each-month field, "Raise my regular saving to $Y" only with exactly one saving series). Never blocks Next.
- Saving series = live series in the Savings category, home currency, not ended (same rule as buildV3Inputs).

## Deviations from Plan

1. **[Rule 3] No existing series or debt editor sheet exists** (the plan says "open the existing series sheet / debt sheet"; neither exists as a stand-alone sheet: series edit lives inside the entry sheet, debts inside the check flow). Added `setupSheetHost.ts`, a small registry (`registerSetupSheetActions`, `setupSheetActions()`) the steps call for Edit, "+ Add a regular payment" (after the quick pick), Loans Edit and "Add a loan or card". With nothing registered those calls do nothing. **The host that mounts setup (plan 32) must register real sheets**, otherwise these buttons are dead. Marking Regular / Not regular, the quick-pick sheet, pays-in-full and all saving writes work without it.
2. **[Rule 3] Pays-in-full writes through `useSetDebtPaysInFull`** (plan 15's new mutation) rather than "the debt edit mutation" in the plan.
3. **Hook file added**: `useRegularCandidates.ts` (not in the plan's file list) holds detection, matching and state so the step stays presentational.
4. **Copy keys added to en.ts** (a11y labels, years/months with no-break space, `readinessReached`, `aprNotSet`); the instruction-verb copy test forced "Regular payment, {name}" and "Loan or card, {kind}" wording for the two picker labels.
5. **Not regular is disabled on a row that is already Regular** (a payment that is already a series is ended where series are edited); Regular is disabled on an already-Regular row. Existing saved buckets stay selected and cannot be unselected here (deleting goes through the envelopes step). Clearing an existing bucket's goal is ignored (the pot patch type cannot null `target`).
6. **"To {account}" uses the series' account name** (falls back to the series name); series carry only one account.
7. **Raise** is offered only when the amount round-trips exactly through the engine's monthly equivalent, so the tile re-renders as "equal". Raise toast uses `undoLabel: 'seriesEdited'` so the existing host replays the series edit step.
8. **Tile accessibility group**: the label "{text}. Two choices." sits on the text block, not around the buttons (an accessible wrapper would hide the buttons from screen readers).
