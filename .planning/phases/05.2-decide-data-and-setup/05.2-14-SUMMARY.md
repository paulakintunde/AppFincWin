# Phase 05.2 Plan 14: Account use and emergency fund writes Summary

Account use (one account or all at once), mixed-account envelope placement and the emergency fund each save as one `apply_patches` call that carries its own undo step, so a refused row refuses the whole batch and Undo reverses all of it. The D-04 rule (what an emergency link does to an account's use) is a pure function.

## Tasks
1. Pure model: `accountUsePatch` / `accountUseOfRow` / `emergencyLinkUse` (commit fa4865b8).
2. Batch mutations with one Undo: `saveAccountUses`, `saveAccountUse`, `saveEmergencyFund` (commit b0cf4d51).

## Behaviour
- Unchanged accounts and goals are left out; nothing to change returns null and queues nothing.
- Emergency save writes only changed settings columns (stamped with the settings currency, or the linked account's when none), plus the account op from `linkUse`. Remove clears reserve and reserve_account_id, keeps reserve_goal, moves nothing, and always returns a step id.
- Conflict: whole batch refused, caches refetched, refusal toast, one failed-write record. Rejection: cache values restored, then refetch. Failed-write records hold ids, counts and column names only.
- Offline: one queued item; caches updated optimistically.

## Deviations
- Minor: `grep -c "scope: WRITE_SCOPE"` returns 2, not 3. The three keys register in one loop (one `scope: WRITE_SCOPE` shared by all three) plus the hook's `useMutation`. All three defaults carry the scope; the test asserts each default's `mutationFn` is registered.
- `accountUseOfRow` wraps the extra set-aside in `minorUnits()` to satisfy the branded type (typecheck).
