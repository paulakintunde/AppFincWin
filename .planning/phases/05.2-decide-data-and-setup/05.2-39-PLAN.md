<objective>
The one schema addition the gap plans need, in a single additive migration:

1. Why a series ended (D-24 Stopped / Paused). The engine already honours `end_date`. Paused needs a marker so the app can show "Paused since {date}" and offer Resume. So that the marker can never go stale, it is written in the same server call as the end date: edit_recurring_series_from learns the `end_reason` patch key, and its server-built undo step (which records the old value of every patched key) restores it on Undo. A plain end (end_recurring_series, the Decide go-ahead) never touches end_reason, and a live series always has end_reason null, so those ends read as Stopped.
2. When a loan or card was paid off (owner addition 2026-10-28, constraint "Life changes are user-led"). Today a debt ends only by being deleted (`deleted_at`); `paid_in_full` / `pays_in_full` mean "a card cleared every month", not "this debt is gone". A dated `paid_off_on` lets Decide stop counting the minimum payment from that date while the past stays as recorded (05.2-48), and lets Undo restore it (05.2-43).

Purpose: owner D-24 and the 2026-10-28 addition. Both columns must be in the single production push (05.2-36), which keeps its count of 12 migrations because this stays one file.
Output: one additive migration (end_reason, paid_off_on, and re-created apply_patches and edit_recurring_series_from), pgTAP 71, the row types and the export manifest.
</objective>
