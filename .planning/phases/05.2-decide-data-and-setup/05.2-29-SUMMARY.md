# Phase 05.2 Plan 29: Envelopes step and PotSheet Held in Summary

The envelopes step lists every envelope (saving buckets tagged "saving bucket") and offers the six chips plus an exclusive "None right now". PotSheet gains a "Held in" account row that saves `account_id` through plan 18's pot hooks.

## Deviations from Plan

1. **[Design call] Chips open PotSheet instead of inserting.** An ordinary pot needs a target and a ready-by date (`validatePot`, DB shape check), so per the plan's fallback a chip that is not yet an envelope opens PotSheet prefilled (new optional `prefill: { name, colorKey }` prop, add mode only; colour is passed as `color_key`). Nothing is inserted by the step; save() returns `{ stepId: null }`. A chip shows selected when an envelope of that name exists, and pressing it opens that envelope. The Undo toast comes from PotSheet's own save.
2. **[Test infra] Three existing test files got two mock lines each** (`@/data/queries/accounts`, `useDecideAccess`) because PotSheet now imports them, and `accounts` pulls in the Supabase client (env error without a mock). No assertions changed; all pass.
3. **[Known limit] Saving-bucket rows open PotSheet, which needs a target and a month to save**, so a bucket's monthly amount and goal are edited in the saving step, not here. Bucket `monthly` shown on the row comes from `monthly_amount`.
4. **[Not done] "account has the switch on" (plan truth)**: no such account flag exists in the data model; the row shows when v3 and at least one live (not archived, not deleted) account has `use === 'mixed'`. The picker lists mixed accounts plus a "Not set" option.
5. Row "set aside" amount is the pot's `opening_saved`; tagged transfers are not added (no goal-lines read in the step). Monthly for ordinary pots comes from `potLineFor` (active state only).
6. The step is not yet registered in a step table or shell (plan 32 / shell plans).
