## Deviations from Plan

1. **[Interpretation] under_logged_month fires for unreviewed months (mark null), not for `normal`.** The plan text says mark 'normal'; but the typical-month rule keeps user-confirmed normal months, so questioning them would contradict the user. Months marked normal, half or out are never suggested. Tested.
2. **[Rule 3] Barrel test pins constant names**, so the 16 REFINE_* names were added to `V3_RUNTIME_EXPORTS` in the RED commit (constants already ship through `export * from './constants'`), not only refine/refineNoise in Task 3.
3. **Cards returned only when due.** A gated or no-trigger result is `{due:false, triggers:[], cards:[]}` (as the plan's gate cases require).
4. **Overrides:** `everyday_override_expiring` is emitted only when no `everyday` value card is shown (avoids two cards for one figure); it carries no suggested figure.

## Known approximations (documented in refine.ts JSDoc)

- `unspent` card compares the rolled-forward unspent with the sum of accounts stated everyday/mixed; bills still due are not taken off. 05.3 may refine.
- `changing_income` is in the type contract but not emitted (D-20 lists no rule for it).
- `REFINE_SNOOZE_DAYS` is exported for the caller (05.3 computes `refine_snooze_until`); the engine only reads the stored date. The caller should clear `setupRough` after a check-in, else the rough trigger repeats each gap.
