## Deviations from Plan

1. **[Rule 3 - Blocking] reasonKey is `decide.setup.shell.neededReason`, not `needOne`.** The key `decide.setup.shell.needOne` named in the plan does not exist in en.ts; plan 20 shipped `neededReason` ("At least one is needed to continue.") with the same copy. Used the existing key. Method and pay steps use the same line.
2. **[Rule 3 - Blocking] Local `PrefillTile` instead of plan 23's `PrefillNote`.** PrefillNote is created by 05.2-23, which runs after this plan. A small local tile with the same look (accentTint1, check glyph, s13_5) lives in `src/features/income/steps/PrefillTile.tsx`. 05.2-23 or 05.2-32 can swap it for PrefillNote with a one-line change.
3. **Plain-string copy keys via `useCopy()`.** Step tables hold keys as data and the typed `t` only accepts literal keys, so `shared.tsx` exports a `useCopy()` wrapper with a string-key signature. Every key resolves in en.ts (verified by the tests rendering real copy).
4. **Other-income "found amount from records" omitted.** Records carry no reliable mapping from a detected payer to a kind of other income (side business, rent, etc.), so each detail card always shows the "About how much" MoneyInput. The pay step does show the found-payer prefill.
5. **"It varies" frequency on other income writes no series.** `recurring_series.freq` has no unscheduled value; a line marked "It varies" is left unsaved rather than mis-scheduled as monthly. Tested.
6. **Incomplete other-income lines are skipped, not blocked.** The step is optional (Next always on); a card missing amount, frequency, counts or (for Other) a name writes nothing.
7. **Remove on pay cards is shown only for unsaved extra cards.** Removing a saved salary series would be a delete, which this step does not do.
8. **Several series writes return the first undo step id.** The usual single pay is one step; with two new pays the toast undoes the first only (each series write has its own undo, as in 05.2-15).
9. **Season saves `income_pattern` only** (as the plan's key link states), not `income_pattern_confirmed`, so the engine's swing question (D-34) still decides for itself.
10. Pay date defaults to today for a new card (a valid, editable date); amount and frequency are the required, un-preselected answers.
