<feature>
  <name>Refund re-dating pre-pass</name>
  <files>src/engine/decide/v3/month/refunds.ts, src/engine/decide/v3/month/__tests__/refunds.test.ts, src/engine/decide/v3/month/__tests__/refunds.properties.test.ts</files>
  <behavior>
    Owner example (May purchase 1,000,000 minor, category C; July refund):
    - full 1,000,000 back -> May has the refund line (date = purchase date, category C, amount 1,000,000, role 'refund', refundOf null); July has no line from it
    - 998,000 back -> May refund 998,000 (shortfall 2,000 stays as May spending in C); July nothing
    - 1,003,000 back -> May refund 1,000,000; July a line id '<refund id>:surplus', role 'other_in', amount 3,000, refundOf null
    - two partials 400,000 (June) + 700,000 (July) -> May gets 400,000 then 300,000 (date order, tie broken by id); July surplus 400,000 'other_in'
    - purchase id not found -> refund line unchanged (still role 'refund', refundOf kept as given)
    - refundOf on a line whose role is not 'refund' -> ignored, line unchanged
    - purchase line role not 'spending' (e.g. income) -> refund unchanged
    - refund and purchase in the same month -> date and category become the purchase's, amount capped as above
    - plan purchase (purchase line has seriesId set) -> credit to its month; series inputs untouched
    - no line with refundOf -> the exact same array reference is returned (and withRedatedRefunds returns the same inputs object)
    Properties (fast-check, style of variableIncome.properties.test.ts):
    - conservation: sum of refund + surplus amounts out == sum of linked refund amounts in
    - never earlier than the purchase month: every moved line's month == its purchase's month
    - idempotent: redateRefunds(redateRefunds(m)) deep-equals redateRefunds(m)
    - non-refund lines are unchanged in every month
  </behavior>
  <implementation>
1. types.ts: append `readonly refundOf?: string | null` to V3Line (comment `05.2 D-06..D-08`) and `readonly bucket?: boolean` to Envelope (comment `05.2 D-23`). Additive optional only; note both in the SUMMARY as a 05.3 heads-up.
2. refunds.ts (header JSDoc citing 05.2 D-06..D-09, D-11 and owner decisions 1-3; imports only `../types`, `../dates`, `../../../money/types` like seasonWalk.ts). Read the sign convention of `V3Line.amount` for 'refund' and 'spending' lines from `src/features/decide/snapshot/v3/buildV3Inputs.ts` (lines around 320-372) and work in magnitudes with `BigInt`; emit with `minorFromBigInt(x, 'redateRefunds')` keeping the refund's own sign convention.
   - Build `byId: Map<string, { line, monthIndex }>` over all lines.
   - Collect linked refunds: `line.role === 'refund' && typeof line.refundOf === 'string'` and target found with role 'spending'. Group by purchase id, sort each group by (date, id).
   - For each group: `room = |purchase.amount|`; per refund `credit = min(|r|, room)`; `room -= credit`; if credit > 0 push `{ ...r, date: purchase.date, categoryId: purchase.categoryId, amount: credit, refundOf: null }` into the purchase's month; if `|r| - credit > 0` push `{ ...r, id: r.id + ':surplus', role: 'other_in', amount: |r| - credit, refundOf: null }` into the refund's own month. Remove the original line from its month.
   - Rebuild only touched months; within a touched month stable-sort lines by date (original index as tie-break). Untouched months keep their object identity.
   - `withRedatedRefunds(inputs)`: if no line has a string refundOf return `inputs`; else `{ ...inputs, months: redateRefunds(inputs.months) }`.
3. evaluate.ts: rename the parameter to `raw` and make the first statement `const inputs = withRedatedRefunds(raw);` (comment "05.2 D-11: one pre-pass so typical, thisMonth, incomePattern and unspent read the same months"). Then `grep -rn "buildMonthModel(\|inputs.months" src --include=*.ts --include=*.tsx | grep -v __tests__` and confirm every production reader of months is reached through evaluate(); if any feature-level caller of `buildMonthModel` exists, wrap its input with `withRedatedRefunds` too and say so in the SUMMARY.
4. Document in refunds.ts: a refund whose purchase sits before the unspent anchor is now dated before the anchor, so `rollForward` ignores it and confirmed unspent does not rise when the refund arrives (intended; fixes the 05.1-18 drift).
5. Engine purity: no import from db/, state/, services/, ui/, react; codes only, no English.
