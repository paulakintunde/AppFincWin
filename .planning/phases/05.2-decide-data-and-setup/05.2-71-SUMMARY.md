# Phase 05.2 Plan 71: Settings money in home currency Summary

Settings money columns now mean home-currency money on both write and read: saves stamp the confirmed home currency, and a stored-vs-home mismatch drops every settings money figure before the engine sees it.

## What changed

- Read side: `settingsMoneyUsable(st, home)` (null row, null currency, or currency equal to home). When false, `withoutMoney` nulls steady_amount, everyday_override, unspent_anchor, rough_saving/debt/invest and unexplained_amount, and the reserve guard uses the same helper.
- rough_* decision: the failing test showed the legacy snapshot does NOT drop `rough_income`/`rough_spending` on a mismatch (it converts them from the stored currency at stored rates, so GBP 4000 became a USD figure). The guard is therefore unconditional: the rough branch is skipped when settings money is unusable, so `rough` is null. Non-money answers still flow.
- Write side: `useStamped` stamps the money-prefs cache `home_currency`; with no cached row it keeps the stored currency, else none (no placeholder). `stampSettingsPatch` clears other money columns on a switch, and Undo restores them.
- `useChangeHomeCurrency` on `applied` invalidates `decideSettings(userId)` and `['decide-answers', userId]`; not on unchanged or failure.
- IN-02: `sameValue` uses a key-sorted `stableJson`.
