# Phase 05.2 Plan 73: Live-key dismissal collision (WR-03) Summary

A "Not regular" / "Not my pay" write whose answer is already live (same household + payee_key + direction) now lands on the live row instead of failing.

## What changed

- `insertDismissal` returns `{ row, own }`. On 23505: lookup by client id (own true, as before); else a new `fetchLiveDismissal` by household + payee_key + direction + `deleted_at is null` (own false); else the original error is thrown. Non-23505 errors throw with no lookups.
- `addDismissal` records an undo step only when `own`. On success it drops the optimistic client-id row when the server row has a different id, then upserts the live row. No failed write is recorded.
- Existing `newTables05_2` db test updated to the new return shape.
