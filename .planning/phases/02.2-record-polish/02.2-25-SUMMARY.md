# Phase 02.2 Plan 25: Entry sheet depth Summary

The entry sheet now takes the amount on the money keypad, has Automatic and Refund toggles, shows up to two engine-chosen notes, words income status as Received/Expected, opens clones as pending new lines, and warns once when a save crosses a category cap.

## What was built

- **Form rules (transactionForm.ts):** `FormState.automatic/refund`; edit direction keys on `is_refund` (refund reopens as an expense with the toggle on); refund saves a positive amount with `isRefund`; `withRefund`/`withAutomatic`; leaving expense clears refund, entering transfer clears automatic; `EntryMode` new variant takes `prefill` (pending, status touched). `toPatch` emits `is_refund`/`is_automatic` only when changed. `useAddTransaction` writes both flags.
- **Sheet:** Keypad (engine applyKey) replaces both OS decimal-pad inputs; the amount figure is a polite live region ("Amount {value}"); for cross-currency transfers tapping a figure selects the active field. Name and note focus hide the keypad. Toggles after Repeats, EntryNotes at the bottom, CategoryPicker gets `usage`, home formatter and an `onManage` that routes to /categories.
- **EntryNotes:** wraps `entryNotes` (transfer, refund, marking, fxConverted/fxKept); FX figures come from stored rates only (no fetch); omitted when a rate is missing; RateAttribution shown for new lines (edit rows keep their stored attribution).
- **useCapCrossing:** compares the pre-save usage with the post-save spend in home currency (stored-rate conversion, skip if no rate), edit deltas count only the change, current month only; `hapticWarning` plus `categories.cap.overToast`.

## Deviations from Plan

**1. [Rule 3 - Blocking] recurringControls.test.tsx updated (outside files_modified)**
- The sheet now imports the Supabase-backed hooks (moneyPrefs, fxLatest, usage), so this existing suite needed the same mocks and keypad presses instead of `changeText` on the removed amount input. Test-only change.

**2. [Design] Cap toast keeps Undo**
- The toast store has one slot; showing an `info` toast after the save's Undo toast would drop Undo. When a step id exists the cap toast is `ordinary` with that step. Hook default remains `info`.

**3. [Design] Scope prompt for Automatic**
- `is_automatic` is not in `TEMPLATE_FIELDS` (recurringForm.ts, outside this plan), so the sheet adds an explicit `recurring_series_id && patch.is_automatic !== undefined` check. This-and-future then patches the row and starts the series change the day after (existing thisAndFuturePlan behaviour for non-template fields).
