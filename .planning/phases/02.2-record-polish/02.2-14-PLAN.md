`create or replace function public.add_activity_month(p_household_id uuid, p_month text, p_today date, p_undo_step jsonb) returns jsonb language plpgsql security definer set search_path = ''`:
1. Membership: `if p_household_id is null or p_household_id not in (select public.user_household_ids()) then raise … 42501`.
2. Validate: `p_month ~ '^\d{4}-(0[1-9]|1[0-2])$'`; `abs(p_today - current_date) <= 2`; p_undo_step object with uuid `id`, `label_key = 'monthAdded'`; else 22023.
3. Replay: if `exists (select 1 from public.undo_log where id = (p_undo_step->>'id')::uuid and owner_id = auth.uid())` return `{"status":"already-applied"}`.
4. Lock and compute: `select * into h from public.households where id = p_household_id for update;` `v_default := to_char(public.recurring_horizon(p_today), 'YYYY-MM');` `v_effective := greatest(coalesce(h.horizon_month, v_default), v_default);` `v_expected := to_char(to_date(v_effective || '-01','YYYY-MM-DD') + interval '1 month', 'YYYY-MM');` if `p_month <> v_expected` -> raise 22023 'month must follow %'. Cap: if `p_month > to_char(date_trunc('month', p_today) + interval '12 months', 'YYYY-MM')` -> 22023.
5. Capture before-state: `v_before_horizon := h.horizon_month;` and for every active series in the household (`deleted_at is null and (end_date is null or end_date >= to_date(p_month || '-01','YYYY-MM-DD'))`), store `(id, materialised_through)` in a temp array/jsonb.
6. `perform set_config('fincwin.system_restamp', 'on', true); update public.households set horizon_month = p_month where id = p_household_id; perform set_config('fincwin.system_restamp', '', true);`
7. For each captured series: `v_inserted := v_inserted || array(select public.materialise_series(s.id, p_today));`
8. Build ops after all writes, reading current versions: (a) one `{"entity":"transactions","id":id,"expectedVersion":version,"patch":{"deleted_at":"$now"}}` per inserted row (in insert order); (b) one `{"entity":"recurring_series","id":id,"expectedVersion":current version,"patch":{"materialised_through": <before value or null>}}` per captured series whose materialised_through changed; (c) `{"entity":"households","id":p_household_id,"expectedVersion":current version,"patch":{"horizon_month": <v_before_horizon or null>}}`. If the ops array would exceed 6000 entries raise 22023 (MAX_UNDO_OPS).
9. `insert into public.undo_log (id, owner_id, label_key, label_params, ops, allow_system_keys) values ((p_undo_step->>'id')::uuid, auth.uid(), 'monthAdded', coalesce(p_undo_step->'label_params','{}'::jsonb), v_ops, true);`
10. Return `jsonb_build_object('status','applied','month',p_month,'inserted',to_jsonb(v_inserted),'undo_step_id',(p_undo_step->>'id')::uuid)`.
11. `revoke execute on function public.add_activity_month(uuid, text, date, jsonb) from public, anon; grant execute … to authenticated;`
Header comment: D-16, RESEARCH Pattern 7 and assumption A7 (the rewind only touches system-inserted rows from this step; undo_replay refuses if the series generation moved since, D-CR-01). Run `npm run lint:migrations`.
