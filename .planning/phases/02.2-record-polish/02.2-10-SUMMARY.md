# Phase 2.2 Plan 10: Record-polish series SQL Summary

The recurring-series SQL now carries the Automatic flag and sample flag from template to occurrences, extends materialisation to the household horizon month, and adds a batch create RPC that records one undo step.

## What was built

- `materialise_series`: `v_through = greatest(recurring_horizon(today), end of households.horizon_month)`; inserts `is_automatic, is_sample` from the series. The daily cron (`materialise_recurring`) inherits both.
- `create_recurring_series`: stores `is_automatic` from `p_series`; `is_sample` is never read from client JSON.
- `edit_recurring_series_from`: accepts `is_automatic` (allowlist and update); future pending occurrences are rebuilt from the template so they follow it.
- `create_recurring_series_batch(p_items jsonb, p_undo_step jsonb)`: 1..50 items (else 22023), replay returns already-applied, each item goes through `create_recurring_series` (membership 42501), concatenated `series_change_inverse` ops stored as one `undo_log` row; all-or-nothing.
- Grants re-issued for all four functions.

## Notes for integration

- Undoing an `is_automatic` template edit replays a `recurring_series` patch containing `is_automatic`; this depends on plan 09 adding `is_automatic` to the `apply_patches` allowlist and type map (its plan states it does). Not tested here because plan 09's migration was not applied.
- `materialised_through` is not rewound by the horizon change; a series already past the old horizon simply materialises further forward on the next run.
