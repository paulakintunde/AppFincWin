# Phase 02.2 — UI Design Contract (Record polish)

> Visual and interaction contract. Generated by gsd-ui-researcher, to be verified by gsd-ui-checker. Source of truth for target depth: `FincWin United.dc.html`. Baseline: `02-UI-SPEC.md` (including its 2026-10-07 colour amendment), `00-UI-SPEC.md`, `03-UI-SPEC.md`.

**Platform note:** React Native / Expo SDK 57. No shadcn, no CSS. All styling is `StyleSheet` + `useTheme()` / `textRole()` from `src/theme/*`. **This phase adds no colours, no type sizes, no radii, no icons, no gradients, no shadows.** Everything below is composed from tokens that already exist in `src/theme/tokens.ts`, `layout.ts`, `typography.ts` and primitives that already exist in `src/ui/` (`Row`, `Pill`, `Chip`, `Sheet`, `SheetHeader`, `ConfirmSheet`, `EmptyState`, `ToastView`, `AmountDisplay`, `SwatchDot`, `CategoryGlyph`). Where this document says "reuse", the executor must not re-style.

**Confirmed:** items were prototype-faithful defaults, all confirmed by the user on 2026-10-08. They are listed in the "Confirmed Decisions" section at the end.

**Scope surface (what this phase touches):**
Activity (`src/features/record/activity/*`): view dropdown, sort, counts, subtotals, series offer, detail sheet, swipe, clone, Scheduled/Paid tags, month list. Entry sheet (`entry/TransactionSheet.tsx`): keypad, toggles, notes. Import (`import/*`): paste-list. Categories (`categories/*`): usage + cap. Accounts (`accounts/*`): delete-empty, Coming in / Going out. You → Money: week start, home currency (REC-25). First-run: sample data + Start fresh banner. The Phase 2 filter system (All / Money out / Money in / Transfers / Unpaid only, search, cross-month) is **unchanged** and applies in every view.

## Spacing Scale

Reuse `src/theme/layout.ts` `space` verbatim (prototype pixel values; exception to the generic 4-multiple scale, as established in Phase 0 and 2). Non-4-multiple values are the documented, project-mandated token exception inherited from Phases 0 and 2; no new values are added.

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| screen-h | 22px | Activity header, subtotal group headers, categories/accounts rows |
| card-pad | 16px | Series-offer card, demo/Start-fresh banner, detail-sheet rows |
| group-gap | 18px | Above each group header (day, week, In, Out) |
| sheet-pad-bottom / sheet-top-radius | 30px / 28px | Detail sheet, clone sheet, paste sheet, series-review sheet (all bottom sheets) |
| row-pad / row-pad-dense | 15px / 13px | Detail-sheet rows 13px (dense field-style), dropdown menu rows 15px |
| gap-sm | 8px | Chip gaps, sort/view control gap, tag-to-label gap |
| gap-md | 10-12px | Keypad key gap, banner internal gaps |
| pill-pad-v | 15px | Primary CTAs in sheets, series-offer buttons |
| touch-target-min | 44px | **Applies to:** every keypad key (min 44px high, keys fill a 3-column grid), view/sort dropdown triggers, swipe-revealed action zones, series-offer buttons ("Review each", "Mark all monthly", "Not now"), calendar day cells, Received/Expected and Paid/Pending status pills, "Add next month" row, Start fresh banner button, detail-sheet action buttons |

**New (derived, no new token):** keypad key height = `touch-target-min` + 8 (52px) using `gapSm` arithmetic from existing tokens; compute as `space.touchMin + space.gapSm`, do not add a literal. Calendar cell = `(screen width - 2 * screen-h) / 7`, min height `touch-target-min`. Swipe reveal width = 88px per action (**Confirmed**; prototype uses a drag gesture, thresholds are executor-tuned, minimum zone must still be 44px high x 88px wide).

Accessibility: every swipe action is also reachable without gesture (detail sheet buttons and bulk bar), and exposed as `accessibilityActions` (`activate` = open detail, plus custom "Mark paid" / "Mark unpaid" / "Delete").

**Focal point:** on Activity the transaction rows and each group's net subtotal are the anchor. The view dropdown, sort control, count and series-offer are secondary chrome; the series-offer card is the only element allowed a tinted container (`fill1`), never `accent` fill, so it cannot outweigh the list. On the entry sheet the amount-display figure (44px) is the anchor and the keypad sits directly below it. On Account detail the balance figure is the anchor; Coming in / Going out are rows beneath.

## Interaction Contract

### 1. View dropdown (ACT-06, ACT-07, ACT-08)

- Trigger: a pill in the Activity header row, label = current view, with chevron; opens the Phase 3 dropdown chrome (anchored menu with radio dots, per prototype `menu==='view'`). Not a tab bar, not a segmented control.
- Menu title "View". Rows (label, sub-label):

| Key | Label | Sub-label | Trigger label |
|-----|-------|-----------|---------------|
| list | By day | Everything together, newest first | By day |
| week | By week | Calendar weeks of the month | By week |
| split | In / out | Income and expenses apart | In / out |
| balance | Running balance | What is left after each line | Balance |
| calendar | Calendar | Due dates on a grid | Calendar |

- Default view: By day. Selection persists per user (local setting), resets to By day on app reinstall only.
- Filters, search, sort, bulk-select and cross-month search apply in **every** view except Calendar, where filters/search narrow which lines mark the grid and bulk-select is hidden.
- **By day:** groups by day, newest first (or per sort); group header "{Mon} {d}" with that day's net subtotal. Within the Paid / Still to come split that Phase 2 established, day groups sit inside each section.
- **By week:** groups "Week 1" to "Week 5" (calendar weeks of the month starting on the week-start setting, section 12); header shows date range ("Oct 1-4") in Label muted and the week's net. A week with no lines is **omitted**, not shown empty. **Confirmed.**
- **In / out:** two groups, "In" then "Out", each with count and subtotal; transfers excluded from both (consistent with D-50 totals); a third group "Moved" is **not** shown (transfers appear only under By day / By week / Balance and Calendar).
- **Running balance:** rows ordered oldest to newest by day; sub-label becomes "{Mon} {d} · balance {amount} after". Balance is for the selected account when a single account filter is active; with no account filter, the label is "Balance across all accounts" in the header and the running figure uses home currency. **Confirmed.** Group header per day with net.
- **Calendar:** 7-column month grid (weekday initials per week-start), each day with lines shows up to 3 dots in the line's category colour (`CategoryGlyph` colour map, as prototype `dots`), a day's net below the grid on selection; tap day toggles selection (selected ring in `accent`); selected day lists its lines below ("Oct 14, 2026" Sheet-title-role heading, then ordinary `ActivityRow`s; empty: "Nothing on this day."). Cell touch min 44px.
- **Net subtotal** = sum of signed home-currency amounts of the group's non-transfer lines (income and refunds positive, expenses negative). Format: signed, locale money formatter, `ink`. Zero renders "0.00" not a dash.

### 2. Sort and counts (ACT-09, ACT-10)

- Sort control: a second pill beside the view pill, label "Sort: Newest" style is **avoided** (long); trigger shows the current option name only ("Newest"), menu title "Sort by": Newest, Oldest, Biggest, Smallest, A - Z (prototype `SORTS`, label "A – Z" with en dash). Default Newest. Sort applies within groups in every view; group order is always chronological (By day/week) or fixed (In then Out). Biggest/Smallest compare absolute home-currency value.
- Hidden in Calendar view.
- Count: in the totals line, "{n} transaction{s}" next to the total (e.g. "27 transactions · -£1,420.50 out"). Also shown per group header as "{n}" in `inkFaint`, Label role, left of the subtotal. When a filter/search is active the count reflects the filtered set.

### 3. Series offer (ACT-11)

- Card shown at the top of the list (above the first group) in By day / By week / In / out / Running balance when there is at least one candidate and the user has not dismissed it for this month. `fill1` surface, card radius, 16px padding. Text (Body): "{n} line{s} also ran in {Mon} at about the same amount. Mark them monthly?" (prototype `hintText`; "about the same" = within max(5, 20%) and same name, matched across **logged history**, not only imports).
- Buttons (Label, pill, 44px): **"Review each"** (accent fill, white text), **"Mark all monthly"** (outlined, 1.5px, `ink` text), **"Not now"** (text button, `inkMuted`). **Confirmed:** the prototype shows two buttons ("Review" and "Mark them monthly"); requirement ACT-11 names three, so "Not now" is added as the third and "Mark all monthly" is the neutral outlined one while "Review each" is the accent primary.
- "Mark all monthly": one undo step; toast "{n} marked monthly" with Undo.
- "Not now": hides the card for the month; set is remembered so the same lines are not re-offered (`recSkip`).
- "Review each": opens a bottom sheet "Recurring review" (Sheet-title role). Body note: "These matched a line in {prevMonth} at about the same amount. Marking one monthly means it clones forward with the rest of the recurring bills." Group label "Matched against {prevMonth}". Each row: name, "{amount} · {category} · day {d}", two compact pills "Monthly" / "One-off". Footer actions: "Mark all monthly" (accent), "Leave them all" (outlined). Empty: "Nothing left to review. New matches appear here whenever a line repeats from one month into the next." Earliest month: "{Month} is the earliest month here, so there is nothing to compare it against yet."
- Frequency beyond monthly is out of scope for the offer (monthly only).

### 4. Row anatomy and tags (ACT-12, ACT-14, ACT-18)

Row (reuse `ActivityRow`): glyph tile (11px radius) | name (Body) over sub-label (meta 12.5, `inkMuted`) | right column: signed amount (Body) over **tag** (Label 13/600, as `ActivityRow` already uses via `textRole(pairing, 'label')`).

| Situation | Tag word | Colour |
|-----------|----------|--------|
| Expense, paid | "Paid" | `accent` |
| Income, paid | "Received" | `accent` |
| Expense, pending, due date today or earlier | "Due" if today, "Overdue" if past | `danger` |
| Expense, pending, future due date within month | "Pending" | `danger` |
| Income, pending | "Expected" | `danger` |
| Future-dated line (date after today) or pending transfer | "Scheduled" | `inkMuted` on `fill1` chip |
| Transfer, paid | "Moved" | `inkFaint` |
| Refund | "Refund" | `accent` |
| Sync queued | "Queued" (existing) | `inkMuted` |

Precedence when several apply: Scheduled > Overdue > Due > Pending/Expected > Paid/Received. Refund shows alongside by replacing sub-label suffix, not the tag. **Confirmed:** whether a pending line dated in the future uses Scheduled (this spec) or Pending (prototype only uses Scheduled for transfers). ACT-12 says "Future-dated lines and transfers show as Scheduled, distinct from Pending", so Scheduled applies; it also replaces "Pending" for future-dated *income*.

**Swipe (ACT-14):**
- Swipe right (reveal left zone): if pending, fill `accent`, word "PAID" (income: "RECEIVED"); if paid, fill `danger`, word "UNPAY". Full-swipe commits; commit fires `Haptics.impactAsync` (light) and a toast "{name} marked paid" / "{name} back to pending" with Undo (3.2s).
- Swipe left (reveal right zone): fill `danger`, word "DELETE". Full-swipe opens no confirm for single rows (consistent with Phase 2: single delete is undoable); toast "{name} deleted" with Undo, destructive 6s variant.
- Not available in bulk-select mode; recurring-series occurrences keep the Phase 2 scope prompt on delete ("This one / This and future").
- Transfers: swipe right toggles Moved/Scheduled; swipe left deletes both legs through the existing delete-both confirmation (confirm shown, since two entries go).

### 5. Detail sheet (ACT-13)

- Tapping a row (not in bulk mode) opens a read-only bottom sheet (`Sheet`, 28px top radius). Header: glyph tile + name (Sheet title), category + date sub-label, amount (Body 15/500 in row colour; large figure is **not** used here) right-aligned.
- Foreign currency: a note line "{native amount} at {sym}1 = {rate}" (meta).
- Rows (Body label left `inkMuted`, value right `ink`, dense 13px padding, separators `fill1`-adjacent hairline as existing): Status; Paid from / Paid into / From; To (transfers); Kind ("Refund to {category}" in `accent`, refund only); Payment type; Repeats; Method ("Automatic" / "Manual"); Applies to; Entered as; Tax deductible; Receipt; Shared with / Split rule / Paid by / Your share (household rows only, once Phase 8 data exists); Note. Rows whose value is empty show "—", except rows gated off by level/feature, which are omitted.
- Status value uses the tag colours above.
- Actions, stacked, full width, 44px+, pill: primary **"Mark as paid"** (accent) / "Mark as received" / "Mark as pending" / "Mark as expected" / for transfers "Mark as moved" / "Mark as scheduled" (prototype `txActionLabel`); secondary **"Edit transaction"** (outlined); destructive **"Delete transaction"** (`danger` text, outlined). Delete uses the existing single-delete confirm copy. After Mark as paid the sheet closes and the toast confirms with Undo.
- Clone entry point: an overflow row **"Clone transaction"** under Edit transaction in the same stack, outlined (REC-19). It opens the entry sheet pre-filled with the line (fresh id, date = today clamped to the viewed month, status = pending, no link to the original), title "New expense" / "New income", so no separate clone sheet is needed for single lines.

### 6. Clone month (REC-19)

- Entry points: (a) empty-month state action "Clone {PrevMonth} recurring" and (b) an Activity header overflow action. Opens a bottom sheet titled "Clone from {PrevMonth}". Body (Label, `inkMuted`): "Recurring lines only, and anything already here by the same name is skipped." Rows list the candidate lines (name, amount/day) each with a tick (`SwatchDot`-style checkbox), all ticked by default, and a footer pill "Clone {n} line{s}" (accent), disabled when 0 lines are ticked (mirrors the paste sheet). Result toast "{n} lines cloned" with Undo (one step).
- **Confirmed:** the prototype's clone sheet lists months (one tap clones a month). This spec adds per-line ticks and defaults to all ticked; cloning a single line is covered by the detail-sheet "Clone".
- Earliest month: toast "{Month} is the earliest month here."

### 7. Month list and Add next month (ACT-15)

- The month switcher popover rows gain sub-label "{n} entries" ("1 entry" singular), `inkMuted` meta, radio dot for the current month. Last row: **"Add {NextMonthName}"** with sub-label "A fresh, empty month" (prototype). Adding creates the month and selects it; undoable. No cap on future months beyond 12 ahead; at the limit the row is removed.
- The Activity empty state for an empty month offers the clone action when a previous month exists (section 6), otherwise only the existing copy.

### 8. Entry sheet additions (REC-20)

- **Keypad:** shown beneath the amount-display figure, 4 rows x 3 columns: `1 2 3 / 4 5 6 / 7 8 9 / . 0 ⌫`. Keys: `fill1` rest, `surface` pressed with opacity; digit label Sheet-title role; `⌫` as the text character. Replaces the system numeric keyboard for the amount field (the field is not focusable by the OS keyboard; name field keeps the OS keyboard, and opening it hides the keypad until the name field loses focus). Input goes through `useAmountParser` rules: max 2 decimals (3 for currencies that need it), single decimal separator, locale decimal on the "." key label, no leading zeros, ceiling per existing validator. Long-press `⌫` clears. Haptic: `Haptics.selectionAsync` per key. **Confirmed:** keypad *replaces* the system keyboard for amount (prototype).
- **Toggles** (toggle-track 46x28, thumb 22), order after Repeats/Link/Share: "Automatic payment" (all dirs except transfer), "This is a refund" (Expense only; hidden on Income and Transfer). Existing "Tax deductible" retains its position/gating.
- **Notes** (meta text under the toggles, `inkMuted`, Body wrapping, one at a time, priority top to bottom):
  - Transfer: existing cash note (copy in 02-UI-SPEC).
  - Refund on: "A refund gives the money back to {category} instead of counting as income, so the envelope shows what you really spent."
  - Foreign currency (and auto-convert on): "Saves as {home amount} in {HOME} at {sym}1 = {rate}. The original {native} stays on the record."
  - Foreign currency (auto-convert off): "Kept in {CUR}. Totals convert at {sym}1 = {rate}."
  - Otherwise, when an account is chosen and status is Pending: "Marking this paid moves {account} by {amount}."
  - The FX note may sit with the "Marking this paid" note (two lines stacked) rather than replacing it; refund and transfer notes replace the "Marking" note.
  - Rates come from the existing on-demand FX layer; never show a live-sounding rate without `RateAttribution`.
- **Received/Expected:** for income the Status pill pair and the status menu use "Received" / "Expected" (expense: "Paid" / "Pending"); menu sub-labels: Received "Money is in the account", Expected "Invoiced or scheduled"; Paid "Already left the account", Pending "Still to be paid". Entry-sheet CTA copy unchanged.
- Category menu rows gain usage sub-labels (section 10).

### 9. Paste to add (REC-21)

- Entry: Import sheet's picker screen gains a first option **"Paste a list"**; also reachable from You -> Import. Opens a bottom sheet titled "Paste to add".
- Rows: "Add to" selector row (Expenses / Income, `fill1` row, chevron) | helper (Label, `inkMuted`): "One per line: name, amount, day." (optional fields: category after day) | multiline field (rows=5, `fill1` surface, 1.5px `inkFaint` border at rest, accent on focus, radius 18, placeholder `Studio rent, 1450, 1` newline `Phone + data, 78, 12`) | live count line left (meta): "{n} line{s} ready" or "{n} ready, {m} skipped" | text button "CSV file..." right (routes to the existing statement import).
- Primary CTA: **"Add {n} line{s}"** (never bare "Add"); disabled with count 0; empty-submit message: "Paste a few lines first."
- Parsing: amounts through the strict `useAmountParser`; lines that fail are skipped and listed after commit ("Skipped 2: line 3, line 7"). Pasted rows land as Pending, dated in the viewed month, flagged to the same duplicate check as statement import ("Possible duplicate"). One undo step. Success toast "Added {n} lines".
- Privacy line is **not** used (paste text is not a file; do not claim device-only).

### 10. Categories: usage and cap (REC-22)

- Category list row gains a meta sub-label: "Used {n} time{s} this month" or "Not used yet"; with a cap: "{spent} of {cap} this month". Cap set, not yet reached: `inkMuted`; at or above 100%: `warn1` text **and** the words "over by {amount}" ("{spent} of {cap} this month, over by {over}") **(Confirmed: `warn1`)**.
- Category sheet (create/edit) gains a "Monthly cap" amount field after Name: label "Monthly cap", helper "Optional. Leave blank for no cap." Amount in home currency via `useAmountParser`. Clearing it removes the cap.
- Entry-sheet category menu: sorted by use this month (most used first), sub-label as above or "Cap {amount} a month" or "Not used yet"; last row "Manage categories..." sub-label "Add, rename or remove".
- Caps do **not** block a save. No "you should" copy anywhere. Cap-breach haptic + toast ("{category} is over its cap by {amount}") is already specified in CLAUDE.md as "cap breach" haptic; this phase uses `notificationAsync(Warning)` on the save that crosses the cap only (once per crossing).

### 11. Sample data and Start fresh (REC-23)

- First run for a user who chose "Explore with sample figures" (onboarding path; the "Bring your history" / "Start fresh" choice in 02-UI-SPEC stays): the app is populated with a clearly synthetic sample (accounts, ~20 lines in the current month, one recurring set) and a persistent bottom banner above the tab bar, `#F4F7F4`-style tint expressed through an existing tone token (use `fill1` if no equivalent exists), top hairline.
- Banner layout: 8px `accent` dot | title (meta 12.5/600) "These are sample figures" | body (eyebrow 11.5, `inkMuted`): "Look around, then clear them to start with your own." | right-aligned pill button **"Start fresh"** (accent, 44px high, white Label text).
- Tap "Start fresh" -> `ConfirmSheet`: title "Start fresh?"; body "The sample accounts, transactions and categories you have not edited are removed, and the app opens empty and ready for your own figures. This can't be undone." Actions: "Cancel" / **"Clear sample figures"** (destructive `danger`). Not undoable via toast (the cleared data is synthetic); the confirm is the guard.
- Sample rows carry no real-user claim: never counted toward Decide inputs, never synced as real data, and never offered to the series detector; the Decide tab (later) must treat them as not-yet-real.
- Copy rewrite: the prototype's "Reset demo data" and "nothing leaves the phone" lines are **not** ported.

### 12. Week start (ACT-16)

- You -> Money (or Settings) row **"Week starts on"**, sub-label "Used by the calendar and week view", value "Monday" / "Sunday" (no Saturday; confirmed 2026-10-08). Opens a two-option dropdown. Default from device locale region (region-preference precedence: user override > device region), falling back to Monday.
- Changing it re-flows the By week groups and calendar columns immediately; no confirm.

### 13. Delete an empty account (REC-24)

- Account detail footer: when the account has **zero** lines (including transfer legs and import history), a destructive text row **"Delete account"** (`danger`) appears; tap -> `ConfirmSheet`: "Delete {name}? It has no transactions. Cancel / Delete account". Success toast "{name} deleted" with Undo.
- When it has lines: the row reads **"Archive account"** (neutral, `ink`); sub-label "{n} transactions stay in your history." Archive already exists in Phase 2; this phase only makes the two states explicit. Never show Delete for an account with lines; never show a disabled Delete.

### 14. Account detail pending split (ACT-17)

Replace the single pending line with rows in the detail rows block (Label left `inkMuted`, value right):

| Row | Value | Colour |
|-----|-------|--------|
| Currency | "{CCY}" + " · {home value} in {HOME}" when foreign, else " · home" | `ink` |
| Coming in | sum of pending positive moves in account currency, "—" when none | `accent` when non-zero |
| Going out | sum of pending negative moves, shown positive, "—" when none | `danger` when non-zero |
| After everything pending | balance + in + out (signed) | `danger` if negative, else `accent` |
| On the statement | balance of cleared lines only | `ink` |
| Not ticked off | "{n} line{s}" or "None" | `ink` |

Pending in/out are computed from existing pending lines (transfers contribute by leg sign). The detail's list of the month's lines uses the Paid/Received tags of section 4. The standing sentence from Phase 2 stays under the balance figure unchanged.

### 15. Home currency change (REC-25)

- You -> Money row **"Home currency"**, value current code. Tap -> currency picker (reuse). ## Accessibility

- Every dropdown trigger has an `accessibilityLabel` stating current value and action ("View: By day. Opens a menu."), `accessibilityRole="button"`.
- Group headers are `accessibilityRole="header"` and read "{label}, {n} transactions, net {amount}".
- Row labels announce tag and amount ("Netflix, 12.99 out, Pending"); swipe actions are exposed as custom accessibility actions; the swipe-reveal words are decorative to the screen reader.
- Keypad keys each have a spoken label (digits as numerals, "Decimal point", "Delete last digit"); the amount figure is a live region announcing the entered value.
- Calendar cells: label "{Mon} {d}, {n} lines, net {amount}" and selected state.
- Toggle rows are `accessibilityRole="switch"` with checked state.
- Colour is never the sole carrier (tags, signs and words throughout); `danger`/`accent` contrast on `surface`/`canvas`/`fill1` was verified in the 2026-10-07 amendment; `warn1` on `surface` is reused as in Phase 2; Scheduled (`inkMuted` on `fill1`, about 4.8:1) is covered by `src/theme/__tests__/contrast.test.ts` line 21. Never use `inkFaint` on `fill1`.
- Respect reduced motion for sheet and swipe animations (existing `motion.ts`).

## Confirmed Decisions (user, 2026-10-08)

All eleven defaults below were confirmed by the user as written.

1. Series-offer button set: "Review each" / "Mark all monthly" / "Not now" with Review as the accent primary (prototype has two).
2. Scheduled definition: future-dated pending lines (including income) show Scheduled, not Pending; Scheduled styled `inkMuted` on `fill1`, not `danger`.
3. Keypad replaces the OS keyboard for the amount field (prototype) vs sits alongside.
4. Cap reached/exceeded colour: `warn1` (spec default) vs `danger`.
5. By week: omit empty weeks; week header shows date range; group nets in `ink` (only In-group net is accent).
6. Running balance across "all accounts" shows a home-currency running figure, with a single-account balance when an account filter is on.
7. Clone month sheet: per-line ticks (all ticked) rather than the prototype's one-tap month list.
8. Week-start options: Monday / Sunday only (no Saturday); default from device region.
9. Sample figures: entry via an onboarding "Explore with sample figures" path; confirmation wording and "unedited items only" clearing rule.
10. Swipe reveal width 88px and full-swipe-commits behaviour for pay/delete (delete single rows without a confirm, relying on Undo).
11. Home currency change presented as a confirm sheet with inline rate-fetch progress, no partial change on failure.
