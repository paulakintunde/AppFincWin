# Phase 2.2 Plan 09: apply_patches patches Summary

One migration replaces undo_log_fill, apply_patches and undo_replay (full bodies, changes marked `2.2`) and adds `undo_log.allow_system_keys`, so the new columns undo and bulk-edit, and the add-month undo can rewind `materialised_through` and `households.horizon_month` without any client being able to.

## What changed
- Allowlist and type map: `transactions.is_refund/is_automatic` (boolean), `categories.monthly_cap` (bigint), `recurring_series.is_automatic` (boolean), `accounts.deleted_at` (timestamptz, `$now` supported).
- `recurring_series.materialised_through` (date) and `households.horizon_month` (text) are in the allowlist only when `fincwin.undo_replay = 'on'`; otherwise they hit the existing 22023 unknown-column error.
- `households` is an accepted entity, scope-checked by `id in user_household_ids()` (42501).
- `undo_log_fill` accepts a households op only when `allow_system_keys` is true. `allow_system_keys` is not in the client column grant on undo_log, so a client insert naming it fails 42501.
- `undo_replay` sets `fincwin.undo_replay` and `fincwin.system_restamp` (transaction-local) around `apply_patches` only for flagged steps, and clears them afterwards and in the refusal handler.

## Deviations from Plan
None in behaviour. Both tasks were committed together in one commit (ad69bc1) because the migration and its test were written as one unit.
