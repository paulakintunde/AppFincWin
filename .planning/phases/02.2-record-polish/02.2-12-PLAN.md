    - pressing a row calls onSelect(key) once, fires hapticSelection, and closes the menu

  <action>
1. `Dropdown.tsx`: 
```typescript
export interface DropdownOption<K extends string> { key: K; label: string; subLabel?: string; triggerLabel?: string; }
export interface DropdownProps<K extends string> { title: string; options: readonly DropdownOption<K>[]; value: K; onSelect: (key: K) => void; triggerA11yLabel: string; disabled?: boolean; variant?: 'pill' | 'row'; rowLabel?: string; }
export function Dropdown<K extends string>(props: DropdownProps<K>): JSX.Element
```
   Trigger 'pill': `fill1` background, Label role text in `ink`, a chevron made from a rotated bordered View (no icon font), minHeight `space.touchMin`. Trigger 'row' (for You settings): a full-width row with `rowLabel` left (Body) and the current option's label right in `inkMuted`, chevron. The menu: an RN `Modal` (transparent, fade unless reduced motion per `motion.ts`) with a scrim tap-to-close, a `surface` card (card radius from `radii`), the title in Label role `inkMuted`, rows padded `space.rowPad` each with a `SwatchDot`-style radio dot (filled `accent` when selected, `fill1` ring otherwise), Body label and meta sub-label in `inkMuted`. Rows `accessibilityRole="radio"` (or "menuitem" if radio is unsupported in RN types — use "button" with accessibilityState.selected), 44px min. On select: `hapticSelection()`, close, `onSelect(key)`. Header comment: CONTEXT D-27; built to 02.2-UI-SPEC sections 1-2 because 03-UI-SPEC has no dropdown contract; Phase 3 adopts this component unchanged.
2. `ToggleRow.tsx`: `export interface ToggleRowProps { label: string; value: boolean; onChange: (next: boolean) => void; disabled?: boolean; accessibilityHint?: string; }`. Track 46x28 (radius 14), thumb 22 (white = `colors.surface`), track `accent` when on, `fill1` with an `inkFaint` 1.5px border when off; label Body `ink` left; whole row pressable, 44px min height; `accessibilityRole="switch"`, `accessibilityState={{ checked: value, disabled }}`. The 46/28/22 numbers are component geometry from UI-SPEC 8, defined as named constants with a comment (not new tokens).
3. Tests per the behaviour list using the recordPrimitives harness.
