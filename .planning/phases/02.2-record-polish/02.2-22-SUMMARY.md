# Phase 02.2 Plan 22: Category usage and monthly cap Summary

Categories now show this month's usage (paid and pending, net of refunds, home currency) or spend against an optional cap, the cap can be set, cleared and undone, and the entry-sheet picker sorts by use.

## Commits
- 20fd97d: usage hook, sub-labels on Categories screen, Row sublabel support
- e5702a9: cap field, mutations, picker

## What was built
- `useCategoryMonthUsage` groups the current month's `useMonthView` rows by category and runs engine `categoryUsage` with each category's `monthly_cap`.
- `usageSubLabel` (pure module) gives the UI-SPEC 10 wording; over-cap is warn1, refunds-exceed is inkMuted and unfloored.
- `CategorySheet` has an optional Monthly cap field (strict `useAmountParser`, home currency, blank clears, hidden for system categories, zero/over 1e13 refused to match the DB check).
- `useAddCategory`/`useEditCategory` carry `monthlyCap`; the undo `before` snapshot restores the previous cap.
- `CategoryPicker` takes optional `usage`, `formatMinor`, `onManage`; sorts by count desc then name, shows usage or "Cap {amount} a month", ends with "Manage categories…".

## Deviations from Plan
**1. [Rule 3 - Blocking] `src/ui/Row.tsx` (outside files_modified)**: Row had no second line, so added optional `sublabel`/`sublabelTone` props (backwards compatible).
**2. [Design] Picker takes `formatMinor` prop** rather than calling `useRecordContext`, so existing callers and tests need no providers; plan 25 passes the formatter with `usage` and `onManage`.
**3. `usageSubLabel` in its own file** (re-exported from the hook file) so the picker does not pull the data layer/env into its import graph.
