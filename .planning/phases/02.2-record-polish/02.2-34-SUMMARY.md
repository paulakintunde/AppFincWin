# Phase 02.2 Plan 34: Activity wiring Summary

Activity now shows Calendar as the fifth view, the series offer card above the first group, a read-only detail sheet on tap, swipe pay/unpay/delete, month counts with Add month, a More menu (Clone, Paste) and a richer empty month.

## Commits
- 7368341 useRowActions hook and tests (Task 1)
- cfa8889 screen, view model, header wiring and integration tests (Tasks 2 and 3, committed together because both change the same three files)

## What was built
- `useRowActions`: pay/unpay (transfers patch both legs in one `useBulkPatch` step labelled `transferEdited`; no partner loaded means nothing is written and an info toast shows), `remove` (plain line deleted with undoable destructive toast; series occurrence returns `scope`; transfer returns `transferDelete`), `deleteThisOne` / `deleteThisAndFuture` (ends the series at the row date and deletes the row) / `deleteTransfer`, `cloneMode` (today for the current month, otherwise the day clamped with `daysInMonth`). Disabled during bulk selection.
- View model: `useRowFlow` (detail sheet, entry sheet target, pending delete prompt), offers (hidden in Calendar and in search), month tools (`counts`, `addableMonth`, `useAddMonth`, clone/paste open state, earliest-month info toast).
- Header: counts/add props to MonthSwitcher and a `MoreMenu` (Dropdown pill, a11y "More actions. Opens a menu.").
- Screen: CalendarView branch (Select and sort hidden), `ListHeaderComponent` offer card, TransactionDetailSheet, RecurringReviewSheet, EditScopePrompt, transfer delete-both ConfirmSheet, CloneMonthSheet, PasteSheet, empty state with Clone/Paste actions.

## Deviations from Plan

**1. [Rule 3 - Blocking] Earliest-month check does not use `fetchHasRowsBefore`**
- That function takes an account id and a date, not a month. "Earlier month has rows" is read from `useTransactionMonths` counts instead (no extra query). Files: useActivityViewModel.ts.

**2. [Rule 3 - Blocking] `useRowActions(` lives in ActivityScreen, flow state in `useRowFlow`**
- The plan's structural grep needs the screen to call `useRowActions(`, and the view model cannot call it before the rows exist, so the sheet/prompt state is a second hook (`useRowFlow`) in the view-model file. Screen holds no new state.

**3. [Rule 3 - Blocking] Edits to ActivityViews.test.tsx (outside files_modified)**
- ActivityScreen now imports modules needing a Supabase env and a QueryClient; the existing screen tests needed the shared mocks plus `useBulkPatch` / `useDeleteTransaction` stubs. Added `activityScreenMocks.tsx` (new test helper). The old "tap opens the edit sheet" test now goes through the detail sheet's Edit.

**4. More menu trigger value**
- `Dropdown` needs a value to show a trigger label; Clone stands in as the (unlabelled) value so the trigger reads "More". The selected dot beside Clone in the open menu is cosmetic. `ui/Dropdown.tsx` was left untouched.

**5. `useTransactionMonths` now receives `rc.horizonMonth`** so an added month appears at once (optimistic horizon).
