# Phase 3.1 — UI Design Contract (Activity header redesign)

> Visual and interaction contract. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **This file amends, and does not replace, `03-UI-SPEC.md` and `02-UI-SPEC.md`.** Anything not stated here is inherited unchanged from them: tokens, spacing scale, type roles, sheet engine, toast, sync line, back history. All decisions come from `03.1-CONTEXT.md` (D-43..D-69, all locked). Where this file and the earlier specs differ for the Activity header, this file wins.

**Platform note:** React Native / Expo SDK 57. No shadcn, no CSS. Styling is `StyleSheet` plus the typed theme (`useTheme()`, `textRole()`, `src/theme/*`). The CLAUDE.md fidelity rule holds: no new colour, gradient, shadow, type size or icon set. Colours are cited by token name only.

**Surface in this phase:** only the header of the Activity tab (the `listHeader` in `ActivityScreen.tsx`, `ActivityHeader.tsx`, the Calendar path's copy of it, and the Activity compact header). Rows, the day groups, entry sheet, FilterSheet internals, BulkBar actions, the FAB and Home are untouched. No new filters, views, sorts or data.

## Layout: four bands (D-43)

Top to bottom inside the existing `Screen` / list header. The large title scrolls away into the compact header (03 D-14, amended below).

| # | Band | Contents | Hidden when |
|---|------|----------|-------------|
| (chrome) | `chrome.largeHeader` | Title row (band 1) plus the sync-problem line (03 D-15, unchanged) | never |
| 1 | Title row | "Activity" (heading role) at left, 42px avatar at right. **No eyebrow** (D-44). | never |
| 2 | Month row | `‹ October 2026 ›` at left; Search, Filter, More icon buttons at right. Becomes the search field while searching. | never |
| 3 | Summary card | Read-only card (see below) | empty month (D-51); searching (D-61) |
| 4 | Display row | Display chip, then filter chips, ending in "Clear all" when 3 or more. Replaced by the select bar in select mode. | empty month (D-51); searching (D-61) |

Then, unchanged in order: `UnpaidBanner` when `filter.unpaidOnly` (Phase 3 D-41, kept, D-66), then the recurring-offer card `SeriesOfferCard` (D-46), then the list. The banner sits directly under band 4 (above the offer card). While searching the banner and offer card also stay hidden so only field, scope switch and results show (D-61).

**Removed from the header (nothing is lost, each moves):** eyebrow, In / Out / Net / Still-to-come strip, View dropdown, Sort dropdown, More dropdown, Accounts and History link row, Select pill, Select all / None pills row, inline `SearchBar`, the Filter chip in the tools row, the stand-alone balance note.

**Focal-point rule (02-UI-SPEC L80, restated):** the list is the anchor. Header chrome never outweighs rows or the figure. The only large type in the header is the title and the card figure, both 26px (the figure is 26/700 like Home, so it cannot outrank the title).

**Above-the-fold acceptance:** on a Pixel 9 at default text size, with the recurring-offer card showing and no active filter, the first entry row is fully visible without scrolling. (Budget: four bands of roughly title 60 + month 44 + card 92 + display 44 plus gaps of 12 leaves room for the offer card and one row on a 915dp-high window. If it fails on device, reduce nothing below 44pt touch targets; trim card padding to `space.cardPad` first.)

## Component contracts

### Title row (band 1) — D-44
Heading "Activity", avatar 42px (hit 44) at trailing edge, exactly as 03-UI-SPEC "Header". The date eyebrow is **not rendered** on Activity (omit the `eyebrow` option in `useTabRootChrome` for this screen). Title is `accessibilityRole="header"` and receives focus on tab change and push (03 D-20, unchanged).

### Month row (band 2) — D-52..D-55
- Left cluster: Previous month button (44x44, chevron per existing `MonthSwitcher`), the month name button (flex, min 44 tall), Next month button (44x44). Tapping the name opens the existing month list sheet with per-month entry counts; "Add {next month}" stays as its bottom row (D-53) and is not repeated in More.
- Right cluster: Search, Filter, More `HeaderIconButton`s, in that order, 44pt hit areas.
- Month name text: long form via `Intl.DateTimeFormat(locale, { month: 'long', year: 'numeric', timeZone: 'UTC' })` ("October 2026"). Shortened form: `{ month: 'short', year: 'numeric' }` ("Oct 2026"). Never a fixed 3-letter slice (03 L3).
- **Tight-space rule (D-55), evaluated by measuring, not by a hard width check:**
  1. If the long name does not fit on one line between the arrows and the icon cluster, use the short name.
  2. If the short name still does not fit (320pt wide, or largest text size), move the three icons to their own row directly under the month row, right-aligned, same 44pt targets. The month cluster then takes the full width.
  3. Search and Filter never move into More. Nothing is truncated with an ellipsis in the month name; step 2 is the last fallback.
- Arithmetic check: at 320pt wide with 22 side padding the row is 276 wide; arrows 88 + icons 132 leaves 56 for the name, so at 320pt step 2 is expected, and that is correct behaviour.
- A11y: name button label "{October 2026}, choose month" (`activity.monthSwitcher.nameA11y`); Previous month and Next month are separate buttons (`activity.monthSwitcher.previous/next`, existing).

### Icon buttons — D-56, D-57
`HeaderIconButton` props: `glyph: 'search' | 'filter' | 'more'`, `label`, `badge?: number`, `onPress`. Role `button`. 36 circle `fill1`, glyph `ink`, hit area 44 via `hitSlop`, pressed opacity 0.72, focus ring 2px `accent` offset 2.
- **Filter badge:** shown only when `activeFilterCount > 0`: `accent` circle, number in `tabLabel` `surface`, capped display "9+" for 10 or more. The badge is `importantForAccessibility="no-hide-descendants"`; the button label carries the count.
- **Counted filters:** category, account, amount (min and/or max counts as one), direction. **Unpaid is not counted** (planner call, decided here): the Unpaid filter owns its own banner (D-66), so the banner and the badge can never contradict. A screen with only Unpaid on shows "Filter" with no badge and the banner.
- Tap Filter: opens the existing `FilterSheet` (unchanged internals).
- Tap More: opens the More menu (below).
- Tap Search: enters search mode (below).

### Glyph drawing spec — D-56 (build precisely)

Common to all three: `react-native-svg` `<Svg width={22} height={22} viewBox="0 0 22 22">`, `accessibilityElementsHidden` and `importantForAccessibility="no-hide-descendants"` (the button carries the name), single prop `color` (= `ink`). Same shape language as `TabGlyphs.tsx`: 3 to 4 unit margin from the grid edge, round caps and joins, rounded rect radius 1.2 to 1.4, **full-strength primary element and the 0.45 / 0.7 opacity two-tone pattern**, strokes 2.2 (like the Decide diamond and Insights ring) or filled shapes. No gradient, no extra colour.

| Glyph | Drawing (22-unit grid) | Two-tone |
|---|---|---|
| Search | Ring: `<Circle cx=9.6 cy=9.6 r=5.9 fill="none" stroke strokeWidth=2.2 />` at opacity 1. Handle: `<Path d="M14.2 14.2 18.6 18.6" stroke strokeWidth=2.4 strokeLinecap="round" />` at opacity **0.45**. | ring 1, handle 0.45 |
| Filter | Three bars narrowing downward (a funnel in the Activity-glyph bar style), all `<Rect height=2.4 rx=1.2>`: `x=3 y=4 width=16` (opacity 1), `x=6 y=9.8 width=10` (opacity 0.7), `x=8.5 y=15.6 width=5` (opacity **0.45**). Centre line of all three is x=11. | 1 / 0.7 / 0.45 |
| More | Three filled dots, `r=2.1`, centred on y=11: `cx=4.5` (opacity 0.45), `cx=11` (opacity 1), `cx=17.5` (opacity 0.45). | 0.45 / 1 / 0.45 |

**Acceptance check (side-by-side with the tab glyphs):** render `TabGlyph` Activity, Insights and Decide at 22 next to the three new glyphs on a `canvas` and a `fill1` background, at 1x and 3x. Pass when: (a) visual weight matches (the Search ring reads the same stroke weight as the Insights ring; the Filter bars read the same thickness as the Activity bars); (b) the glyph occupies the same optical box (3 to 4 unit margin); (c) the faded element is clearly secondary but visible at 0.45; (d) no glyph appears heavier or thinner than a tab glyph. Add a snapshot test of the three glyph trees and a visual check screenshot under the phase's verification artifacts. Do not use any icon library (CLAUDE.md).

### Summary card (band 3) — D-47..D-51
- Container: `surface`, `radii.card`, `shadows.card`, padding `space.cardPad`, margin-top 12. **One accessibility stop** (D-50): the card is `accessible` with a single label, read-only (no `onPress`, not a button; pressed state absent).
- Layout (top to bottom):
  1. Top row: left, the figure (`heading`, capped 1.3x) with its caption underneath in `label` `inkMuted`: "left after everything · {count} entries"; right (top corner), the still-to-come line "{amount} still to come" in `warn1` (`meta`-size label). **Source (F3):** the unpaid-outflows quantity from the engine month position (`unpaidOutflows` / `position.unpaid` in `src/engine/activity/monthFigures.ts`), the same figure as Home's UNPAID and the deduction inside `leftAfterEverything`. It is **not** the signed `MonthTotals.stillToCome`, which mixes in expected income. The corner therefore cannot disagree with the big figure. Hidden when the month has no still-to-come amount (zero or none).
  2. 8px below: the In/Out line "In {amount} · Out {amount}" (paid totals, D-10 intact), or in Running balance view the balance note instead (D-49): "Balance across all accounts" or "Waiting for a rate" (existing `activity.balance.allAccounts` / `activity.balance.waiting`, from `vm.balanceHeader`). The figure itself does not change in Running balance view.
  3. When `unconvertedCount > 0`: one `label` `inkMuted` line "{count} line(s) waiting for a rate" (existing `activity.totals.unconverted`), 8px below, same as Home.
- Figure source: `leftAfterEverything` / month position from `src/engine/activity/monthFigures.ts`, the same call Home uses, so Home and Activity always agree. Format: leading "+" when >= 0, locale minus when negative, home currency via `useMoneyFormatter`. Colour per Typography. No bar.
- **Wide text / narrow width (planner's discretion, decided here):** when the corner label does not fit beside the figure column, or font scale is above 1.3x, the corner line wraps under the caption (stacked, left-aligned) instead of shrinking. Nothing truncates.
- **Loading** (month query pending, nothing cached): the card renders with `fill1`-on-`line4` placeholder blocks at final size (figure, one line), `accessibilityLabel` "Loading overview" (`home.loading`, reused), `busy: true`. **Error / offline uncached:** reuse the existing Activity query-error handling (stay on the cached month; the sync line carries the problem); the card shows the cached figures.
- A11y label (one string, `activity.summary.a11y`): "{figure} left after everything, {count} entries. In {in}. Out {out}. {stillToCome} still to come." In Running balance view, the In/Out sentences are replaced by the balance note. Omit "still to come" when zero. The balance note in the Running balance variant is the real string "Balance across all accounts" (or "Waiting for a rate").
- **Empty (D-51):** if `totals.count === 0 && position.unpaidCount === 0 && position.unconvertedUnpaid === 0` (the same expression as `ThisMonthCard` line 84), hide bands 3 and 4 entirely. A month with only expected bills is not empty. The title row and month row remain, and the existing empty state (Add, Clone, Paste) follows. Searching an empty month still shows the search field (search is in band 2).

### Display chip and sheet (band 4) — D-64, D-68
- **Chip:** the existing `Chip` primitive, not selected-styled (neutral `fill1`, `ink`), label `"{view} · {sort}"`, e.g. "By day · Newest", "Running balance · Newest". For Calendar the label is just "Calendar" (no sort). The Running balance label uses the full name "Running balance" in the chip (the old "Balance" trigger short name is retired).
- Tap opens one `DisplaySheet` (built on `Sheet`, `accessibilityViewIsModal`): title "Display"; section heading "View" with five single-select rows (By day, By week, In / out, Running balance, Calendar) each with its existing sub-line; section heading "Sort by" with five rows (Newest, Oldest, Biggest, Smallest, A – Z). The Sort section is **not rendered** when Calendar is the chosen view. Selected row shows the same tick treatment as the existing `Dropdown`. Choosing a row applies it immediately and keeps the sheet open (so View and Sort can both be set); the sheet closes via backdrop, drag, Android back or a "Done" action (`a11y.close` label for the backdrop). Sheet corners, backdrop, drag-to-dismiss, stacking: unchanged from 03-UI-SPEC "Sheets". Choosing Calendar while a sort is stored keeps the stored sort for when the user leaves Calendar.
- A11y: chip role `button`, label contains the visible text (WCAG 2.5.3): "{view} · {sort}, display options" e.g. "By day · Newest, display options" (`activity.display.triggerA11y`); for Calendar "Calendar, display options" (`activity.display.triggerA11yCalendar`).

### Filter chips — D-65..D-67
- After the Display chip, one chip per active filter, in this order: category, account, amount, direction. Label examples: "Groceries", "Cash", "£20 – £100", "Money out". When a filter holds several values the chip lists the first and "+{n}" (`activity.filterChip.more`).
- Chip is selected-styled (accent text on accent tint, existing `Chip` selected look) with a trailing "×". **The label area opens the Filter sheet; the × clears just that one filter** (its own 44x44 hit area; the chip body hit area excludes it). The × is a drawn glyph (two rounded bars at 45 degrees, 2px, round caps, 10px box), not a text character.
- A11y: label area "Filter: {label}. Opens filters." (`activity.filterChip.openA11y`); × "Remove filter {label}" (`activity.filterChip.removeA11y`). Removing a filter moves focus to the next chip, or to the Display chip if none remain.
- **Unpaid gets no chip** (D-66): the `UnpaidBanner` ("Showing unpaid bills" + "Clear") stays directly under band 4.
- **Three or more filter chips (D-67):** band 4 becomes a horizontal `ScrollView` (no scroll indicator), one line high, ending in a "Clear all" chip (`activity.filter.clearAll`) that clears all non-Unpaid filters. Fewer than three chips: a normal row, no "Clear all". The Display chip scrolls with the rest (it is first). The row never wraps to a second line.
- Screen-reader order: Display chip, then each filter chip left to right, then "Clear all".

### More menu — D-45
`ActivityMoreMenu` replaces the old More dropdown, opened from the More icon through the `Dropdown` / `Sheet` primitives. Title "More" (`activity.more.label`). Three groups separated by 1px `line1` dividers:

1. **Select entries** (`activity.more.select`) — hidden in Calendar (D-63, D-68).
2. **Clone {previous month}** with sub-line "Lines that aren't repeating" (`activity.more.cloneSub`, shortened, see copy) and **Paste a list** with sub-line "One line per item".
3. **Accounts** and **History** (existing `activity.accounts`, `activity.history`; open the same routes via `onOpenAccounts` / `onOpenHistory`).

The old trigger a11y "More actions. Opens a menu." is reused for the icon button. Clone is omitted when `prevMonthName` is empty, as today.

### Search — D-59..D-62
- Tapping Search replaces the month row with the search field (existing `SearchBar` behaviour: field, clear button) plus a "Cancel" text button at the field's trailing edge (44pt). Beneath the field: the This month / Every month scope switch (existing). **Opens on This month** (D-60). The keyboard comes up and the field takes focus.
- While searching: bands 3 and 4, the Unpaid banner and the recurring-offer card are hidden; the first list line is the results count (existing `activity.count_*`). Title row stays.
- Cancel: clears the term, restores the scope to This month, restores the month row, and returns focus to the Search icon.
- **Motion:** cross-fade between month row and search field over **150ms** (new `DURATION.searchFade = 150` in `src/theme/motion.ts`, `EASING`), opacity only; both layers occupy the same box (absolutely overlaid with the month row's height reserved) so the list does not jump. With Remove animations on (03 D-21) it is instant.
- A11y: field label "Search {month}" / "Search every month" (existing `activity.searchMonth/searchAll`); Cancel label "Cancel search" (`activity.search.cancelA11y`).

### Select mode — D-63
- Entry: More > "Select entries", or **long-press on a row** (starts with that row ticked; the row's existing selection tick is the feedback and no new haptic is added). Not offered in Calendar.
- A **select bar replaces band 4** (band 3 stays): left "{n} selected" (existing `activity.selected_*`), then "Select all", "None" and "Done" as `Pill variant="secondary"` (existing labels `activity.selectAll`, `activity.selectNone`, `activity.done`). Wraps to two lines at large text rather than shrinking. The existing `BulkBar` actions work as today.
- The Display chip and filter chips are hidden in select mode (they return on Done). The FAB hide rule for bulk select is unchanged (03 D-10).
- Long-press a11y: each row exposes a named custom action "Select" (`a11y.selectRow`, existing) so the gesture is never the only route.

### Compact header — D-58
Amends 03 D-14 for Activity only; Home's compact header is unchanged.
- Appears once the large title has scrolled away (`compactThreshold`, unchanged). Contents, left to right: back chevron when history exists (36), title "Activity · {short month}" (`sheetTitle`, single line, ellipsis, short month via Intl `month: 'short'`, no year unless the viewed month is not in the current year, then "Activity · Oct 2025"), then the **three icon buttons** (36 visible, 44 hit). **The avatar is not shown while scrolled.**
- Mechanism: `useTabRootChrome` gets a `compactTrailing` option (distinct from the large header's `trailing`); Activity passes the three buttons, other tabs pass nothing and keep the avatar.
- Compact icon behaviour: Filter and More behave as in the month row. **Search in the compact header scrolls to the top (`scrollTo` 0) and then opens search mode** so the field is visible.
- Background `canvas`, 1px bottom `line1`, fade `DURATION.fade` 200ms, as 03-UI-SPEC.
- At 320pt or largest text the title ellipsises first; icons never shrink below 44 targets.
- The Calendar path's `calendar-scroll` `Animated.ScrollView` gets the same compact header (03-15 pattern), driven by the same `chrome.onScroll`.

### Calendar view — D-68
All four bands remain. Display chip reads "Calendar". No sort, No "Select entries" in More. The card is unchanged. The filter chips and badge work as in other views.

## Accessibility

- **Reading order (D-69):** title; month (name button, with Previous and Next as separate buttons); Search, Filter (with count), More; summary card (one stop); Display chip; each filter chip then "Clear all"; then Unpaid banner, offer card, list. Implementation must match visual order in the tree so TalkBack and VoiceOver agree.
- Focus: 03 D-20 unchanged. Tab change and push focus the title; the compact title is the target once visible.
- When search opens, focus moves to the field; on Cancel, back to the Search icon. When a filter chip is removed, focus moves to its neighbour.
- All icon-only controls carry `accessibilityLabel` and role `button`; every touch target is >= 44pt (hit area), including the chip ×, the arrows, the avatar and the compact-header icons.
- Colour is never the only carrier: the warning amount is text ("still to come"); negative figures use the minus sign; the badge is mirrored in the Filter label.
- Sheets (Display, More, Filter) set `accessibilityViewIsModal` and expose the "Close" escape action (03 D-12).
- Text scaling: body text up to 2x, figures and badge 1.3x. At 2x the card stacks the corner line, the select bar wraps, chips keep their 44pt minimum and the chip row scrolls sideways.
