# Phase 03.1: Activity header redesign - Context

**Gathered:** 2026-10-15
**Status:** Ready for planning

<domain>
## Phase Boundary

This phase reorganises the header of the Activity tab. Today the header stacks up to ten bands and twelve controls that are always visible: title, month switcher, In/Out/Net/Still-to-come strip, View, Sort and More dropdowns, Accounts and History links, search box with scope, and Filter and Select. Above the first entry there can also be the Unpaid banner, the running-balance note, Select all/None and the recurring-offer card. The first entry ends up below the fold.

After this phase the header is **four bands**, and no feature is lost:
1. Title row
2. Month row with the Search, Filter and More icons
3. One summary card
4. One Display chip plus active-filter chips

This phase changes only where existing Activity controls live and how they read.
- **Not added:** new filters, views, sorts or data.
- **Unchanged screens:** Home and the other tabs, except for the shared header pieces they reuse.

Approved proposal (2026-10-15): https://claude.ai/artifact/BNKMdaVimhwxtkev8PJ8Yp. The decisions below are the final word where they differ from it.

</domain>

<decisions>
## Implementation Decisions

### Layout (pre-locked when the proposal was approved)
- **D-43:** **Build all four bands, top to bottom:**
  - **Title row:** "Activity" and the avatar.
  - **Month row:** ‹ Month › on the left; the Search, Filter and More icons on the right.
  - **Summary card.**
  - **Display row:** the Display chip followed by the active-filter chips.
  - Every current control moves; none is dropped. The "where everything goes" table in the proposal is the map.
- **D-44:** **Drop the month eyebrow above the title.** The title row is "Activity" plus the avatar. The month row directly below already names the month.
- **D-45:** **The More menu (⋯) holds, in three groups separated by dividers:**
  1. Select entries
  2. Clone {previous month} (sub-line "Lines that aren't repeating") and Paste a list (sub-line "One line per item")
  3. Accounts and History
  - This removes the Accounts/History link row, the More dropdown and the Select pill from the header.
- **D-46:** **The recurring-offer card stays as the first card in the list.** It sits below the four bands and above the first day, as it does today.

### Summary card
- **D-47:** **The big figure is "left after everything".** Use the same figure and caption as Home's This month card, from the engine's `leftAfterEverything` / month position, so Home and Activity always agree.
  - Under it, one line shows In and Out (paid).
  - Still to come goes in the card's top corner in the warning colour, with the entry count beside the label ("Net · 28 entries" in the proposal; use the Home caption wording).
  - This changes what Activity shows, not what it computes. Phase 2 D-10 still holds: paid totals plus a separate still-to-come figure.
- **D-70:** **Filters and search do not change the card's figures** (decided at plan time, 2026-10-15). The big figure, In/Out and still to come always come from the whole, unfiltered month, so they match Home under any filter. Only the entry count follows the filter or search, reading as "12 of 48 entries" when narrowed and "48 entries" otherwise.
  - This amends Phase 2 ACT-10 ("count and figures beside it follow the filtered set"): only the count still follows the filtered set.
- **D-71:** **While the search field is open, filters are set aside** (decided in the code-review fix WR-01, 2026-10-15). Search hides the filter badge, chips and Unpaid banner (D-61), so results come from the whole month or all months, never a hidden filter. The filters are kept and apply again on Cancel. The compact header's Filter badge still shows the saved count.
  - Build the card from the unfiltered `monthView` position (`monthPosition(monthView.totals, …)`), not from `vm.totals`, which narrows under filters.
- **D-48:** **No paid-versus-pending bar.** Home has the bar; Activity's card stays short.
- **D-49:** **In Running balance view, the In/Out line is replaced by the balance note** ("All accounts" or "Waiting for a rate", from `vm.balanceHeader`). The big figure does not change.
- **D-50:** **The card is read-only.** Tapping it does nothing. Screen readers read it as one stop: figure, caption, In, Out, still to come.
- **D-51:** **Empty month:** when the month has no recorded rows, no unpaid items and no unconverted items, hide the summary card and the Display row.
  - Use the same `empty` rule as Home after G1: a month with only expected bills is not empty.
  - The title and month row stay, and the existing empty state (Add, Clone, Paste) follows.

### Month row
- **D-52:** **Keep the ‹ Month › arrows.** Tapping the month name opens the existing month list sheet, with entry counts per month. Do not use Home's month chips here; they need the whole row.
- **D-53:** **"Add {next month}" stays as the bottom row of the month list sheet.** It is not repeated in ⋯.
- **D-54:** **The month name reads "October 2026"**, shortened to "Oct 2026" only when space is tight. Format it through Intl for the device locale, never with a fixed 3-letter cut (Phase 3 L3).
- **D-55:** **When space is tight (320pt width or the largest text size):**
  1. Shorten the month name first.
  2. If it still doesn't fit, wrap the three icons onto their own row under the month.
  - The icons always stay 44pt touch targets.
  - Search and Filter never move into ⋯.

### Icons and the compact header
- **D-56:** **Draw the three new glyphs (Search, Filter, More) by hand in `react-native-svg`, in the tab-glyph style.** That means the 22-unit grid, rounded strokes and the 45% two-tone treatment `TabGlyphs.tsx` uses. Each glyph is ink on a `fill1` circle with a 44pt hit area.
  - Do not use an icon library (CLAUDE.md: "no substituted icon set").
  - The proposal's thin outlines were placeholders.
- **D-57:** **The Filter icon shows a count badge:** a small accent circle with the number of active filters. Its label reads "Filter, {n} active", or "Filter" when none are on.
  - Count category, account, amount and direction filters.
  - Whether Unpaid counts is the planner's call, provided the banner and the count never contradict each other.
- **D-58:** **The compact header (on scroll) shows "Activity · {short month}" and the three icons.**
  - The avatar drops off while scrolled.
  - This amends Phase 3 D-14 for the Activity tab only. Home's compact header is unchanged.

### Search
- **D-59:** **Search sits behind the Search icon (pre-locked).** Tapping it turns the month row into the search field, with the This month / All months switch beneath it. Cancel brings the month row back.
- **D-60:** **Search opens on This month,** the same default as today.
- **D-61:** **While searching, only the field, the scope switch and the results show.**
  - The summary card and the Display row hide until Cancel.
  - The results count is the first line of the list.
- **D-62:** **Search opens with a quick cross-fade** (about 150ms) and the keyboard comes up. With Remove animations on it is instant (Phase 3 D-21).

### Select mode
- **D-63:** **Select mode starts from ⋯ "Select entries", or from a long-press on a row** (which starts with that row ticked).
  - Rows have no long-press today, so nothing clashes.
  - In select mode a bar with Select all, None and Done replaces band 4.
  - The existing BulkBar actions work as they do today.
  - Select is not offered in Calendar view (as today).

### Display row and filter chips
- **D-64:** **One Display chip replaces the View and Sort dropdowns.**
  - It reads "{view} · {sort}" (for example "By day · Newest"), or just the view where sort doesn't apply ("Calendar").
  - It opens one sheet with a View section (By day, By week, In / out, Running balance, Calendar) and a Sort section (Newest, Oldest, Biggest, Smallest, A – Z).
  - Sort is hidden in Calendar.
- **D-65:** **Each active filter shows as a chip after the Display chip.**
  - The chip's × (44pt hit area) clears that one filter.
  - The chip's label opens the Filter sheet.
- **D-66:** **The Unpaid filter keeps the Phase 3 D-41 banner ("Showing unpaid bills · Clear") and gets no chip.** Other filters show as chips.
- **D-67:** **With three or more chips, band 4 scrolls sideways and ends in a "Clear all" chip.** It stays one line high.

### Calendar view
- **D-68:** **In Calendar, the header keeps all four bands.** The Display chip reads "Calendar", there is no sort, ⋯ has no Select, and the summary card does not change. The Calendar path's scroll view gets the same compact header (Phase 3 03-15 covered this path).

### Accessibility
- **D-69:** **TalkBack reads the header in visual order:**
  1. Title
  2. Month ("October 2026, choose month", with Previous month and Next month as separate buttons)
  3. Search, Filter (with its count) and More
  4. Summary card, as one stop
  5. Display chip, then each filter chip
  - The Phase 3 D-20 focus rules still apply: tab change and push move focus to the title.

### Claude's Discretion
- How the summary card's corner label fits next to the caption at large text sizes (wrap or stack).
- Exact glyph drawings, provided they follow D-56 and pass a side-by-side check against the tab glyphs.
- Whether the Display sheet uses the existing Dropdown/Sheet primitives or a new two-section sheet built on `Sheet`.
- Whether Unpaid counts toward the Filter badge (D-57).
- How the search field and the month row share layout during the cross-fade.

</decisions>

### Established Patterns
- Text uses `textRole` and the `Text` wrapper. The scaling caps are 2x for body and 1.3x for figures (D-19).
- Copy goes through `src/i18n/locales/en.ts`, and `shellCopy.test.ts` checks the voice. No "advice", "recommendation" or "you should".
- Colours come only from `src/theme/tokens.ts` and the user's accent; `noRawColours.test.ts` enforces this. Accent tints use `ACCENT_TINT_OPACITY`.
- Pressed state uses `PRESSED_OPACITY`. Double-tap pushes go through `pushOnce` (per href since review round 3).
- RNTL tests are async and there are no `UNSAFE_*` queries. Sheets set accessibilityViewIsModal.

### Integration Points
- `src/features/record/activity/ActivityScreen.tsx` `listHeader` (around line 225): the stack being replaced, including the links row, the tools row and the balance note.
- The Calendar path (`calendar-scroll` Animated.ScrollView) renders the same `listHeader`.

- Accounts and History routes are opened today by `onOpenAccounts` and `onOpenHistory` in ActivityScreen. They move into ⋯.

<specifics>
## Specific Ideas

- The user's complaint, in their words: the header "is so disorganized". It has "3 drop down, scrolling month, in, out, net, still to come, filter that can be an icon, accounts and history, this month, every month and search box, select."
- The proposal's summary line "Net · 28 entries / $612 still to come / +$9,455.79 / In … Out …" is the visual target. D-47 makes "left after everything" the figure, using the Home caption wording.
- Success means the first entry is visible above the fold on a Pixel 9 at default text size, with a recurring-offer card showing.

</specifics>
