# Phase 03.1: Code Review Report

**Reviewed:** 2026-10-15T06:37:37Z
**Depth:** standard
**Files Reviewed:** 31
**Status:** issues_found

## Summary

I reviewed the four-band Activity header (summary card, month row, icon cluster, Display chip and sheet, filter chips, select bar, More menu), the compact-header changes in the shell, and the shared `monthFigureInputs` mapping now used by Home and Activity. I read each changed file in full and checked the phase diff from `5affac6`.

Engine isolation holds: nothing new was added under `engine/`, and the new pure helpers (`activeFilters`, `monthLayout`, `monthFigureInputs`) live in `features/`. Money stays in integer minor units, and the card formats engine output without doing its own arithmetic. The copy stays declarative, and the new glyphs are drawn by hand in `react-native-svg`.

The main defect: the new "left after everything" card ignores the month's data state. Home refuses to show this figure when a read has failed or is offline. Activity shows it anyway: overstated when only the recurring-series read failed, and as an "empty month" when nothing was read. This breaks D-47 ("Home and Activity always agree") on the one number the card exists to show.

The other findings concern header state combinations the visibility rules did not cover:
- Search hides the filter indicators while still applying the filters.
- Select mode can be left with no Done control and no visible count.
- The search results count excludes rows that are shown.
- The Out figure loses its sign in a month where refunds outweigh spending.
- The filter-chip row can overflow off-screen.

## Critical Issues

### CR-01: Summary card ignores `dataState`: it shows an overstated figure after a partial read failure, and a false empty month when offline or after an error

**File:** `src/features/record/activity/useActivityViewModel.ts:204-215`, `src/features/record/activity/header/ActivityHeaderBands.tsx:89,140`, `src/features/record/activity/header/ActivitySummaryCard.tsx:52-68` (compare `src/features/home/ThisMonthCard.tsx:99-108`)

**Issue:** `monthLoading` is `!rc.ready || monthView.dataState === 'loading'`, so the `'error'` and `'offline'` states fall through to the "ready" path. `useMonthView` substitutes `[]` for any query with no data (`data/queries/activity.ts:123-124`), which leads to two failure cases:

1. **Partial failure (tx cached or loaded, series read failed with no cache):** `dataState === 'error'` and `projections === []`. `monthPositionOf` then computes `left` without any projected recurring bills, so the card shows a higher, green "left after everything" than the truth. On the same data, Home shows `home.state.monthError` and no figure (T-03-22-01). The user sees the two tabs disagree, and Activity overstates what is left.
2. **Uncached month offline, or tx read error:** rows and projections are both `[]`, so `isMonthEmpty` returns true. `hideBands` then hides the card and the Display row, and the list falls through to the "Nothing in {month} yet / Clone / Paste" empty state. A failed or offline read is presented as a real empty month, which T-03-22-01 / WR-01 (`monthDataState.ts` header comment) exists to prevent.

The UI-SPEC's "card shows the cached figures" only holds when the core queries have cached data. Neither case above has cached data.

**Fix:** Carry `dataState` into the view model and gate the card on it, the same way Home does:
```ts
// useActivityViewModel.ts
const dataState = rc.ready ? monthView.dataState : 'loading';
const monthLoading = dataState === 'loading';
const monthUnavailable = dataState === 'error' || dataState === 'offline';
const monthEmpty = !monthUnavailable && isMonthEmpty(monthView.totals, position);
```
```tsx
// ActivitySummaryCard: add `state` and render the Home copy instead of a figure
if (state === 'error' || state === 'offline') {
  return (
    <View testID="activity-summary-card" style={container}>
      <Text style={{ ...textRole(pairing, 'label'), color: colors.inkMuted }}>
        {t(state === 'error' ? 'home.state.monthError' : 'home.state.monthOffline')}
      </Text>
    </View>
  );
}
```
The list's `ListEmptyComponent` should not render the month-empty state (with Clone/Paste) when `monthUnavailable` is true. Add a test where the series query errors with no cache and tx has rows, and assert that no figure is shown.

## Warnings

### WR-01: Search hides every filter indicator but still applies the filters (including Unpaid), so results can be silently incomplete

**File:** `src/features/record/activity/header/ActivityHeaderBands.tsx:89,96-100,143,164`, `src/features/record/activity/useActivityViewModel.ts:191-195`

**Issue:** While `searchOpen` is true:
- The month row, which holds the Filter badge, is faded out and hidden from screen readers.
- Band 4 (the filter chips) is hidden.
- The Unpaid banner is hidden (`!searchOpen && p.unpaidOnly`).

`narrowed` still runs `filterRows(base, filter)`, so a search for "Rent" with an account or Unpaid filter left on can return "Nothing matches" for an entry that exists. Unpaid is not counted in the badge either. The only remaining hint is the compact header badge, and that only appears when scrolled. Before this phase, the Filter chip and its selected state sat next to the search field.

**Fix:** Pick one rule and apply it everywhere:
- Option 1: keep a one-line filter indicator under the scope switch while searching, for example the existing chips row without the Display chip, or "Filters on · Clear".
- Option 2: have search ignore filters while open:
```ts
return flat || searchOpen ? base : filterRows(base, filter);
```
Option 2 needs `searchOpen` threaded into the memo. Add a test for search plus an active filter.

### WR-02: Select mode can end up with no Done, Select all or None, and no visible selected count

**File:** `src/features/record/activity/header/ActivityHeaderBands.tsx:89,143-150`, `src/features/record/activity/ActivityScreen.tsx:226-234,455-464`, `src/features/record/activity/BulkBar.tsx:26-38`

**Issue:** `SelectBar` sits inside `!hideBands`, and `hideBands` is true while search is open or when the month is empty. Long-press stays enabled on search results (`allowLongPress` defaults to true), ⋯ still offers "Select entries" while searching, and the month arrows stay usable in select mode. Several paths therefore leave select mode active with the FAB hidden and BulkBar showing, but no Done, Select all or None:
- Long-press a search result.
- Choose ⋯ "Select entries" from the compact header during search.
- Step to an empty month while selecting.

Commit 67113d9 removed the selected count from BulkBar, so in these states the user also cannot see how many rows a Delete will touch until the confirm sheet appears.

**Fix:** Render `SelectBar` whenever `selectionActive`, independent of `hideBands`:
```tsx
{p.selectionActive ? <SelectBar … /> : !hideBands ? <FilterChipRow … /> : null}
```
Alternatively, call `selection.exit()` when search opens or the month changes. Also make sure the count stays visible somewhere whenever BulkBar is shown.

### WR-03: The search results count excludes transfers and skipped rows that the results list shows

**File:** `src/features/record/activity/ActivityScreen.tsx:320`, `src/engine/activity/totals.ts:48-56`

**Issue:** `resultsCount={searching ? vm.totals.count : null}`, and `MonthTotals.count` excludes transfer legs and skipped rows. `narrowed` and `buildFlatItems` still list both. D-61 makes this number the first line of the results, so a search that matches 2 transfers and 1 skipped line reads "0 transactions" above three rows.

**Fix:** Count the rows actually shown:
```tsx
resultsCount={searching ? vm.itemRows.length : null}
```
Alternatively, expose `narrowed.length` from the view model.

### WR-04: The Out figure uses `Math.abs(paidOut)`, so a month where refunds outweigh spending shows the refund as money out

**File:** `src/features/record/activity/header/ActivitySummaryCard.tsx:94,126`

**Issue:** The engine allows `paidOut > 0` when refunds outweigh spending (`monthFigures.ts` L6 comment). `fmt(Math.abs(position.paidOut))` turns +$50 of net refunds into "Out $50", which reads as $50 spent. The removed `MonthTotalsBar` printed `paidOut` signed, so on Activity this is a regression. Home has the same expression, but D-47 copies Home's figure, not its sign handling.

**Fix:** Only negate a real outflow:
```ts
const outText = position.paidOut <= 0 ? fmt(-position.paidOut) : `+${fmt(position.paidOut)}`;
```
Use the same value in the a11y label, and fix `ThisMonthCard.tsx:137` the same way.

### WR-05: The category chip label drops the "Uncategorised" selection and miscounts when the first id is unknown

**File:** `src/features/record/activity/header/activeFilters.ts:34-53`

**Issue:** `categoryLabel` strips `null` (Uncategorised) before calling `firstPlus`, so the filter `[null, 'groceries']` reads "Groceries" instead of "Groceries +1". The chip then understates the filter. Separately, if the first id is deleted or unknown, `firstPlus` returns the generic "Category" with no "+N", even when other named categories are selected.

**Fix:** Count the full selection and pick the first resolvable name:
```ts
function categoryLabel(ids: readonly (string | null)[], deps: ChipLabelDeps): string {
  const names = ids.map((id) => (id === null ? deps.t('record.sheet.uncategorised') : deps.categoryName(id)));
  const first = names.find((n) => n !== '');
  if (first === undefined) return deps.t('activity.filter.category');
  return ids.length > 1 ? deps.t('activity.filterChip.more', { label: first, count: ids.length - 1 }) : first;
}
```
Apply the same "first resolvable name, total count" rule to accounts.

### WR-06: The filter-chip row has `nowrap` and no scroll below three chips, so chips and their × go off-screen at 320pt or large text

**File:** `src/features/record/activity/header/FilterChipRow.tsx:94,128-132,150`

**Issue:** With one or two chips, band 4 is a plain `View` with `flexWrap: 'nowrap'`. The Display chip ("Running balance · Biggest") plus two filter chips (each label + a 44pt ×) easily exceeds about 288pt of content width at 320pt, and does at 2x text. `Chip` has no `flexShrink`, so the trailing chip's × is clipped and cannot be tapped. UI-SPEC line 309 says "the chip row scrolls sideways" at 2x, but scrolling only switches on at `CLEAR_ALL_FROM`.

**Fix:** Always render the horizontal `ScrollView`, and only add the "Clear all" chip at three or more:
```tsx
return (
  <ScrollView horizontal showsHorizontalScrollIndicator={false} contentContainerStyle={styles.scrollContent}
    testID={scrolls ? 'filter-chip-scroll' : 'filter-chip-row'}>
    {items}
  </ScrollView>
);
```

### WR-07: "Clear all" leaves screen-reader focus on a removed node

**File:** `src/features/record/activity/header/FilterChipRow.tsx:83-92,112`

**Issue:** The focus-return effect only runs when `pendingFocus.current` is set, which happens only in a single chip's ×. "Clear all" calls `onClearAll` directly. All chips and the Clear all chip unmount, and the container switches from `ScrollView` to `View`, which remounts the Display chip too. TalkBack and VoiceOver focus is then lost. The UI-SPEC rule is "focus to the Display chip when none remain".

**Fix:**
```tsx
{scrolls ? <Chip label={t('activity.filter.clearAll')} onPress={() => { pendingFocus.current = 0; onClearAll(); }} /> : null}
```
The `chips.length === 0` branch then focuses `leadingFocusRef`.

### WR-08: Focus return on search close also fires when Home's filter intent closes search, competing with D-20 title focus

**File:** `src/features/record/activity/ActivityScreen.tsx:133-137`, `src/features/record/activity/useActivityViewModel.ts:144-152`

**Issue:** The effect moves accessibility focus to the Search icon on any `searchOpen` change from true to false. The HOME-01 intent effect also sets `searchOpen` false when Home hands over "Pay bills" or "See all", in the same transition where the tab change should focus the title (Phase 3 D-20). If the user left search open on Activity, the handoff lands focus on the Search icon instead of the title.

**Fix:** Only return focus on a user Cancel:
```ts
const cancelSearch = () => {
  vm.setTerm(''); vm.setScope('month'); vm.setSearchOpen(false);
  requestAnimationFrame(() => focusAccessibility(searchIconRef.current));
};
```
Then drop the `wasSearchOpen` effect.

**File:** `src/features/record/activity/header/ActivitySummaryCard.tsx:77`, `src/i18n/locales/en.ts:653`

**Issue:** The corner shows `position.unpaid` (unpaid outflows only, per UI-SPEC F3), labelled "{amount} still to come". The list's `activity.section.pending` header, also "Still to come", groups pending income too. A month with pending income shows a corner figure that does not match the section beneath it.
