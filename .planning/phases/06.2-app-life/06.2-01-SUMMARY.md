# Phase 06.2 Plan 01: Own icon set and size tokens Summary

FincWin's own 64-icon set generated byte-for-byte from the board SVGs (57 from L07 plus 7 glyphs from L01-L08), drawn by a one-colour `Glyph` (16/20/24, back layer 45%), an `IconTile` (36/48, corner 11, letter fallback), category/account icon maps, and the D-05/D-08..D-10 size tokens; `check:icons` in CI fails on any drift from the boards.

## What was built

**Task 1 (0ae88365):** `scripts/icons/extract-board-icons.mjs` (Node ESM, no new dependency, regex over the machine-written boards, no eval).
- L07: skips the 3 size samples, pairs each SVG with the label beside it, maps it through a section-aware LABELS table (so "Savings" under Categories is `savings`, under Account types `acctSavings`). Unknown label, unknown heading or a table name not found on the board fails with exit 1.
- Other boards: every 24-viewBox SVG whose drawing is not already in L07 is named from an EXTRAS table keyed by the first 40 characters of its geometry key; unknown geometry fails and prints the key. Two different drawings under one name also fail.
- Attributes are copied as written; hex fill/stroke become `'C'`; `fill="none"` kept; class/style/aria-hidden/pathLength dropped.
- Writes `scripts/icons/icons.generated.json` (sorted, 2-space) and `src/ui/icons/iconData.ts` (header "GENERATED by ...", `IconNode`, `IconDef`, `ICONS ... as const satisfies Record<string, IconDef>`, `IconName`), LF endings.
- `--check` regenerates in memory and compares both files (line endings normalised): "icons drift: run npm run icons:extract".
- package.json `icons:extract`, `check:icons`; ci.yml step "Icon set matches the boards (06.2 D-29)" right after the cache version check, same job.

**Task 2 (863f3752):**
- `layout.ts`: `step { hair 4, tight 8, row 12, card 16, edge 22, section 28 }`, `rowHeight { one 52, two 64 }`, `tile { row 36, big 48 }`, `iconSize { inline 16, row 20, big 24 }`. Old tokens and the "Do not round these" comment left as they are (plan 24 handles them, D-11).
- `Glyph.tsx`: `Glyph({ name, size = 20, color, accessibilityLabel, testID })`, `GlyphSize`, `BACK_OPACITY = 0.45`; recursive render to Svg/G/Path/Rect/Circle with camelCase props and numeric parsing; hidden from a11y unless labelled (then accessible, role image). Default testID `glyph-<name>`.
- `IconTile.tsx`: 36 -> 20 glyph, 48 -> 24 glyph, `radii.glyphTile` (11), background = tint, letter fallback in `textRole(pairing,'label')` and the colour, empty tile otherwise; hidden from a11y.
- `iconFor.ts`: `iconForCategory` (15 seed keys first, then `icon_key` if it is an own key of ICONS, else null; takes the row shape so plan 17's `icon_key` works with no caller edit), `iconForAccountKind` (checking->acctCurrent, savings->acctSavings, credit->acctCard, cash->acctCash, loan->acctLoan, investment->acctInvestment, other->acctOther), `CUSTOM_CATEGORY_ICONS` (15 category icons + acctPension, acctInvestment, acctCash, acctCard, payBills, household, calendar, alerts, profile, headphones, laptop, camera; no state shapes).

## Deviations from Plan

1. **[Rule 3 - Blocking] Tests read the rendered host tree, not `UNSAFE_getByType`.** RNTL 14.0.1 here has no UNSAFE_* queries; tests walk `toJSON()` for RNSVG* hosts and compare colours as react-native-svg's `{ type: 0, payload: 0xAARRGGBB }`. Files: glyph.test.tsx. Commit 863f3752.
2. **[Rule 3] Non-icon SVGs skipped by viewBox before parsing.** The L01 chart contains `<text>`, which the parser rejects; any SVG whose viewBox is not `0 0 24 24` (tab glyphs at 22, the chart) is skipped before parsing. Tab glyphs are therefore detected by viewBox (one of the two options the plan allowed).
3. **`export function Glyph` wraps a memoised drawing** (plan said "Memoise with React.memo" and the acceptance grep wants `export function Glyph`): both hold.
4. **`step` is written across lines with a comment per use**; the values line itself is the exact grep string.
