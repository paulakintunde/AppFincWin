# Phase 06.2 Plan 05: Status map, StatusBadge and SectionHeader Summary

One `STATUS` map (19 statuses, each with a tone, an icon from the 06.2 set and an `appLife.status` word) now drives a 24-tall `StatusBadge` that always shows colour, shape and word together. There is also a shared 28-tall `SectionHeader` with no icon, showing either a count or a See all link.

## What was built

- **statusMap.ts** (D-12..D-14): `STATUS`, `StatusKey`, `StatusTone`, `StatusDef`, typed with `as const satisfies Record<string, StatusDef>`.
  - Red (`short`) is used only by overCap, overdue and short.
  - Amber (`tight`) is used only by dueSoon, behind and tight.
  - The slate clock (`notYet` + `stateDue`) is used by due, pending and notYet.
  - Up and down are neutral and carry an arrow and a word.
  - safetyNet uses `net`, and draft is neutral with `firstEntry`.
- **StatusBadge.tsx**: the pill has minHeight 24 and no fixed height. It has a 16 Glyph, a `step.hair` gap, `step.tight` side padding, the label role at `fontSize.meta`, and the tone colour on the tone tint (neutral: `fill1` / `inkDim`).
  - The badge is one accessible `text` element whose label is the word (or the override). The icon is hidden.
  - It takes `label`, `params` and `accessibilityLabel`.
- **SectionHeader.tsx** (D-24, D-06): a row with minHeight 28 and space-between.
  - The title is an `accessibilityRole="header"` label in `inkMuted` at weight 700.
  - The count is shown in `inkMuted`.
  - The See all link is a Pressable with `minHeight: space.touchMin`, `LINK_HIT_SLOP` and the press feedback, with the word in `accent`. It appears only when both `seeAllLabel` and `onSeeAll` are given.
  - There is no Glyph import.

## Deviations from Plan

1. **[Rule 3 - Blocking] Added three missing status words.** STATUS needs fits, tight and short, but `appLife.status` (plan 04) had no words for them. I added `fits: 'Fits'`, `tight: 'Tight'`, `short: 'Short'` to `src/i18n/locales/appLife/status.ts`. This file is outside the plan's file list. Commit ff306d26.
2. **[Rule 1 - Type error] Typed `t` overload.** The typed `t` rejected the union of map keys with a generic params record (`up`/`down` need `percent`). StatusBadge now calls `t` through a `(key: string, options?) => string` cast. Words with params still resolve, as the tests show.
3. **TDD gate:** I wrote the tests together with the code, and they passed on the first run, so there is no separate `test(...)` RED commit. Each task is a single `feat` commit that includes its tests.
