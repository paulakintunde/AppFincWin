# Phase 06.2 Plan 09: ProgressRing and StatTile Summary

The last two shared parts from D-24: a progress ring in 36 and 124 that sweeps over 0.55 s only on the first view in a session (never under Reduce Motion, never with events at quarter marks), and an 88-tall stat tile that sits two across and stacks instead of clipping.

## What was built

**ProgressRing** (`src/ui/ProgressRing.tsx`)
- `ProgressRing({ percent, size = 36, color, sessionKey, accessibilityLabel, children, testID })`.
- Size 36 uses stroke 4; size 124 uses stroke 10. The track is `colors.line2`; the arc is `color`, or the accent by default. The cap is round, and the svg is turned -90 deg so the arc starts at the top.
- `percent` goes through the shared `clampPercent` from ProgressBar.
- Sweep rule (`ringSweeps`): a sweep runs only when there is a `sessionKey`, it is the first view for that key (`useOncePerSession`, imported as `useFirstView`), and Reduce Motion is off (`useMotion().reduced`). In that case `withTiming(now, { duration: DURATION.fill, easing: EASING })` runs. In every other case the ring is drawn at its value at once. If Reduce Motion turns on after mount, the effect snaps the arc to its value.
- D-19: there is no haptic, tick or motion at quarter marks. At 100% the arc closes, and any milestone icon is left to the caller.
- `children` sit centred in normal layout, with no absolute wrapper around text, so the 36 ring can hold a Glyph and the 124 ring a value.
- The ring is one `accessibilityRole="progressbar"` element, with `accessibilityValue { min: 0, max: 100, now }` and the caller's label (appLife.grow.ringA11y).

**StatTile / StatTileRow** (`src/ui/StatTile.tsx`)
- `StatTile({ label, value, status, statusText, testID })` is a white card (`colors.surface`) using `shadows.edge`, `radii.card`, `padding: step.card` and `minHeight: 88`, with no fixed height. A muted label sits over a tabular figure in the heading role, with an optional `status` node underneath.
- The tile is one accessible element that reads "label, value[, statusText]" (`statTileLabel`). The visual status node is hidden from the screen reader.
- `StatTileRow({ children })` lays out at most two tiles side by side (`flex: 1`, gap `step.tight`) and stacks them when `useShouldStack()` says so.

## Deviations from Plan

**1. [Rule 3 - Test harness] The sweep is checked through a withTiming spy, not by reading the animated value**
- **Found during:** Task 1
- **Issue:** In Jest, Reanimated does not update the arc's `strokeDashoffset` (or `jestAnimatedProps`) after timers move forward, so the end of the sweep cannot be read from the tree.
- **Fix:** The test wraps `withTiming` in a spy. It checks that the first frame is empty, that one `withTiming(50, { duration: DURATION.fill })` call is made, and that a later mount draws at the value with no `withTiming` call.
- **Files:** src/ui/__tests__/ringAndStat.test.tsx

**2. [Plan wording] useOncePerSession is imported under an alias**
- The acceptance check asks for exactly 1 `useOncePerSession` line in ProgressRing.tsx. Both the import and the call would match, so the import renames it (`useOncePerSession as useFirstView`). The key_link pattern still matches.

**3. Commit split**
- The shared test file imports both parts, so it was committed with Task 2 (StatTile) to keep each commit compiling. Task 1's commit holds ProgressRing.tsx only.
