# Phase 06.2 Plan 14: Toast to the L06 kit and the D-20 failed-save haptic Summary

The undo toast now matches the L06 kit (a 16 icon, at least 48 tall, one row, Undo, a thin time-left bar, an 8 dp rise over 0.24 s and a 0.15 s leave fade, one at a time), and a save that really failed gives one Error haptic.

## What was built

**Task 1: ToastView to the L06 kit** (commit 80f1b407)
- `ToastView` gets four new optional props: `icon` (a 16 Glyph in the surface colour, hidden from screen readers), `durationMs` (draws the bar when it is a number), `shownAt` (the bar starts at the time already used) and `enterDelayMs`.
- `minHeight: 48`. The row is icon, message (flex 1, not clamped), action, Dismiss. The C-CR-02 structure is kept: the container is not accessible, the message is the alert, and the controls can each be focused. Dismiss is still 48 x 48.
- Time-left bar: 2 dp, at the bottom edge, inset by the corner radius. It shrinks from the left (`transformOrigin: 'left'`, scaleX) over the time left. It is hidden from screen readers and takes no touches. There is no bar when `durationMs` is null (screen reader on).
- Motion: the toast rises 8 dp and fades in over DURATION.appear with EASING. It leaves with a fade over DURATION.toastOut, set on its own wrapper. With Reduce Motion on, it does not rise, the fade is a quick DURATION.press, and the bar steps once a second instead of moving smoothly. Fades use `ReduceMotion.Never`, so the root ReducedMotionConfig does not skip them.
- `toastIconFor` (in `history/toastIcon.ts`) picks the icon. The warning tone gives stateOverCap, ordinary gives stateFits, destructive gives delete and refusal gives stateDue. Info shows savedOffline only for `appLife.toast.savedOffline` and otherwise shows no icon.

**Task 2: D-20 Error haptic** (commit 657c55b2)
- `useFailedSaveHaptic()` subscribes through `subscribeFailedWrites`. It calls `hapticFailed()` once each time the list grows, only when at least one new entry was recorded since the first mount. Boot hydration does not fire it, even if it finishes after mount, and neither does the list shrinking or a saved-offline (paused) write. The subscription is shared at module level and counts its users, so the app host and the sheet host together give one haptic, not two.
- `UndoToastHost` calls `useFailedSaveHaptic()` once and passes `icon`, `durationMs` (the same value that drives the auto-dismiss timer, from `toastDurationMs`), `shownAt`, `key={toast.id}`, and `enterDelayMs = DURATION.toastOut` when a toast replaces one still on screen. Toast durations and the queue are unchanged.

## Deviations from Plan

1. **[Rule 3 - Blocking] Two flow tests' partial `failedWrites` mocks extended.** `UndoToastHost.potsFlow.test.tsx` and `UndoToastHost.decide52Flow.test.tsx` mocked `@/data/sync/failedWrites` with `recordFailedWrite` only. The host now mounts the haptic hook, so those tests threw "getFailedWrites is not a function". I added `getFailedWrites: () => []` and `subscribeFailedWrites: () => () => undefined`. Commit 657c55b2.
2. **[Rule 3] Icon choice moved to its own module** (`src/features/record/history/toastIcon.ts`, not in the plan's file list). Importing UndoToastHost into a ui test loads its data modules, which need EXPO_PUBLIC env vars. The pure function now lives apart and the host imports it.
3. **[Rule 2] Shared subscription for the haptic hook.** UndoToastHost mounts twice (placement 'app' and 'sheet'). A plain per-mount subscription would give two Error haptics for one failure. The hook counts its users and shares one subscription.
4. **Hydration detection without a `hydrated` flag.** failedWrites.ts exports no such flag and is outside this plan. The hook ignores entries whose `at` is before its first mount, which is what the plan's fallback asks for.
5. **Commit split.** UndoToastHost carries both tasks' wiring (icon/bar/key and the hook). It is committed once, in the Task 2 commit.
6. **Bar thickness 2 dp, as the plan says.** The L06 board draws 3 px. The bar fill is the surface colour, not the board's mint, because the mint is not a palette token.
