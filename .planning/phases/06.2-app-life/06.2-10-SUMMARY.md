# Phase 06.2 Plan 10: Activity row icons and exception badges Summary

Every Activity row, the transaction detail and the category picker now show the category's own icon in a 36 tile in its category colour (letter only as fallback); rows carry one calm StatusBadge only for exceptions (Overdue, "£40 over cap", Due / Due <date>, Expected), spending stays ink, and swipe actions show an icon above the word.

## What was built

**Task 1 (7132cd7c): CategoryGlyph on IconTile (D-07).** `CategoryGlyph` keeps its file and export but now delegates to `IconTile`: new optional `icon?: IconName | null`, `size?: 36 | 48` (default 36), `testID`. Old callers (colorKey + letter) still render, now the letter in a 36 tile. Still hidden from screen readers. `TransactionDetailSheet` and `CategoryPicker` pass `iconForCategory(category)` (the row itself, so plan 17's `icon_key` flows through later).

**Task 2 (938b45f5): rows, badges, over-cap, swipes (D-12..D-14).**
- `overCapRows(rows, categories): Map<rowId, overBy>`: pure, integer minor units, home currency. Counts what category usage counts (paid and pending, net of refunds; never skipped lines, transfer legs or lines without a home figure), per category with a cap and per month, in date then created order. Marks the first spending row whose running total goes strictly past the cap with running total minus cap. Returns nothing if the month ends at or under the cap after refunds.
- `ActivityRow`: tile shows `iconForCategory(category)` (transfers get the Transfer icon through its builtin key; projections too). New optional `overCapBy?: number | null`. One badge per row, priority overdue > overCap > due > expected; the old red `unpaid` Tag tone is gone (D-14) — a projection's Expected tag is now muted. A normal paid row keeps its quiet Paid / Received tag; an over-cap badge replaces the Paid tag visually but the spoken label still says "Paid, £40.00 over cap". Spoken label = name, amount, foreign/home figures, tag word, badge word. Tag indent follows the 36 tile (`tile.row`).
- `SwipeRow`: `SwipeAction.icon?: IconName` drawn as a 16 Glyph above the word in the word's colour. ActivityRow passes stateFits (paid / received / moved), stateDue (unpay / scheduled), delete.

## Deviations from Plan

1. **[Scope] overCapRows not wired into ActivityScreen.** ActivityScreen.tsx is plan 11's file (and plan 12 is editing Activity views), so `overCapBy` stays an optional prop. **Plan 11 wires it**: compute `overCapRows(view.rows, categories.all)` once with `useMemo` and pass `overCapBy={map.get(row.id) ?? null}` to each `ActivityRow`.
2. **[Rule 3 - keep peers green] SwipeRow still calls `hapticLight`, not `hapticTap`.** `hapticLight` is an alias of `hapticTap` (06.2-03), so behaviour is identical. Switching the import would break every test that mocks `@/ui/haptics` with only `hapticLight` (SwipeRow, ActivityRow, several Decide tests). Header comment notes the alias.
3. **[Design reading] "Pending" badge.** The StatusBadge `pending` status is used for pending money in (word stays "Expected"); the sync-queued tag ("queued") stays a plain neutral tag beside the badge, as before. Over-cap badge also only shows when the month still ends above the cap (guards against a wrong money cue, T-06.2-10-01).
4. **appLife/activity.ts unchanged.** Existing swipe words (`activity.swipe.*`, e.g. PAID / UNPAY) kept so swipe words stay consistent; the appLife swipe words only cover Paid / Delete / Edit.
5. **Row heights.** Not changed: the existing 44 touch minimum plus 13 padding already meets the 52 / 64 minimum.
