# Phase 06.2 Plan 13: Home cards made clearer inside each card Summary

Home keeps its four cards in the same order (D-02). Inside them:
- The This-month bar now stretches by scaleX from the left edge, only on the first view each session (D-18).
- The cards fade in once per session.
- Quick actions are 48 icon tiles, and Pay bills shows the month's unpaid count.
- Account rows show 36 account-type icon tiles and a real arrow.
- Coming up shows a red Overdue badge or an amber Due soon badge (0 to 3 days out). Every other row has no badge.

## What was built

- **ThisMonthCard**
  - `Segment` is a full-width absolute view with `transformOrigin: 'left'`. Its animated style is `transform: [{ scaleX }]`, and no width is animated.
  - A new `MonthBar` reads `useOncePerSession('home.thisMonth.bar')` only when the bar is drawn. A first view that starts on the loading placeholder therefore still stretches when the figures arrive.
  - First view: the bar stretches from 0 over `DURATION.fill`.
  - Later views and Reduce Motion: the bar is drawn at its length at once.
  - A changed pct moves from the old length over `DURATION.swap`. The headline figure changes at once, with no count-up.
- **HomeScreen**
  - Each card is wrapped in `FadeIn once="home.card.quick|thisMonth|comingUp|accounts"` with testIDs `home-card-*`. The order is unchanged.
  - Passes `unpaidCount` (`vm.position.unpaidCount`, but 0 unless `dataState === 'ready'`) to QuickActions.
  - Passes `today` (`rc.today`) to ComingUpCard.
- **QuickActions**
  - Removed the hand-drawn bar glyph and its constants (`BAR`, `BAR_LONG`, `ARROW_ARM`).
  - Each action is an `IconTile` at 48 with the `add`, `payBills` or `import` icon, in the accent on `accentTintOver(fill1, accent)`.
  - The word sits below at meta/600 in inkDim.
  - The Pay bills count is a 22 accent bubble with surface text, hidden from screen readers. The count is spoken in the button label: "Pay bills, 5 unpaid".
  - The column minHeight is now `tile.big` (48). The same three actions and handlers are kept.
- **AccountsCard**
  - The letter tile and the cash accent overlay are replaced by `IconTile` at 36 with `iconForAccountKind(kind)`, in the accent on the flattened accent tint.
  - The CSS chevron is replaced by `Glyph arrowRight` 16 in inkFaint, the same as Row.
- **ComingUpCard**
  - Exports `daysUntil(date, today)`, which takes the difference between the two UTC calendar days and rounds to whole days, and `dueCue(date, today, overdue)`.
  - Exports `DUE_SOON_DAYS = 3`.
  - Overdue rows show `StatusBadge overdue` with "Overdue N days". It falls back to "Overdue" when the day count is 0.
  - Rows 0 to 3 days out show `StatusBadge dueSoon` with "Due today", "Due tomorrow" or "Due in N days".
  - The red overdue text is gone.
  - The row label reads "name, amount, badge words, due/was due date". A row without a badge keeps `home.upcoming.a11y`.
  - The new `today` prop is required.
- **appLife.home** gains `payBillsUnpaid_one/_other`, `rowDue` and `rowWasDue`. The `badge` placeholder is not on the copy guard's allow-list, so the row label is joined in code.

## Deviations from Plan

1. **[Rule 3] Existing Home tests updated for the changed behaviour.** These files are outside the plan's file list:
   - `HomeScreen.test.tsx`: added FadeIn order and wrapping tests, and the `unpaidCount`/`today` pass-through.
   - `AccountsCard.test.tsx`: the M4 cash-overlay test now checks the type icon on the flattened tint. The L3 letter test was removed because there is no letter tile any more.
   - `ComingUpCard.test.tsx`: the overdue assertion now checks the badge, and the tests pass `today`.

   The HomeScreen assertions live in HomeScreen.test because that suite already mocks the cards as probes.
2. **Pay bills count bubble uses the accent, not the board's red (D-14).** The board draws it in danger. An unpaid bill is not overdue, and D-14 keeps red for overdue, over cap and debt.
3. **Coming up fit check exemptions.** Two things predate this plan and are not changed by it: the date block's one-line month word ("SEPT", capped scale) and the Pay pill's declared size (padding plus 8 hit slop, which the static check reads as 16). The fit test exempts both and gives the reason.
4. **Row label joined in code.** The plan's per-badge sentence needed a `{{badge}}` placeholder, which the appLife copy guard does not allow. The label is built as name, amount, badge word and `rowDue`/`rowWasDue`.
5. **Negative balance colour (D-14) is not changed here.** Home's account rows use the shared `AccountBalanceBlock`, which plan 16 owns. Plan 16's rule (red only for owed debt or over the limit) will apply to Home when it lands.
6. **Commit protocol note.** This checkout is the shared `feat/06.2-app-life` worktree named by the orchestrator, not a `worktree-agent-*` branch. I committed there as instructed, by explicit paths.
