# Phase 06.2 Plan 22: Decide home open-check rows and answer haptics Summary

Decide home's open checks are now plain 64 rows led by a 36 IconTile that draws the state's set icon in the state stroke on the state tint (draft: the pen-in-square on neutral fill), and every new Decide answer gives one light tap plus a single warning when it is short or crosses a money rule; the signed answer boards and wording are untouched.

## What was built

**Task 1 (D-23, D-13, L08)**: `OpenChecksCard` rows: IconTile 36 then name, then a wrapping line with the existing StateBadge word and the meta text, then `arrowRight` (16, inkFaint). Row minHeight 64, gap 12. State colour sits only in the tile and the badge; the name stays ink and the row background stays transparent. Spoken label, testIDs, the press tick (`hapticSelection`, the hapticTick alias) and "See all" are unchanged. The tile is hidden from screen readers (IconTile). Exported `OPEN_CHECK_TILE_ICON` / `OPEN_CHECK_DRAFT_ICON` locally; statusMap not edited.

**Task 2 (D-20, D-23)**: `useAnswerEffects` fires, once per `id|code|variant`, `hapticTap()` and then `hapticWarn()` if `stateForVerdict(code, variant).tone === 'short'` or a `line_crossed` fact is present. needs_input, not-ready and loading fire nothing; no Success/Milestone anywhere. markSeen / recordHistory / analytics order unchanged. AnswerScreen.tsx lines 369-532 checked: every `hapticLight()` is in a save or button handler (spare confirm, unexplained answer, delete, waiver, skip line, no overdraft, no debts, change answer), so there was no duplicate appearance tap and the file is untouched.
