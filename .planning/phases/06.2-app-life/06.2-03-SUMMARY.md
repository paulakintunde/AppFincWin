# Phase 06.2 Plan 03: Haptics by meaning behind one switch Summary

Five meaning-named haptics (tap, warn, milestone, failed, tick) all pass through one gate that reads a device-stored Haptics switch. The switch is ON by default and hydrated at boot. Clone month and mark monthly now give a light tap instead of Success.

## What was built

- **`src/ui/hapticsSetting.ts`**: the store keeps its value in memory and has a set of listeners. `setHapticsEnabled` updates the value at once, notifies listeners and writes `'true'`/`'false'` under `fincwin:haptics-enabled`; a failed write is ignored. `hydrateHapticsSetting` turns haptics off only when it reads the exact string `'false'`. `useHapticsEnabled()` returns `[enabled, setEnabled]` through `useSyncExternalStore`. A wipe handler (`id: 'haptics-setting'`) sets the value back to ON. The `fincwin:` prefix means sign-out also removes the stored key.
- **`app/_layout.tsx`**: calls `void hydrateHapticsSetting();` at module scope, right after `SplashScreen.preventAutoHideAsync()`. The boot import still comes first.
- **`src/ui/haptics.ts`**: the header comment is now the D-20 meaning table. A private `gate()` returns early when `!getHapticsEnabled()` and catches both rejected promises and synchronous throws. It uses only `impactAsync`, `notificationAsync` and `selectionAsync`. The old names are kept as `@deprecated` aliases: Light→Tap, Medium→Tick, Selection→Tick, Warning→Warn, Success→Milestone. The roughly 70 existing call sites therefore obey the switch today.
- **`cloneMonth.ts` / `markMonthly.ts`**: `hapticSuccess()` is replaced by `hapticTap()`. `pasteLines.ts` still uses Success (import done).

## Deviations from Plan

1. **[Rule 3 - Blocking] Wipe handler shape.** The plan said `registerWipeHandler({ name, wipe })`, but the real interface in wipe.ts is `{ id, wipe }`. The code uses `id: 'haptics-setting'`.
2. **[Rule 2 - Robustness] `gate()` also catches synchronous throws.** It now ignores an error thrown at call time, not just a rejected promise, so a missing native module cannot break the action (T-06.2-03-02).
3. **markMonthly test had no haptic assertion.** One was added: the success test expects `impactAsync('light')` and no `notificationAsync`. Its expo-haptics mock gained `impactAsync` and `ImpactFeedbackStyle`. The cloneMonth test was changed the same way.
4. **RNTL `renderHook`/`act` are async in this repo.** The hook test awaits them, as other tests here do.
