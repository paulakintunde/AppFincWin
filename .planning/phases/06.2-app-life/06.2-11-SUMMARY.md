# Phase 06.2 Plan 11: Activity save moment Summary

A row saved a moment ago now fades into Activity with a short green wash under its content (fits tint holding 0.35 s, clearing over 1.0 s), every new-entry save gives one light tap (list saves no longer fire Success), day headers are 28 tall with a '−' / '+' day net, and the over-cap badge from plan 10 is wired into the list.

## What was built

**Task 1 (5fb08c58): justSaved store, NewRowWash, light taps (L02, D-20).**
- `src/state/justSaved.ts`: `markJustSaved(ids)`, `takeJustSaved(id)` (true once per id, within 10 s; the mark is dropped either way), `peekJustSaved(id)` (read without using up, for render), `resetJustSavedForTests`; registered with the sign-out wipe.
- `NewRowWash` wraps a row: Reanimated `FadeIn` over `DURATION.appear` and a context saying "wash this card". `WashUnderlay` (drawn by `ActivityRow` as the first child of its card, with the card's corners via the new `cardCorners(position)`) is an absolute layer of `stateColors.fits.tint` whose opacity goes 1 -> 0 after `WASH_HOLD_MS` 350 over `WASH_CLEAR_MS` 1000 (inside the board's 1.4 s). It has `pointerEvents="none"` and is hidden from screen readers; the row is pressable at once. Reduce Motion: no fade-in; the tint clears in `DURATION.press` with no hold (`ReduceMotion.Never` so it stays a quick fade).
- `TransactionSheet`: single add, add with Repeats (series), transfer and list save each call `markJustSaved` with the new row ids and `hapticTap()` once. The list save's `hapticSuccess` is gone. If the save crosses a cap (`runCapCheck` now returns the boolean `checkCap` already gave), the warning haptic stands for the save and no tap is added. Edits are not new rows: no mark, no extra tap. Add to list and rule-added keep `hapticLight` (alias of `hapticTap`, see plan 10's note on test mocks).
- Ids: single and series use the id `add()` already returns; transfers now get `legIds` back from `useAddTransfer().add` (outId/inId were minted inline; same `randomUUID` call order); list save passes `markJustSaved` as a new optional `onRowIds` callback to `useBulkAdd().save`, called with the client-minted row ids right after `mutate`.

**Task 2 (55968d0d): list wiring and day headers (D-14).**
- `ActivityScreen`: `const overCap = useMemo(() => overCapRows(vm.monthView.rows, categories.all), ...)` from the whole month (not the filtered/search subset), `overCapBy={overCap.get(row.id) ?? null}` on every `ActivityRow` (list and the calendar's day rows share `renderActivityRow`).
- `JustSavedRow` wraps list rows only (calendar untouched): peeks the mark in a state initialiser, re-peeks when FlashList reuses the cell for another row id, and takes the mark in an effect after the first commit, so the wash plays once and a fresh load never washes.
- `GroupHeader`: line at least 28 tall (`step.section` plus the existing group gap padding), items centred; spending net `−£58.40` in ink, money-in net `+£4,400` in accent (any positive day net), never red; the spoken label keeps the formatter's sign.

## Deviations from Plan

1. **[Rule 3 - blocking] Two additive mutation-hook changes outside the plan's file list.** Transfers did not hand back their leg ids and the list save did not hand back row ids, so the rows could not be marked. `useAddTransfer().add` now also returns `legIds`; `useBulkAdd().save` takes an optional third `onRowIds` callback. Both additive; existing callers and test mocks unchanged (`legIds ?? []` guards mocks that return only `{ transferId, stepId }`).
2. **[Rule 3 - design] ActivityRow touched (one line + `cardCorners` helper).** A wash on a wrapper would sit behind the card's own white background and be invisible; a layer on top would cover the text. The tint is drawn as the card's first child through `WashUnderlay`, which renders nothing outside a `NewRowWash`.
3. **[Design reading] Cap-crossing save gets only the warning haptic**, not tap + warning (D-20 one meaning each). Tested.
4. **Tests for the TransactionSheet paths live in the existing `TransactionSheet.test.tsx`** (its harness), and ActivityScreen wiring tests in `ActivityScreen.test.tsx`; `saveMoment.test.tsx` covers the store, the wash and the headers.
6. **[Rule 1] Raw hex in a comment** tripped the colour guard; replaced with token names (folded into the summary commit).
5. **`peekJustSaved` added** beside the two planned exports so render stays pure under a double render; the mark is used up by `takeJustSaved` in an effect.
