# Phase 06.2 Plan 06: Motion kit and play-once Lottie wrapper Summary

The calm motion kit: six new D-15 timing steps, a quick-fade rule under Reduce Motion, a once-per-session check, FadeIn and FadeSwap, a guard test that fails on any loop, bounce, spring or confetti in `src`, and lottie-react-native **~7.3.8** behind a crash-proof, play-once `AnimatedIcon` that shows the still Glyph on any build without the native view.

**New development build and new preview build needed** before any animated icon can show (D-25). Until then every `AnimatedIcon` draws its still Glyph. `runtimeVersion` is fingerprint, so OTA updates from this branch will not reach older builds.

## What was built

**Task 1 (945c3498): motion steps, once-per-session, FadeIn, FadeSwap, guard**
- `motion.ts`: `DURATION` gains `press 100, swap 180, appear 240, fill 550, icon 1200, toastOut 150` with a D-15 comment table. Existing keys unchanged. `useMotion()` gains `fade(ms)`, which returns `DURATION.press` under Reduce Motion and `ms` otherwise.
- `useOncePerSession(key)`: a module-level `Set`, decided once per mount through a `useState` initialiser. `resetSessionMotion()` is for tests.
- `FadeIn({ once, children, style, testID })`: a Reanimated `FadeIn` layout `entering` over `fade(DURATION.appear)`. If `once` was already seen this session it renders a plain View. There is no opacity style and no pointerEvents change, so content can be tapped on the first frame.
- `FadeSwap({ value, children, style, testID })`: when `value` changes, opacity goes from 0.35 to 1 over `fade(DURATION.swap)`. Nothing happens on mount and nothing moves. The lowest opacity is 0.35, never 0.
- `calmMotion.test.ts`: walks `src/**/*.ts(x)`, skipping `__tests__` and `*.test.*`. It blanks comments and strings, then fails on `withRepeat(`, `withSpring(`, `Easing.bounce`, `Easing.elastic`, `loop={true}`, a bare `loop` JSX prop, or `confetti`. A line can opt out with `// calm-motion-ok: <reason>`. No current file trips it and nothing is on the allow-list. A self-test proves each pattern is caught and that comments, strings and `loop={false}` are ignored.
- `reducedMotion.test.tsx`: adds cases for `fade()` with Reduce Motion off and on. Under Reduce Motion, FadeIn has no transform and no opacity style, and FadeSwap ends at opacity 1 with no transform.

**Task 2 (8a159df5): lottie-react-native and AnimatedIcon**
- `npx expo install lottie-react-native` installed `~7.3.8` (7.3.8). The package-lock diff is that one package only.
- `lottieAvailable()` checks `UIManager.hasViewManagerConfig('LottieAnimationView')`. On the bridgeless UIManager that calls `unstable_hasComponent`. It falls back to `globalThis.__nativeComponentRegistry__hasComponent`. The check runs in try/catch and the result is cached.
- The `lottie-react-native` package is loaded with a lazy `require` in try/catch, through a module-level `LottieHost`, so no component is created during render.
- `AnimatedIcon({ source, still, color, size = 24 | 48, testID })` shows the still `<Glyph name={still} size={24}>` centred in a `size` box when:
  - Lottie is missing,
  - Reduce Motion is on, or
  - another icon is playing.
  Otherwise it plays the LottieView with `autoPlay loop={false} speed={1}`.
- The one-icon slot is released when the animation finishes, on unmount, when Reduce Motion turns on, and on a render error. A class error boundary falls back to the Glyph. The icon box is hidden from accessibility.
- `jest.setup.ts` mocks `lottie-react-native` with a plain View in every suite.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Slot leaked by a discarded render**
- **Found during:** Task 2 (error-boundary test)
- **Issue:** Claiming the one-icon slot inside a `useState` initialiser left it held by a render that React discarded and retried after an error. Every later icon then showed the still Glyph.
- **Fix:** The slot is now claimed in `useLayoutEffect` (before paint) and released in its cleanup.
- **Files:** src/ui/icons/AnimatedIcon.tsx
- **Commit:** 8a159df5

**2. [Rule 3 - Blocking] Lint rules on the new code**
- `react-hooks/refs`: the token now comes from `useState(() => ({}))`, not `useRef().current`.
- `react-hooks/static-components`: the lazy Lottie component is rendered through a module-level `LottieHost`.
- `i18next/no-literal-string`: test JSX text is written as expressions.
- **Commit:** 8a159df5

**3. [Rule 2] `fade` fallback in FadeIn/FadeSwap**
- Many existing suites mock `useMotion` without the new `fade` key. Both components fall back to the same rule (`reduced ? DURATION.press : ms`), so they cannot crash inside those suites.

**4. Test timeouts**
- The FadeSwap timer test and the AnimatedIcon suite have longer Jest timeouts (20 s and 30 s), because two other agents were running Jest on the same machine.
