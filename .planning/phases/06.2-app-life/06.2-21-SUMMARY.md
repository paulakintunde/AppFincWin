# Phase 06.2 Plan 21: Debts and investing, calmly alive Summary

Clearing a debt by a recorded payment now plays the debt-cleared icon once with the words "Debt cleared" and one Success tap. Later visits show the badge only. Each line chart draws once per session. Investing values fade to a new value and never count up. Gains and losses read by arrow and word ("up 11.2%"), and a stale value carries the slate clock badge "Updated N days ago".

## What was built

**Task 1 (c4e87642): debt cleared moment (D-19, D-20)**
- `src/state/debtCleared.ts`:
  - `markDebtCleared(id)` and `takeDebtCleared(id)` work once per id, and a mark is ignored after 60 s.
  - `subscribeDebtCleared(fn)` lets an open debt detail take a mark that arrives after it mounted (when the queued write finishes).
  - A wipe handler clears the marks.
- Payment flow: in `record_debt_sale` `onSuccess` (`src/data/mutations/growDebts.ts`), one added call marks the debt when the payment carries the balance to zero and the server did not keep the debt open. Partial payments, a sale on its own, and `paidOff: false` never mark it. This is the only flow where the client knows the balance after the payment (see Deviations).
- `DebtClearedMoment`:
  - `MilestoneIcon name="debtCleared"` in the `fits` state colour, the shared `StatusBadge` cleared with the label "Debt cleared" (`appLife.debts.debtCleared`), and one `hapticMilestone()` on mount.
  - `DebtClearedBadge` is the quiet version: the badge only.
  - `useDebtClearedMoment(id, cleared)` takes the mark only while the debt reads as cleared. Once true it stays true for the life of that screen.
- `DebtDetailScreen`:
  - A paid-off debt used to fall through to "Debt not found", because the plan model leaves paid-off debts out. It now has a quiet cleared view: the moment or the badge, "See all in Activity", and Remove.
  - A debt with nothing left owed shows the badge under its figure.
- `DebtsSegment` rows: the minimum-estimated state now uses `StatusBadge` (`notYet`: slate clock) and keeps its words through the label override.

**Task 2 (3184b802): line draws once; investing fades; arrows and words (D-12, D-14, D-16)**
- `LineChart`:
  - Takes an optional `sessionKey`.
  - On the first view in a session it reveals the stroke over `DURATION.fill` (550 ms) with `EASING`, using an animated `strokeDashoffset`.
  - Later views, Reduce Motion, and single-point charts draw at once with no dash.
  - `lineLength()` helper. No `useReduceMotion` import, so the existing chart no-loop guard still holds; it uses `useMotion()`.
- `InvestingSegment`:
  - The hero total and each holding value sit in `FadeSwap`, keyed on the formatted value. They fade only when the value changes, never on mount.
  - `GainBadge` is `StatusBadge` up or down, neutral in colour, with an arrow and the word `up/down {{percent}}%`. The percent comes from the read model's `gainPercentTenths` through the existing `tenthsText`, so no float maths was added. When nothing was put in there is no percent, so the word is the signed amount.
  - The spoken label is "up 11.2%, $650 above what you put in".
  - The stale row shows a `StatusBadge pending` (slate clock) with `appLife.status.updatedAgo` (count of whole UTC calendar days, `daysBetween`).

## Deviations from Plan

1. **[Rule 1 - Bug] A paid-off debt showed "Debt not found".** `buildDebtsModel` skips paid-off debts, so the detail had no `line` once a sale cleared the loan, and the moment had nowhere to show. A paid-off row now gets its own quiet cleared view in `DebtDetailScreen`.
2. **"Paid in full" is not "cleared".** The plan text says "when the debt is paid in full". In the read model, `point.paidInFull` means a card paid in full each month. Cleared is `paid_off_on <= today`, or a balance at or below 0 on a debt that is not paid in full each month. A test pins that the pays-in-full card never plays the moment.
3. **The payment-flow file is outside the plan's list:** `src/data/mutations/growDebts.ts`, with one call plus its import. It marks in `onSuccess` (the server's answer) rather than at sheet save, for T-06.2-21-01. Because the optimistic patch already shows the debt as cleared, the detail subscribes to the store so a mark that arrives later still plays the moment.
4. **Only the sale flow marks.** The "Use $1,000 once" one-off and the recurring payments only add Expected lines. Their balance moves later, server-side, when a line is marked paid in Activity, and that flow does not know the debt's balance after the payment. Marking there would need the debt row's balance after the write in the mark-paid path. That is a follow-up, not done here.
5. **There is no debt payoff LineChart.** The Debts screens draw no line chart: the payoff card uses bars and progress. The only LineChart call site is `HoldingDetailScreen`, which is not in this plan's files. So `sessionKey` defaults to `line-chart:{accessibilityLabel}`, which makes each chart draw once per session, instead of using the chart's testID. Every LineChart would share that testID, so only the first chart in a session would ever draw.
6. **[Rule 1] `investingScreens.test.tsx` expectations (not in the list).**
   - `'+$650'` became `'up 11.2%'`.
   - `'-$100'` became `'down 1.7%'`, and the spoken label is now `'down 1.7%, $100 below what you put in'`.
   - `'Last updated Oct 3'` became `'Updated 34 days ago'`.

   The behaviour changed as planned (D-14, D-12). The holding detail's own "Last updated" line is unchanged.
7. **No new copy.** `appLife/debts.ts` already had `debtCleared` from plan 04, so the file was not edited.
