# Phase 06.2 Plan 16: Accounts life Summary

Accounts now read by type at a glance: a 36 account-type tile on every card, a 48 tile on the detail header and icons in the kind picker. Negative balances keep their minus, say "minus" to screen readers, and go red only for debt or a limit passed. The empty screen has one icon, one sentence and one button that opens Add.

## What was built

- **AccountsScreen**: each card is a row of IconTile 36 (`iconForAccountKind`, accent on accent tint, testID `account-tile-<id>`), then name / kind line, then the compact balance block, then `arrowRight` 16. The card's spoken label uses `spokenLabel` ("Current, Current account · GBP, minus £25.00, Overdrawn"). Empty: `EmptyState icon="accounts"` with `appLife.empty.accounts.heading/body/action`; the button calls the same `setAdding(true)` as the header's Add account pill.
- **AccountDetailScreen**: header row with IconTile 48 (testID `account-detail-tile`) beside the account name. The not-found EmptyState gains the `accounts` icon only, with no button.
- **AccountBalanceBlock**: new exported `balanceIsDanger`. The figure colour uses it in both the compact and full forms. A negative figure has `accessibilityLabel` = `appLife.accounts.negativeA11y` ("minus £25.00"). `CompactBalance` gains `danger` and `spokenLabel`.
- **AccountSheet**: the kind choice uses a local `KindPicker` (Sheet + SheetHeader + Row with a leading Glyph 20 in the accent). The selection behaviour is unchanged.
- No "updated N days ago" clock, because accounts have no balance-as-of date. A test checks this.
- `src/i18n/locales/appLife/accounts.ts` is unchanged: `negativeA11y` already existed from plan 04. The old `accounts.emptyHeading/emptyBody` keys stay in en.ts for plan 24.

## Deviations from Plan

1. **[Rule 3 - scope] Kind picker built locally instead of changing OptionPicker.** OptionPicker is shared and is not in this plan's file list. A local KindPicker in AccountSheet keeps the same sheet, rows and selected-state announcement, and adds the icon.
2. **[Design] Account rows not moved onto `Row`.** Row's amount slot holds one string, but the account card needs a figure plus a short line (Overdrawn / ≈ home amount, D-39). The card keeps its own layout, which matches Home's AccountsCard. testIDs and handlers are unchanged.
3. **[Scope] Home's card label is not changed to "minus".** `useCompactBalance().label` is unchanged, so Home's exact-label test still passes. Home shows the new colour rule because it shares AccountBalanceBlock. A follow-up can switch AccountsCard to `spokenLabel`.
4. **[Process] One combined feat commit, with no separate RED commit.** Both tasks change the same four files, so they went in together.
5. **[Process] Commit made on `feat/06.2-app-life` in the shared worktree.** The lead asked for this. It is not a `worktree-agent-*` branch, and the executor's allow-list check was skipped for that reason.
