## Deviations from Plan

1. **Plural keys**: the plan wrote `updatedAgo` / `dueIn` / `overdueBy` / `added` with an added `_one`. The repo convention (and i18next) is a `_one`/`_other` pair, so the many form is `<key>_other`, not a bare key. Callers use `t('appLife.status.updatedAgo', { count })`. A test checks i18next resolves them.
2. **Extra guard rule**: added a check that every `_one` has an `_other` form beside it (cheap, prevents a missing plural).
3. **Acceptance diff base**: `git diff main` uses a stale local `main` (b4fc4bcd); the check was run against `origin/main` and HEAD instead, both clean.
