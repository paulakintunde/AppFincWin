# Phase 06.2 Plan 19: Category icons and the custom icon picker Summary

Every category surface now shows the category's own icon in its swatch colour (seed icon, picked icon, or the letter), and a custom category picks its icon from FincWin's own set through a radio grid that ticks on pick and saves `icon_key` (null for Letter).

## Tasks

**Task 1 (ea50b472): icons on every surface.** `CategoryGlyph` gets `icon={iconForCategory(row)}` in CategoriesScreen rows, the RemoveCategoryPrompt merge list, the RuleSheet chosen-category row and RulesScreen rule rows (unresolved rules pass null, so the letter stays). The empty rules list passes `icon="categories"` to EmptyState with its existing words. Rows already use the shared Row (52/64) and the 36 tile; testIDs and handlers unchanged.

**Task 2 (8adb3d99): icon picker.**
- `CategoryIconPicker`: a nested `Sheet` + `SheetHeader` ("Pick an icon"), a `radiogroup` grid (gap `step.tight`) of the Letter tile then every `CUSTOM_CATEGORY_ICONS` entry, each a 36 CategoryGlyph in the chosen colour inside a 48 Pressable radio (`accessibilityState.checked`, accent border when chosen, label `"{word} icon"`). Picking calls `hapticTick()` (D-20) then `onPick`.
- `useIconWord()` maps an IconName to `appLife.categories.iconNames.*` (type-guarded against the word map), null to `iconNone`.
- `CategorySheet`: `iconKey` draft (initial = `iconForCategory({ icon_key: editing.icon_key })`, so only a real icon counts), included in the D-26 dirty check; an Icon Row (tile + word + chevron) for custom categories only; add passes `iconKey` only when set (existing add calls unchanged); edit adds `patch.iconKey` when it differs (null clears `icon_key`).
- `appLife/categories.ts`: `iconNone: 'Letter'` and 27 plain words (`iconNames`), one per pickable icon.
