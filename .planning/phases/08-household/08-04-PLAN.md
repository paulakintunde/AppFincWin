<feature>
  <name>Per-pair balances, settlement rule, settle-up total</name>
  <files>src/engine/household/balances.ts, src/engine/household/settlement.ts, tests</files>
  <behavior>
    Types (export from balances.ts):
    ```ts
    export interface SharedLineForBalance {
      readonly lineId: string;
      readonly payerKey: string;            // who paid (paid_by, else creator)
      readonly paidFromJoint: boolean;      // D-17
      readonly status: 'open' | 'pending' | 'settled' | 'written_off';
      readonly pendingSettlementId: string | null;
      readonly shares: readonly { readonly memberKey: string; readonly amount: MinorUnits }[]; // household currency, stored at share time (D-35, D-39)
    }
    export interface PairBalance {
      readonly otherKey: string;
      readonly net: MinorUnits;             // > 0: other owes viewer; < 0: viewer owes other
      readonly pending: MinorUnits;         // part of net inside a pending settle-up
      readonly lineIds: readonly string[];  // every line contributing (traceability, D-23)
    }
    export function pairBalances(lines: readonly SharedLineForBalance[], viewerKey: string): readonly PairBalance[];
    export function owedToMeTotal(pairs: readonly PairBalance[]): MinorUnits; // sum of positive nets only
    ```
    Cases:
    - Paul pays 8400 even with Sam (shares 4200/4200), open -> Paul's view: Sam net +4200; Sam's view: Paul net -4200.
    - same line paidFromJoint -> no pair entry (or net 0, no lineIds).
    - status settled or written_off -> excluded.
    - status pending -> included in net and in pending.
    - 3 people, lines between different payers -> per pair only; A->B and B->C never merged into A->C (D-23).
    - viewer not on a line and not payer -> line ignored for viewer.
    - pairs with net 0 and no lineIds are omitted; output sorted by otherKey for determinism.
    Properties (fast-check): antisymmetry (A's net for B equals minus B's net for A); for any line set the sum of all members' nets over all pairs is 0; joint-paid lines never change any net; owedToMeTotal >= 0.
    settlement.ts:
    ```ts
    export function isSettlement(tx: { readonly isSettlement?: boolean | null }): boolean; // the ONE rule (ARC-18)
    export function excludeSettlements<T extends { readonly isSettlement?: boolean | null }>(rows: readonly T[]): T[];
    export function settleUpTotal(lines: readonly SharedLineForBalance[], payerKey: string, receiverKey: string, tickedLineIds: ReadonlySet<string>):
      { readonly amount: MinorUnits; readonly lineIds: readonly string[] };
    ```
    - settleUpTotal counts only ticked open lines between that pair (pending/settled lines refused by omission), amount = what payer owes receiver across them (can be 0 or negative when the ticked set nets the other way; the UI disables at <= 0 for the payer label).
    - All lines ticked -> amount equals the pair's net from pairBalances (property).
  </behavior>
  <implementation>
For each line with !paidFromJoint and status in open|pending: every share whose memberKey != payerKey means that member owes the payer `amount`. Accumulate into a map keyed by the unordered pair, oriented to the viewer. Use integer addition only. Comment: "D-17 joint lines create no owing; D-23 no simplification; ENG-25 owed money is a separate figure and is never added to spendable money by any caller."
  </implementation>
</feature>
