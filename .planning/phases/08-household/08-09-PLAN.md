```sql
create table public.household_invites (
  id uuid primary key default gen_random_uuid(),
  household_id uuid not null references public.households(id) on delete cascade,
  created_by uuid not null default auth.uid() references auth.users(id) on delete cascade,

  used_at timestamptz, used_by uuid references auth.users(id) on delete set null,
  cancelled_at timestamptz,
  created_at timestamptz not null default now());
create table public.redeem_attempts (
  id bigint generated always as identity primary key,
  user_id uuid not null references auth.users(id) on delete cascade,
  ok boolean not null, at timestamptz not null default now());
create index redeem_attempts_user_at on public.redeem_attempts (user_id, at desc);
create index redeem_attempts_fail_at on public.redeem_attempts (at desc) where not ok;
```

   RLS on both. household_invites: select policy `created_by = (select auth.uid()) and household_id in (select public.user_household_ids())`; `revoke all from anon`; `revoke insert, update, delete, truncate from authenticated`; `grant select (id, household_id, created_by, expires_at, used_at, cancelled_at, created_at)` only (no code, no code_hash). redeem_attempts: no policies, `revoke all ... from anon, authenticated`.
2. Code generation `public.hh_new_invite_code() returns text` (not client-callable): alphabet `'0123456789ABCDEFGHJKMNPQRSTVWXYZ'` (Crockford, 32 symbols), 12 symbols from `extensions.gen_random_bytes(12)` taking `get_byte(b, i) % 32` (256 is a multiple of 32, so unbiased). 12 x 5 bits = 60 bits.
   `public.hh_normalise_code(p text) returns text` immutable: upper, remove `-` and whitespace, translate `O`->`0`, `I`->`1`, `L`->`1`.
   Hash: `encode(extensions.digest(public.hh_normalise_code(code), 'sha256'), 'hex')`.
3. `public.hh_rate_limited(p_user uuid) returns boolean`: true when the user has >= 5 failures in the last hour, or >= 20 in the last 24 hours. Per-user only — no global blocking brake: a global brake would let a few attacker accounts lock every legitimate joiner out (DoS), and it buys no security because the 60-bit space already makes guessing futile at any realistic account count (1,000,000 accounts x 20 guesses/day still gives under 2e-11 success chance per day).
   `public.hh_redeem_failure_rate() returns integer` (count of failures in the last hour; revoke from public, anon, authenticated — service role and dashboards only). After each failure insert in preview/redeem, if that count is >= 200, `raise log 'hh_redeem_global_failure_rate %', n;` — log only, for alerting; it never changes the result or blocks anyone. Comment both functions: "Global rate is alert-only by design (DoS trade-off, T-08-109)."
4. RPCs (security definer, `set search_path = ''`, revoke from public/anon, grant to authenticated, return jsonb, never raise except 42501 for no auth.uid()):

   - `redeem_invite(p_code text)`: (a) rate limit -> `slow_down`; (b) `select ... from household_invites where code_hash = ... for update`; not found/used/cancelled/expired -> insert failure attempt, return `invalid`; (c) if caller already a member of that household -> return `{ok:true, household_id, already_member:true}`; (d) caller's current household `v_old`: if it has more than one member -> `in_other_household` (D-06, not counted as a failed guess); (e) `select 1 from households where id = target for update`; member count >= 6 -> `full`; (f) `perform set_config('fincwin.household_rpc','on', true)`; `perform public.hh_move_rows(v_uid, v_old, target, true)`; insert membership `(target, v_uid, false, 0, display_name copied from old membership)`; delete household v_old (cascade removes its membership); (g) re-split weights evenly in join order (`created_at`): floor(100/n) each, +1 to the first `100 % n` members (matches engine evenWeights); (h) mark invite `used_at = now(), used_by = v_uid, code = null`; insert success attempt; (i) events: `joined` (subject = caller, audience null) and `weights_changed` with before/after params; (j) return `{ok:true, household_id: target, household_name}`.
