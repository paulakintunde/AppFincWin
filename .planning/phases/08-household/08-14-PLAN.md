Create M8 (date shift per 08-PRECONDITIONS.md). Conventions as in 08-09..08-11.
1. FK fix (Pitfall 3): `alter table public.households alter column owner_id drop not null;` drop the owner_id FK and re-add it `on delete set null`.
2. Columns: `transactions.copied_from uuid` and `transactions.copy_share bigint` (server-only; a personal copy of a shared line; when the copy carries the full paid amount, copy_share is the member's share and "my share" readers use it — note for plan 08-25); `accounts.tombstone_of uuid` (server-only); `household_invites.departure_id uuid`.
3. Tables (RLS: household members read; no client writes):
```sql
create table public.household_former_members (
  id uuid primary key default gen_random_uuid(),
  household_id uuid not null references public.households(id) on delete cascade,
  user_id uuid references auth.users(id) on delete set null,   -- null once the account is deleted
  former_key uuid not null default gen_random_uuid(),          -- stable key used in splits/settlements after deletion
  display_name text, colour_key smallint not null, name_hidden boolean not null default false,
  reason text not null check (reason in ('left','removed','deleted')),
  left_at timestamptz not null default now());
create table public.member_departures (
  id uuid primary key default gen_random_uuid(),
  household_id uuid not null references public.households(id) on delete cascade,
  user_id uuid references auth.users(id) on delete cascade,
  actor_id uuid references auth.users(id) on delete set null,
  kind text not null check (kind in ('left','removed')),
  new_household_id uuid,
  copy_ids uuid[] not null default '{}', tombstone_account_ids uuid[] not null default '{}',
  prior jsonb not null,               -- role_label, colour_key, weight, display_name, name_hidden
  undo_until timestamptz not null default now() + interval '24 hours',
  restored_at timestamptz, created_at timestamptz not null default now());
```
4. `public.hh_depart(p_user uuid, p_household uuid, p_kind text, p_actor uuid) returns uuid` (internal):
   a. set the flag; capture prior member fields; create household H2 (name from display_name, reporting_currency = the user's profile home_currency) and owner membership weight 100.
   b. Tombstones: for each personal account of p_user in p_household that carries shared lines, insert an archived shared account in p_household (`is_shared true, archived_at now(), tombstone_of = account id, created_by p_user`, same name/currency/kind, opening 0) and re-point those shared lines to it, so `transactions_account_same_household` still holds after the account moves.
   c. Personal copies: for every non-deleted shared line in p_household with a split row for p_user: insert into H2 a personal transaction (`created_by p_user, is_shared false, copied_from = line id, local_date, name, note, category_id` = p_user's transaction_member_categories override, else the line's category when p_user owns it, else null). If p_user paid it from their own (moving) account: the copy goes on that account with the FULL original amount and currency and `copy_share` = their share (their account balance stays right). Otherwise it goes on one archived tracking account per departure created in H2 (`name` = old household name, kind 'other', currency = household currency, `archived_at now()`) with amount = their share in household currency. Record copy ids.
   d. `perform public.hh_move_rows(p_user, p_household, H2, true)` restricted to personal rows: extend hh_move_rows with `p_only_personal boolean default false` (re-create it) that adds `and not is_shared` where the column exists; shared rows the user created stay.
   e. Former member row (reason, display name, colour, name_hidden), member_departures row, delete the membership, re-split remaining weights proportionally to 100 (largest remainder; if all remaining are 0, evenly), events `left`/`removed` (audience: everyone remaining) and for removal also an event in H2 for the removed user `removed` with params `{household_name}` so they see "You're no longer in [household]" (D-28).
5. RPCs (definer, jsonb):
   - `transfer_ownership(p_new_owner uuid)`: owner only; target a current member; old owner `is_owner false, role_label 'Flatmate'`; new `is_owner true, role_label 'Owner'`; households.owner_id; event `owner_changed` (subject new owner).
   - `leave_household(p_new_owner uuid default null)`: if caller is alone -> `alone`; if owner with others and p_new_owner null -> `pick_new_owner`; else transfer then `hh_depart(caller, ..., 'left', caller)`; returns `{ok, new_household_id, open_balances:[{other_id, amount}]}` computed from hh_pair_owed over open lines before departure (for the warning, D-25).
   - `remove_member(p_user uuid)`: owner only, not self; `hh_depart(p_user, ..., 'removed', caller)`.
   - `reinvite_removed(p_departure_id uuid)`: owner only, `now() < undo_until`, not restored; creates an invite with `departure_id` and returns its code (reuses the 08-09 code generator) — the 24-hour undo path (D-28).
   - Re-create `redeem_invite` from 08-09 adding: when the invite has `departure_id` and the redeemer is that departure's user within undo_until: move the user's personal rows back from H2 (hh_move_rows), re-point tombstoned lines to the original account and delete the tombstone accounts, hard-delete the copies listed in copy_ids (personal rows in H2, never visible to other members), delete the tracking account, restore prior role/colour (if colour taken, next free), re-add membership, delete H2, remove the former-member row, set restored_at, event `departure_undone`.
   - Former-member balances: re-create `record_received` and add `record_paid(p_other uuid, p_line_ids uuid[], p_payer_account uuid, p_expected_amount bigint)` so that when the counterparty is a former member (not a current member, present in household_former_members) the caller's side settles at once with only the caller's record (no confirmer exists) — D-25 "either person can still settle it or write it off".
   - `my_departed_balances()`: for the caller, rows of member_departures where user_id = caller with open amounts per other member (recomputed from hh_pair_owed treating the caller's original user id), plus household name; read-only (the leaver sees "You owe Paul $40").
   - `account_deletion_preview()`: `{in_shared_household, is_owner, next_owner_user_id, household_name}` for the UI paragraph (next owner = earliest joined other member).
6. Deletion (D-27, D-29, CMP-F23): `public.hh_before_user_delete()` trigger function, `before delete on auth.users for each row`, security definer, revoke from all client roles:
   a. For the user's household H: if other members exist: if the user is owner -> earliest-joined other member becomes owner (is_owner, role_label 'Owner', households.owner_id) with event `owner_changed` audience `{new owner}`; insert a former-member row with `reason 'deleted'`, `display_name null` (a name is personal data); stamp `transaction_splits.former_member_key` and settlements `payer_former_key/receiver_former_key` with that row's former_key where they reference the user (so balances keep a stable counterparty after the FK nulls the id); run tombstones (4b) for the user's personal accounts carrying shared lines; then delete every personal row of the user in H in dependency-safe order (transactions not shared -> recurring_series not shared -> accounts not shared -> remaining owner-column tables), leaving shared rows (their `created_by` becomes null through `on delete set null`, rendered "Former member"); delete the membership; re-split weights as in 4e; event `left` with params `{deleted: true}`.
   b. If the user is alone: `delete from public.households where id = H` (cascade erases everything household-scoped).
   c. Never raise: wrap the body so any unexpected error is re-raised only for data-integrity violations; otherwise deletion proceeds (deletion is never blocked, D-27). Document the choice in a comment.
