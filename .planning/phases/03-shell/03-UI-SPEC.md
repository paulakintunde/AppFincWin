# Phase 3 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Updated 2026-10-13** against `03-CONTEXT.md` (updated 2026-10-13). Sections marked "(updated 2026-10-13)" were revised or are new; every unmarked section is carried over unchanged from the approved 2026-09-26 contract. Status is reset to `draft` until the checker re-verifies. Where this file and `03-RESEARCH.md` (2026-09-26, assumes `@gorhom/bottom-sheet`) disagree on sheets, this file and CONTEXT win.

**Platform note:** FincWin is React Native / Expo SDK 57 (iOS + Android). There is no CSS, no Tailwind, no shadcn — styling is `StyleSheet` + the typed theme context already built in Phase 0 (`src/theme/*`). All "Design System" template fields that assume a web/shadcn stack are **N/A** and answered with the RN-equivalent, exactly as `00-UI-SPEC.md` and `02-UI-SPEC.md` established. Colour, type and layout tokens are pulled verbatim from `BUILD-PROMPT.md` §2 / `FincWin United.dc.html`, already encoded in `src/theme/tokens.ts`, `layout.ts`, `typography.ts` and `motion.ts`. The design-fidelity rule (CLAUDE.md) holds: no new colour, gradient, shadow, icon set or type size.

**Phase 3 UI surface (updated 2026-10-13):** the tab bar (five bespoke SVG glyphs, directional slide, hidden-not-placeholder tabs), the app-wide 8-deep back history spanning tabs and detail screens, detail-screen push/pop chrome that covers the tab bar, **the app's own Sheet gaining drag-to-dismiss, one backdrop value, stacking and dismissal rules**, the context-aware floating action button and its long-press quick menu, the tab-root header, **toasts drawn above open sheets**, the sync-problem line, pull-to-refresh **and its completion toast**, shell haptics, screen-reader/text-scale behaviour, and **the Home tab's content** (quick actions, This month, Coming up, Accounts). **Not in this phase:** the screens inside the other tabs, the Home net-worth hero / range chips / sparkline (Phase 7) and health card (Phase 7), level gating (Phase 9), the app-switcher privacy snapshot (DSG-08), feature-specific haptics, Coach, split-by-category, receipt photo, envelope rollover, custom types (backlog).

## Design System (updated 2026-10-13)

| Property | Value |
|----------|-------|
| Tool | none — shadcn is not applicable to React Native. No `components.json` exists or is expected. |
| Preset | not applicable |
| Component library | none as a package. ## Color (updated 2026-10-13)

Reuse `src/theme/tokens.ts` and `src/theme/accents.ts` exactly — **no new hex or rgba values**.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `canvas` `#FBFAF7` | Screen backgrounds behind shell chrome and Home |
| Secondary (30%) | `surface` `#FFFFFF` | Sheet background; every Home card |

| Accent (10%) | `accent` (user-selected, default `#1B4D3E`) | **Reserved only for:** the FAB fill, the focus ring (2px, 2px offset), the pull-to-refresh tint, and on Home: the quick-action glyphs, the paid portion of the This-month bar, the "left after everything" figure when ≥ 0, the Pay button text, the "See all" link (Coming up, prototype L164), the detail-header "Edit" link (prototype L1999 region, owned by the record's phase), and the Accounts-glyph tile for the cash account. **Never** for tab selection, the backdrop, or the toast. |
| Destructive / loss | `danger` `#B4472A` | "Discard" in the discard dialog; on Home: the UNPAID figure, the "left after everything" figure when < 0, and the "Overdue" word in a Coming-up row. Always paired with text, never colour alone. |

- **Tab selection does NOT use accent.** Selected glyph + label: `ink`. Unselected: `inkMuted` (prototype L4884).
- FAB pressed state: `ink`.
- **Sheet backdrop (updated 2026-10-13, D-23):** the prototype's `rgba(20,21,15,.38)` (L2119) is the palette's own `ink` (`#14150F` = rgb 20,21,15) at 38%. Express it **from the ink token**: a full-bleed `View` with `backgroundColor: colors.ink` and an animated `opacity` from 0 to 0.38. Do not write an `rgba()` literal (the `noRawColours` test forbids it). **The `colors.scrim` token (`rgba(0,0,0,.4)`, added by quick 261013-izi) is removed** from `tokens.ts`, along with the "bar the Sheet scrim" wording in its header comment; `Sheet.tsx` and `Dropdown.tsx` read `colors.ink` + the shared opacity constant instead. `Sheet.scrim.test.tsx` is rewritten to assert ink at 0.38 and the `colors.scrim` assertion is dropped. This single value is used by every sheet, picker, `ConfirmSheet` and the FAB quick menu. This replaces the earlier "ink at 38–40%" line.
- **Sheet handle (updated 2026-10-13):** `line2` `#E2DED2`. This is exactly the prototype's handle colour, so no mapping is needed.
- Toast background `ink`; message text `surface` in the `body` role (15/500, as shipped); the warning tone (`tone="warning"`, the cap-crossing toast) keeps its `warn1` background as already shipped.
- **Toast "Undo" text:** `surface` in the shipped `label` role (13/600), distinguished by position and the role's heavier weight (deliberate deviation from the prototype's fixed `#9BC0B2`, which is a tint of the default green and would misrepresent other accents). No new token.
- **No toast shadow.** The prototype's `0 12px 30px -12px rgba(0,0,0,.5)` (L2794) is not in the §2 shadow set and is not added; the ink pill reads against both canvas and the backdrop.
- Home surfaces: card `surface` with `shadows.card`; track of the bar and Pay-button fill `fill1`; row separators `fill2` (prototype `#F2EFE7`); avatar fill `line1`, initials `inkDim`; Accounts chevron `inkSoft3`; quick-action circle `surface` with 1px `line1` border; label `inkDim`; eyebrow and card headings `inkMuted`.
- **Pending portion of the bar:** the prototype's `#C8D6CD` is not in the palette. Use `accent` at 0.3 opacity over the `fill1` track (a derivation of an existing token, like the backdrop; decided 2026-10-13). The bar is never the only signal: IN / OUT / UNPAID figures and the accessible summary carry the same information.
- `warn1` is used by the shell only as the existing toast warning-tone background (phase 2, unchanged); the shell adds no other use. Category colours are not used on Home except where the Accounts tile reuses the existing account-type tint pairs already used by `src/features/record/accounts`.

## Header

- Cancel, Save and backdrop taps: **instant**, no animation, backdrop gone with the sheet.
- Drag past the threshold: the sheet slides away over about 0.24s (`DURATION.sheetDrag = 240`, `EASING`) to `translateY(110%)` and the backdrop fades with it; the dismissal callback fires at about 190ms (prototype L6490–6491).
- Drag short of the threshold: the sheet **snaps back over about 0.24s** (L6492), backdrop unchanged.

**Drag-to-dismiss (NAV-04, D-12a/b; prototype L6481–6494):**
- The sheet follows the finger **1:1**, clamped at 0 (it never rises above its rest position): `dy = max(0, y − y0)`.
- The **threshold is 92px**. Release beyond 92px dismisses; release at or under 92px snaps back. A fling may count as past the threshold if on-device testing finds it feels right (executor discretion); no velocity rule is required.
- **Drag zone:** the drag handle's 44px hit area and the sheet header always drag. The body drags **only while its scroll offset is at the top** and the gesture is moving down. A body that is scrolled does not start a sheet drag until it returns to the top.
- **Horizontal gestures win inside the body:** the vertical Pan uses `activeOffsetY` (~10px) with `failOffsetX` (~±10px), so a horizontal `SwipeRow` pan (entry list REMOVE swipe, Activity row swipe) is never stolen. Composition with `SheetScroll` is executor discretion (gesture-handler `Gesture.Pan` with `simultaneousWithExternalGesture` on the scroll view is the expected route).
- A `selectionAsync` haptic fires when a sheet closes by drag (D-18), through `src/ui/haptics.ts`.
- **Non-gesture alternatives (WCAG 2.5.1):** the backdrop "Close" button, the sheet's Cancel, Android back, and for screen readers an accessibility `escape` / `dismiss` action on the sheet container (iOS `onAccessibilityEscape`, Android custom action "Close"). Drag is never the only way out.

**Stacking (D-28, D-29):**
- A sheet opened from another sheet (a `ConfirmSheet` over the entry sheet, sheets inside import's extras detail, the discard dialog) **stacks over it**. The first sheet stays mounted and in place, dimmed under **its own backdrop layer** (each Sheet draws its own `ink`-at-38% layer, so depth reads as a little darker — an accepted result of D-23, not a bug). Closing the top sheet returns to the first, unchanged.

- Picker hand-offs that already **close then open** (picker → Add account, the `TransactionSheet` next-frame hand-off) keep close-then-open, because the destination replaces the picker and the user does not return to it.
- Screen-reader focus: the top sheet holds focus (`accessibilityViewIsModal` on iOS, Modal window focus on Android) and announces its title; lower sheets are not focusable.

**Dismissal with unsaved work (D-25, D-26, D-27):**

| Sheet | Swipe-down / Android back / backdrop tap | Cancel |
|---|---|---|
| Entry sheet (form and list) | Closes at once, **no prompt, nothing lost**. Form and list are written to the one device draft (`useEntryDraft`, extended from the list to the form). The next Add offers "Continue list" (copy reused from 02.3 §5c). | Closes without asking, **except** with list entries: "Discard list" prompt ("Keep for later" / "Discard list"). |

Each sheet reports `dirty` through the shared Sheet interface (shape is executor discretion). The "Discard changes?" dialog is itself a stacked `ConfirmSheet` (D-28). "Keep editing", its backdrop and Android back all return to the edit sheet; "Discard" closes both.

- **Screen-reader order:** header (title focused) → quick actions → This month → Coming up → Accounts → (tab bar). Focus lands on the title on arrival and after a pull-to-refresh completes.
- **Refresh:** pulling refetches Home's queries (month totals, coming-up rows, accounts) and retries the write queue; completion toast per Pull-to-Refresh.
- **FAB:** default "Add" (Home row of the FAB table), so there are two routes to Add (the quick action and the FAB), by design: the quick action row is the prototype's, the FAB is the app-wide control.
- **Performance of bar and figures:** all derived from the one already-cached month query that Activity uses; Home mounts no extra server call.
- **Text scaling:** Home body text scales to 200% and wraps or stacks as above; the headline figure, the three totals and the date-block numerals cap at 1.3× (D-19); tab labels cap at 1.3×. Test Home at the largest iOS and Android accessibility sizes, and at 320pt wide.
- **Reduced motion:** the bar width animation and the tab slide in are the only Home motion; both honour `motion.ts`.

## Accessibility & Text Scaling (updated 2026-10-13)

- **Text scaling (DSG-07, D-19):** body text and labels scale to 200% of the OS setting, wrapping or stacking rather than clipping. Large display figures (net worth 42, health score 32, entry amount 44, **and Home's headline, IN / OUT / UNPAID and date numerals**) and **tab labels** cap at about 1.3× (`maxFontSizeMultiplier`). Test at the largest iOS and Android accessibility sizes. The migration of text components to the scaling rules touches about 68 files, not 12 (CONTEXT plan impact).
- **Screen-reader focus (NAV-06, D-20):** a tab change or push moves focus to the new screen's title. Sheets hold focus while open and announce their title; with stacked sheets only the top one is focusable. Toasts are announced politely without taking focus, including over a sheet. Tab buttons expose `role="tab"`, selected state and "{label}, tab, {n} of {total}".
- **Sheet dismissal without drag:** every sheet has the backdrop "Close" button, Cancel (where it has one), Android back and an accessibility escape action (see Sheets).
- **Reduced motion:** see Animations.
- **Touch targets:** every icon-only control and every Home tappable (chips, Pay, See all, quick actions, rows) has at least a 44px hit area, using `hitSlop` where the visual is smaller.
- **Colour is never the only signal:** the tab bar's selected state is `ink`/`inkMuted` plus `selected`; the UNPAID and negative figures are in `danger` but also labelled by caption and word ("Unpaid", the minus sign, "Overdue"); the pending bar segment is mirrored by the UNPAID figure and the bar's text summary; "Discard" in `danger` is reinforced by its text.
- **Labels contain the visible text** (WCAG 2.5.3): "Pay {name}, mark as paid" contains "Pay"; "Pay bills, shows unpaid items in Activity" contains "Pay bills".
