# Phase 3 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Platform note:** FincWin is React Native / Expo SDK 57 (iOS + Android). There is no CSS, no Tailwind, no shadcn — styling is `StyleSheet` + the typed theme context already built in Phase 0 (`src/theme/*`). All "Design System" template fields that assume a web/shadcn stack are **N/A** and answered with the RN-equivalent, exactly as `00-UI-SPEC.md` and `02-UI-SPEC.md` established. Colour, type and layout tokens are pulled verbatim from `BUILD-PROMPT.md` §2 / `FincWin United.dc.html`, already encoded in `src/theme/tokens.ts`, `layout.ts`, `typography.ts` and `motion.ts` — this document reuses those, adding only the tokens Phase 3 introduces and flagging the two `layout.ts`/`motion.ts` additions the plan must make.

**Phase 3 UI surface (per `03-CONTEXT.md`):** the tab bar (five bespoke SVG glyphs, directional slide, hidden-not-placeholder tabs per D-02), the app-wide 8-deep back history spanning tabs and detail screens (D-05–D-08), detail-screen push/pop chrome, the bottom-sheet **container** (drag-to-dismiss, discard-changes guard — not the per-feature sheet contents, which are Phase 2/5/6/7's own), the context-aware floating action button and its long-press quick menu, the tab-root header (large title → compact on scroll, avatar, back chevron), the toast's shell-level placement rule (lifting above it, not its copy — that's Phase 2 D-31), the sync-problem line (D-15, reusing Phase 1's `useSyncStatus`/`SyncStatusLine`), pull-to-refresh, shell haptics, and screen-reader/text-scale behaviour for all of the above. **Not in this phase:** the screens inside the tabs, level gating (Phase 9), the app-switcher privacy snapshot (DSG-08), feature-specific haptics.

**Accessibility:** every icon-only shell control (back chevron, avatar, tab buttons, FAB) carries an `accessibilityLabel` from the i18n catalogue and the correct `accessibilityRole`; `touch-target-min` (44px) applies regardless of the visual glyph's own smaller size (e.g. the 22px tab glyph sits inside a ≥44px tappable button, matching the prototype's `flex:1;padding:4px 0` tab-button sizing, which already exceeds 44px in practice on a 5-tab row at typical device widths — verify at implementation, do not assume).

**Focal point:** on every tab root, the screen's own large title (owned by that tab's phase) is the primary anchor; the shell's own chrome — eyebrow date line, avatar, tab bar, FAB — is secondary and must never carry more visual weight than the content beneath it. The tab bar's selected glyph/label uses plain `ink` (near-black), not `accent`, precisely so the shell's own navigation chrome never competes with a screen's actual accent-coloured calls to action (see Color, below).

| Role | Size | Weight | Line Height | Used for |
|------|------|--------|-------------|----------|
| Heading | 26px | 700 | 1.16, letter-spacing -.01em | The tab-root header's large title and the compact header's faded-in title. **Note:** the raw prototype renders this title in the *display* face (`--fw-disp`) at letter-spacing -.025em; the already-approved `02-UI-SPEC.md` instead reuses the codified `heading` role (body face, weight 700, letter-spacing -.01em) for exactly this element ("Activity", "Accounts", "Categories" screen titles). Phase 3 follows that established, checker-approved precedent rather than the raw prototype literal, for consistency across phases — this is a deliberate continuation, not a drift. |
| Sheet title | 16px | 600 | 1.2, letter-spacing -.01em | The shell's own quick-menu sheet's accessible title (draft copy "Quick add", see Copywriting); also the pushed detail-screen header title (see Declared exceptions below and Header, below) |

| Label | 13px | 600 | 1.4 | (reserved; no direct shell use beyond the meta-size override below) |

**Declared exceptions, already in `typography.ts`'s `fontSize` map — reused, not new:**

| Element | Size / weight | Note |
|---|---|---|
| Tab label | `fontSize.tabLabel` = 10.5px, weight 600 | The five tab-bar labels ("Home", "Activity", "Decide", "Grow", "Insights") — exactly the prototype's value, already declared |
| Header eyebrow (date line) | `fontSize.eyebrow` = 11.5px, weight 600, letter-spacing `.16em` | Part of the reusable `TabHeader` chrome even though the date string itself is each tab's own content |

| Avatar initials | mapped to `fontSize.s13_5` = 13.5px, weight 600 | The prototype specifies a literal 14px here (`Component` line ~61); 14px does not exist in the closed type scale and the 0.5px difference is not visually meaningful, so this maps to the nearest existing declared size rather than opening a seventh size. Flag for the checker as an intentional, minor, closed-scale mapping — not a new violation. |
| Detail-screen header title | mapped to `fontSize.sheetTitle` = 16px, weight 600, letter-spacing -.01em | The prototype specifies a literal 15.5px here (`FincWin United.dc.html` line 1999, `font-size:15.5px;font-weight:600;letter-spacing:-.01em`); 15.5px does not exist in the closed type scale. Using the same collapsing logic as the avatar initials row above, this maps to `sheetTitle` (16/600/-.01em) rather than `body` (15/500): the prototype's own weight (600) and letter-spacing (-.01em) already match `sheetTitle` exactly, only the 0.5px size differs, whereas `body`'s weight (500) would additionally mismatch the prototype's 600. Flag for the checker as an intentional, minor, closed-scale mapping — not a new violation. |

No new font size is introduced by this phase. Weights stay inside the existing closed set (400/500/600/700/800).

## Color

Reuse `src/theme/tokens.ts` and `src/theme/accents.ts` exactly — no new hex values.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `canvas` `#FBFAF7` | Tab-root and detail-screen backgrounds behind shell chrome |
| Secondary (30%) | `surface` `#FFFFFF` | The shell's own sheet container background |
| **Tab bar surface (new named use, existing token)** | `tabBar` `rgba(251,250,247,.94)` (already declared in `tokens.ts`) | The tab bar's translucent background, paired with a blur effect (`expo-blur` or platform equivalent) and a `1px` `line1` top border — this is a distinct token from plain `canvas`/`surface`, already reserved for exactly this purpose |
| Accent (10%) | `accent` (user-selected, default `#1B4D3E`) | Reserved **only** for: the FAB's fill, the focus ring (2px solid accent, 2px offset), and the pull-to-refresh spinner's tint colour. **Never** for tab selection (see below) |
| Destructive | `danger` `#B4472A` | Reserved **only** for: the "Discard" action in the discard-changes dialog (D-13) — matching the existing precedent that a destructively-labelled action renders in `danger` (Phase 2's "Delete" in the same dialog family) |

**Explicit callout — tab selection does NOT use accent.** The prototype hardcodes the tab bar's active/inactive colours as plain `ink`/`inkMuted` (`on='#14150F', off='#6E6A5E'`, `FincWin United.dc.html` line 4884), never the themeable `--fw-accent`. This is deliberate and must be preserved exactly: a user's accent choice never turns the tab bar itself into a second, competing colour signal. Selected tab glyph + label: `ink`. Unselected: `inkMuted`.

- FAB pressed/hover state: `ink` (`#14150F`) — matches the prototype's `style-hover="background:#14150F"`, i.e. the FAB darkens toward `ink` on press, it does not lighten or use a second accent shade.
- Sheet scrim: `ink` at 38–40% opacity (`rgba(20,21,15,.4)`) behind every shell-wrapped sheet and the FAB quick menu — standardises the prototype's two slightly different literal values (.38/.42) into one, since the difference is not perceptible and a single value is easier to keep consistent.
- Sheet handle: `line2` `#E2DED2`.
- Toast background: `ink` `#14150F`; toast body text: `surface` `#FFFFFF` at weight 500.
- **Toast "Undo" text — deliberate deviation from the prototype's literal `#9BC0B2`.** That hex is a lightened tint of the *default* green accent, hardcoded; since accent is user-themeable across four colours (green/navy/rust/slate), a fixed light-green would misrepresent a user who has chosen navy, rust or slate, and would also add a colour outside the documented token set. Shell instead renders "Undo" in `surface` (white) at weight 700 — distinguished from the toast body's weight 500 by boldness and position alone, not colour. No new token is needed.
- `warn1` — **not used in this phase.** It is reserved for Phase 2's account-standing indicator; Shell introduces no new colour usage of it.
- Category colours — not applicable to shell chrome.

Accent reserved for: FAB fill, focus ring, pull-to-refresh tint. Never for tab selection, never for the sheet scrim, never for the toast, never as a decorative fill.

## Tab Bar & Glyphs

**Order (D-01, a deliberate deviation from the prototype's Home · Activity · Grow · Decide · Insights):** Home · Activity · Decide · Grow · Insights. Record this deviation wherever DSG-01's screenshot-parity check runs, so the reordered tab bar is not flagged as a regression. The five glyphs themselves are unchanged from the prototype.

**Availability (D-02/D-03):** the tab bar renders from a list of currently-available tabs. Decide, Grow and Insights switch on as Phases 5/6/7 land; Home and Activity are present from Phase 3. A hidden tab is absent from layout entirely (not shown disabled/greyed) — the remaining tabs re-flow to fill the row. Levels (Phase 9) never hide a tab; the availability mechanism is for build rollout only.

**Container:** `tabBar` background (see Color), `blur(14px)`, `1px solid line1` top border, padding `9px` top, `6px` sides, bottom = `max(insets.bottom, 12)` (see Spacing).

**Glyphs — transcribed exactly from `FincWin United.dc.html` lines 1858–1875, each `22×22` viewBox `0 0 22 22`, `aria-hidden="true"` on the `<Svg>` itself (the button carries the accessible name):**

| Tab | SVG shape | Fill/stroke colour |
|---|---|---|
| Home | Four rounded rects (7×7, rx 2) at `(3,3)`, `(12,3)`, `(3,12)`, `(12,12)` — top-left and bottom-right full opacity, top-right and bottom-left at `opacity="0.45"` | `fill={tabColor}` |
| Activity | Three rounded bars (rx 1.2): `x=3 y=4 w=16 h=2.4` (opacity 1), `x=3 y=9.8 w=11 h=2.4` (opacity .45), `x=3 y=15.6 w=14 h=2.4` (opacity .7) | `fill={tabColor}` |
| Decide (centre slot, D-01) | Diamond outline: `path d="M11 3.2 18.4 11 11 18.8 3.6 11Z"` stroke width 2.2, `stroke-linejoin="round"`, fill none; plus a checkmark `path d="M7.9 11.1l2.2 2.2 4.1-4.4"` stroke width 2, round caps/joins, fill none | `stroke={tabColor}` on both paths |
| Grow | Three rounded bars (rx 1.4, vertical): `x=3 y=13 w=4 h=6` (opacity .45), `x=9 y=8 w=4 h=11` (opacity .7), `x=15 y=3 w=4 h=16` (opacity 1) | `fill={tabColor}` |
| Insights | Circle outline `cx=11 cy=11 r=8` stroke width 2.2, fill none; plus a filled centre dot `cx=11 cy=11 r=2.6` | `stroke`/`fill={tabColor}` respectively |

`tabColor` = `ink` when selected, `inkMuted` when not (see Color — this is the one place in the whole app's shell where `accent` is deliberately *not* used).

**Interaction:**
- Directional slide (NAV-01): tab content animates in via `fw-slideL`/`fw-slideR` (see Animations) with direction determined by comparing the tapped tab's D-01 index to the current tab's index — moving right in the tab order slides content in from the right (`fw-slideR`... verify sign convention against the prototype's `dir` computation at implementation, since the prototype's own variable naming (`slideL`/`slideR`) versus its `dir` sign is easy to invert by accident).
- Re-tapping the active tab (D-08): first re-tap pops to that tab's root (clears its own detail stack); a second tap (already at root) scrolls to top.
- No haptic on tab change (D-18, explicit).
- Selected state exposed via `accessibilityRole="tab"` + `accessibilityState={{ selected: true }}`; label per the Copywriting table above.

## Header

**Tab-root header (D-14):** a large title that scrolls away with content, replaced by a compact header that fades in at the top.

- **Large state:** eyebrow date line (11.5px/600, `.16em` letter-spacing, `inkMuted`) above a 26px/700 title (`heading` role), with the 42px avatar button at the trailing edge — matches the prototype's row exactly (`FincWin United.dc.html` lines 56–62), positioned at `insets.top + 21` from the top (`space.headerExtra`, already the `Screen.tsx` convention).
- **Compact state:** appears once the screen has scrolled past its large title's own height (exact threshold is executor discretion — a reasonable default is "once the large title's bounding box has fully scrolled under the compact header's own height", not a fixed pixel guess). Shows: the 26px/700 title (same `heading` role, now on a single fixed line), the back chevron (36px, `back-chevron-compact`) when the tab has back history, and the avatar (42px) on tab roots. Background `canvas`, `1px` bottom border in `line1` (the prototype's own detail-header border colour `#EFECE4` is not in the documented token set — map it to the nearest existing token, `line1` `#EDEAE1`, rather than introducing a new hex).
- Fade transition between the two states uses `fw-fade` at `DURATION.fade` (200ms, already declared in `motion.ts`) — see Animations.
- Built in JS (a `TabHeader` component composing `Screen.tsx`'s insets), explicitly **not** the native large-title header API, per D-14.
- Focus moves to the new screen's title on a tab change or a push (D-20/NAV-06) — the compact title is the accessible target once it is the visible one.

**Detail-screen header (NAV-03):** unchanged shape from the prototype (`FincWin United.dc.html` lines 1993–2002) — 38px back button (`back-chevron-detail`), a single-line title using the `sheetTitle` role (`fontSize.sheetTitle` 16px/600, letter-spacing -.01em) in place of the prototype's literal 15.5px — see Typography's Declared exceptions table for the collapsing rationale — and an optional trailing "Edit" text link in `accent` when the record is editable (owned by the record's own phase, not Shell — Shell only supplies the header shell and the back action).

**Base (D-09):** `fab-height` 50px pill, `accent` fill, `surface` label text at `fontSize.s13_5` (13.5px)/600/-.01em letter-spacing, `fab-icon-box` plus glyph in `surface`, `shadows.fab` (already declared in `tokens.ts`), positioned `right: fab-right` (16px, literal) and `bottom: fab-bottom` (computed, see Spacing — never the prototype's literal 96px).

**Per-screen action table (D-09):**

| Screen | Label | Aria | Action |
|---|---|---|---|
| Home | "Add" | "Add a transaction" | New transaction |
| Activity | "Add" | "Add a transaction" | New transaction |
| Decide | "New check" | "Start a new affordability check" | Start a check |
| Grow | follows sub-view | set by Phase 6 | "New goal" / "Add debt" / "Add holding" |

The shell exposes a registration API (any screen can set its own label/aria/action; unregistered screens get the default "Add" — implementation shape is planner/executor discretion per `03-CONTEXT.md`).

**Hide rules (D-10, NAV-05) — exact prototype logic (`fabShow`, `FincWin United.dc.html` line 6866), carried forward:** hidden during any open detail screen, any open sheet, the entry/step-flow state, the lock screen, while signed out, during onboarding, during the Decide check editor and its date pickers, and during bulk select. **Lift above toast (D-16):** while a toast is visible, the FAB translates upward by the toast's own height plus a `gap-sm` (8px) gap, so neither element overlaps and the Undo action stays reachable. Animate via Reanimated, `DURATION.entrance` (220ms), `EASING`; settle back on toast dismissal with the same timing. Exact lift distance is computed from the toast's measured height, not a hardcoded constant, since toast text can wrap to two lines on a narrow device or at 200% text scale.

**Haptics (D-18):** light `impactAsync` on a normal press; medium `impactAsync` when the long-press menu opens. Suppressed when the OS haptics setting is off.

## Sheets & Back Navigation

**Sheet container (D-12):** short, single-purpose tasks (add/edit an entry, settle up, a cap, a filter, the Pro gate, the FAB's own quick menu) render inside the shell's `SheetContainer`, built on `@gorhom/bottom-sheet` v5: `sheet-top-radius` (28px) on the top corners, `surface` background, `sheet-handle` (38×4px, `line2`, centred, top padding matching the prototype's drag-affordance spacing), scrim `ink` at ~40% opacity behind it. Multi-step flows (the Decide five-step check, statement import, onboarding) are full-screen stacks instead, pushed like a detail screen, and the FAB hides for them (D-10).

**Drag-to-dismiss (NAV-04):** any sheet can be dragged down to dismiss via `react-native-gesture-handler` + Reanimated, matching `fw-up`'s reverse. A `selectionAsync` haptic fires when a sheet closes by drag (D-18).

**Discard-changes guard (D-13):** if the sheet being dragged down (or dismissed via Android back) has unsaved changes, the drag snaps back to its open position and the discard-changes dialog appears ("Discard changes?" / "Discard" / "Keep editing" — "Discard" in `danger`). An untouched sheet dismisses immediately with no dialog. The "has unsaved changes" signal is reported by the sheet's own content (API shape is planner/executor discretion) — the shell only owns the drag/dialog mechanics.

**Back history (D-05–D-08):** one app-wide, 8-deep ordered history spanning both tab switches and detail pushes — a deliberate fix to the prototype's tab-only `hist`, which the prototype itself drops on a tab change (`FincWin United.dc.html` line 4877 `detail:null`). Visually, a back step replays whichever transition type it is popping: a detail pop uses the reverse of `fw-push`; a tab-history pop uses `fw-slideL`/`fw-slideR` per the D-01 order comparison, exactly like a forward tab tap.

- **Android hardware/gesture back (D-06):** close an open sheet (running the D-13 discard check) → else pop the history → else, on a non-Home tab with empty history, go to Home → else exit.
- **iOS edge swipe-back (D-07):** works only on detail screens, popping to their origin; it never switches tabs. Tab-to-tab back uses the compact header's back chevron.
- Sheets hold focus while open and announce their own title on open (D-20) — the `SheetContainer` should call the platform's screen-reader "announce" API or rely on RN's automatic modal-focus behaviour; verify both platforms at implementation.

## Animations

The seven named prototype animations (`FincWin United.dc.html` lines 20–28), each ported to a Reanimated worklet and gated by reduced-motion:

| Name | Effect | Duration | Easing | `motion.ts` token |
|---|---|---|---|---|
| `fw-slideL` / `fw-slideR` | Tab content enters, `translateX(±22px)` + fade | 260ms | `EASING` (`cubic-bezier(.2,.8,.3,1)`) | **New:** add `DURATION.tabSlide = 260` |
| `fw-push` | Detail screen enters, `translateX(26px)` + fade | 240ms | `EASING` | **New:** add `DURATION.push = 240` |
| `fw-up` | Sheet rises, `translateY(102%)` → 0 | 260ms for a standard sheet; 220ms for the FAB's own quick menu (a lighter, smaller surface) | `EASING` | 260ms reuses the new `DURATION.tabSlide`; 220ms reuses existing `DURATION.entrance` |
| `fw-fade` | Scrim fade-in, compact-header fade | 200ms | linear/`ease` | existing `DURATION.fade` |
| `fw-rise` | FAB entrance, `translateY(14px)` + fade | 220ms | plain `ease` (the prototype uses `animation:fw-rise .22s ease`, **not** the standard cubic-bezier — keep this distinction) | existing `DURATION.entrance` |
| `fw-spin` | Refresh spinner rotation | not ported | — | Superseded by the native `RefreshControl` (D-17); no custom spinner exists in Shell to animate |

**FAB lift above toast** (D-16, not one of the seven named animations — a new Shell-specific motion) uses `DURATION.entrance` (220ms) and `EASING`, per the Floating Action Button section above.

**Reduced motion (D-21):** the app's root layout already mounts `<ReducedMotionConfig mode={ReduceMotion.System} />` (Phase 0 00-17), which collapses every Reanimated-worklet-driven animation above to near-zero duration automatically. Any duration computed in plain JS outside a worklet (for example, deciding *when* the compact header should start its fade, if that threshold calculation itself has a debounce) must still route through `useReduceMotion()`/`duration()` from `motion.ts`, since `ReducedMotionConfig` does not reach plain-JS timing.

**Required `motion.ts` additions for this phase:** `DURATION.tabSlide = 260` and `DURATION.push = 240`, alongside the existing `entrance`/`progress`/`fade` — flag for the plan, do not hardcode 260/240 inline per animation site.

## Accessibility & Text Scaling

- **Text scaling (DSG-07, D-19):** body text and labels (including quick-menu rows, dialog copy, the sync line) scale up to 200% of the OS setting, wrapping rather than clipping. Large display figures and **tab labels** cap at ~1.3× — the tab label's 10.5px base must not grow past ~13.65px equivalent, so five labels still fit the row at the largest accessibility sizes. Test at the largest iOS and Android accessibility text sizes as part of this phase's acceptance.
- **Screen-reader focus (NAV-06, D-20):** a tab change or a push moves focus to the new screen's title (the compact header's title once scrolled, otherwise the large title). Sheets hold focus while open and announce their title. Toasts are announced politely without stealing focus (screen-reader users additionally get the D-31 non-auto-dismiss behaviour from Phase 2, already shipped). Tab buttons expose `accessibilityRole="tab"`, `accessibilityState={{selected}}`, and the "{label}, tab, {n} of {total}" label from the Copywriting Contract.
- **Reduced motion:** see Animations, above — applies to all seven named animations plus the FAB lift.
- **Touch targets:** every icon-only shell control meets the 44px `touch-target-min` regardless of its visual glyph size (22px tab glyphs, 36/38px chevrons, 42px avatar all sit inside ≥44px tappable areas).
- **Colour is never the only signal:** the tab bar's selected state is carried by both colour (`ink` vs `inkMuted`) and the `accessibilityState.selected` flag, never colour alone. The discard-changes dialog's "Discard" in `danger` is reinforced by its own text, not colour alone.
