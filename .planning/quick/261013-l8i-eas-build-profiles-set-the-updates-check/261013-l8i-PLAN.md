# Quick 261013-l8i: EAS build profiles set the updates check through env

## Problem

The preview build 24f383ae (2026-10-13, from main c2dd26c) failed at "Configure expo-updates" with a runtime version mismatch. The local fingerprint was 4a445c9f…; the one computed on EAS was a1a27962…. The config difference is `updates.checkAutomatically`: ON_ERROR_RECOVERY locally, ON_LOAD on EAS.

Cause: quick 261009-uuw (PR #66) derived `checkAutomatically` from `EAS_BUILD_PROFILE`. That variable is set only on the EAS builder, and `eas build` also evaluates app.config.ts locally to compute the fingerprint, so no preview or production build can match.

## Task 1: move the switch into build-profile env

- eas.json: development `env.APP_UPDATES_CHECK = "ON_ERROR_RECOVERY"`; preview and production `env.APP_UPDATES_CHECK = "ON_LOAD"`.
- app.config.ts: `checkAutomatically` is ON_LOAD only when `APP_UPDATES_CHECK === 'ON_LOAD'`, else ON_ERROR_RECOVERY. That keeps local runs and Metro on ON_ERROR_RECOVERY, as 261009-uuw requires.
- docs/ops/ota-policy.md: describe the mechanism and the reason for it.

## Verify

- `npx eas config --profile <preview|production|development> --platform android` resolves ON_LOAD / ON_LOAD / ON_ERROR_RECOVERY.
- `npx expo config` resolves ON_ERROR_RECOVERY.
- typecheck and lint are clean.
- After merge, an EAS preview build from main gets past "Configure expo-updates".
