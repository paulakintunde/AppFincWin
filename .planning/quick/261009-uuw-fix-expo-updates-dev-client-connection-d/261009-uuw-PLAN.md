<objective>
Stop the dev-client APK from dropping to the dev-launcher screen on cold start. Root cause (confirmed via adb logcat): `updates.checkAutomatically: 'ON_LOAD'` bakes `EXPO_UPDATES_CHECK_ON_LAUNCH=ALWAYS` into AndroidManifest.xml, so every launch fetches from https://u.expo.dev/<EAS_PROJECT_ID>. Nothing has been published to EAS Update yet, so the fetch fails with `UpdateFailedToLoad`. The app then goes to DevLauncherErrorActivity and back to DevLauncherActivity instead of loading from Metro.

Purpose: get a working dev loop back on the Pixel 9 without weakening production OTA rollback.
Output: one changed value in app.config.ts, a regenerated android/ project, a reinstalled dev-client APK, and a matching line in docs/ops/ota-policy.md.
</objective>

<planner_correction>
IMPORTANT: the requested value `'WRONG_VERSION'` is NOT a valid expo-updates option. Do not use it. I checked the installed packages:

- `node_modules/@expo/config-types/build/ExpoConfig.d.ts:123` accepts only `checkAutomatically?: 'ON_ERROR_RECOVERY' | 'ON_LOAD' | 'WIFI_ONLY' | 'NEVER'`. `'WRONG_VERSION'` fails `npm run typecheck`, because app.config.ts returns `ExpoConfig`.
- `node_modules/@expo/config-plugins/build/utils/Updates.js` `getUpdatesCheckOnLaunch()` maps unknown values to the default `return 'ALWAYS'`. Even if typechecking were bypassed, `'WRONG_VERSION'` would bake ALWAYS back in and fix nothing.

The valid option that matches the intent ("don't eagerly check every launch, only when the launch is in trouble") is `'ON_ERROR_RECOVERY'`. It maps to the native value `ERROR_RECOVERY_ONLY`.

There is a second constraint. docs/ops/ota-policy.md line 73 says the production rollback path depends on `checkAutomatically: 'ON_LOAD'` ("every cold launch checks the channel... the rollback reaches every device on its next app open"). Changing the value for every build would silently break that ops runbook. So the change is profile-aware: `ON_LOAD` stays for EAS `preview` and `production` builds, and `ON_ERROR_RECOVERY` applies to the `development` profile and to local `expo run:android` / prebuild, where `EAS_BUILD_PROFILE` is unset. EAS sets `EAS_BUILD_PROFILE` on the build worker before prebuild evaluates app.config.ts.
</planner_correction>
