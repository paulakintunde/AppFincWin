# Receipt corpus fixtures

Each `rNN.json` is the on-device OCR text of one receipt photo: `{ name, module, ocr, expected }`.

- Made on the Pixel by the dev reader (10.1-02) from the photos in `C:/dev/fincwin-private/receipts-corpus`. The photos are never committed.
- **The 2026-11-25 set (r01-r26) is synthetic.** At the owner's request, the receipts were generated by `gen_receipts.py` (kept beside the photos, outside git). They use made-up stores, a slight tilt, noise, fading and one blurred image, then were read by the real on-device reader. The true values for each receipt are in `answers.json` in the same private folder, for labelling `expected` in 10.1-15. Real paper (creases, curl, smudged thermal print) is not covered; add owner photos as r27+ when available.
- Scrubbed by `scripts/receipts/scrub-ocr-dump.mjs` (long digit runs, emails and phone numbers masked).
- `expected` is null until plan 10.1-15 labels each receipt. The scrub script never overwrites a labelled fixture.
- OCR module used: `@react-native-ml-kit/text-recognition@2.0.0`, with line frames (2026-11-25). Lines come back in reading blocks, often all item names and then all prices, so rows must be rebuilt from `frame` positions, not from line order.
- Known scrub gap: a phone number with a stray OCR space (`752 -555-8427`) is not masked. Harmless here (made-up 555 numbers), but fix the phone pattern before real receipts are added.
