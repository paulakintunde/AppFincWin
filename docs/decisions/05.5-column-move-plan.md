## The safe-step order (per column)

1. **Stop writing.** The app no longer sends the column in any patch (`DECIDE_SETTINGS_PATCH_KEYS`, `RESET_COLUMNS`).
2. **Stop reading and exporting.** Remove it from `DECIDE_SETTINGS_COLUMNS`, the row type, and `EXPORT_MANIFEST.decide_settings` in `src/data/exportManifest.ts`. Bump `CACHE_SCHEMA_VERSION` in `src/data/cache/persister.ts` (today '7') so cached rows with the old shape are discarded.
3. **Release installed.** The 05.5 release (plan 05.5-23) is on testers' phones. Old app versions that still read the columns must be gone or refused first.
4. **Floor raise.** `min_supported_version` is raised to 0.2.0 (Band B `20261121000200`), so an old build cannot read or write the dropped columns.
5. **Drop with `contract-ok`.** The drop migration (`20261121000300`) carries the `contract-ok` marker that the migration-compatibility check (`docs/ops/migration-compatibility.md`) requires for a contract-phase change, and is pushed with `npm run supabase:db:push` (preflight first).
